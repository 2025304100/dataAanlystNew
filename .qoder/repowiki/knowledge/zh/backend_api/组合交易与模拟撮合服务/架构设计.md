模块按职责划分为五个协作层：
- 组合状态层（portfolio_members.py）：通过 PortfolioMember/Position 模型提供成员的 CRUD、归档与持仓约束校验，作为所有交易入口的前置数据源。
- 资金与撮合层（sim_accounts.py + simulation_matching_engine.py + cost_model.py）：sim_accounts 负责模拟账户 CashLedger 流水与 _upsert_position 持仓更新；simulation_matching_engine 暴露 match_order_plan / apply_cost_model / update_portfolio_state 三个纯函数式接口，统一处理涨跌停、停牌、最小手数、滑点与最终状态码；cost_model 提供可配置的佣金/印花税/滑点纯函数，被 sim_accounts 与回测共用。
- 风控与预算层（allocation.py）：compute_allocation 汇总组合总仓/行业敞口，compute_position_budget 基于 PortfolioRule 的单只/行业/资产类别/可投资比例/最大开仓数等规则输出 can_open 与推荐金额，被 auto_trade_task 与 trade_plans 共同调用。
- 执行编排层（auto_trade_*.py + trade_plans.py）：auto_trade_task.run_auto_trade 遍历持仓与最新 ScanResult，根据 Score.action 决定 exit/reduce/open/buy_dip，并复用 place_sim_order 实际下单；trade_plans 基于 Score、阶段与价格区间生成分仓买入计划与预期收益场景。
依赖方向单向向下：auto_trade → allocation/sim_accounts/market_rules → cost_model；trade_plans → allocation/bar_queries；sim_accounts → cost_model/market_rules；各层不反向引用上层编排逻辑。
