## 机会中心页面 UI 诊断与改造建议

- 输入：运行态截图（任务已中止 / 候选 2 只），分析 `frontend/src/components` 实现。
- 产出：`机会中心页面改造建议.md`（根目录）。
- 核心结论：页面是「筛选配置器」而非「机会看板」，需改为 状态带 / 条件带 / 结果带 三带式 + 配置抽屉。

### 定位到的代码问题（供后续改造参考）
- `Discovery.tsx:1041-1046`：进度条用 `task.percent`，计数文案用 `total/processed`，两个分母并排 → "100% / 已完成 0" 矛盾。
- `Discovery.tsx:117-126` `stepClassName()`：无 `cancelled` / `failed` 分支，异常时五步全灰。
- `DataPrepActions.tsx:253`：`<Alert message={notice} showIcon />` 无 `action`，只报忧不给解。
- `CandidatePool.tsx:28`：直接渲染 `<Discovery />`，筛选表单与结果表耦合，阻碍"结果优先"布局。
- 页面存在两套任务体系（`prepTask` / `scanTask`），各渲染一个 primary 按钮。

### 建议的改造优先级
P0：步骤条异常态、进度同源、Alert 带 action、主按钮唯一化（仅 3 个文件，不改后端）。
P1：结果上首屏 + 配置进抽屉、筛选条件 chips 化 + 放宽预览、排除项"差多少分"。
P2：术语统一（只留"更新数据"/"筛选"）、破坏性操作收菜单。
