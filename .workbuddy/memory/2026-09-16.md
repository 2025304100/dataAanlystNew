### ★ 两个 P0 级实现阻断（v1.0 完全没发现，本项目最重要结论）

1. **`purge_days`/`embargo_days` 单位歧义**
   `build_time_split`（`factor_evaluator.py:268-269`，`val_start_idx = train_end_idx + purge_days`）
   把该参数当作**传入 `all_dates` 的索引间隔**。挖掘传的是「有效调仓点」而非交易日，传 `5` 会让：
   周频=隔离 5 周、月频=隔离 5 个月，与"阻断 T+5 持有期标签跨界"的本意完全不符。
   换算：`purge_points = max(1, ceil(target_horizon_days / REBALANCE_INTERVAL_DAYS[freq]))`，
   `REBALANCE_INTERVAL_DAYS = {daily:1, weekly:5, monthly:21}` → **daily 5 / weekly 1 / monthly 1**。

2. **默认 `min_validation_days=50` 使周/月频必然 `hard_fail`**
   `derived_min_total = max(20, ceil((50+purge+embargo)/0.2))` → 归一化后仍 = **260**
   （daily 用 purge=5 时是 300）。周频 243 点、月频 60/120 点全部抛
   `ValueError("insufficient_dates ...")`。
   **必须显式传 `min_validation_days`/`min_test_days`/`min_total_days`**：
   `SPLIT_MINIMUMS = {daily:(252,100,50), weekly:(104,20,10), monthly:(36,6,3)}`。
   ⚠️ **两处必须同时改**——已实测：只做归一化、仍用默认 50 仍然全抛异常。

### 核心设计（可复用的方法论）
**Agent 排期 ≠ 人类排期**，五个本质差异：
| 维度 | 人类 | Agent |
|---|---|---|
| 上下文传递 | 会议/口头 | **`PROGRESS.json` 的 `decisions` 字段**（必须落盘，否则新 Agent 会重新决策→漂移） |
| 任务粒度 | 人日 | **单会话 ≤3h / ≤8 产物 / ≤3 条 DoD** |
| 验收 | 评审会 | **可执行命令 + exit code**，没跑=没做 |
| 并行约束 | 协商分工 | **写权限文件级互斥**，脚本自动排除 |
| 失败 | 找人问 | **标 blocked + 结构化理由 + 停手**，禁止自行发挥 |

**四个机制**：① 状态账本（唯一事实来源，未登记=pending）② 任务卡 8 字段（ID/目标/前置/产物/DoD/读/不做/预算）③ 写权限互斥表 ④ `next_task.py` 把"我该做什么"从主观判断变成确定性输出。

**关键设计**：`decisions` 字段。上一个 Agent 的非显然取舍必须写在这里，否则下一个会重新想一遍（通常想得不一样）。
