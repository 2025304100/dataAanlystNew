## P1：先修复的 11 组问题

### S01 规则配置的保存按钮没有提交动作

[Settings.tsx:333](D:/ai_project/dataAanlystNew/frontend/src/components/Settings.tsx:333) 使用 Antd `Button type="primary"`，没有 `htmlType="submit"`，也没有 `onClick`。保存函数只绑定在同文件 239 行的 form `onSubmit`；当前安装的 Antd 默认 HTML 类型为 `button`。

结果：点击「保存规则」不会调用保存 API，刷新会丢失编辑。保存 API 和实际消费者本身存在，断点在前端操作入口。

### S02 接口管理的「禁用」不能阻止真实请求

配置更新真实落库并刷新缓存，但 [akshare_registry.py:639](D:/ai_project/dataAanlystNew/app/services/akshare_registry.py:639) 的 `is_api_enabled` 在生产代码中没有调用者。[akshare_utils.py:205](D:/ai_project/dataAanlystNew/app/services/akshare_utils.py:205) 读取重试次数和延迟后，在 237 行直接执行供应商函数，没有检查 `enabled`。估值、行情等业务通过该入口请求。

结果：关闭某个接口后，相关业务仍可能调用它。修复应明确禁用后的跳过、备用源及任务结果口径，不能仅让开关变色。

### S03 评分因子的方向可以保存，但不会改变评分

[ScoringConfigSettings.tsx:486](D:/ai_project/dataAanlystNew/frontend/src/components/ScoringConfigSettings.tsx:486) 可改 `higher_better / lower_better / range_better / lower_or_range_better`；[scoring_config_engine.py:610](D:/ai_project/dataAanlystNew/app/services/scoring_config_engine.py:610) 只取因子值、缺失策略和权重，没有读取方向。

隔离复现：输入分数 80，四种方向最终都得到 80。部分内置分数已在前置计算中转换过方向，修复时需要建立原始值与标准分契约，不能把全部分数简单反转。

### S04 公式计算失败、历史不足被伪装成真实 0 / false

[backtest.py:1710](D:/ai_project/dataAanlystNew/app/services/backtest.py:1710) 对计算结果 None 或异常返回 `False`；[custom_indicators.py:341](D:/ai_project/dataAanlystNew/app/api/routes/custom_indicators.py:341) 在数值预览中执行 `float(False)`，变成 `0.0`，仍按正常结果返回。机会筛选与回测复用该求值器。

纯内存复核：`1 / 0`、不满足计算条件的 `macd(12,26,9)`、仅 1 根 K 线时的 `sma(20)` 均可通过静态校验，实际返回 False。用户无法区分计算错误、数据不足和真实零值，筛选结果可能被污染。

### S05 相似信号的「20 日收益」会使用不足 20 日的行情

[signal_stats.py:138](D:/ai_project/dataAanlystNew/app/services/signal_stats.py:138) 只截取前 N 日，后续仅判断切片非空；168 行把未满 20 日的末值计为 `return_20d`，208 行纳入 20 日胜率。

内存样本只有 1 日后续行情，仍同时得到 3 / 5 / 10 / 20 日收益 10%，20 日胜率 100%。规则预览的收益期限和样本成熟度不可信，应各期限分别满足完整交易日数量后才纳入统计。

### S06 两类告警可以创建启用，却永远不触发

[AlertCenter.tsx:45](D:/ai_project/dataAanlystNew/frontend/src/components/AlertCenter.tsx:45) 提供「指标触发」与「观察信号」；API schema 也允许创建为 enabled。实际 [alerts.py:508](D:/ai_project/dataAanlystNew/app/services/alerts.py:508) 的 `indicator_trigger` 无条件返回空列表，`watchlist_signal` 不在 514 行执行器映射中，会被直接跳过。

这是未向用户明确禁用的空实现。研究页还有默认创建指标告警的入口，公式的提醒适用范围也没有接入该执行器。

### S07 因子集合删除成员时，前后端使用不同 ID，可能删错因子

[FactorModelPage.tsx:2808](D:/ai_project/dataAanlystNew/frontend/src/components/factors/FactorModelPage.tsx:2808) 和 3868 行传成员记录 `m.id`；[client.ts:3059](D:/ai_project/dataAanlystNew/frontend/src/api/client.ts:3059) 原样拼到 URL；后端 [factor_sets.py:132](D:/ai_project/dataAanlystNew/app/api/routes/factor_sets.py:132) 及 [factor_set_service.py:255](D:/ai_project/dataAanlystNew/app/services/factors/factor_set_service.py:255) 却按 `factor_id` 删除。返回 DTO 明确区分这两个字段。

独立内存 SQLite 复现：A 的 `member_id=2, factor_id=1`，B 的 `member_id=11, factor_id=2`。点击 A 对应传入 2，真实服务删除 B，A 仍保留。若没有 ID 碰撞则通常报找不到成员。现场只读集合中 9 个成员有 8 个两种 ID 不同；现场集合为 frozen，未执行删除，也不能将其当作已发生误删。

## 不能混作“空架子”的项目与待确认边界

1. **告警评估目前只有手动执行。** 生产代码对 `evaluate_all_rules` 的唯一调用为 `alerts.py:127` 手动路由，没有后台定时评估。能手动评估的规则不是空实现，但当前「启用」不能理解为常驻自动监控，应明确显示运行方式，或接入调度器。
2. **因子基础配置的本地演示项已说明不落库。** 这仍是未完成功能，应按此前产品要求默认隐藏或收进“暂不支持”视图，但不能伪称它正在假保存。
3. **挖掘里已禁用的停牌、指数成分等字段不计作假执行。** 本轮不重复列已修复、已诚实限制的历史问题；已有验收报告中仍列出的后续事项继续有效。
4. **公式的 review 适用范围未找到实际复盘消费者。** 当前更像分类元数据；没有足够证据认定某个已承诺的复盘动作失效，单列待补定义与闭环。
5. **评分配置 API 的结构校验偏弱。** config 接收任意 dict，损坏结构可能保存 / 激活后在引擎报错，analysis 再静默回退旧评分；尚未通过正常 UI 编辑复现结构损坏，应补 API 契约测试与显式失败提示。
6. **覆盖率有近似口径。** 单标的诊断按 5/7 估算预期交易日，不能将节假日差异直接当成真实缺数；这是口径精度问题，不是没有读取数据。
