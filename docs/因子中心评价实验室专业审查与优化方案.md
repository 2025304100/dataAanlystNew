# 因子中心评价实验室专业审查与优化方案

> 审查日期：2026-08-12  
> 审查范围：设置 → 因子中心 → 评价实验室  
> 审查视角：专业量化研究、前端交互、数据依赖、计算准确性、任务可靠性与上线门禁

## 1. 执行摘要

当前“因子评价实验室”具备因子定义、版本管理、公式编译、异步任务、基础指标展示等研究基础，但现阶段只能视为**研究原型和界面联调工具**，不能作为因子上线、实盘配置或投资决策依据。

主要结论如下：

1. 截图中的直接异常已定位：编译器返回 `ExecutionPlan` 数据对象，失败诊断代码却把它当作列表遍历，触发 `'ExecutionPlan' object is not iterable`。
2. 该异常属于二次异常：因子没有成功出数后，本应执行数据诊断，但诊断代码自身崩溃，覆盖了真正的数据或公式问题。
3. 当前评价任务没有使用仓库中已经存在的真实未来收益标签，而是使用因子值自身移位构造“目标收益”，导致 IC、分组收益和门禁结论失去量化意义。
4. 当前正式评价通过每日 `preview()` 逐日读取，并限制为 500 个标的；实际股票池约 5550 个标的，样本被严重截断。
5. 滚动公式在保留完整历史窗口之前被过滤为单日数据，移动平均、滚动波动率等时序因子可能没有按预期计算。
6. 默认回看区间和门禁要求不匹配：120 个自然日产生的验证交易日远低于“至少 50 个验证交易日”的门槛，默认任务可能天然无法通过。
7. 前端虽然已经使用左右双栏，但配置、进度、错误、任务列表和报告继续纵向堆叠，用户仍需频繁向下滚动。

建议立即暂停将“评价通过”连接到因子激活、Shadow、Ridge 或实盘流程。先完成 P0 计算链路修复和黄金样本验证，再恢复门禁的业务含义。

## 2. 现状与证据

### 2.1 截图异常的直接根因

编译器返回的执行计划是数据类：

```python
@dataclass
class ExecutionPlan:
    compiler_version: str
    formula: str
    formula_ast: dict[str, Any]
    params: dict[str, Any]
    postprocess: dict[str, Any] | None
    direction: str
    data_dependencies: dict[str, Any]
    complexity_score: float
```

但评价任务在无因子输出时执行了类似逻辑：

```python
for step in compile_result.execution_plan or []:
    ...
```

`ExecutionPlan` 不可迭代，因此产生：

```text
TypeError: 'ExecutionPlan' object is not iterable
```

正确方式应直接读取结构化依赖：

```python
plan = compile_result.execution_plan
dependencies = plan.data_dependencies if plan else {}
required_fields = dependencies.get("fields", [])
source_tables = dependencies.get("source_tables", [])
```

相关代码位置：

- `app/services/factors/factor_compiler.py`：`ExecutionPlan` 定义。
- `app/services/factors/wp5_eval_task.py`：错误遍历执行计划的位置。

### 2.2 实际数据仓库并非完全无数据

审查时核验到的数据规模：

| 数据对象 | 规模或范围 |
|---|---:|
| 日行情 `raw_daily_bars` | 约 2,068,673 条 |
| 行情交易日 | 383 日 |
| 行情标的数 | 约 5,550 |
| 真实目标标签 `factor_targets` | 约 8,969,409 条 |
| 可交易目标标签 | 约 8,336,900 条 |
| 行情日期范围 | 2025-01-13 至 2026-08-12 |
| 标签日期范围 | 2025-01-13 至 2026-08-10 |

因此截图问题不能简单归因于“没有初始化补数”。系统已经有基础行情和真实目标标签，但评价任务没有正确复用这些数据，诊断路径还可能错误推断“未补数”。

### 2.3 当前目标收益是占位实现

评价任务目前使用如下方式构造目标收益：

```python
forward_returns = factor_values.shift(-target_horizon).pct_change(
    periods=target_horizon,
    fill_method=None,
)
```

这相当于用因子值自身生成标签，而不是使用未来价格收益。其后果包括：

- 特征与标签同源，产生机械相关或伪相关。
- IC 不再表示因子对未来收益的预测能力。
- 分组收益不代表真实投资收益。
- 换手和成本后的净收益没有可交易解释。
- “通过/拒绝”门禁不具备量化研究意义。

项目中已经存在真实标签引擎 `app/services/factors/target_engine.py`，能够生成 T+1 开盘至 T+5 收盘收益，并处理停牌、无成交、涨停无法买入、跌停无法卖出等可交易性问题。评价任务应直接使用 `factor_targets` 中冻结批次的真实标签。

## 3. 专业量化可用性评价

### 3.1 总体判断

| 能力 | 当前评价 | 是否可用于生产 |
|---|---|---|
| 因子定义与版本 | 已具备基础结构 | 可继续建设 |
| 公式编译与安全执行 | 基础较完整，但执行窗口存在风险 | 修复后可用 |
| 异步任务与进度 | 已具备框架，错误分类不够可靠 | 修复后可用 |
| 数据依赖诊断 | 存在错误接口假设和二次异常 | 当前不可用 |
| IC/ICIR 计算框架 | 形式存在，但输入标签不可信 | 当前不可用 |
| 分组收益与成本 | 过度简化，缺少真实组合口径 | 当前不可用 |
| 因子上线门禁 | 依赖失真的指标 | 必须暂停 |
| 前端实验工作台 | 功能齐全但信息架构低效 | 需要重构 |

### 3.2 P0 级准确性问题

| 问题 | 当前表现 | 影响 |
|---|---|---|
| 执行计划类型使用错误 | 将 `ExecutionPlan` 当列表遍历 | 真正失败原因被二次异常覆盖 |
| 目标收益错误 | 使用因子值自身移位生成目标 | IC、分组收益和门禁失效 |
| 标的截断 | 每日只取 500 条预览结果 | 正式评价样本不完整 |
| 滚动历史丢失 | 过滤到单日后再执行滚动公式 | 均线、波动率等计算错误 |
| 自然日代替交易日 | 连续遍历 120 个自然日 | 无效查询多、样本日不足 |
| 回看期与门槛冲突 | 默认验证集少于 50 个交易日 | 默认配置天然易失败 |
| 数据诊断能力不存在 | 调用不存在的 `describe/list_trade_dates` | 有数据也可能误报未补数 |
| 因子方向未统一 | `lower_better/nonlinear` 未充分进入计算 | 负向因子可能被反向判定 |

### 3.3 P1 级研究可信度问题

1. **股票池没有按历史日期冻结**  
   可能存在幸存者偏差、退市样本遗漏、新股上市期处理不一致等问题。

2. **Point-in-time 数据约束不足**  
   财报、估值和事件数据必须按当时已知日期进行 as-of join，不能把后续修订值写回历史。

3. **横截面后处理边界不明确**  
   去极值、标准化、排序和缺失值处理必须按交易日横截面执行，不能跨日期混合。

4. **换手率不等于可执行组合换手**  
   当前基于全体排名权重估算，未体现选股数量、权重约束、停牌和涨跌停等真实组合规则。

5. **成本模型过度简化**  
   固定单边费率不能覆盖佣金、印花税、滑点、冲击成本和成交容量。

6. **训练、验证、测试边界不完整**  
   虽然存在 purge 和 embargo 参数，但结果主要在验证区间计算，没有真正独立且只使用一次的测试集结论。

7. **事件因子和状态因子使用同一表单**  
   事件因子需要事件样本、窗口和对照组；状态因子需要状态区分与持续性分析，不能直接复用连续因子的 IC 表单。

8. **缺少多重试验治理**  
   用户反复调整参数后选择最好结果，会形成严重的数据挖掘偏差，需要保存每次试验和候选数量。

### 3.4 复核新增的实现风险

本轮交叉检查还发现以下容易被首轮方案遗漏、但会直接影响结果或故障定位的细节：

| 优先级 | 风险 | 具体影响 |
|---|---|---|
| P0 | 字段目录与仓库表结构可能漂移 | 例如字段目录声明 prev_close，实际日行情表未必存在该列；SQL 失败后可能被当成“无数据” |
| P0 | 数据读取异常被静默跳过 | 执行器对单表查询异常直接 continue，用户看不到真实表名、字段和数据库错误 |
| P0 | 多源表默认按 symbol + trade_date 合并 | 财报使用公告日等异构时间字段，不能直接套用日行情连接方式 |
| P0 | 正式评价使用 raw_value | 因子版本配置的去极值、标准化、排序和缺失策略没有进入评价值口径 |
| P0 | 目标表与因子值表存在多批次 | 查询时如果不冻结唯一批次并去重，可能产生重复样本或混合不同计算版本 |
| P0 | 单飞任务只按因子代码复用 | 同一因子、不同区间或费用参数可能错误复用旧任务 |
| P0 | 历史终态运行可能没有时间切分 | 后续压力测试直接访问空 time_split 时仍可能二次异常 |
| P0 | 门禁先终态、压力测试后写入 | 压力测试失败时可能出现“运行已终态、任务却失败”的不一致状态 |
| P1 | 滚动函数 min_periods=1 | 20 日因子在第 1～19 日也产生值，形成不可比的预热期样本 |
| P1 | 后处理没有明确按日分组 | 全区间统一 winsorize/zscore 会混合不同日期的横截面 |
| P1 | 无有效截面被记为 IC=0 | 样本不足日不应作为零 IC 参与均值，否则系统性压低或扭曲指标 |
| P1 | ICIR 和 Sharpe 未注明是否年化 | 当前均值除标准差的数值容易被用户误认为年化指标 |
| P1 | 5 日未来收益存在重叠 | 相邻信号共享未来收益区间，显著性和稳定性需要 Newey-West 或块自助法修正 |
| P1 | 换手只比较共同标的 | 新进入和退出股票被忽略，换手和成本可能被低估 |
| P1 | 成本周期可能不匹配 | 5 日持有收益不能直接减去未经调仓频率对齐的日换手成本 |

这些问题需要进入 P0/P1 排期，而不是只作为技术备注保留。

## 4. 前端交互与信息架构方案

### 4.1 设计目标

- 用户在首屏完成因子选择、数据检查和运行操作。
- 在提交任务前发现依赖问题，不让用户等待到 30%～70% 才失败。
- 运行详情、历史记录和诊断按任务切换，不继续向页面底部叠加。
- 错误信息提供“事实证据 + 影响 + 修复动作”，不把 Python 异常作为主文案。
- 基础用户看到合理默认值，专业用户可进入高级参数。

### 4.2 推荐页面结构

#### A. 首屏固定配置区

建议顶部使用一行或两行紧凑工作台：

- 因子与版本。
- 因子方向与类型，默认从版本元数据读取，不允许随意覆盖。
- 股票池。
- 评价区间。
- 目标收益口径。
- 数据截止日。
- 运行评价按钮。

分组数、费用、purge、embargo、去极值、标准化等放入“高级参数”抽屉。

#### B. 自动前置检查卡

选择因子后立即调用预检查接口，显示：

| 检查项 | 示例内容 |
|---|---|
| 公式 | 已通过编译 |
| 依赖字段 | 已满足 3/4 |
| PIT 安全性 | 通过 / 有风险 |
| 因子数据区间 | 2025-01-13 至 2026-08-10 |
| 目标标签 | 238 个可用交易日 |
| 股票池覆盖率 | 91.4% |
| 预计有效样本 | 1,042,300 |
| 预计耗时 | 约 35 秒 |

有阻断项时禁用“运行评价”，同时给出明确动作：

- 补齐行情。
- 同步估值或财务数据。
- 修改公式。
- 调整评价区间。
- 切换为事件型评价模板。

#### C. 结果区改为页签

推荐四个页签：

1. **评价结果**：门禁、IC、ICIR、分组收益、换手、成本、覆盖率。
2. **稳定性**：滚动 IC、年度表现、市场状态、参数扰动、衰减分析。
3. **数据诊断**：日期 × 字段覆盖、异常样本、缺失原因和依赖证据。
4. **运行记录**：历史任务、配置差异和结果对比。

选择历史运行后，在同一区域替换报告内容，不要在页面底部追加整份报告。

#### D. 任务进度改为右侧抽屉

运行后显示轻量抽屉：

- 当前阶段和进度。
- 当前处理日期或批次。
- 已用时与预计剩余时间。
- 取消任务。
- 最近结构化日志。
- 阻断原因。
- 修复后重新运行。

任务列表默认只显示最近 5 条，其余进入独立历史视图。

### 4.5 各模块位置与设计要求

#### 4.5.1 页面标题栏

- 位于因子中心页签正下方。
- 左侧放标题和一行说明，标题不超过 20px，控制页头高度。
- 右侧只保留“刷新”和“口径说明”，不放运行按钮。
- 标题栏底部与配置工作台间距为 8～12px。

#### 4.5.2 吸顶评价配置工作台

- 占内容区完整宽度，是页面最高优先级操作区。
- 第一行放因子、版本、股票池、评价区间和目标收益。
- 第二行左侧只读展示因子类型、方向、数据截止日和复权口径。
- 第二行右侧依次放“高级参数”和唯一主按钮“运行评价”。
- 主按钮固定在工作台右下方，用户不必滚动寻找。
- 因子类型和方向从版本读取，使用只读标签，避免手工选择造成口径冲突。
- 吸顶状态只增加轻微底边或阴影，不使用大面积强调色背景。

- 位于工作台下方右侧，与左侧结果页签顶部对齐。
- 桌面端局部吸顶，顶部距离配置工作台底部 12px。
- 顶部显示“可运行”“存在 1 个阻断项”或“正在检查”。
- 中部依次展示公式、依赖字段、行情、股票池、目标标签、PIT 和样本规模。
- 每项只显示状态图标、名称和关键证据值，长说明默认折叠。
- 底部展示预计样本数、耗时和修复动作。
- 有阻断项时，“前往修复”成为该卡片主动作，“运行评价”同步禁用。

#### 4.5.4 左侧主结果区

- 与就绪检查区顶部对齐，占 8 列。
- 顶部使用“评价结果、稳定性、数据诊断、运行记录”页签，不再为每类信息增加大卡片。
- 默认页首屏先展示结论条和 4～6 个关键指标，再展示 IC 与分组收益图。
- 次要指标进入折叠区或指标表，不使用一项一卡片。
- 主图建议高 280～340px，保证 900px 高度下至少看到一张完整图。
- 历史报告在当前区域替换，不追加到页面最底部。

#### 4.5.5 运行记录页签

- 位于主结果区第四个页签。
- 顶部放状态、因子、日期区间和门禁结果筛选。
- 使用单一表格合并“任务”和“运行结果”，避免两张相似表。
- 点击某行后在当前区域打开详情，或从右侧滑出详情抽屉。
- 默认每页 10 条，不设置过高的表格内部纵向滚动区。

#### 4.5.6 任务进度抽屉

- 从浏览器最右侧覆盖打开，建议宽 380px。
- 头部固定展示因子、状态、取消或关闭操作。
- 正文顺序为阶段进度、当前步骤、耗时、结构化日志、错误和修复动作。
- 正文独立滚动，底部操作区固定。
- 成功时主按钮为“查看评价结果”；失败时为“前往修复”或“按原配置重试”。
- 关闭抽屉不取消任务，页面右上角保留轻量任务状态入口。

#### 4.5.7 高级参数抽屉

- 与任务抽屉使用相同右侧位置，但不能同时打开。
- 参数按“分组与目标、时间切分、成本、后处理”分组。
- 每组先显示推荐值，专业参数配合口径说明。
- 底部固定“恢复推荐值”和“应用参数”。
- 应用后只更新工作台参数摘要，不自动提交任务。

### 4.9 结果页图表与信息密度规范

#### 4.9.1 首屏指标位置

“评价结果”页签从上到下建议排列：

1. 门禁结论条：占满左侧主结果区宽度，包含结论、主要失败原因、数据截止日和运行版本。
2. 核心指标行：最多 6 项，顺序为 Rank IC、ICIR、正 IC 比例、Top-Bottom 收益、覆盖率、有效样本。
3. 第一主图：滚动 IC 时序图。
4. 第二主图：分组收益柱状图或折线图。
5. 换手、成本和风险暴露表。

核心指标必须同时显示数值、单位、口径和验证区间；不能只显示一个没有解释的数字。门禁失败项应直接标出“实际值 / 阈值”，例如“ICIR 0.08 / 要求 ≥ 0.15”。

#### 4.9.2 图表规格

| 图表 | 位置 | 必须包含 |
|---|---|---|
| 滚动 IC | 评价结果第一主图 | 0 基准线、滚动窗口、验证/测试区间、缺失区间、悬浮日期和数值 |
| 分组收益 | 第一主图下方 | Q1～Q5、方向说明、成本前后切换、单调性标识 |
| IC 分布 | 稳定性页签 | 直方图或箱线图、均值、中位数、显著性 |
| 分年度/状态 | 稳定性页签 | 统一纵轴，避免视觉夸大差异 |
| 数据覆盖热力图 | 数据诊断页签 | 日期 × 字段、缺失类型、可点击问题单元格 |
| 参数扰动 | 稳定性页签 | 基准参数、邻域结果、符号是否一致、断崖点 |

图表不得用红涨绿跌的市场颜色表达“通过/失败”，以免状态语义与收益方向冲突。收益正负可使用产品统一的行情色，门禁状态使用独立图标和文字。

#### 4.9.3 长文本与表格

- 因子代码、任务 ID、运行 ID 默认单行省略，悬浮显示全量并提供复制。
- 错误详情最多默认展示两行，展开后显示证据和技术参考号。
- 表格列优先级按“因子、状态、区间、结论、时间、操作”排列。
- 低优先级批次字段在窄屏进入展开行，不依赖横向滚动才能看到主要操作。
- 空状态必须说明下一步，例如“选择因子开始前置检查”，不只显示空图标。

### 4.10 可访问性、状态保持与本地化

- 所有状态不能只靠颜色表达，必须配合图标和文本。
- Tab、Enter、Space、Esc 应覆盖页签、抽屉、下拉框、按钮和错误修复操作。
- 打开抽屉后焦点进入抽屉，关闭后返回触发按钮；Esc 关闭抽屉但不取消任务。
- 错误汇总使用可被辅助技术识别的实时区域，但避免轮询时重复播报相同内容。
- 图表提供可访问摘要和数据表替代入口。
- 所有图标按钮必须提供可见文字或 accessible name。
- 因子、运行 ID、筛选条件和选中页签应写入 URL 查询参数或稳定状态存储，刷新和修复返回后可恢复。
- “新配置”与“当前报告配置”必须分开保存，避免用户编辑参数时悄悄改变正在查看的历史报告语境。
- 用户修改任何影响结果的配置后，旧报告显示“结果基于上一配置”，不得继续表现为当前结果。
- 时间统一展示用户时区，并在口径说明中注明后台保存格式；避免 UTC 时间与本地时间混淆。
- 中英文文案必须通过 i18n key 管理；按钮宽度按中英文最长文案验证，避免中文可用、英文截断。
- 数值统一使用本地化格式：比例、bps、金额、交易日和样本量分别使用明确单位。

### 4.11 性能、轮询与埋点

- 前置检查输入变化后使用 300～500ms 防抖，并取消已过期请求，避免旧响应覆盖新选择。
- 运行任务优先采用事件推送；若保留轮询，前台建议 2～3 秒、后台标签页降频，并在终态立即停止。
- 页面恢复网络连接后先拉取任务最终状态，不重复创建任务。
- 运行按钮需前端防重复点击，后端使用完整配置哈希保证幂等。
- 长表格超过约 200 行时再启用虚拟化；默认 10 行分页不需要虚拟化。
- 图表只渲染当前页签，切换时保持筛选状态。
- 至少记录以下产品埋点：前置检查完成率、阻断类型、从阻断到修复的点击率、任务成功率、失败阶段、平均完成时间、重试成功率和用户放弃位置。
- 埋点不得包含公式全文、个人数据、数据库路径或异常堆栈等敏感技术信息。

### 4.12 错误信息规范

推荐统一为以下结构：

```json
{
  "code": "eval.data.target_coverage_insufficient",
  "severity": "error",
  "category": "data",
  "title": "未来收益标签覆盖不足",
  "evidence": {
    "required_trade_days": 100,
    "available_trade_days": 19,
    "required_samples": 10000,
    "available_samples": 3862
  },
  "impact": "无法形成可靠的 IC 和分组收益结论",
  "fix_action": {
    "type": "navigate",
    "target": "init-backfill",
    "label": "补齐目标收益所需行情"
  },
  "retryable": true,
  "technical_reference": "correlation_id"
}
```

前端主界面不应直接展示 `TypeError`、`NoneType` 或堆栈信息。技术信息可放在“查看诊断详情”中。

## 5. 后端与数据链路改造

### 5.1 P0：恢复正确运行

1. 修复 `ExecutionPlan` 依赖读取，并增加无因子输出场景的回归测试。
2. 新增 `POST /factor-evaluation/preflight`，在创建任务之前完成依赖、日期、股票池、标签和样本规模检查。
3. 使用真实交易日历选取评价日期，禁止按自然日逐日猜测。
4. 批量读取完整时间区间的因子面板，取消每天调用一次 `preview()`。
5. 正式评价禁止 `limit=500`；预览采样与正式计算必须使用不同接口和明确命名。
6. 在完整历史窗口上计算滚动公式，计算完成后才截取目标信号日。
7. 从 `factor_targets` 读取真实、可交易、冻结批次的未来收益。
8. 当前标签引擎只提供固定 5 日收益时，前端只能选择 5 日；若开放 1～60 日，标签引擎必须同步参数化。
9. 数据不足、公式错误、全 NaN、目标不足、样本不足和系统异常分别使用不同错误码。
10. 任何 P0 阻断不得生成正式 EvaluationRun，也不得进入激活门禁。
11. 启动时校验字段目录与 DuckDB 实际 schema；发现字段或日期键不一致时，直接指出表名与字段名。
12. 数据读取不得静默吞掉 SQL 异常，必须返回 source_table、required_fields、exception_category 和 correlation_id。
13. 多源数据按各自时间语义连接：日行情使用 trade_date，财报使用公告日 as-of join，禁止统一外连接。
14. 明确正式评价值列：raw、winsorized 或 normalized 只能选择一个冻结口径，并与因子版本后处理配置一致。
15. 因子值和目标标签按唯一 calc_batch_id 查询，并在指标计算前验证 symbol + signal_date 唯一性。
16. 任务幂等键必须包含因子版本、股票池、区间、目标、分组、成本及高级参数，不能只使用 factor_code。
17. 压力测试完成前不写入最终门禁终态；任何子阶段失败都要保证任务状态与运行状态一致。
18. 历史运行缺少时间切分证据时不得继续压力测试，应标记为旧版不可完全复现记录。

### 5.2 推荐的正式评价数据流

```text
选择因子与版本
    ↓
解析执行计划和数据依赖
    ↓
冻结股票池、行情批次、目标批次和截止日
    ↓
前置检查：日期、字段、PIT、覆盖率、样本数
    ↓
完整历史窗口批量计算因子值
    ↓
按信号日截取，并按历史股票池过滤
    ↓
连接真实未来收益标签和可交易状态
    ↓
按交易日进行横截面后处理
    ↓
Purged / Embargo 时间切分
    ↓
IC、分组、换手、成本、稳定性与风险归因
    ↓
冻结运行证据和生成报告
```

### 5.3 P1：恢复量化结论可信度

每个评价运行必须冻结并持久化：

- 因子 ID、版本 ID、公式和执行计划哈希。
- 行情数据批次。
- 目标标签批次。
- 股票池快照 ID。
- 数据截止日期。
- 复权口径。
- PIT 连接策略。
- 评价参数哈希。
- 评价器代码版本。
- 创建人和创建时间。

数据与计算要求：

- 财报按公告日进入可见集。
- 估值、事件和另类数据执行严格 as-of join。
- 股票池按历史日期恢复上市、退市、ST、停牌和可交易状态。
- 横截面去极值、标准化、排序和中性化按每个交易日独立执行。
- 所有因子统一转换为“数值越大越看多”的研究方向。
- 时序函数必须配置完整预热期；20 日窗口默认前 19 个有效交易日不进入正式样本，不能以 min_periods=1 直接放行。
- 样本不足、常数截面或无法计算相关性的日期标记为 invalid date，不得按 IC=0 混入均值。
- 使用 walk-forward 或 purged time-series split。
- 最终测试集只允许使用一次，调参只能使用训练和验证区间。
- 对重叠未来收益和 IC 序列自相关使用 Newey-West、块自助法或非重叠抽样给出稳健显著性。
- ICIR、Sharpe、收益与换手必须显示原始频率、是否年化、年化因子和持有周期。
- 组合换手使用前后完整持仓并纳入新进入与退出标的，不能只比较共同股票。
- 输出市场、行业、市值和波动率暴露，避免把风险暴露误判为 alpha。

### 5.4 指标体系建议

#### 连续型因子

- Rank IC 均值、中位数、标准差和 ICIR。
- 正 IC 比例和 IC 显著性。
- 滚动 IC、年度 IC、牛熊市 IC。
- 五分组或十分组收益及单调性。
- Top-Bottom 收益、波动、夏普和最大回撤。
- 覆盖率、有效日期、每日有效标的中位数。
- 因子换手、组合换手和成本后收益。
- 行业、市值、Beta、波动率暴露。

#### 事件型因子

- 事件样本数、事件覆盖率和重叠事件比例。
- 事件日前后的累计异常收益。
- 对照组或匹配样本结果。
- 事件窗口稳定性。
- 按事件类型、市场状态和行业分层。

#### 状态型因子

- 状态持续时间和转移概率。
- 不同状态下的收益差异。
- 状态覆盖率和样本均衡性。
- 状态切换的滞后与稳定性。

### 5.5 成本与可交易性

成本模型至少应包含：

- 佣金。
- 印花税。
- 买卖双边换手。
- 固定或成交额相关滑点。
- 涨跌停无法成交。
- 停牌和无成交量。
- 最小成交单位。
- 可选的容量与冲击成本约束。

不能只把因子排名变化作为真实组合换手；应先形成明确的选股、权重和再平衡规则，再计算可执行成本。

## 6. 分阶段实施计划

### P0：阻断修复与正确性恢复

目标：任务能够稳定运行，并且输入数据、因子值和目标收益真实可信。

- 修复 `ExecutionPlan` 二次异常。
- 建立前置检查接口和结构化错误码。
- 接入真实 `factor_targets`。
- 使用交易日批量计算完整因子面板。
- 修复滚动窗口、500 标的截断和默认日期不足问题。
- 暂停门禁到激活流程的连接。
- 增加黄金样本和端到端测试。

### P1：量化研究可信度建设

目标：结果可复现、无明显未来函数和幸存者偏差，可用于研究评审。

- 冻结数据、股票池、目标和执行计划批次。
- PIT 数据连接和历史股票池恢复。
- 按日横截面后处理。
- Walk-forward、purge、embargo 和独立测试集。
- 真实组合换手、成本及可交易性。
- 风险暴露和稳定性分析。

### P2：研究效率与产品化

目标：提高因子研究、比较和治理效率。

- 多版本、多区间、多股票池并排对比。
- 一键复制配置和基于失败项重跑。
- 因子相关性、边际 IC 和组合增量贡献。
- 研究报告导出。
- 多重试验记录和数据挖掘偏差提示。
- 连续型、事件型和状态型独立模板。

## 7. 验收标准

### 7.1 黄金样本验证

必须提供以下确定性测试：

1. 人工构造与未来收益正相关的因子，Rank IC 必须显著为正。
2. 将该因子乘以 `-1` 后，IC 符号必须反转。
3. 随机因子在足够长样本下 IC 应接近 0。
4. 常数因子不得产生伪 IC。
5. 修改截止日之后的数据，不得影响此前截止日的因子值和报告。
6. 相同输入批次和配置重复运行，指标必须一致。

### 7.2 时间与 PIT 验证

- 信号日只能使用当时已经公布和可见的数据。
- 目标退出日期不得晚于运行数据截止日。
- 训练、验证和测试窗口不得因目标 horizon 发生重叠。
- purge 和 embargo 必须按交易日执行。
- 财报修订值不得回写到修订公布前的历史样本。

### 7.3 覆盖与口径验证

- 正式评价不能出现隐式 500 标的截断。
- 页面展示的交易日数、标的数和有效样本数必须能通过仓库 SQL 复核。
- 因子方向反转后，分组顺序和 Top-Bottom 收益必须同步反转。
- 滚动 20 日公式必须使用不少于 20 个有效历史交易日。
- 标签口径、复权方式、入场和退出价格必须在报告中明确展示。

### 7.4 任务与错误验证

- 公式失败、字段缺失、目标不足、样本不足和系统异常使用不同错误码。
- 失败任务不得生成可通过的正式运行记录。
- 取消任务不得被后台线程覆盖为失败或成功。
- 前端不得把 Python 异常作为主提示。
- 每个阻断项必须包含证据、影响、修复入口和是否可重试。
- 字段目录与实际 schema 不一致时，测试必须断言错误中包含表名、字段名和 correlation_id。
- 同一配置重复点击运行只能产生一个任务；不同区间、成本或股票池必须产生不同幂等键。
- 任务、运行记录和压力测试的状态必须遵循统一状态机，不能出现任务失败但运行已通过的组合。
- 网络断开后恢复页面，不能重复创建任务，必须先读取已有任务最终状态。
- 轮询在任务进入终态后必须停止，后台标签页不得持续高频请求。

### 7.5 前端交互验证

- 在 1440 × 900 分辨率下，因子选择、前置检查和运行按钮全部位于首屏。
- 用户无需滚动即可判断当前任务是否可以运行。
- 历史运行切换不增加页面总高度。
- 高级参数默认收起，并提供合理默认值和口径说明。
- 运行失败后可从错误项直接进入对应修复页面。
- 修复返回评价页后，原配置能够保留并重新执行前置检查。
- Tab 顺序、焦点返回、Esc 关闭抽屉和图表数据表替代入口均可用键盘完成。
- 刷新页面后能恢复因子、页签、筛选和当前报告语境。
- 中文、英文、长因子代码、长错误和窄屏下均不发生按钮、表头或状态重叠。
- 结果页明确显示数据截止日、时区、复权口径、目标持有周期、年化口径和测试区间。
- 前置检查请求防抖且旧响应不会覆盖新选择；任务按钮不可重复提交。

## 10. 因子中心改造：公式定义器弹窗方案

### 10.1 改造结论

公式编辑不应长期占据因子中心主页面，也不应把函数库、字段树和脚本编辑器继续堆在页面下方。建议改为**页面内居中弹窗**：主页面只展示因子摘要、当前版本和“编辑公式”入口；点击后打开公式定义器，完成编辑、AI 辅助、编译、预览和校验后再返回主页面。

该弹窗不是独立业务页面，必须继承当前因子、版本、语言、权限和未保存状态。关闭弹窗不能丢失草稿，也不能改变当前已保存版本。

### 10.2 弹窗位置与尺寸

桌面端（建议基准 1440×900）：

| 区域 | 位置 | 建议尺寸 | 设计要求 |
|---|---|---:|---|
| 遮罩层 | 覆盖当前因子中心内容区 | 全部可视区域 | 背景降噪，不遮挡弹窗；禁止点击背景误提交 |
| 弹窗外框 | 页面水平、垂直居中 | 1240～1320px × 760～820px | 最大不超过视口 92%；圆角 6～8px |
| 顶部标题栏 | 弹窗最上方 | 56px 高 | “公式定义器”、因子代码、版本、编辑模式、全屏、关闭 |
| 左侧表达式区 | 标题栏下方左侧 | 300～340px 宽 | 搜索、字段树、函数树、已选项高亮；独立滚动 |
| 右侧脚本区 | 标题栏下方右侧 | 剩余宽度 | 编辑器、格式化、编译预览、AI 助手、诊断信息 |
| 底部操作栏 | 弹窗最下方 | 64～72px 高 | 模拟运行、保存、校验、取消；保存前显示未保存状态 |

弹窗内部只有一个主滚动方向：左侧资源树和右侧编辑器内容各自滚动，弹窗标题栏与底部操作栏固定。不得让主页面和弹窗同时出现两个纵向滚动条。

移动端或视口宽度小于 768px 时，弹窗切换为全屏抽屉式编辑器：标题栏固定，表达式区改为“资源”抽屉，脚本区占满屏幕，底部操作栏保留主操作。

### 10.3 左侧表达式区

左侧标题使用“表达式”，不是笼统的“函数库”。内容按可插入对象组织：行情与基本面字段、时间序列函数、截面函数、常量与参数、最近使用和收藏。每一项显示名称、技术标识、类型和可用状态；点击插入光标位置，点击函数后显示签名、参数、返回类型、数据依赖、热身窗口和示例。

搜索结果必须经过当前 DSL 版本、权限和依赖数据可用性过滤。不可用函数仍可展示，但标注“缺少依赖”或“评价专用”，并禁止插入后直接运行。

### 10.4 右侧脚本区与 AI 助手

右侧顶部操作顺序固定为：`问 AI 写公式`、格式化、编译并预览。AI 只基于当前 DSL 函数白名单、字段目录和因子类型生成候选公式，同时返回依赖、热身窗口、缺失处理和方向解释。用户点击“插入并替换”或“插入到光标位置”后，候选公式才进入编辑器；不能自动保存、自动提交或触发正式评价。

插入后必须重新编译、预览和运行前检查；任何错误都回到结构化诊断，不显示原始 Python 堆栈。记录提示词版本、模型版本、目录版本、生成时间、是否采纳和最终保存版本；敏感数据、内部路径和完整数据集不得发送给模型。

### 10.5 与现有功能的兼容策略

| 现有功能/组件 | 可能冲突 | 兼容方案 |
|---|---|---|
| `FactorFormulaBuilder` | 路由和状态模型重复 | 保留业务内核；弹窗只做容器，复用解析、编译、校验 hook |
| 因子详情页 | 编辑后摘要不同步 | 关闭弹窗返回 `draftChanged` 事件；详情页重新拉取元数据，不覆盖已保存版本 |
| 评价实验室 | 预览被误认为正式结果 | 预览接口与正式评价接口分离；预览不生成 `EvaluationRun` 或门禁结论 |
| Shadow / 模型门禁 | 未校验草稿进入下游 | 只允许已保存、已编译、依赖冻结且有版本 ID 的公式进入评价 |
| Ant Design `Modal` | z-index、焦点、滚动锁定冲突 | 统一弹窗层级；打开锁定背景滚动，关闭恢复；支持 Esc 和焦点回退 |
| 刷新与返回键 | 弹窗状态丢失或重复提交 | 查询参数记录 `factor_code`、`version`、`editor=open`；草稿使用独立 draft ID |
| i18n | 中文长文案溢出 | 文案使用 i18n key；按钮按中英文最长文案验收，代码标识不翻译 |
| AI 服务 | 网络、权限或配额不可用 | AI 失败不影响手工编辑；显示可重试和 request ID |
| 内容编辑器 | HTML 注入、光标错位 | 生产使用受控代码编辑器；公式按纯文本解析，禁止直接执行 HTML |
| 旧版草稿 | DSL、字段或函数不兼容 | 打开时做迁移检查；无法迁移时只读展示，并提供复制为新版本 |

### 10.6 改造风险审核

#### P0：上线前必须关闭

- AI 生成不存在的函数、未来数据字段或未登记标签字段，造成隐性未来函数。
- 弹窗保存绕过权限、版本冻结和审计，未授权公式进入评价或生产。
- 预览复用正式评价接口，因样本截断、缓存或数据批次差异产生错误结论。
- 关闭、刷新或重复点击造成草稿覆盖、重复任务或重复版本。
- 编辑器接受 HTML/脚本内容，产生 XSS 或破坏公式解析。

#### P1：联调阶段验证

- 新 CSS、z-index、滚动锁定影响现有抽屉、表格和全局通知。
- 新字段树查询增加首屏请求和后端压力。
- 函数目录与编译器白名单不一致，出现界面可选但编译失败。
- AI 解释、依赖和后端真实执行计划不一致。
- 移动端软键盘遮挡底部按钮或焦点无法返回。

#### P2：上线后观测

- 用户过度依赖 AI，公式缺少经济含义和可交易性审查。
- 函数目录增长带来搜索、分类和文档维护成本。
- 生成记录包含内部字段、业务规则或用户输入，产生数据泄露风险。

### 10.7 冲突处理原则

1. 业务内核优先复用，不复制编译器、校验器、版本保存和权限判断。
2. 预览与正式计算隔离，预览不共享正式运行状态。
3. 增加 feature flag `factor_formula_modal_v2`，灰度期间保留旧编辑器回退。
4. 弹窗提交 `draftId + baseVersionId + formulaText`，后端返回新版本 ID；前端不拼装版本对象。
5. 版本不可变，评价、Shadow 和门禁只读固定版本 ID。
6. 函数目录、AI、编译和数据预览分别显示错误与重试入口，不能互相吞错。

### 10.8 分阶段落地与验收

| 阶段 | 内容 | 放量条件 |
|---|---|---|
| M0 | 复用现有编辑器内核，增加弹窗容器、表达式树和关闭恢复 | 不影响旧路由，单元测试通过 |
| M1 | 函数目录、依赖检查、结构化补全、预览隔离 | 函数白名单与编译器一致 |
| M2 | AI 公式助手和审计记录 | AI 失败可回退，敏感信息过滤通过 |
| M3 | 小流量灰度 | 连续两个发布周期无 P0 回归 |

- 1440×900 下无需滚动即可识别弹窗标题、表达式树、脚本、AI 入口和底部保存按钮。
- 左侧字段/函数可插入光标位置；重开弹窗保留未保存草稿。
- AI 公式必须经过用户确认、编译、依赖检查后才能保存。
- 预览不会创建正式 `EvaluationRun`，不会改变 Shadow 或模型门禁状态。
- 关闭、Esc、刷新、返回和重复点击不会丢稿、覆盖历史版本或重复创建任务。
- AI 不可用时，手工编辑、字段树、补全、编译和保存仍可用。

## 11. 因子中心全页面改造补充

上一节重点描述了公式定义器弹窗。本节补齐因子中心其余页面，形成完整的“因子库 → 因子详情 → 编辑器 → 评价实验室 → Shadow → 模型门禁”闭环。

### 11.1 全局导航与页面关系

顶部页签固定为：`因子库`、`因子详情`、`编辑器`、`评价实验室`、`Shadow`、`模型门禁`。当前因子、版本和筛选条件必须通过 URL 参数或稳定状态存储保持，不能只依赖 React 内存状态。

推荐业务流：

```text
因子库筛选 → 因子详情确认定义、血缘和版本 → 编辑器弹窗修改草稿并编译 → 评价实验室执行正式评价 → Shadow 观察生产偏差 → 模型门禁审批与灰度启用
```

所有页面共享 `factor_code`、`factor_version_id`、`draft_id`、`data_cutoff_at`、`calc_batch_id` 和 `status`，但不能共享可变的“当前结果对象”。评价、Shadow 和门禁读取不可变版本与批次。

### 11.2 因子库改造

**位置与布局**：页面标题下方放搜索和筛选工具栏；工具栏下方放 4 个摘要指标；主体使用完整表格，桌面端显示在首屏，移动端转为列表卡片。不要把筛选项堆到页面底部。

**核心功能**：按代码、名称、字段、标签搜索；按类型、负责人、生命周期、评价结论和更新时间筛选。表格列固定为因子名称/代码、类型、版本、覆盖率、评价结论、生命周期、负责人、更新时间。行操作提供查看详情、编辑草稿、运行评价、加入 Shadow、查看门禁，具体操作按状态启用或禁用。支持批量比较，但批量操作必须显示版本、数据截止日期和任务数量确认。状态不能只用颜色表达。

列表查询必须返回版本 ID、最新评价运行 ID、数据批次和状态更新时间，禁止前端通过多个接口拼出可能过期的状态。分页、排序和筛选使用后端参数；超过 200 行再考虑虚拟化。删除采用软删除，已被评价、Shadow 或门禁引用的版本不可物理删除。

### 11.3 因子详情改造

**位置与布局**：顶部为因子名称、代码、当前版本、生命周期状态和主操作；第二行展示 Rank IC、覆盖率、Shadow 偏差、门禁进度等摘要；下方使用页签切换“概览、数据血缘、版本记录、评价记录、变更审计”。

概览展示公式摘要、信号方向、频率、股票池、复权口径、目标收益和负责人；数据血缘展示字段、函数、热身窗口、数据批次和 PIT 证据；版本记录展示差异、提交人、编译器版本和变更说明；评价记录只读展示运行配置和结果；变更审计记录保存、提交、回滚、AI 采纳和门禁审批。

详情页不可把当前草稿覆盖到历史版本；切换版本必须重新请求对应指标和证据。版本已被下游引用时显示只读原因和“复制为新版本”。

### 11.4 编辑器改造

编辑器采用上一节定义的居中公式定义器弹窗。主页面不嵌入长编辑器。必须具备左侧表达式树、函数签名、自动补全、AI 公式助手、纯文本编辑、格式化、编译、样本预览、依赖检查、草稿恢复、版本提交和审计记录。

样本预览只用于快速检查，不得复用正式评价结果模型；预览可抽样 500 只，正式评价必须使用完整历史窗口和完整股票池；编辑器保存只产生新版本或草稿，不直接激活因子。

### 11.5 评价实验室改造

**位置与布局**：顶部吸顶评价配置工作台；主体左侧结果、右侧运行前检查；任务进度使用右侧抽屉，不把任务卡片堆在结果下方。

运行前检查公式、依赖字段、交易日、历史股票池、真实目标标签、PIT、批次和样本规模。正式评价只读取冻结的因子版本、股票池快照、行情批次和 `factor_targets`。结果页分为评价结果、稳定性、数据诊断、运行记录；指标显示口径、单位、频率、样本数和数据截止日期。阻断项提供证据、影响、修复入口和是否可重试。

### 11.6 Shadow 改造

**位置与布局**：顶部放观察因子、观察窗口、股票池和导出证据；第一行显示链路健康、覆盖率、IC 漂移和连续运行天数；主体左侧显示研究基线与生产实际曲线，右侧显示异常和告警。

对比同一因子版本、同一股票池、同一目标标签和同一数据口径下的研究结果与生产输出。展示每日输出数量、缺失率、截面相关性、Rank IC 偏差、延迟、重试和任务耗时。观察周期、覆盖率、漂移、任务稳定性和缺失敏感度必须有明确门槛。每日证据冻结数据批次、执行计划 hash、公式版本、产出时间和异常说明。

Shadow 只能读取已保存且已通过评价的版本；不允许直接从编辑器草稿读取。生产端缺失或延迟时标记为“数据异常”，不能把缺失填充为零后继续计算漂移。

### 11.7 模型门禁改造

**位置与布局**：顶部使用五阶段流程条：研究定义、正式评价、Shadow 观察、投委复核、生产启用。主体左侧显示逐条门禁规则和证据，右侧显示审批责任人、灰度比例、自动回滚和审批记录。

每条规则显示通过/等待/阻断、实际值、阈值、证据批次、计算时间和修复入口。未完成正式评价、Shadow 周期或数据审计时，生产启用按钮必须禁用。审批绑定版本 ID、评价运行 ID、Shadow 周期和审批人。灰度比例、回滚条件、容量限制和监控指标在启用前冻结。任何新版本自动回到对应门禁阶段，不继承旧版本“已通过”。

### 11.8 全中心跨页面风险与冲突处理

| 风险 | 影响 | 兼容方案 |
|---|---|---|
| 顶部页签与旧路由冲突 | 刷新或返回状态丢失 | 保留原路由别名；新页签通过 query 参数恢复因子和版本 |
| 详情、评价、Shadow 使用不同版本 | 结果无法追溯 | 所有下游接口强制接收 `factor_version_id` 和 `calc_batch_id` |
| 编辑器草稿出现在因子库 | 用户误认为可运行 | 草稿单独状态；保存并编译成功后才进入可评价列表 |
| 评价通过直接驱动 Shadow | 错误结果扩散 | P0/P1 门禁前仅允许研究状态；feature flag 控制下游连接 |
| Shadow 状态影响模型门禁 | 单日异常误下线 | 使用连续窗口、告警等级和人工确认，不用单点值切换状态 |
| 删除/回滚破坏审计 | 历史报告无法复现 | 版本不可变、软删除、回滚生成新版本 |
| 多页面同时轮询 | 请求量暴增、状态互相覆盖 | 统一任务订阅/轮询服务；终态立即停止；页面只订阅当前任务 |
| 权限不一致 | 能编辑但不能审批 | 前后端同时校验 RBAC；按钮禁用不替代后端检查 |
| AI 生成公式绕过白名单 | 未来函数进入生产 | AI 输出走同一 DSL parser、依赖检查和版本保存接口 |
| 数据批次不一致 | 页面数字互相矛盾 | 页面固定显示截止日、批次 ID 和口径；切换不隐式刷新批次 |

### 11.9 全中心验收标准

- 六个页签均有首屏布局、空状态、加载状态、阻断状态和无权限状态。
- 因子库可进入详情；详情可进入编辑弹窗；保存新版本后可评价；评价完成后才可 Shadow；Shadow 达标后才可提交门禁。
- 刷新、返回或网络恢复后，因子、版本、页签、筛选和当前任务可恢复。
- 所有结果可追溯到同一组因子版本、数据批次、股票池快照、目标标签批次和执行计划。
- 新页面不改变旧接口业务含义；旧路由在 feature flag 关闭时保持可用。
- 改造优先新增容器和适配层，不直接重写编译器、评价引擎、任务状态机和权限服务。

### 11.10 表达式弹窗实际实现映射

本轮前端落地采用适配层方式，不重写既有因子业务内核：

- `FactorEditor` 保留因子基本信息、校验结果、预览结果、后处理配置和版本保存，仅将长公式输入区替换为公式摘要与“编辑表达式”入口。
- 新增 `FactorFormulaEditorModal` 作为公式定义器容器，内部继续复用 `FactorFormulaBuilder` 的字段、函数、运算符和示例目录。
- AI 继续复用 `AiChatDrawer` 和现有 `formula_mode="factor"` 接口；AI 插入后仍调用同一公式变更和校验失效逻辑。
- 打开弹窗时快照公式、方向、版本说明、参数、校验结果和预览结果；取消时完整恢复，应用时只更新当前草稿，不创建版本。
- 公式、方向或参数变化后，原校验与预览结果立即失效；保存仍要求公式重新校验通过。
- 校验或预览请求进行中时禁止关闭、取消和应用，避免异步结果覆盖已恢复的草稿状态。
- 正式保存 payload、版本 ID、评价接口、Shadow 和模型门禁接口未改变，因此现有下游继续读取已保存的不可变版本。

对应回归覆盖：表达式字段/函数/示例、光标插入、AI 公式插入、校验、预览、应用、取消恢复和异步关闭保护。
