# 行情统计看板口径优化与回归

用户指出：ETF 显示“1717/1717、100%”，但上市日期仍全部缺失，面板容易使人误认为数据已完整。本轮改进只读统计与页面展示，保留全部行情和业务字段，不执行补数、资料回填、缓存修复、迁移或调度。

## 【问题审查结论】

| 编号 | 结论 | 核验证据 |
|---|---|---|
| D1 | ✅同步标记被误当成实际记录覆盖，已修复 | 旧接口按 `is_synced` 聚合。1717 是 1642 只 A股ETF 加 75 只美股ETF 的同步标记数；实际只有 1716 只有行情。美股 SLY 标记已同步，但没有日线记录。 |
| D2 | ✅未满覆盖被四舍五入显示 100%，已修复 | 股票 5554/5555 原单小数计算为 100.0；现在按实际数量显示 99.98%。创业板 1402/1403 的同步标记显示 99.93%，不会冒充已全部覆盖。 |
| D3 | ✅已有记录、上市资料和历史完整性混用，已修复 | 有行情仅要求至少一条日线；上市日期、历史交易日覆盖、价格与量额口径分别展示。全部登记标的的上市日期仍缺，未借改界面伪造完整。 |
| D4 | ✅自然日新鲜度误导，已修复 | 周日“今日最新0”不能说明周五行情落后。境内按本地日历确认的最近完整交易日判断；日历不足及美股日历未核验时明确待核验。 |
| D5 | ⚠️只读发现，未修改旧值 | SLY 和 301583 没有行情；000004 登记缓存行数 2263，实际 2264，最新日期均为 2026-07-13。这些差异在新看板展示，未自动修复。 |

“有行情”指至少一条已存日线，不能解释为全历史、所有关键字段或可交易条件均完整。上市日期“已登记”也不等于来源已认证。此前只读补到的 86 只上市日期证据继续独立归档，本轮未回填业务字段。

## 【修复方案】

### 只读统计

[universe_health.py](D:/ai_project/dataAanlystNew/app/services/universe_health.py)按实际日线表分标的聚合，再关联登记范围，不依据同步标记推测有无记录。返回每市场的登记数、有行情数、无行情数、上市日期登记/缺失/异常数、实际最新日、登记缓存差异及缺失样本。记录存在、同步标记和缓存差异分别计数。

境内最近完整交易日仅使用本地 `trade_calendar`，盘中 15:00 前使用前一完整交易日。必须沿已知日历回溯，缺日历不猜工作日。未来日期、未收盘当日记录及无法确认日历的市场归入待核验。美股日历在此看板未核验，因此不显示“已最新”。日期较早仍需结合停牌、退市等逐日状态确认，不直接视为应补缺口。

[universe_sync.py](D:/ai_project/dataAanlystNew/app/services/universe_sync.py)保留原接口字段供已有调用使用，新增 `quality`。原覆盖率改为两位小数，任何未满分子最多 99.99%；新看板使用实际数量重新计算百分比，不信任旧接口四舍五入值。总日线数复用同一聚合，避免再全表计数一次。

### 页面

[UniverseHealthDashboard.tsx](D:/ai_project/dataAanlystNew/frontend/src/components/UniverseHealthDashboard.tsx)展示四项概览：已登记、有行情、未取得行情、已存日线。各市场卡片并列展示记录覆盖率、上市日期登记情况及交易日核验；ETF 合计明确列出境内/美股组成、实际有行情数及历史同步标记数。

新增“查看未取得行情的标的”，展示 SLY、301583。统计明细中保留按板块的同步标记，但明确其不代表完整历史。历史交易日覆盖、价格与量额口径持续标为未核验，没有生成综合“健康100%”。读取旧版接口缺少新指标时显示“详细核验结果暂未提供”，不将缺少的指标当成零。

[UniverseDataPanel.tsx](D:/ai_project/dataAanlystNew/frontend/src/components/UniverseDataPanel.tsx)新增“刷新统计”，仅 GET 读取。统计查询涉及全量日线，客户端超时调整为 60 秒；读取失败继续保留上次结果并提示重试，不发起下载或修复。

### 数据库只读校验

完整脚本：[行情看板只读校验-2026-10-25.sql](D:/ai_project/dataAanlystNew/docs/行情看板只读校验-2026-10-25.sql)。在只读一致性事务中核对实际记录覆盖、同步标记、上市日期、无行情样本、000004 缓存差异、总行数、版本和空闲任务。

```sql
USE gpfx_validation;
SET TRANSACTION READ ONLY;
START TRANSACTION WITH CONSISTENT SNAPSHOT;

SELECT u.symbol,u.region,u.asset_type,u.is_synced,u.bar_count,u.last_bar_date
FROM universe_symbols u
WHERE NOT EXISTS (
    SELECT 1 FROM universe_daily_bars b WHERE b.universe_symbol_id=u.id
)
ORDER BY u.id;
-- 应为 SLY、301583；保留同步标记，不能据此自动删除或补造行情。

SELECT COUNT(*) AS actual_rows,11734896 AS expected_rows FROM universe_daily_bars;
SELECT version_num FROM alembic_version;
SELECT COUNT(*) AS active_tasks FROM async_tasks WHERE status IN ('running','queued');
ROLLBACK;
```
