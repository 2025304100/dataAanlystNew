## 1. 设计目标与硬约束

### 1.1 设计目标

1. **可并行**：模块边界清晰到"两个开发同时改同一个 PR 的概率极低"，接口先冻后写。
2. **可回滚**：任一里程碑可关闭写开关回退，不删数据、不影响因子中心/因子模型的既有链路。
3. **可复现**：固定随机种子 + 配置快照 + 模板版本号 + 数据截止日，同配置重跑结果一致。
4. **可观测**：M1 起即埋性能探针，M3 的 G1 决策有数据支撑而非猜测。
5. **不越权**：挖掘只是"因子中心"内的一次研究实验，不产出 active 因子、不训练模型、不下单。

### 1.2 十条架构硬约束（不可谈判）

| # | 约束 | 校验方式 |
|---|------|---------|
| C1 | 不新增独立服务/进程/数据库；挖掘复用现有 FastAPI 进程与 `async_tasks` 状态机 | 代码评审 |
| C2 | 不新增 App 顶级 Tab。菜单入口为 **设置(Settings) 左侧导航新增一栏「因子挖掘」** | 前端用例 |
| C3 | 挖掘域**不执行** Ridge 训练、评分生成、模型激活，只做结果页跳转并携带 4 项上下文 | 单测 + 代码评审 |
| C4 | 跨域只依赖公开 Facade/DTO；禁止前端解析 `hyperparameters_json` / 权重内部格式；禁止挖掘直接写 FactorModel 域表 | 契约测试 |
| C5 | 挖掘**不直接读写 F1 表**，只调 `POST /factor-experience` 与 `GET /factor-experience/sample` | 静态扫描（禁 import F1 model） |
| C6 | 候选转正式因子**必须走** `factor_registry.create_factor_draft` / `create_factor_version`，不绕过 `/factors` 写入口 | 单测 |
| C7 | G2 缓存**只在主进程内存**，绝不写 DuckDB（规避单写锁） | 单测断言无 DuckDB 写 |
| C8 | 适应度计算**只用 train 段**；val 仅用于 D1 早停与 C1 参考；test 全程锁定、仅最终确认评估一次且禁止回炉 | 单测断言 |
| C9 | 所有写 DuckDB 的任务必须经 `duckdb_write` 锁；`mining_domain` 冲突直接拒绝不排队 | 并发穿透测试 |
| C10 | 所有新增文案走 `t()`，禁止硬编码中文；首期只填 `zh-CN` | 前端 lint |

**分层规则（评审强制）**

| 规则 | 说明 |
|------|------|
| R1 | 上层可依赖下层，下层**禁止** import 上层 |
| R2 | L2 是横向能力层，**不得** import L3（否则循环依赖） |
| R3 | L3 各模块之间只通过 `mining/contracts.py` 中的数据类交互，不互相 import 实现 |
| R4 | L1 已有文件**只允许**新增函数/分支/目录项，不允许修改既有函数签名 |
| R5 | L5 只做 DTO 转换与校验，**禁止**出现业务计算逻辑（阈值、切分、指标一律在 L3/L1） |

### 2.2 进程与并发模型

```text
uvicorn 单进程（现状）
├── FastAPI 事件循环（API 请求）
├── async_tasks worker 线程池（ThreadPoolExecutor，现状）
│    ├── task_type='factor_pipeline'   （既有）
│    ├── task_type='factor_mining'     ★新增，持有 mining_domain + duckdb_write
│    ├── task_type='factor_mining_validation' ★新增，独立任务类型，**不持 mining_domain**
│    ├── task_type='data_mirror'       ★新增，持 duckdb_write
│    └── task_type='factor_grade_review' ★新增，由 scheduled_tasks 触发
└── 主进程内存（G2 子表达式缓存，任务生命周期内有效，**不落盘**）
```

- **不做多进程并行**（G1 归 M3，由探针数据决定）；M1/M2 全部串行，进程内 `ThreadPoolExecutor` 仅用于 AI 并发（4 路）。
- 写 DuckDB 的路径统一经 `FactorWarehouse.safe_write_context()` + `task_locks` 的 `duckdb_write`，两层叠加（前者是进程内/文件锁，后者是跨任务业务锁）。

## 3. 与「因子中心」「因子模型」的集成关系

### 3.1 三者定位

| 模块 | 定位 | 产出 | 是否本期改动 |
|------|------|------|-------------|
| **因子中心** | 因子资产库与实验室：因子 CRUD、版本、公式校验/预览、评估、影子观察 | `factors` / `factor_versions` / `factor_evaluation_runs` / `factor_shadow_observations` | 只**扩展**（DSL、字段注册、`factor_versions` 加 4 列），不改既有语义 |
| **因子挖掘**（新增） | 因子中心内的一次**研究实验**（遗传算法范式），止步于候选产出 | 候选因子 + 统计校正 + 质量等级 + F1 沉淀 | 全新增 |
| **因子模型** | 多因子权重学习与上线：FactorSet、建模、影子、激活 | `factor_sets` / `factor_model_runs` / 评分 | **不改动**；仅在结果页接收跳转上下文 |

### 3.2 依赖方向与集成矩阵（单向，禁止反向）

```text
                ┌────────────────┐
                │   因子挖掘      │   ← 只依赖，不被依赖
                └───────┬────────┘
        ┌───────────────┼────────────────────┐
        ▼               ▼                    ▼
   ┌─────────┐   ┌──────────────┐    ┌──────────────┐
   │ 因子中心 │   │ DuckDB 仓库   │    │ 任务/通知平台  │
   │ (L1 复用)│   │ (raw_*)      │    │ async/outbox │
   └────┬────┘   └──────────────┘    └──────────────┘
        │ 候选 → 正式因子（唯一写入口）
        ▼
   ┌─────────────────┐
   │ FactorSet(draft)│
   └────────┬────────┘
            │ 跳转携带 4 项上下文
            ▼
      ┌──────────┐
      │ 因子模型  │  ← 反向禁止：因子模型不得调用挖掘任何函数
      └──────────┘
```

| 集成面 | 方向 | 载体 | 本设计处理 |
|--------|------|------|-----------|
| 公式编译/校验/预览 | 挖掘 → 因子中心 | `factor_compiler.compile_formula` / `validate_formula`；HTTP `/factors/validate`、`/factors/preview` | 直接复用，**不新增编译实现** |

## 4. 数据流转路径

### 4.1 主链路 L1：候选池 → 冻结快照 → 看板（同步，2~15 秒）

```text
前端 Step1（条件筛选 300ms 防抖 或 Excel/CSV 导入）
  → POST /factor-mining/candidate-pools/preview          实时命中数/排除统计（不落库）
  → POST /factor-mining/candidate-pools                  创建池（写 source_type，此后不可切换）
  → POST/DELETE .../{pool_id}/members                    成员增删（软删除 + 审计）
  → GET  .../filter-presets?as_of_date=&markets=         服务端按分位数算预设边界
  → POST .../{pool_id}/analyze                           ① 校验成员数 ≥50（硬门禁）
                                                         ② 冻结快照（成员+规则哈希+data_cutoff_at）
                                                         ③ 计算看板（市值/行业/风格/市场环境/数据质量）
                                                         ④ analysis_status: not_analyzed→analyzing→analyzed
                                                         ⑤ is_locked = 1
  ← 返回 snapshot_id + analysis_json
前端弹出只读看板；筛选/导入/批量删除置灰
  → POST .../{pool_id}/reset-analysis                    「重新选择」：清分析 + 解锁 + 回到初始
```

**关键点**：挖掘只引用 `snapshot_id`，**永不实时重筛**；同一候选池多次挖掘各生成独立快照。

### 4.2 主链路 L2：字段异步校验（异步，独立任务类型，不占挖掘锁）

```text
前端 Step3 勾选字段 → 保存草稿 → POST /factor-mining/validations
  → config_hash = sha256(fields + snapshot_id + time_split + target + max_lookback + formula_config)
  → 查同 draft_id + config_hash 的活动任务：有则直接复用返回（幂等）
  → create_async_task(task_type='factor_mining_validation', payload)
  → worker：按「字段 × 时间段」分片校验
       ① 快照存在且 ≥50
       ② 字段物理表/列/首末日期/来源批次
       ③ train/val/test 三段截面覆盖率、缺失率、最长缺失连续期
       ④ PIT 约束：announcement_date <= trade_date
       ⑤ 回看窗口是否超出区间前置数据
       ⑥ 目标收益存在性 + 未来数据重叠
       ⑦ ST/停牌/退市/上市日期快照字段可用性
       ⑧ 资源初估
  → 报告写 factor_data_validation_runs（**不允许只在前端展示**）
  → 状态：passed / blocked / warning；分片支持断点续跑
  → 完成/失败 → notifications.outbox.enqueue 推送
前端 5s 轮询 GET /factor-mining/validations/{id}（**不引入 WebSocket**）
阻断 → 只给两个出口：重新选择字段 / 去修复数据（草稿转 waiting_data_recheck）
回流 → POST /factor-mining/validations/{id}/recheck（重新生成 config_hash）
```

### 4.3 主链路 L3：进化闭环（核心，异步长任务）

```text
POST /factor-mining/runs（Step4 提交）
  ├── ① 最终准备校验（秒级，不同步执行深度扫描）
  │     5 步完整 / 快照 ≥50 / 时间一致 / 校验未过期（默认 24h）/ 参数合法 / 资源达标
  ├── ② 双锁检查
  │     mining_domain：已有 (queued|running) → **直接拒绝**（不排队）
  │     duckdb_write ：空闲 → 立即执行；被占 → 进 queue_json 排队并返回位次
  ├── ③ 冻结不可变实验快照：config_hash / evolution_params_json / split_config_json / random_seed
  └── ④ create_async_task(task_type='factor_mining')  → 返回 run_id + 排队位次

worker(_run_factor_mining)：
  P0 数据准备
     读取快照成员 → 一次性载入内存分析表（不逐行查主库）
     target_engine.calculate_targets() 确保 factor_targets 就绪
     build_time_split(all_dates=有效调仓点, ...) → 写 split_config_json + test_start/end_date
  P1 初始种群（两层结构）
     第一层 经典底座（同步、确定性）：
       模板过滤(类别启用+字段已选) → 参数网格展开 → 批量校验 → 来源内去重
       → 按覆盖策略分配名额（均衡/优先级）→ 锁定 → operation=enumerated, generation=0
     第二层 探索层（剩余名额 = 种群大小 − 经典实际入库数）：
       F1 抽取 GET /factor-experience/sample（字段硬过滤→场景匹配→加权抽取→参数实例化）
       AI 生成（4 路并发，10 次 × 8~12 骨架，单次 30s，总 5min，成本 ≤¥10/500k token）
         强制输出 formula_ast + category + economic_logic + expected_direction，缺一丢弃
       受约束随机（算子≤4、嵌套≤2、字段引用≤3）
     四层去重 → 按「锁定经典 → AI 取 Top → 随机补足」入库
     写 factor_mining_candidates（generation=0）
  P2 逐代进化  for g in 1..max_generation：
     ① 短样本评估（sample_length=1y，**仅 train 段**）
          建当代 G2 缓存 → 提取子表达式 → SHA-256 去重 → 向量化计算 → 组装（compute_node 调用=0）
          计算 IC/ICIR/覆盖率/换手率/复杂度
     ② 观测：D3 算三层多样性 health；D1 更新 convergence_delta 与 stall_count
     ③ 选择：B1 非支配分层 rank + 拥挤度 CD → A1 分 6 赛道定配额 → B2 赛道内锦标赛 → 精英直留
     ④ C1 调度：读 health/stall/代数 → 输出本代 strategy(g)（三率+变异类型分布+跨赛道率，安全区间夹取）
     ⑤ 繁殖：C2 变异 / C3 交叉 / D2 随机注入（严格按 strategy 执行）→ 校验 → 非法丢弃用 D2 补位
     ⑥ G2 抽样校验：随机抽 5 个因子，缓存结果 vs 直接全量计算，差异 >1e-6 → 报警 + 废弃重算
     ⑦ 落库：factor_mining_generations（含 actual_* 三率 + 探针字段 + cache_validation_*）
             + 新个体写 factor_mining_candidates
     ⑧ 心跳：update_heartbeat（每代结束）
     ⑨ D1 停止判断：C1 已自救且 stall_count≥3 仍无进步 → converged，跳出
  P3 最终验证
     取最终种群 Top 50（可配置）→ 全量区间评估（**此时才碰 test 段，且只评一次**）
     → 门禁（ICIR≥0.3 / 覆盖率≥80% / OOS 同向 / 相关性<0.95）
     → 统计层 8 方法（M2）→ 写 factor_evaluation_runs.metrics_json.stats
     → 质量分级（M2）→ 写 factor_versions.quality_grade + factor_grade_history
     → 最终验证每完成 10 个因子更新一次心跳
     → **评估后禁止回炉**（run.status 置 validating→succeeded，test 段不可再进进化）
  P4 结果与沉淀
     结果页数据就绪 → notifications.outbox.enqueue 推送
     用户确认后：
       POST /factor-mining/candidates/{id}/submit → factor_registry.create_factor_draft
       → POST /factor-experience 自动存回 F1（无需人工）
       → POST /scoring/factorsets/{id}/members 加入 **draft** FactorSet（frozen 拒绝）
       → 前端跳转因子模型页，携带 factor_set_id/data_cutoff_at/candidate_pool_snapshot_id/rebalance_frequency
  P5 释放
     释放 mining_domain + duckdb_write → **自动拉起 duckdb_write 队首**
     任务结束释放 G2 主进程内存缓存
```

### 4.4 主链路 L4：统计校正与质量分级（M2，P3 内联）

```text
train 段 IC 序列 + test 段 IC 序列 + total_trials
  ├── t 检验          scipy.stats.ttest_1samp(ic_series, 0)
  ├── Bonferroni      自研：p_adj = min(p × n, 1.0)
  ├── FDR(BH)         自研 _bh_adjust()：p 升序 → p×n/rank → 自后向前单调化
  ├── Bootstrap       numpy 有放回重采样 1000 次 → ICIR 2.5%/97.5% 分位
  ├── 置换检验        随机打乱因子值 1000 次重算 ICIR → 经验分布
  ├── Deflated Sharpe total_trials + IC 分布偏度峰度 → dsr_icir
  ├── 衰减率          test_ICIR / train_ICIR（<0.5 → 疑似过拟合）
  └── Walk-Forward    全区间切 3~4 滚动窗口，各窗口内再切 train/val/test
                      → 只做方向一致性计数（≥3/4 同向），**不做跨窗口合并检验**
月频降级：test 仅 12 点 → 跳过 Bootstrap/置换，stats.degraded=true，最高评 B 级
  ↓
写 factor_evaluation_runs.metrics_json.stats（不新建统计表，避免与评估链路分叉）
  ↓
factor_grading.grade(metrics, thresholds) -> (grade, reason)   # 纯函数、无副作用
  8 维度全部满足该级阈值才定级；decay_ratio<0.5 → 不得 B 级以上
  ↓
factor_versions.quality_grade / grade_updated_at / grade_metrics_json / grade_manual_adjusted
factor_grade_history（trigger=initial, reason=...）
  ↓
季度重评（scheduled_tasks: factor_grade_review，每季首日）
  扫描 quality_grade ∈ {S,A,B,C} 且 grade_manual_adjusted=0 → 重算 → 重评 → 写 history
  B 级连续 2 季稳定 → 升 A
  S/A 连续 2 季下滑（ICIR 降幅>30% 或 OOS 反转）→ 降级 + 移出 FactorSet + 高优先级通知
  D 级 → 结构写入 F1 且 is_negative_sample=1
  → notifications 摘要：「升级 N 个、降级 M 个、移出 K 个」
```

### 4.6 状态机

```text
挖掘批次（factor_mining_runs.status）
  draft ──提交──▶ queued ──获锁──▶ running ──进化完──▶ validating ──▶ succeeded
                   │                  │                                   │
                   │                  ├─用户中断──▶ paused ──resume──▶ running
                   │                  ├─用户提前停止──▶ converged ──▶ validating
                   │                  └─取消──▶ cancel_requested ──▶ cancelled
                   └─获锁失败（duckdb_write 被占）→ 留在 queued + queue_json 位次
  异常：failed（写 error_code）；invalidated（上游配置变更，需重新校验）
  paused 保留 checkpoint 与已进化结果、释放资源、可 resume
  cancelled 才清理中间数据（或 7 天保留期到期由 cleanup 清理）
  **合法迁移表由 task_state_machine.py 校验，非法迁移返回 409 + 写审计**

草稿（factor_mining_drafts.status）
  draft / waiting_data_recheck（去修复数据后）/ invalidated（上游变更）

候选池（training_candidate_pools.status）
  draft → frozen（analyze 后）→ needs_recheck（成员<50）→ invalidated

快照分析（training_candidate_pool_snapshots.analysis_status）
  not_analyzed → analyzing → analyzed → reset（重新选择）

校验（factor_data_validation_runs.status）
  queued → running → passed / blocked / warning（可分片续跑）
```

### 4.7 血缘链（不可变 ID 引用）

```text
CandidatePoolSnapshot(snapshot_id)
   └─ MiningRun(run_id, config_hash, template_id, template_version, rule_hash)
        └─ Candidate(candidate_id, formula_hash, generation, parent_ids_json, operation)
             ├─ FactorVersion(factor_version_id)   ← 提交后
             │    └─ FactorSetMember → FactorSet(factor_set_id, draft)

```

### 6.3 状态与数据获取

| 关注点 | 方案 |
|--------|------|
| 长任务跟踪 | `MiningTaskPolling` hook 统一 5s 轮询（校验/挖掘/镜像共用），**不引入 WebSocket**；页面离开后由任务中心继续跟踪 |
| 草稿持久化 | 服务端 `factor_mining_drafts` 为准，前端 localStorage 仅存"当前草稿 ID + 当前步骤" |
| 上游变更失效 | 修改 Step1/2/3 后，前端把 Step3/4/5 标记 `invalidated` 并调后端同步草稿状态；**前端不得自行判定"仍可用"** |
| 防抖预览 | Step1 条件筛选 300ms 防抖调后端预览；**防抖结果不得作为挖掘快照**（快照只能由 `analyze` 生成） |
| 锁状态 | Step4 提交前 `GET /factor-mining/locks/status` 拉最新；提交后按返回的排队位次渲染 |
| 请求封装 | 追加到 `api/client.ts` 的 `api` 对象；类型定义 `types/mining.ts` |
| 错误展示 | 统一走 `utils/errorRender.ts` + `ErrorEnvelope.fix_action` 渲染"重新选择字段 / 去修复数据"按钮 |

### 6.4 i18n 与主题

- 所有文案 `import { t } from "../../i18n"`，**禁止硬编码中文**；key 命名 `mining.<domain>.<item>`（如 `mining.wizard.step1.title`）。
- 首期只填 `zh-CN.ts`；`en-US.ts` 在 M3 补齐，缺失时回退并 DEV 告警（既有机制）。
- 图表颜色统一走 `constants/chartTheme.ts`，theme 相关色值不得硬编码；涨红跌绿（中国市场惯例）。

## 9. 关键机制设计

### 9.1 双任务锁

| 锁 | 范围 | 冲突行为 | 实现要点 |
|----|------|---------|---------|
| `mining_domain` | `task_type='factor_mining'`，判定 `(queued, running)` | **直接拒绝**（不排队），返回当前任务 ID/状态/代数 | `INSERT INTO task_locks` 靠 `lock_key` 唯一约束原子获取；冲突时读 `owner_task_id` 拼拒绝体 |
| `duckdb_write` | 所有写 DuckDB 的任务 | **排队**，返回位次 + 估算等待 | 冲突时追加到 `queue_json`；释放时 `trigger_queue=True` 主动拉起队首 |

- **心跳**：默认 1800 秒（可配），更新点 = 每代结束 + 最终验证每完成 10 个因子。超时由 `expire_stale_locks`（复用 `_expire_stale_tasks` 类逻辑）释放并通知。
- **队列消费者**：复用 `async_tasks` 状态机 + 锁释放时主动触发，**不引入新调度器**。
- **字段校验任务不占 `mining_domain`**，但同一草稿 + 同一 `config_hash` 活动任务唯一。
- 提交流程严格顺序：查 `mining_domain`（有则拒）→ 查 `duckdb_write`（空闲执行 / 被占排队）→ 完成/失败/取消释放并拉起队首。

### 9.3 G2 子表达式缓存与抽样校验

```text
AST 遍历提取子表达式（含叶子字段引用）
  → key = sha256(算子类型 + 参数 + 字段唯一 ID + 数据快照版本 + schema_version + hash_algorithm_version)
  → 向量化批量计算（numpy/DuckDB，float32 存储，不逐股票循环）
  → 主进程内存缓存（**不写 DuckDB**，规避单写锁）
  → 组装时递归查缓存（单测断言 compute_node 调用次数为 0）
```

| 风险 | 措施 |
|------|------|
| 哈希碰撞/语义不等价 | SHA-256 强哈希（**禁用 Python 内置 hash，有随机化种子**）；每代抽 5 个因子对比，差异 >1e-6 **报警 + 废弃重算 + 落库** |
| 缓存污染 | 每个子表达式算完检查 NaN/Inf/空值比例，异常不写入并标记 `failed`；记录带 `status`（valid/failed/computing） |
| 版本不兼容 | 缓存带 `schema_version` + `hash_algorithm_version`，不匹配自动废弃 |
| 范围混用 | 预筛阶段与全量验证阶段**分别建缓存** |

**抽样校验结果必须落库**：每代写 `cache_validation_passed`(0/1) 与 `cache_validation_max_diff`，为 0 时前端进化曲线标记该代并提示"缓存校验未通过，已重算"。

### 9.4 性能探针（M1 必埋）

逐代记录 6 个阶段耗时 + 3 个缓存指标，写 `factor_mining_generations`。M3 依据探针数据定位瓶颈后再决定 G1 并行哪一段，**否则"压测后决定"无从谈起**。

### 9.5 AI 生成与降级

| 项 | 值 |
|---|---|
| 调用上限 | 10 次 × 每次 8~12 骨架 ≈ 80~120 个 |
| 并发 | 4 路 `ThreadPoolExecutor` + `asyncio.to_thread`（`llm_client` 为同步 def） |
| 超时 | 单次 30 秒；**AI 环节总超时 5 分钟** |
| 成本 | ¥10 / 500k token |
| 强制输出 | `formula_ast` + `category` + `economic_logic` + `expected_direction`，**缺一丢弃、名额回退随机** |
| 降级 | 失败/超时/成本超限/校验不通过 → 剩余名额全部回退**受约束随机**，**不阻塞进化** |
| 最坏情况 | 80 个叠满损耗（15%+20%+10%）剩约 49 < 57，随机补足，实际占比可能低于配置 57%，**属预期行为** |

### 9.6 四层去重

| 层 | 手段 | 阶段 |
|----|------|------|
| 1 生成时规避 | AI：Prompt 注入已入库公式 + 4 批递进 + 类型配额 + 去重反馈重试（≤3 次）+ 结构差异化<br>随机：实时哈希拦截（≤20 次）+ 同结构 ≤3 变体 + 分层采样 + 相似度降权 | 生成 |
| 2 `formula_hash` 精确去重 | 交换律归一 + 参数排序 + 去冗余括号 + 算子别名统一后哈希；跨来源合并保留优先级 **经典 > AI > 随机** | 生成后 |
| 3 AST 结构相似度 | M1 简化相似度 / M2 树编辑距离；>0.9 归组留 1 代表 | 生成后 |
| 4 因子值相关性 | 三层指纹预筛 → 精确 Spearman；≥0.95 标 `eliminated_similar`（**不物理删除**） | 每代评估 |

### 9.7 选择机制（M2）

| 机制 | 职责 | 关键参数 |
|------|------|---------|
| A1 赛道竞争 | 决定"在哪个因子类型池里选" | 6 类归类优先级 `quality > valuation > volatility > volume_price > reversal > trend`；配额「保底 60% + 动态 40%」；`weak_category_generations=3`；`cross_category_crossover_ratio=0.2` |
| B1 多目标 NSGA-II | 决定"用什么标准判优劣" | 目标池固定（ICIR↑/覆盖率↑/换手率↓/复杂度↓ + 可选 oos_stability、monotonicity）；启用 3~5；`dominates(a,b)`；rank + CD；边界 CD=∞；比较「rank 升 → 同 rank 比 CD 降」 |
| B2 锦标赛 | 决定"用什么动作选出父代" | `k=3`（2~7）；可重复抽中；精英不参与 |
| 偏好档位 | **只作用于结果排序与前沿高亮** | balanced/stable/aggressive/simple；**不进入进化计算** |

> 与已有因子相关性（<0.95）**不进帕累托**，作为硬门禁单独卡（避免目标过多导致分层失效）。

### 9.8 繁殖自适应（M2）—— 九机制单向信号流

```text
评估(每代指标)
  → D3 产 health（类型均衡度 + 基因型 + 表现型三层合成）+ D1 产 stall / convergence_delta（只观测）
  → 选择阶段：A1 定配额 → B1 定标准 → B2 选父代（独立运作，不依赖 C1）
  → C1 读【health + stall + 代数】→ 输出 strategy(g)（唯一调参者）
  → C2 变异 / C3 交叉 / D2 注入（严格按 strategy 执行）+ 校验补位
  → D1 判断：C1 已自救且连续 3 代无进步 → 早停
```

**安全护栏（写死，规则不得突破）**：变异率 [0.40, 0.80]、交叉率 [0.10, 0.50]、注入率 [0.05, 0.20]，三率和归一为 1；滞回 `hysteresis_generations=2`；单步 `max_step=0.10`；精英永不参与变异/交叉/注入。

**分期**：M1 用朴素选择（按 ICIR 排序）+ 固定三率；M2 换完整机制。

### 9.9 统计层 8 方法

| 方法 | 实现 | 依赖 | 输出 |
|------|------|------|------|
| t 检验 | `scipy.stats.ttest_1samp(ic_series, 0)` | scipy | `p_value` |
| Bonferroni | **自研** `p_adj = min(p × n, 1.0)` | numpy | `p_adj`、是否 <0.001 |
| FDR (BH) | **自研** `_bh_adjust()`：p 升序 → `p×n/rank` → 自后向前单调化 | numpy | `q_value`、是否 <0.1 |
| Bootstrap | numpy 有放回重采样 1000 次 → ICIR 2.5%/97.5% 分位 | numpy | `ci_lower`/`ci_upper` |
| 置换检验 | 随机打乱因子值 1000 次重算 ICIR → 经验分布 | numpy | `perm_p_value` |
| Deflated Sharpe | `total_trials` + IC 分布偏度/峰度校正 | scipy | `dsr_icir` |
| 衰减率 | `test_ICIR / train_ICIR` | — | `decay_ratio`（<0.5 疑似过拟合） |
| Walk-Forward | 3~4 滚动窗口，每窗口内再切 train/val/test；**只做方向一致性计数** | — | `{windows, same_direction, per_window_icir}` |

**存储约定**：写 `factor_evaluation_runs.metrics_json.stats`（**不新建表**，避免与评估链路分叉）。若后续字段膨胀影响查询性能再考虑拆表。

**实现路径唯一**：Bonferroni/FDR 不做双路径开关，避免两条实现结果不一致。

### 9.10 质量分级（M2）

```python
def grade(metrics: dict, thresholds: dict | None = None) -> tuple[str, str]:
    """纯函数：8 维度指标 → (等级, 理由)。阈值可注入，默认读设置页配置。"""
```

- **8 维度**：统计显著性、经济显著性、稳定性、覆盖率、换手率、复杂度、与已有因子相关性、OOS 表现。
- **五级阈值「每一级全部满足才定级」**：S / A / B / C / D（默认值见需求 §6.8，可在设置页调整）。
- **硬约束**：`decay_ratio < 0.5` → 不得 B 级以上；月频任务 → 最高 B 级。

## 12. 风险与待决项

### 12.1 风险登记

| # | 风险 | 影响 | 概率 | 对策 |
|---|------|------|------|------|
| R1 | **DuckDB 历史镜像不足**（当前 `raw_daily_bars` 仅约 1.65 年，watermark 起点最早 2025-01-12） | 周频约 80 < 104、月频约 19 < 36，**样本量硬门槛不达标，无法启动挖掘** | 高 | M0 必须先完成 5 年镜像；M1a 交付镜像 UI；镜像失败时给出结构化阻断 + "去镜像"跳转 |
| R2 | 项目**无 ProcessPool 先例**，Windows 无 `fork`，`shared_memory` 有 resource_tracker 泄漏坑 | G1 实施成本与风险高于预期 | 中 | G1 归 M3，由 M0 压测 + M1/M2 探针数据决定；不达标就明确"不做" |
| R3 | `scipy` 当前仅为 sklearn 传递依赖 | 换环境或 sklearn 升级时 `import scipy` 断裂 | 高 | **M1a 立即写入 `requirements.txt`** |

| R5 | 三次切分/锁的实现偏差导致 eval 泄漏 | **结论不可信**（比性能问题严重得多） | 中 | `assert_no_leakage` 每代断言；M1a 单测 + M1b 端到端双验证；评审强制检查 |
| R6 | 统计层 8 方法理解偏差（尤其 Walk-Forward 重叠窗口） | 高估显著性 | 中 | 重叠窗口**只做方向一致性计数**，UI 强制标注"不作独立统计检验"；各方法与手工小样本对拍 |
| R7 | 候选池看板分析（2~15 秒）阻塞 UI | 体验 | 低 | 同步计算 + loading；>2000 只走异步提示（预留） |
| R8 | `Settings.tsx` 已 682 行，继续加栏加剧维护成本 | 可维护性 | 中 | M3 拆 `Settings.tsx`；新栏以独立 Shell 组件承载，不在 `Settings.tsx` 内堆逻辑 |
| R9 | 月频用户误以为可达 S/A 级 | 期望落差 | 中 | Step2 蓝色引导 + 结果页黄色提示 + 抽屉灰掉 Bootstrap/置换行 |
| R10 | 多个开发并行改 `factor_compiler.py` | 冲突 | 中 | M2 模块**单人 codeowner**；DSL 与字段注册在 M1a 一次性完成，避免多人同时改 |
