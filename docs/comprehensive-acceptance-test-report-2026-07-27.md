## 1. 最终结论

本轮发布判定：**不通过（NO-GO）**。

当前版本已有大量功能和测试资产，7 个一级页面均能打开，消息管理 P0、AI 会话路由、因子流水线启动异常、迁移链和前端生产构建等修复取得了明确进展。但本轮仍存在以下发布阻断：

1. 后端全量测试有 26 个失败、112 个跳过。
2. 真实 HTTP 黑盒有 12 个失败、8 个跳过。
3. 观察池真实页面返回 `DB_CONNECTION_FAILED / HTTP 503`。
4. 工作台聚合接口发生读取超时。
5. 17 个接口批量探测实际耗时约 648～658 秒，超过文档 180 秒目标。
6. 原始 Spec、后续 WP9.5 清单和自动化测试对成员来源默认值存在直接冲突。
7. 真实验收库存在测试数据残留，无法保证验收数据可重复和不污染业务数据。
8. 移动端存在横向溢出和一级导航严重挤压。
9. AI、自动交易、真实外部消息渠道及真实大规模扫描仍受配置或环境阻断，未形成完整验收证据。

因此，当前不能声明“功能全部符合预期”，也不能声明“42 个 Spec Scenario 全部符合文档预期”。

## 11. 测试基础设施问题

1. 日期 fixture 固定在 2026-07-19，运行到 2026-07-27 后自动变成过期快照，导致 14 个 discovery 测试失败。
2. 日志级别/禁用状态在测试文件之间泄漏，导致多项 `caplog` 测试全套失败、单独通过。
3. 前端异步测试等待静态标题，而不是等待实际数据节点，产生波动。
4. 真实黑盒直接使用当前业务库，产生测试组合和任务残留。
5. 真实服务启动会运行调度器，不适合作为可重复 UAT 环境。
6. 统一错误协议已替换 FastAPI 旧 `detail`，但部分黑盒测试仍检查旧字段。
7. `docs/uat-checklist.md` 没有记录命令、时间、环境和证据。

建议建立：

- 独立 `gpfx_uat` 数据库；
- 固定种子和自动清理事务；
- `UAT_DISABLE_SCHEDULER=true`；
- `freezegun` 或可注入时钟；
- 每个测试恢复 logger 状态；
- E2E 启动脚本统一检查 8000/5173；
- 发布报告自动汇总 JUnit/Vitest/性能 JSON。
