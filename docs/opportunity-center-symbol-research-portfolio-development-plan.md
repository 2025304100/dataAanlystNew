## 0. 开发结论

本次改造不是重新建设量化系统，而是在当前已具备的数据、因子、评分、扫描、回测、模拟交易、任务和告警底座上，完成产品对象收口和工程稳定性升级。

实施顺序固定为：

```text
基线与开关
-> 稳定性、缓存、错误和前置条件
-> 评分快照与5分钟快速扫描
-> 机会中心与正式观察池
-> 统一消息管理
-> 状态流转、组合成员与标的研究
-> AI上下文助手
-> 自动交易、组合回测与绩效归因
-> 旧入口清理与生产验收
```

四条强制原则：

1. 本地数据优先。已有合格行情、评分或因子数据时，用户操作不得访问第三方接口。
2. 条件先行。前置条件未满足时，页面可浏览，但危险操作必须阻断并给出修复入口。
3. 双轨切换。自动交易、组合回测和旧页面不能一次性替换，必须通过功能开关与影子对比迁移。
4. 外部增强可降级。AI、微信、钉钉、QQ和邮件失败时，不得阻塞扫描、告警、交易和数据入库。

## 1. 建设目标

### 1.1 业务目标

- 建立清晰的候选→观察→组合成员→持仓/订单生命周期。
- 将投资中心收敛为共享标的研究能力。
- 将“目前观察池”恢复为真正的组合交易与模拟账户。
- 普通用户能按引导完成数据准备、扫描、观察、组合和模拟交易。
- 用户能解释每个候选、订单、回测和绩效结果的来源、版本与数据日期。

### 1.2 性能目标

- ready 快照下，A股约5,500只或ETF约1,600只快速扫描 P95 ≤ 300秒。
- 相同快照和参数的重复扫描 ≤ 10秒。
- 不含高级指标的普通扫描目标 ≤ 60秒。
- 无可用快照时10秒内明确返回准备状态，不允许进度条长期卡住。

### 1.3 稳定性目标

- 本地缓存命中时第三方请求数为0。
- 相同外部请求并发时只产生一次真实请求。
- 403、429、超时和响应格式变化均可熔断、降级或给出可理解错误。
- 取消或异常退出后释放数据库、线程池和DuckDB文件锁。
- 长任务必须有心跳、阶段预算和终态巡检。

### 1.4 易用性目标

- 所有阻断错误回答：发生了什么、影响什么、下一步做什么。
- 第一次使用通过向导完成，不要求用户理解数据库、DuckDB或任务状态机。
- 页面按钮不能在条件不足时进入必然失败分支。
- AI和外部推送未配置时显示用途与配置入口，不直接报连接错误。

## 2. 范围边界

### 2.1 必须完成

- 统一外部数据网关、缓存命中、单飞、限流和熔断。
- 统一错误协议、能力门禁和首次使用向导。
- 评分快照、增量更新、快速扫描和分层结果清理。
- 机会中心四个页签与正式观察池。
- 候选、观察和组合成员统一流转与审计。
- `portfolio_members`、成员级执行模式和历史有效日期。
- 标的研究组件化与本地收藏/提醒迁移。
- AI上下文、只读工具、草稿、确认和审计。
- 站内、WxPusher、钉钉、QQ/OneBot、邮件和通用Webhook消息管理。
- 自动交易和组合回测切换到成员来源。
- 订单、回测和绩效归因。

### 2.2 复用且禁止重写

- `Symbol`、`DailyBar`、`UniverseSymbol`、`UniverseDailyBar`。
- Score、评分配置、因子仓库、Ridge和模型运行模式。
- Discovery扫描算法和公式校验器。
- 事件驱动回测与VectorBT研究引擎。
- 模拟账户、现金流水、订单、成交、成本和市场规则。
- 异步任务、任务中心、定时任务和数据健康。
- 告警规则与告警事件。

### 2.3 明确不做

- 真实券商下单。
- Level-2、毫秒级或日内T+0。
- 用AI直接触发自动交易。
- 为QQ个人账号写死不稳定的非官方接口。
- 删除或重建现有组合、持仓、订单、成交、回测和告警历史。
- 用新UI掩盖未解决的任务卡死和数据不透明问题。

## 5. 十二周实施路线

周期是单主开发者的参考，不允许为了赶周数跳过退出门槛。外部平台联调、真实数据双跑或迁移问题可顺延。

### Week 1：WP0 基线与安全开工

| 任务 | 内容 | 交付物 |
| --- | --- | --- |
| BASE-001 | 记录当前Schema、表数量、功能入口和关键API | `docs/migration-baseline-*.md`或可重复执行的只读脚本 |
| BASE-002 | 增加机会中心、成员来源、自动交易新来源、回测新来源等功能开关 | 配置、读取接口和默认值测试 |
| BASE-003 | 建立Alembic增量迁移模板和SQLite/MySQL兼容规则 | 首个无损迁移Revision |
| BASE-004 | 建立旧路由、旧activeTab和旧API兼容约束 | 兼容映射测试 |
| BASE-005 | 建立迁移前后自动对账 | 观察、组合、持仓、现金、订单、成交、回测数量对账 |

主要文件：

- `app/core/config.py`
- `app/db/init_db.py`
- `alembic/versions/`
- `frontend/src/App.tsx`
- `frontend/src/context/AppContext.tsx`

退出门槛：

- 所有新功能开关关闭时，当前行为完全不变。
- SQLite新库、SQLite旧库和MySQL旧库均可启动。
- 重复执行迁移不重复回填或改变历史ID。

- `akshare_registry.py`
- `market_data_sources/chain.py`
- `async_tasks.py`
- `TaskCenter.tsx`

退出门槛：

- 本地有合格数据时相关操作第三方请求数为0。
- 20个相同并发请求只产生一个真实请求。
- 403/429/超时后进入熔断并可读取旧缓存或备用源。
- 普通用户界面不直接显示HTTP 500、Python异常或数据库锁文本。
- 强制取消任务后DuckDB文件可以立即再次打开。

### Week 4～5：WP-P 快照与5分钟扫描

| 任务 | 内容 | 交付物 |
| --- | --- | --- |
| PERF-001 | 记录当前各阶段耗时、查询数、内存和写入量 | 性能基线报表 |
| PERF-002 | 新增评分快照Manifest和Item | `discovery_score_snapshots/items`迁移与模型 |
| PERF-003 | 将评分物化接到现有基础数据/因子任务之后 | 可取消、原子ready的快照任务 |
| PERF-004 | dirty标的增量更新 | 行情、财报、因子变化失效规则 |
| PERF-005 | 快速扫描API | SQL粗筛→Top300高级过滤→组合约束 |
| PERF-006 | 相同快照和参数缓存 | `cache_key`及结果复用 |
| PERF-007 | 限制ScanResult写放大 | Top-K结果和运行摘要 |
| PERF-008 | 分层清理 | 候选、结果、快照、运行摘要不同TTL |
| PERF-009 | 真实规模性能测试 | A股5,500、ETF1,600的SLA报告 |

退出门槛：

- ready快照下快速扫描P95≤300秒。
- 相同参数二次扫描≤10秒。
- 快速扫描路径没有第三方HTTP调用。
- 扫描写入量不再接近三倍全市场标的数。
- 候选过期不会删除行情、Score和可复用快照。
