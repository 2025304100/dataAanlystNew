## 1. 优化目标与总体方案

把“行情消息”改造成“宏观政策与行业趋势的高影响事件筛选器”。通过 AI 提取事实、对比变化，再按固定规则评分；只有证据充分、存在实质变化、达到门槛的事件，才主动提醒用户。

首版采用以下默认策略：

| 项目 | 首版建议 |
|---|---|
| 关注范围 | 宏观政策与行业趋势 |
| 处理单位 | 独立事件及其关键变化版本 |
| 提醒起点 | 总分至少 85 分，同时通过证据、实质影响、新增变化等门槛 |
| 提醒数量 | 按北京时间，每天最多 3 次主动提醒，允许当天 0 次 |
| 重复处理 | 同一事件合并展示，关键事实没有变化时不重复提醒 |
| 模型使用 | 复用现有模型，先进行样本标注、评分校准和评测 |
| 上线方式 | 先只评分、暂不主动提醒，验证后开启站内提醒 |

验收围绕提醒价值、重要事件遗漏和依据可追溯性展开。消息数量、模型调用次数和高分数量不作为价值指标。

## 2. 关注范围与事件类型

第一版围绕宏观政策与行业趋势，优先识别以下变化：

| 关注方向 | 重点识别的事实 |
|---|---|
| 货币与财政政策 | 利率、准备金、财政支出、专项资金、税费发生明确变化 |
| 产业与监管政策 | 补贴标准、准入条件、采购要求、出口限制、监管约束发生变化 |
| 行业需求 | 订单、销量、招标、资本开支等出现有依据的变化 |
| 行业供给与成本 | 产能退出、限产、供给中断、原料成本及供需缺口发生变化 |
| 行业趋势验证 | 多个时点或多类数据，相互印证需求、盈利或供需趋势 |

“国际形势”作为分类保留。国际新闻必须能说明如何影响上述变量，才能进入重点评估。“紧急”“利多”“利空”等关键词标签继续服务检索；主动提醒由新的影响评估决定。

百度经济日历、财报日历进入“待公布事项”。日历上出现一个事件，不代表已经发生了有价值的变化。真实结果公布后，再评估结果及其新增信息。

行业趋势判断需要多个时点或多类事实相互印证。单条报道可以成为线索，但不能仅凭一次报道就认定趋势已经形成。

## 3. 处理流程与事件归并

完整处理链路：

```text
采集消息
  → 初筛
  → 同一事件归并
  → 补充原文和历史依据
  → AI 结构化分析
  → 固定规则评分
  → 提醒门槛判断
  → 页面展示与受控提醒
  → 用户反馈
```

### 3.1 从新闻条目转向独立事件

同一份政策被多家媒体转载时，形成一张事件卡并保留各来源。后续出现实施细则、资金规模变化、正式落地或撤回，再形成事件的新版本。

归并时识别以下要素：

- 主体与事件对象。
- 政策文件、文件编号或其他稳定标识。
- 具体动作与发生时间。
- 金额、比例、范围、执行状态等关键事实。

仅讨论同一个行业的消息不能全部合并。同一文件的转载不能因为标题不同而再次提醒。政策草案、正式文件及后续实施细则需要保留各自的时间和变化关系。

### 3.2 事实变化与评分版本分离

事件关键事实版本用于判断是否出现新的实质变化；模型、提示词和评分规则版本用于评估审计。

仅模型版本变化、分数波动、措辞变化或转载数量增加，不构成再次提醒的理由。

相关性、新颖度和情绪分别处理，是成熟新闻分析产品采用的维度。本文的具体权重、档位和提醒规则属于本项目的初始设计，需要自行验证。[LSEG News Analytics 官方说明](https://developers.lseg.com/en/product/news/news_analytics)

## 4. AI 分析职责与证据要求

AI 负责提取事实、对比变化并输出有依据的判断；程序负责校验结构、计算分数和决定是否提醒。

### 4.1 每个候选事件的必需分析内容

| 分析内容 | 必须回答的问题 |
|---|---|
| 已核实事实 | 谁在什么时候发布了什么？原文在哪里？ |
| 新增变化 | 相比旧政策、前次数据或已有事实，具体改变了什么？ |
| 实质影响 | 改变了资金、需求、供给、成本，还是监管约束？ |
| 影响路径 | 通过什么机制，影响哪些行业？ |
| 规模与持续性 | 变化多大、持续多久，有哪些缓冲或抵消因素？ |
| 不确定性 | 哪些依据缺失？哪些结论暂时无法判断？ |

关键判断需要关联原文片段或数据出处。缺少依据时标记“待核实”，不能通过模型补全缺失的事实。

模型可能生成貌似可信的错误事实和引用，因此解释流畅、模型自报高置信度都不能替代核验。[NIST 生成式 AI 风险说明](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)

### 4.2 区分新增信息与超预期

| 概念 | 判定要求 |
|---|---|
| 新增信息 | 相对于已有资料，确实出现新事实 |
| 超预期 | 相对于发布前可查的市场预期，出现偏离 |

没有可靠的发布前预期，就不输出“超预期”。政策新增变化可以依据新旧条款对比判断，不必虚构市场一致预期。

### 4.3 时间与证据不足的处理

- 分开记录原始发布时间、采集时间和日历计划时间。
- 发布时间无法核实时，不把采集时间当成首次发布时间来获得时效分。
- 缺少原文、可比基线或关键量化依据时，明确记录缺失内容。
- 证据不足不等于影响低，应标记“待核实”；补充依据后再评估。
- 模型超时、服务不可用、返回结构异常时保留待评估状态，不通过关键词等级替代 AI 影响度提醒。

## 5. 影响度评分

### 5.1 总分公式与档位

```text
影响度总分（100 分）
  = 实质影响（40 分）
  + 新增变化（30 分）
  + 影响范围与持续性（20 分）
  + 信息时效（10 分）
```

| 维度 | 权重与档位 | 判断依据 |
|---|---|---|
| 实质影响 | 40 分；0 / 10 / 20 / 30 / 40 | 是否改变实际经济变量，变化是否有约束力、达到值得关注的规模 |
| 新增变化 | 30 分；0 / 10 / 20 / 30 | 是重复报道、补充说明，还是关键条款、数据或执行状态发生变化 |
| 影响范围与持续性 | 20 分；范围与持续性各 0 / 5 / 10 | 涉及哪些行业，影响是短暂扰动还是持续改变 |
| 信息时效 | 10 分；0 / 5 / 10 | 是否首次获知、是否仍有研究价值，避免旧消息重新包装 |

采用明确档位，避免没有校准依据的精细打分。分数代表本方案下的关注优先级，不代表上涨概率、下跌概率或盈利胜率。

### 5.2 实质影响的初始档位

| 档位 | 初始判断标准 |
|---|---|
| 0 分 | 经核实没有相关变量变化，或属于无新增事实的表态 |
| 10 分 | 有影响线索，但传导较弱、变化有限 |
| 20 分 | 有明确变化，影响局部，或存在较强抵消因素 |
| 30 分 | 有证据支持较显著的变化，能说明规模、约束条件和传导路径 |
| 40 分 | 有充分依据支持广泛、强约束或显著改变供需与资金条件的影响 |

证据不足时暂不形成可用于提醒的总分，不能直接归为 0 分。

### 5.3 按事件类型判断实质影响

| 事件类型 | 重点判断内容 |
|---|---|
| 专项资金与财政支持 | 新增净额、是否属于存量延续、覆盖范围、执行条件与拨付进度 |
| 限产与供给中断 | 有效产能占比、持续时间、库存、替代供给及恢复条件 |
| 行业需求变化 | 订单或销量口径、季节性、可比基线和多个时点的验证 |
| 成本变化 | 成本占比、持续时间、传导能力以及上下游承担方式 |
| 监管与准入变化 | 法律或执行约束、适用对象、生效时间和过渡安排 |

金额大、比例高或标题措辞强烈，均不能单独决定分数。各类型的量化边界需要通过样本校准，不能预设一个对所有行业通用的百分比阈值。

### 5.4 分类型量化与行业校准

实质影响采用“分事件类型基准量化＋行业与指标口径校准＋定性规则修正＋样本迭代调优”的四层体系。完整公式、五类规则表、字段定义和回归验收设计见[实质影响评分量化细则](实质影响评分量化细则-行情消息-2026-10-26.md)。

执行约束如下：

- 类型模板的数值边界仅用于试算；未验证的“事件类型＋行业＋指标口径”配置不能参与自动提醒。
- 行业占比已经进行规模归一化，不再默认按行业绝对产值叠加 0.7 / 1.0 / 1.5 系数。行业差异根据利润敏感性、弹性、库存、替代能力和样本分布校准，参数需要独立验证。
- 缺少原文、基线或关键数据时分数为 null，保留待核实状态；经核实没有相关变化时才可计 0 分。
- 多年度资金与年度规模不能直接混除；产能与期间产量不能混除；增速偏离使用百分点。
- 净供给和净成本中已扣除的缓冲不再次降档；发布主体、预期、范围与持续性不重复升降实质影响档位。
- 尚未建立模板的利率、准备金等宏观事件进入复核，不隐式套用最接近的五类模板，并统计由此造成的遗漏。

## 6. 提醒门槛、频率与去重

### 6.1 提醒必须同时通过的条件

| 条件 | 首版要求 |
|---|---|
| 关注相关性 | 能明确关联宏观政策或行业趋势 |
| 证据 | 关键事实有可核验的原始文件、数据，或能够核验的可靠报道 |
| 实质影响 | 至少 30 分 |
| 新增变化 | 至少 20 分 |
| 总分 | 至少 85 分 |
| 配置验证 | 本事件使用的评分配置已经验证并显式启用，模板试算结果不直接提醒 |
| 重复判断 | 首次提醒，或已提醒事件出现新的实质变化 |
| 时效 | 发布时间可信，仍处于可关注窗口 |

总分达到门槛不能抵消证据、实质影响或新增变化不满足要求的问题。

### 6.2 分数对应的产品行为

| 结果 | 页面处理 | 提醒方式 |
|---|---|---|
| 95—100 分且通过全部门槛 | 高影响事件 | 及时提醒，占用每日额度 |
| 85—94 分且通过全部门槛 | 重点事件 | 盘前、盘后集中筛选后提醒 |
| 70—84 分 | 观察列表 | 用户主动查看 |
| 低于 70 分 | 全部消息中保留 | 不主动提醒 |
| 证据缺失或分析失败 | 待核实或待评估 | 补充依据或恢复后再评估 |

### 6.3 提醒数量与纠错

- 按北京时间，每天最多 3 次主动提醒，按价值排序，允许当天 0 次。
- 达到 95 分的事件也占用同一每日额度。
- 同一事件出现新的实质变化而再次提醒时，占用当日额度。
- 超过额度的高分事件继续在重点区展示，并注明“未主动提醒”。
- 相同事实的重试、并发执行及重复入队需要保持幂等。
- 原始事实被撤回或证实错误时，对已经提醒的内容进行明确更正；更正属于已送达内容的纠错，单独记录，不作为普通新事件提醒处理。

## 7. 页面展示与统计降噪

### 7.1 默认入口与信息层次

页面默认进入“重点事件”，提供“观察列表”“全部消息”和“待公布事项”的访问入口。

每张重点事件卡突出以下内容：

> 发生了什么 → 比之前新增了什么 → 为什么可能影响行情 → 影响哪些行业 → 依据与不确定性

以下为假设示例，不对应真实政策：

> **85 分｜某行业专项支持政策正式落地**  
> **新增变化：** 相比征求意见稿，明确了新增资金、执行范围与生效时间。  
> **影响路径：** 改变相关企业的项目投入条件，可能带动设备采购需求。  
> **评分：** 实质影响 30 ＋ 新增变化 30 ＋ 范围与持续性 15 ＋ 时效 10。  
> **待验证：** 后续资金拨付和实际订单。  
> **来源：** 正式文件及对应条款。

### 7.2 方向标签与热点统计

“利多/利空”落到具体行业和传导路径，允许同一事件对上游、下游产生不同影响，不把整条消息的方向直接套给所有相关行业。

现有热点统计保留为“报道热度”。新增事件统计按独立事件数、影响等级和验证状态展示，避免转载越多的题材看起来越有价值。

### 7.3 空状态与未完成状态

- 没有符合条件的事件时，显示“暂无达到提醒门槛的事件”。
- 尚未完成分析时，显示“评估中”。
- 缺少证据时，显示“待核实”及缺失项。
- 不通过补入旧事件或降低门槛来填满重点区。

## 8. 样本标注、校准与验收

### 8.1 首版模型策略

首版复用现有模型，先做样本标注、评分校准和评测。训练模型不能替代最新原文、历史条款和行业基线的获取。

准备 100—200 个独立事件作为起步样本，覆盖真正重要的变化、旧政策转载、标题夸张、规模有限、证据不足等类型。

人工只需判断：

1. 值得提醒、不值得提醒，还是资料不足。
2. 重要或不重要的原因。
3. 关联哪个宏观或行业主题。

分数由规则生成，避免要求用户直接标注精细分值。

实质影响校准可以另行标注 0 / 10 / 20 / 30 / 40 或无法判断，但应先独立形成提醒价值判断，再核对规则档位。只检验人工能否复现同一张规则表，不能证明提醒有用。

### 8.2 评测方法

- 同一事件及其转载放在同一组，避免训练示例与测试集相互泄漏。
- 留出较新的事件做独立测试。
- 评估时只使用当时能够获得的信息，不能将后续文件、行情或行业数据用于还原当时判断。
- 后续价格和基本面变化可以用于事后复盘，不作为“当时是否值得提醒”的唯一标签。
- 接入实际消息后，先运行“只评分、暂不主动提醒”的模式。
- 检查高分事件是否值得看，以及重要事件为什么被漏掉。
- 实际消息试运行保持自然流量分布，避免只用人工挑选的均衡样本估计线上提醒有用率。

### 8.3 首轮建议验收目标

| 指标 | 建议目标 |
|---|---|
| 提醒有用率 | 目标至少 90%，由人工复核判断 |
| 重复提醒 | 自动化回归用例中为 0，试运行逐条核查 |
| 关键依据可追溯 | 100% |
| 每日主动提醒 | 默认不超过 3 次 |
| 重要事件遗漏 | 对标注集和试运行样本逐条分析，包含待核实、未评分及额度截断造成的遗漏 |

同时分别记录门槛筛选造成的遗漏与每日额度截断造成的遗漏。采集覆盖不足造成的遗漏也要单独分析，不能通过只统计已评分事件来提高表面指标。

上述指标是试运行目标。100—200 个样本可以帮助发现规则问题，但不能保证长期准确率。只有在标注标准稳定、错误持续存在且评测支持时，再评估是否需要微调模型。

## 9. 实施顺序与技术落地

### 9.1 分阶段实施

| 阶段 | 交付内容 | 完成标准 |
|---|---|---|
| 第一阶段：事件与依据 | 事件归并、日历分流、原文与历史对比、结构化分析、评分记录 | 能解释每个事件为何高分、低分或待核实 |
| 第二阶段：页面与校准 | 重点事件页、反馈标注、历史评测、实际消息试运行 | 有用率和漏报问题达到可接受水平 |
| 第三阶段：受控提醒 | 阈值、每日额度、事件版本去重、失败恢复与审计 | 自动化回归通过，再开启站内提醒 |

### 9.2 复用现有能力

复用现有 MySQL 5.7、AI 调用管理、调度和通知队列，新增以下持久化能力：

| 数据能力 | 用途 |
|---|---|
| 事件归并关系 | 关联独立事件、原始消息和事件关键变化版本 |
| 带版本的评估记录 | 保存输入依据、模型与规则版本、分项分数及提醒决定 |
| 用户反馈 | 保存提醒价值判断、原因及修正结果，支持后续校准 |

相同事实复用评估结果，出现实质变化再评估。AI 调用沿用现有用途、额度、并发和审计管理，避免逐条转载重复调用。

数据结构变更采用独立迁移，继续兼容 MySQL 5.7；历史原始消息和已有人工修正需要保留。历史评估用于校准，开启提醒时应设置启用边界，避免历史高分事件集中补发。

### 9.3 通知验证范围

按既有约定，先完成站内消息与本机 Webhook 闭环。第三方实际送达另行安排。

本机验证需要覆盖发送重试、并发处理、重复入队和接收方幂等。第三方渠道启用前，还需针对目标渠道验证实际送达及其去重能力。

## 10. 自动化回归重点

| 回归方向 | 关键场景 |
|---|---|
| 事件归并 | 跨来源转载归并；同一行业不同事件不误合并；同一文件不同标题不重复提醒 |
| 事件版本 | 草案到正式文件；实施细则；资金与执行条件变化；措辞变化不生成实质新版本 |
| 文本理解 | 否定句、取消或解除限制、双重否定、撤回、更正及不同产业链环节方向差异 |
| 时间与日历 | 日历计划时间不作为实际发布时间；旧消息重采不获得新鲜度；北京时间每日额度边界 |
| 证据校验 | 缺少原文、引用无法核验、可比基线缺失、预期未知、模型无依据补全 |
| AI 异常 | 超时、服务不可用、返回异常结构、评估中断和恢复，不误发提醒 |
| 评分门槛 | 分项档位、85 分总分、实质影响 30 分、新增变化 20 分及证据门槛组合 |
| 量化细则 | 分子分母与期间口径、百分点、互斥边界、净额去重、缺失为 null、未验证配置拦截及未支持类型复核 |
| 通知控制 | 重复任务、并发入队、失败重试、每日额度、额度超限展示、已发送内容纠错 |
| 历史与版本 | 模型或规则升级不重复提醒；历史高分不集中补发；人工修正保留 |
| 老功能 | 分页、收藏、全量导出、标签修正、热点统计、筛选、采集状态与失败提示 |

## 11. 剩余风险与持续观察项

| 风险 | 影响与处理方向 |
|---|---|
| 重要事件未被采集 | 评分无法补救来源缺失；验收需同时检查重点宏观与行业来源覆盖及采集时延 |
| 严格证据要求延迟早期线索 | 部分事件暂缓提醒；通过观察列表和待核实状态保留线索，及时补充依据 |
| 影响方向与行情表现不一致 | 高影响度不代表价格一定按预想方向变化；分开记录事实、传导判断及事后验证 |
| 初始权重与阈值偏差 | 85 分及各档位需要校准，不能作为未经验证的准确率保证 |
| 事件误合并或拆分 | 可能造成遗漏或重复提醒；评测与回归需覆盖相似事件、政策版本和跨来源转载 |
| 提醒额度截断 | 高分事件可能未主动提醒；重点区保留并标记，评测单独记录额度造成的遗漏 |
| 模型与规则变化 | 可能导致评分漂移；保留评估版本，进行固定样本回归和实际消息对比 |

上线验收应同时检查来源覆盖、重要事件遗漏、依据可追溯和提醒价值，不能只检查分数是否超过 85。
