## 3. 合理测试数据设计

> 全部测试数据均来自对真实库的实测，非臆造；命中/样本量满足系统硬下限（50 只）与「最小值 ≤ 最大值」等格式约束。

### 3.1 Step1 条件筛选数据（合理区间）

| 条件组合 | 实测命中 | 可用性 |
|---|---|---|
| 总市值 100 亿 ~ 500 亿（`min=10000000000`/`max=50000000000`，单位元） | **1407 只** | ✅ 可生成 |
| 总市值 50 亿 ~ 200 亿 | 2178 只 | ✅ 可生成 |
| 创业板板块（`boards=["gem"]`） | 1402 只 | ✅ 可生成 |
| 沪深主板（`boards=["sh_main","sz_main"]`） | 3198 只 | ✅ 可生成 |

> 设计要点：正常股票总市值一般 ≥ 数亿元，用"100~500 亿"这类中盘区间代表可生成的合理条件；命中 >50 硬下限保证后续物料可用。

### 3.2 Step1 导入模式数据（合理代码 + 逐行错误分类）

导入 CSV（UTF-8 BOM，`symbol,name` 表头；模板契约：symbol 必填，name/market/note 可选）：

```csv
symbol,name
603013,亚普股份
603014,威高血净
603015,弘讯科技
603016,新宏泰
999999,不存在的代码
HK00700,港股
abc,非法格式
603013,重复亚普
```

预期逐行结果（实测完全一致）：

| 状态 | 数量 | 行 |
|---|---|---|
| 成功入池 | 4 | 603013 / 603014 / 603015 / 603016 |
| 未匹配（非系统代码） | 1 | 999999 |
| 港股（非首期支持资产） | 1 | HK00700 |
| 格式错误 | 2 | abc、HK00700（含不规范代码） |
| 文件内重复 | 1 | 603013（重复行） |

> 全链路：下载模板 → 上传 → 预览逐行匹配（不落库）→ 确认入池 → 成员表 4 行。

## 5. 本次黑盒发现并已修复的问题

> 用户流程要求：先黑盒自测、发现问题即修；问题得到控制后再出测试用例文档。本次共发现 3 类问题，全部修复后各项验证通过，因此按流程**未生成「测试不通过报告」**。

| # | 问题 | 根因 | 修复 | 验证 |
|---|---|---|---|---|
| P1 | Step4 资源确认弹窗「确认提交」被永久禁用，向导无法提交 | worker 重启/崩溃后 `task_locks` 的过期锁行无人回收：`expire_stale_locks` 只在 task_runner patrol 触发，普通运行（无 patrol 调度）下 12 小时锁不释放；前端 `domainBusy=true` → 提交按钮 disabled | `GET /factor-mining/locks/status` 查询前先 `expire_stale_locks`（幂等、best-effort），前端每次打开资源弹窗都能自愈；同步清理了 2 条历史残留 run（状态归一为 failed） | 走查 4.4/5.1 由 FAIL→PASS；task_lock 并发单测 21/21 |
| P2 | 控制台 React key 警告（`PoolFilterPanel` 列表缺 key） | `catFields.map` 对 `RANGE_SLOT` 字段返回 `rangeControl(f)` 未带 key | 用 `<Fragment key={f.field}>` 包裹 | key 警告清零；前端挖掘域单测 156/156；tsc 0 |
| P3 | 偶发资源 404（观察期） | vite 开发态瞬时资源（热更新中间态），复测无 404 | 无需修复（观察结论） | 复测 404 列表为空 |

## 6. 已知边界（非缺陷，测试设计时需留意）

1. **周频/月频样本不足**：DuckDB 镜像起点 2025-01-13（401 交易日），周频有效点 76 < 104、月频更低；Step2 会展示切分预算/降级引导（设计 §4.1、§10）。**首期走查/自动化用日频（2025-01-01~2026-09-01，397 点）作为达标数据**。
2. **估值快照数据截止日回落**：9 月估值截面标的数骤降（~1,904 vs 8 月 ~5,544），`as_of_date` 自动回落 2026-08-21（`as_of_date_adjusted` 在响应中显式回报）。
3. **行业/上市时间/股息率/净利润字段当前无数据**：对应筛选条件以 `blocked` 呈现并附实测原因（不静默忽略，符合设计红线）。
4. **worker 中断后 run 状态归一**：锁已可由 `locks/status` 自愈回收；run 状态残留 `running` 由运维/patrol 归一（本次测试环境已清理），属集群运维边界，不阻塞单用户流程。
