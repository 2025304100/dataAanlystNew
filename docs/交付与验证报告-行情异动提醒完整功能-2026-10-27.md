## 2. 关键口径与安全默认值

默认只做影子验证。用户可以明确选择“试用提醒（效果待验证）”；没有把未经验证的模型分数包装为命中概率，也没有自动开启第三方接收方。

评分由实质影响0～40、新增变化0～30、范围0～10、持续性0～10及时效0～10组成。前四项由模型根据证据提出档位，时效由程序计算；结构和引用由程序校验。默认85分仅为候选门槛。没有在本版实现全行业、经过实测校准的量化基线库，也没有使用模型虚构的行业产值或利润数据。

日线版在交易日09:30～15:00不发送新提醒。只用送达时已经可知的最近收盘价，计算后续完整交易日的高低价。盘中候选会在后续时段重新检查；已经过期或已被市场消化而没有新事实的候选不会补发。

真实日历不完整、个股前复权口径不明确、行情缺失或自适应历史不足时明确阻塞。不会用工作日近似日历或未来价格补齐，也不会把到期缺失样本从严格命中率中删除。

## 5. 验证中发现并修复的问题

| 问题 | 修复与验证 |

| 同股多窗口被事件去重吞掉 | 预测按规则及窗口记录，通知仍按事件事实合并；1日/3日独立且只发一条 |
| 公布前的整日大涨被错误计入风险 | 固定最近已知收盘价，只算后续真实交易日；发送前高点120、后续仅1%仍判未命中 |
| 日期精度在转UTC后被误判 | 在来源本地时间判断日期精度，再归一UTC；精确08:00不会因UTC00:00误判日期消息 |
| 500字摘要截断重要条款 | 原始内容单独保留，按需提取原文，旧列表摘要长度不变 |

| 单渠道停用导致所有渠道取消 | 单运输失败独立处理，任一已授权渠道成功可恢复真实送达 |

## 7. 剩余风险与实际使用条件

1. **75%未被证明**：规则分数、合成200样本统计及功能测试都不能证明真实效果。默认影子，真实试用结果单独累计，不把低门槛或延长窗口当成模型能力提升。
2. **日线边界**：本版没有分钟行情，不提供盘中30/60分钟实时提醒；有效期过短的盘中消息可能失去下一可发送时段，需要观察遗漏与提前量。
3. **来源质量与覆盖**：公开源可能限流、延迟、缺原文或缺精确时间；有限股票轮转与AI配额会产生处理延迟，不能承诺全市场无遗漏。
4. **行业/股票关联和语义归并**：模型仍可能误判传导、实质影响或把同事件写成不同身份。需要真实样本复核；没有行业全量基线库或训练好的专属概率模型。
5. **行情与日历**：停牌、供应商修正、复权标记可信度、官方日历年度覆盖和自选板块代理代表性会影响可结算性；系统明确阻塞/缺失，不能替代数据审计。
6. **对照与区间的局限**：历史波动对照、事件簇和5日块区间是诊断工具；尚未完成匹配同时点对照、独立留出集和完整重叠标签隔离的正式前向验收。历史门槛状态不等于正式效果达标。
7. **运行成本与数据增长**：有每轮上限和原模型日配额；默认自动排程最多尝试960个证据×对象分析/日，实际取决于候选与缓存，手工运行、供应商重试和故障转移另计。建议为主模型及可能使用的故障转移配置明确设置日配额，再观察真实Token账单。原文和审计数据保留会增长，需按原有运维流程备份和制定归档策略。
8. **Webhook交付**：发送端提供稳定幂等键；响应丢失场景仍要求接收端幂等。进程崩溃留在sending的记录沿用通知系统的人工复核/重试流程，不冒险自动重复发送。
9. **第三方送达与生产接入**：本轮按用户决定只验证本机闭环；真实付费模型、真实第三方渠道及业务库尚未接入验证。

行情异动命中率不能推出交易收益率。实际投入产出须用真实省时、有效提醒数量、提前量、模型账单、数据与维护成本衡量；本轮没有产生实盘收益率结论。
