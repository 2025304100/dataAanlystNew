# 因子中心与因子模型优化方案开发计划文档

> 配套需求：docs/因子中心与因子模型优化方案需求文档.md
> 版本：v1.1
> 日期：2026-09-02

## 1. 最终交付目标：把系统做成链式操作

本次开发的最终结果必须是“傻瓜式链路”，而不是一组需要用户自行拼接的功能页面。用户从因子开始，系统要持续告诉用户当前处于哪一步、缺什么、为什么不能继续，以及点击哪个按钮可以完成下一步。

统一主流程：

```text
因子库 → 因子版本 → 创建因子集合 → 添加因子版本 → 质量预检 → 冻结
→ 评估与治理预检 → 冻结 → 训练模型 → 模型因子和权重确认
→ 影子运行 → 正式启用 → 流水线刷新评分 → 回测/决策消费
```

开发原则：不要求用户理解内部对象名和 ID；不让用户在多个页面之间猜下一步；不提供没有后端执行意义的假按钮；缺少前置条件时阻断当前动作并提供直达修复入口；完成一个节点后提供进入下一个节点的主按钮。

## 开发约束：内聚、隔离、兼容

本计划所有工作包必须遵守以下硬性边界：

- 功能内聚：因子定义和集合管理放在因子中心，模型训练和生命周期放在因子模型域，流水线运行放在设置任务域；不得把同一业务逻辑复制到组合、回测、交易或告警页面。
- 业务脱离：跨业务调用只通过公开业务接口、Facade 和 DTO，禁止直接引用其他模块的 ORM、Session、DuckDB、内部 service 或状态表。
- 不侵占别业务：组合、回测、今日决策、告警、数据中心等模块只消费已发布的模型、FactorSet 和 Score，不承担因子配置、模型训练和因子内部状态管理。
- 失败隔离：新增功能失败只能使当前请求或当前异步任务失败；必须保留原活动模型、手工回退和已有评分，不能阻断其他页面和总体服务。
- 兼容优先：新增字段和接口向后兼容；历史模型没有关联时显示未关联，不用不可靠规则强行回填。
- 最小修改：每个提交只覆盖当前工作包需要的文件和模块，不进行无关重构，不改变无关业务行为。
- 可回滚：所有启用、切换和写入操作必须有审计、旧状态和回滚路径；异常时事务回滚或保持旧版本继续服务。

依赖方向固定为：外部业务模块 → 因子域公开接口/Facade → 因子域内部实现。因子域不得反向依赖外部业务域；外部业务不得穿透接口调用因子内部实现。每个工作包完成前必须检查 import、API 路由和数据库访问，防止边界被绕过。

## 2. 当前实现基线（2026-09-02）

已落地并作为后续开发基线的能力：

- 因子评估报告已接入生产保真/非保真实验标识、过滤规则状态、排除计数、目标批次和数据截止展示。
- 因子评估指标已使用安全数值组件，缺失指标保留缺失语义。
- 回测预检 API 和前端预检交互已接入，支持警告/阻断分离、最低交易日和目标覆盖提示。
- 回测过滤治理已形成独立模块，包含配置、PIT 证券状态、规则引擎、审计、退市清算和停牌冻结。
- 回测结果已补充运行阶段、进度、结构化错误、可重试标识和数据截止快照，并保留旧字段兼容。
- 回测短窗口重复提交已增加复合键去重。
- 后端/前端跨域审计脚本和测试门禁已增强，跨业务调用继续统一走 Facade/业务接口。

已完成的核心链路：

- FactorSet 前端创建、成员选择、版本选择、复制和链式下一步入口。
- 设置页流水线 FactorSet 显式选择和禁止隐式挑选。
- 模型与因子集合、因子版本、权重的关联展示。

仍需实施或持续完善的能力：

- 历史未关联模型迁移报告和人工确认。
- 所有训练/异常路径的不可变因子权重快照回查。
- 因子、模型、评分、回测的全链路回归验收。

新增能力必须复用现有 BFG 过滤配置、预检 DTO、结构化错误和跨域门禁，不得在因子中心、回测或组合页面复制规则。

## 3. 开发主线

所有开发任务围绕一条可执行链路展开：

创建或选择因子 → 创建 FactorSet → 添加因子版本 → 冻结 → 训练 FactorModelRun → 查看因子权重 → 影子运行 → 正式启用 → 流水线更新评分

前一阶段未通过验收，不进入后一阶段。

## 4. 当前基线和缺口

已存在：

- 因子库创建因子草稿和版本。
- 后端 FactorSet 创建、查询、添加成员、移除成员、冻结和废弃接口。
- 因子中心已有集合列表、冻结和训练按钮。
- 训练接口接收 factor_set_id，并写入模型记录。
- 设置页已有流水线、训练开关、评分开关和任务进度。

缺口：

1. 前端没有创建 FactorSet 的按钮和弹窗。
2. 前端不能从因子库选择因子版本加入集合。
3. 没有集合成员编辑、复制版本和覆盖率预检流程。
4. 设置页训练时自动取第一个可用集合。
5. 设置页模型表没有显示因子集合和因子数量。
6. 未关联历史模型没有解释和迁移报告。

## 5. P0：补齐链式入口和因子集合配置

### 5.1 前端 API Client

复用现有接口，补齐类型和错误处理：

- POST /factor-sets：创建 draft 集合。
- GET /factor-sets：集合列表。
- GET /factor-sets/{id}：集合详情和成员。
- POST /factor-sets/{id}/members：添加因子版本。
- DELETE /factor-sets/{id}/members/{factor_id}：移除成员。
- POST /factor-sets/{id}/freeze：冻结集合。
- POST /factor-sets/{id}/deprecate：废弃集合。

补充 FactorSetCreateRequest、FactorSetMemberCreateRequest 和 readiness 类型。禁止让用户手填 factor_id 或 factor_version_id。

### 5.2 因子模型页

在因子集合卡片增加：

1. 新建因子集合按钮。
2. 创建弹窗：名称、描述。
3. draft 集合的编辑成员按钮。
4. 成员编辑抽屉：因子搜索、版本选择、角色、方向约束、缺失策略。
5. 成员表：代码、名称、版本、状态、覆盖率、移除操作。
6. 冻结前显示成员摘要和不可逆确认。
7. frozen 后禁用成员编辑和移除操作。

因子和版本使用现有因子库查询接口，按可训练状态过滤。

### 5.3 链式引导交互

因子中心和设置页都必须显示步骤导航：

```text
因子 → 因子集合 → 预检 → 冻结 → 训练 → 验证 → 启用 → 评分
```

当前步骤高亮，已完成步骤可回看，未完成步骤显示阻断原因。每个阻断提示必须带直达按钮，例如“暂无因子集合”进入“新建因子集合”，“集合没有因子”进入“添加因子”，“集合未冻结”进入“冻结集合”，“没有可用模型”进入“训练模型”。完成动作后优先自动打开下一步，或显示唯一主按钮“下一步：……”。

### 5.4 P0 验收

- 页面可以创建 draft 集合。
- 页面可以选择因子版本并加入集合。
- draft 集合可以移除成员。
- 没有 feature 因子时不能冻结或训练。
- frozen 集合不能修改成员。
- 集合行可以直接训练模型。
- 从创建因子集合开始，用户不需要自己猜测下一步页面。
- 每个阻断状态都有明确原因和直达修复按钮。

## 6. P1：展示完整关联链路

### 6.1 统一关联读取

在因子域 facade 增加统一模型详情 DTO，内部完成以下解析：

model.hyperparameters.factor_set_id → FactorSet → FactorSet.members → Factor/FactorVersion

返回至少包括：模型 ID、因子集合 ID、集合名称、成员数、因子代码、因子版本、模型权重、IC和覆盖率。各前端组件禁止重复解析模型 JSON。

### 6.2 因子中心页面

按以下顺序实现：

1. 模型表显示“因子集”中文列。
2. 显示集合名称、短 ID和成员数。
3. 点击因子集定位并高亮集合。
4. 展开模型行显示因子权重和版本。
5. 展开集合行显示集合成员。
6. 因子详情显示所在集合和使用该因子的模型。
7. 未关联模型显示原因和修复入口，不显示普通短横线。

### 6.3 设置页面

设置页模型版本表增加只读的“因子集”和“因子数量”列，并提供“去因子中心查看”入口。设置页不编辑集合成员。

### 6.4 P1 验收

- 新模型能回查到 FactorSet。
- FactorSet 能展开到具体因子版本。
- 模型能展开到权重明细。
- 因子中心和设置页显示同一份关系数据。

## 7. P2：修正流水线选择逻辑并接入链路

### 7.1 前端

当训练 Ridge 打开时增加因子集合下拉框：

- 只显示 frozen 且 readiness 通过的集合。
- 一个集合时可以预选，但显示名称、ID和成员数。
- 多个集合时要求用户明确选择。
- 没有集合时禁用运行按钮并跳转因子中心。
- 训练关闭时清除集合必填校验，并提示不会创建模型。

增加阶段预览：数据同步、因子计算、目标生成、模型训练、评分生成。

流水线是链路的最后一段，不是用户第一次接触模型的入口。没有完成因子集合和模型配置时，页面必须显示当前缺失节点和跳转按钮。

### 7.2 后端

- train_model=true 且 factor_set_id 为空时拒绝请求。
- 校验集合存在、状态 frozen、包含 feature 成员且 readiness 通过。
- 不再在后端自动选择第一个集合。
- 将最终使用的 factor_set_id 写入任务 payload、模型和审计记录。

### 7.3 P2 验收

- 多集合时不会静默使用第一个集合。
- 任务中保存用户确认的集合 ID。
- 关闭训练开关不会创建新模型。
- 错误信息能指出数据、因子、目标、训练或评分阶段。

## 8. P3：历史血缘和训练快照

### 8.1 历史模型处理

按三类生成报告：

1. 已有 factor_set_id，直接展示。
2. 具备完整因子版本信息且能唯一匹配，生成迁移候选并要求审计确认。
3. 无法唯一确定，保留未关联，不自动猜测。

报告显示总数、已关联、候选匹配和无法判断数量。

### 8.2 不可变训练快照

训练成功时保存：FactorSet ID、content hash、因子 ID、因子版本 ID、角色、约束、缺失策略、训练/验证窗口、数据截止日、模型权重和训练模式。

历史集合被废弃或新建版本后，历史模型详情不发生变化。

## 9. 测试计划

### 9.1 后端

- draft 可添加和移除成员。
- frozen/deprecated 拒绝修改成员。
- 因子和版本不匹配时拒绝添加。
- 空 feature 集合不能冻结和训练。
- 模型训练必须保存 factor_set_id。
- 流水线训练拒绝空 factor_set_id。
- 多个集合时不自动选集合。

### 9.2 前端

- 创建集合提交正确 payload。
- 添加版本后成员表更新。
- 冻结后编辑控件禁用。
- 模型表显示因子集和因子数量。
- 模型展开显示权重。
- 未关联模型显示解释。
- 流水线训练打开时必须选择集合。

### 9.3 端到端

新建或选择因子 → 新建集合 → 添加版本 → 冻结 → 训练 → 查看因子权重 → 影子运行 → 正式启用 → 运行流水线 → 查看 Score 使用的模型和因子版本。

每一步都必须显示对象 ID、状态和下一步操作。

新增零基础用户链路用例：测试人员不阅读开发文档，只根据页面提示从因子库开始操作，必须能够完成到评分生成；任何失败都必须能从当前提示直接修复，不能要求回到文档或联系开发人员查内部 ID。

## 10. 发布和回滚

发布顺序：后端兼容 DTO → FactorSet 配置 UI → 模型关系展示 → 流水线显式选择 → 历史血缘报告 → UAT 后开放正式启用。

回滚只回滚 UI 或开关，不删除集合、模型和审计记录。新模型写入失败时保持原活动模型；激活失败时保持原运行模式。

## 11. 完成定义

只有同时满足以下条件才算完成：

1. 用户不调用 API 即可沿着页面链路配置因子集合。
2. 用户能区分单模型训练和完整流水线。
3. 新模型能看到因子集合和具体因子版本。
4. 流水线不会隐式选择错误集合。
5. 历史未关联模型有解释且不被伪造关联。
6. 主流程具备后端、前端和端到端测试。
7. 零基础用户可以仅根据页面引导完成“因子 → 评分”主流程。
8. 所有缺失前置条件都有清晰原因、唯一下一步和直达入口。
9. 因子功能通过业务接口与其他模块隔离，未侵占其他业务边界。
10. 因子或模型任务失败不会导致总体功能失败，原活动模型和回退路径仍可用。
11. 改造范围外的接口、数据和业务行为通过兼容性回归测试。
