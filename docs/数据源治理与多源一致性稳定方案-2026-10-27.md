## 0. 方案总览

### 0.1 一份方案，两层能力

| 层 | 解决的问题 | 核心产物 | 对应章节 |
|---|---|---|---|
| 多源编排层 | 从哪些源取、谁是主/备/权威、怎么切换、怎么对账 | 源角色矩阵、契约注册表、降级组、冲突表 | 第 2 章 |
| 数据治理层 | 取回来怎么存、单位/复权/源标签怎么统一、怎么修、怎么验收 | 单一事实表、统一适配器、单一写入、质量门禁、覆盖台账 | 第 3、5、6 章 |
| 行情稳定性层 | 限流、熔断、埋点、降级、存量修复，保证行情链路稳定 | Pacer/Breaker、单一取数入口、单位闸门、双表对账 | 第 4.5 章 |

### 0.2 一条落地主线

**源角色 → 契约/单位/复权 → 单一事实表 → 统一适配器 → 单一写入 → 质量门禁 → 修复现有数据 → 影子/双跑/切读 → 扩源**

### 0.3 核心决策

1. **一个数据集一个事实表**，但可以有多个 provider。
2. **同一时刻、同一字段只有一个 canonical 源**。
3. **所有源过契约注册表**：单位、复权、字段、角色、配额、历史起点。
4. **统一单位**：股、元、份、倍、百分点；生产 CN 股票/ETF 只用 qfq。
5. **统一写入层**：源守卫、质量门禁、冲突表、覆盖台账。
6. **先修数据，再加源；先影子，再切读**。

## 1. 目标与原则

### 1.1 目标

- 行情、估值、财报、资金流、龙虎榜、人气榜、ETF、指数、宏观、公告十类数据可长期稳定同步。
- 同一指标在库内只有一个口径、一个单位、一个复权方式。
- 多源只用于冗余、补数和交叉校验，不产生“同一列两种单位”。
- 每行数据可回答：来自哪个源、什么单位、什么复权、什么质量状态、哪一批次写入。

### 1.2 原则

| 原则 | 说明 |
|---|---|
| 先修后加 | 现有 P0 未修复前，不接入新源 |
| 事实表唯一 | 一个数据集一个事实表；多源通过角色切换 |
| 口径唯一 | 同一字段同一时刻只有一个 canonical |
| 单位显式 | 单位入库前转换；不按数值猜单位 |
| 复权显式 | 生产 CN 股票/ETF 只允许 qfq；raw/hfq 只进研究/导入表 |
| 未知置空 | 无真实值就 NULL，不写 0、不伪造历史 |
| 留痕 | `source_tag`、`field_sources`、`raw_json`、`batch_id`、`unit_version` |
| 可回滚 | 旧表/旧列保留；切读开关可回退 |

### 2.4 多源运行规则

1. **角色固定**：`primary / backup / official / enrichment / validation`，登记在契约注册表。
2. **整行切换**：主源失败→备源接管整行/整段序列；不允许只补某个字段而不记录。
3. **字段级多源仅限字段互斥**：ETF NAV/份额/收盘/基准、财报 5 字段+公告日、估值 PE/PB+市值。
4. **同一序列不跨源拼接**：换源标 `source_break`；要么整段重刷，要么保留原源。
5. **源守卫**：已有行只能被同源更新，或走显式迁移；备源不能自动覆盖主源行。
6. **对账不覆盖**：重叠日期双源比较，超差写 `data_conflicts`，不自动改值。
7. **切换触发条件**：失败、空返回、过期、熔断打开；不因为数值不同而切换。
8. **独立限流/配额**：每个 provider 独立令牌桶、独立日/月配额。
9. **逐行留痕**：`source_tag`、`field_sources`、`raw_json`、`batch_id`、`unit_version`、`quality_status`。
10. **质量状态**：`complete / partial / composite / conflict / legacy_unverified`；覆盖台账只认 `complete`。

### 2.5 允许 vs 禁止的字段级组合

| 场景 | 是否允许 | 说明 |
|---|---|---|
| ETF NAV 用天天基金、份额用上交所、收盘用腾讯 | 允许 | 字段互斥，记 `field_sources` + `nav_basis` |
| 财报 5 字段用东财、公告日用 Baostock | 允许 | 记 `announcement_source`；5 字段本身同源 |
| 估值 PE/PB 用东财、市值用腾讯 | 允许（谨慎） | 记 `field_sources`；市值单位必须元 |
| PE 用东财、PB 用 Baostock | 禁止 | 同一指标组跨源，口径不同 |
| 资金流主力用东财、超大单用 Fuyao | 禁止 | 主力定义不同，必须整行同源 |
| 龙虎榜机构买入用东财、卖出用交易所 | 禁止 | 席位归类不同，整行同源 |
| 指数 close 用东财、amount 用腾讯 | 仅允许记 `field_sources` | 默认不补，避免混源 |
| 行情 amount 用东财补腾讯空值 | 禁止自动补 | 腾讯备源行标 `partial`，等主源重刷 |

### 2.6 故障切换与对账

| 场景 | 动作 |
|---|---|
| 主源超时/429/熔断 | 同组备源整行接管；记 `fallback_used=true`、`attempted_sources` |
| 备源缺字段（腾讯无 amount/turnover） | 该行标 `partial`；不跨源补；主源恢复后重刷 |
| 双源重叠日期 | 按容忍度对账；超差写 `data_conflicts` |
| 主源与备源值不同但都合法 | 保留 canonical 主源；备源只作证据，不覆盖 |
| 序列中途换源 | 标 `source_break`；因子按段处理或整段重刷 |

### 2.7 多源数据模型

| 字段/表 | 用途 |
|---|---|
| `source_tag` | 整行主源，如 `ak:em:cn-stock:v1:qfq` |
| `field_sources`（JSON） | 字段级组合，如 `{"nav":"ttjj","shares":"sse","close":"tx"}` |
| `nav_basis` | ETF NAV 是 `iopv` 还是 `official_nav` |
| `pe_definition` | `pe_ttm / pe_dynamic / pe_static` |
| `roe_definition` | `roe_ttm / roe_weighted / roe_avg` |
| `flow_definition` | `main=super_large+large` 等 |
| `unit_version` | `cn-share-v1 / cny-v1 / percentage-point-v1` |
| `quality_status` | `complete / partial / composite / conflict / legacy_unverified` |
| `source_break` | 序列中途换源的日期标记 |
| `data_conflicts` | 双源对账差异表，不覆盖事实表 |

## 3. 数据治理层：统一契约与写入

### 3.1 契约注册表

每个 `(provider, endpoint, dataset, asset_type)` 登记：

| 字段 | 示例 |
|---|---|
| `source_tag` | `ak:em:cn-stock:v1:qfq`（最长 64 字符） |
| `dataset` | `daily_bars / valuation / financial / capital_flow / lhb / hot_rank / etf / index` |
| `unit` | 价格元、成交量股、成交额元、份额份、市值元、比率倍、百分比百分点 |
| `adjust_mode` | `raw / qfq / hfq / none`；生产 CN 股票/ETF 只允许 `qfq` |
| `fields` | 必填/可选字段清单 |
| `role` | `primary / backup / official / derived` |
| `history_start` | 该源真实起点 |
| `batch_limit` | 单次最大行数/标的数 |
| `rate_limit / quota` | 次/分钟、次/天、次/月 |
| `fallback_group` | 同组才可降级，禁止跨组混写 |

### 3.2 规范单位

| 类型 | 规范单位 | 常见源陷阱 | 换算 |
|---|---|---|---|
| 价格 | 元/股 | 腾讯行情元；部分接口分 | 分 ÷ 100 |
| 成交量 | 股 | 东财/腾讯/Tushare `daily` 是“手”；新浪是股；新浪 ETF 是手且当前未转 | 手 × 100 |
| 成交额 | 元 | Tushare `daily` 千元；腾讯行情万元；东财元 | 千元 ×1000；万元 ×10000 |
| 市值/规模 | 元 | Tushare `daily_basic` 万元；腾讯行情亿元 | 万元 ×10000；亿元 ×1e8 |
| ETF 份额 | 份 | 上交所/天天基金常用万份 | 万份 ×10000 |
| PE/PB | 倍 | 东财“市盈率-动态”不是 TTM | 统一取 TTM/MRQ 字段 |
| 换手率 | 百分点 | 东财返回比率（0.0175），当前部分行按百分点直接落库 | 比率 ×100 |
| 占比/ROE | 百分点 | 有的源返回 0.0523 | 统一乘 100 |
| 日期 | DATE | 有的带时间戳/时区 | 日频只存 date |

### 3.3 复权与源标签

- 生产 CN 股票/ETF 只允许 `qfq`；`raw/hfq` 只进研究/导入表。
- 每行存 `price_basis`（`qfq/raw/hfq/none`）。
- `source_tag` 统一格式：`provider:endpoint:dataset:vN[:basis]`。
- 示例：`ak:em:cn-stock:v1:qfq`、`ak:sina:cn-etf:v1:raw`、`baostock:cn-financial:v1:pit`。
- 旧行无标签的标 `legacy_unverified`，不回填假标签。

### 3.4 单一事实表定版

| 数据集 | 稳定事实表 | 策略 |
|---|---|---|
| 行情 | **`universe_daily_bars` 作为唯一历史事实表**；`daily_bars` 降为业务镜像/兼容视图 | 先双写同一 payload + 同一 `source_tag`，再切读，最后退役一张 |
| 估值 | `stock_valuations` | 一标的一日一行；加 `pe_definition/pb_definition/unit_version` |
| 财报 | `stock_financial_reports` | 保留 `report_type/source` 版本；加 `roe_definition/net_profit_scope/revenue_scope` |
| 资金流 | `capital_flows` | 一标的一日一行；加 `flow_definition/amount_unit/unit_version` |
| 龙虎榜 | `lhb_institution_trades` | 官方源为 canonical；其他源只进对账表，不混入事实表 |
| 人气榜 | `stock_hot_rank_snapshots` | `hot_rank_total` 未知则 NULL；`hot_rank_pct` 未知则 NULL |
| ETF | `etf_indicators` | 加 `nav_basis`（IOPV/官方净值）、`fund_size_basis`、`tracking_error_window` |
| 指数 | `index_prices` | 加 `volume_unit/amount_unit/amount_available`；写入前源兼容检查 |
| 因子仓库 | `raw_daily_bars` | **主键加 `source_origin`**，或先选 canonical origin 再写；禁止后写覆盖 |

### 3.5 单一写入层

- 所有写入走同一个 `CanonicalWriter`，禁止各服务自己 upsert。
- 写入前必须通过：`unit gate → OHLC gate → adjust gate → source guard → PIT gate`。
- 同一 `(symbol, date)` 出现不同源/不同值时，写 `data_conflicts`，不自动覆盖。
- 覆盖台账只统计 `quality_status='complete'` 且 `unit_version` 有效的行。

### 3.6 质量门禁

| 校验 | 容忍度 | 处理 |
|---|---|---|
| 双源收盘价 | ≤0.5% 或 0.01 元 | 超差写 `data_conflicts` |
| 双源成交量 | ≤1% | 超差标记单位/源冲突 |
| 双源成交额 | ≤2% | 超差标记 |
| `amount ≈ volume × VWAP` | ≤2% | 超差说明单位错 |
| `market_cap ≈ close × shares` | ≤1% | 超差说明股本口径错 |
| ETF NAV 双源 | ≤0.1% | 超差标记 NAV 口径 |
| ETF 份额双源 | ≤0.5% | 超差标记万份/份 |
| 单位 sanity | `vwap/close`、`fund_size/(nav×shares)` | 超出合理区间拒写 |
| PIT | `report_period ≤ announcement_date ≤ trade_date` | 违反拒写 |
| 复权 | CN 股票/ETF 生产只允许 `qfq` | 违反拒写 |

## 4. 当前数据问题审计（方案依据）

### 4.1 审计方法

- 对 MySQL `gpfx` 执行只读 `SELECT`，覆盖：
  `daily_bars`、`universe_daily_bars`、`index_prices`、`stock_valuations`、`capital_flows`、`etf_indicators`、`stock_financial_reports`、`stock_hot_rank_snapshots`、`lhb_institution_trades`。
- 审计维度：源标签分布、空值率、单位合理性、表间一致、覆盖范围、字段完整度。
- 未做逐行跨源数值对比；未查 DuckDB `raw_daily_bars` 实际内容。

### 4.2 P0 问题

#### 4.5.3 实际链路：三套实现并存，只有最旧的一套在跑

```
生产在跑：
market_data._fetch_history()
  · 内联 4 源降级：EM → Sina → Tencent → TDX
  · 每源 call_akshare_with_retry(max=2)

  → universe_sync._upsert_universe_bars → universe_daily_bars
  → market_data._upsert_bars → daily_bars

写好了但没人调用：
market_data_sources.registry.get_chain() → SourceChain（含单位契约）
external_data_gateway.fetch_via_gateway()（缓存/单飞/并发/熔断/降级）
akshare_guard.acquire()/record_failure()（Pacer/Breaker）
```

**一句话**：单位契约、限速、熔断、缓存这些“正确答案”都已写好，但全部挂在不可达链路上；真正在跑的是最老的内联 fallback。

#### 4.5.6 根因链

```
① 无全局 QPS 上限
   5 worker × per-thread sleep(300~800ms) ≈ 6~9 QPS/端点
   ↓
② 东财 WAF 返回 403/429/RemoteDisconnected
   stock_zh_a_spot_em 99.98% 失败；index_zh_a_hist 96.9% 失败
   ↓
③ 适配器把异常一律转 SourceUnavailable，静默降级到新浪/腾讯
   ↓
④ 备源单位不同且未归一 → 成交量存“手”、换手率存“比率”
   ↓
⑤ source 标签退化为裸 `akshare`，单位信息丢失
   ↓
⑥ 增量同步只拉尾巴、不回补历史 → 错误永久固化
   ↓
⑦ 量比、放量突破、换手率分位、资金流强度等因子被 100 倍误差污染
```

**关键洞察：限流和单位不是两个问题，是一条因果链的两端。** 只修限流，单位仍会在下次降级时漂移；只修单位，主源持续被打挂，永远在走备源。

| | 熔断可触发 | 否 | **是（可演练）** |

#### 4.5.9 可复现 SQL

```sql
-- 成交量单位：比值 ≈1 表示股；≈100 表示手
SELECT source,
       COUNT(*) n,
       SUM(amount / volume / close > 50) AS lots_rows
FROM universe_daily_bars
WHERE volume > 0 AND amount > 0 AND close > 0
GROUP BY source;

-- 换手率量级：正常 A 股中位数 ≈1.5–2.0；<0.1 基本可判定被 /100
SELECT u.source,
       COUNT(*) n,
       SUM(u.turnover_rate > 0 AND u.turnover_rate < 0.1) AS too_small
FROM universe_daily_bars u
JOIN universe_symbols s ON s.id = u.universe_symbol_id
WHERE s.asset_type = 'stock' AND u.turnover_rate IS NOT NULL
GROUP BY u.source;
```

### 11.2 Q1：复权基准日

**结论：成立，P0。** 不同源的前复权默认以各自最新交易日为基准；两源更新节奏不同，或在不同日期回补同一段历史，同一交易日的前复权价会因分红除权产生系统性偏差。分红越多偏差越大，双源对账会出现虚假冲突，主备切换时序列出现非市场跳变。

**修订：**

1. 契约新增 `adjust_base_date`、`adjust_base_policy`、`adj_factor_source`、`adj_factor_version`。
2. 不直接采信源端 qfq：存原始 OHLC + `adj_factor`，本地按统一基准日计算前复权；或存 qfq 时强制记录基准日。
3. 所有源 re-base 到 canonical 最新交易日；每次除权后整段重算并版本化。
4. 双源对账优先比较原始价/量，或比较同一基准日下的 qfq；禁止比较不同基准日的 qfq。

**验收：** 同一标的同一日期，双源 qfq 差 ≤0.01%；`adjust_base_date` 全表一致；主备切换点无价格跳变。

### 11.3 Q2：存量单位修复

**结论：成立，P0。** 单信号 `amount/(volume×close)≈100` 会被成交额单位错误、拆并股、极端行情量价偏离误判；原地 `UPDATE` 违反不可变原则；写新版本又没有主键扩展规则，会主键冲突。

**修订：**

1. 三重判定：
   - 信号 A：`amount/(volume×close)`，同时考虑 amount 可能的千元/万元倍率；
   - 信号 B：换手率恒等式 `turnover ≈ volume_shares / 流通股本 × 100`，看哪个 volume 单位能让等式成立；
   - 信号 C：同日跨源重叠值、相邻日连续性、除权/拆并股识别。
2. 不原地 `UPDATE`：写 shadow 表或新批次，字段含 `repair_batch_id`、`original_volume`、`candidate_volume`、`signal_a/b/c`、`confidence`、`quality_status`。
3. 主键扩展：同表加 `data_version`/`batch_id`，或使用独立 shadow 表；验证后切读。
4. 三信号不一致的行标 `unit_conflict`，不自动修，排除出因子。

**验收：** 抽样 500 行人工核对准确率 100%；shadow 与原表行数对账一致；无主键冲突；可一键回滚。

### 11.4 Q3：源守卫与存量迁移

**结论：成立，P0。** 当前 99% 以上是裸 `akshare` 标签，新主源是标准 `source_tag`。严格执行同源更新，主源无法覆盖旧行；放开守卫，单位污染又能进来。

**修订：**

1. 增加 `source_state`：`legacy_unverified / claimed / migrated / canonical`。
2. 存量行允许被 canonical 主源**一次性认领**：在 `migration_id` 批次内，整行通过单位/口径门禁后，`source_state=migrated`、`quality_status=complete`，记录 `from_source/to_source/evidence`。
3. 认领必须整行，不允许只补一个字段。
4. 迁移窗口结束后关闭例外，恢复严格同源更新；跨源变更只能进 `data_conflicts` 或人工审批。

**验收：** 100% 行有 `source_state`；因子只读 `migrated/canonical`；迁移期无未处理冲突；窗口关闭后无跨源写入。

### 11.5 Q4：备源雪崩

**结论：成立，P0。** 串行兜底会把全量流量瞬时打到备源；备源反爬更严、承载更弱，没有独立限流和冷却，很快连锁熔断，从“主源不稳定”恶化为“全链路瘫痪”。

**修订：**

1. 每个 provider 独立令牌桶、熔断、冷却、日/月配额：东财、新浪、腾讯、Baostock、Fuyao、交易所全覆盖。
2. 备源按承载能力保守设限，不能继承主源 QPS。
3. 主源熔断后，备源只承接核心标的（持仓、观察池、指数）；非核心标的延后回补。
4. 增加“全源熔断”总闸：所有源都 open 时停止同步并告警，不再空转。
5. 恢复用半开探测 + 逐步放量（10%→50%→100%）。

**验收：** 模拟主源 403，备源 QPS 不超自身上限；核心标的覆盖率 ≥95%；不出现全源 open；恢复过程无二次雪崩。

### 11.6 Q5：修复顺序

**结论：成立，P0。** `raw_daily_bars` 主键不含 `source_origin`，两张业务表后写覆盖先写。先修其中一张，另一张仍会覆盖它，上游修复无效。

**修订：**

1. **0 阶段先动因子仓库**：主键加 `source_origin`，或拆成 `raw_daily_bars_business` / `raw_daily_bars_universe`；明确 canonical origin；停掉非 canonical 镜像。
2. 因子只读 canonical origin。
3. 然后再修业务表；DuckDB 迁移在 shadow warehouse 做，不在原库上直接改主键。

**验收：** 同 `(symbol,date,adjust)` 不再出现两个 origin；仓库行数/值稳定；修一张业务表不会覆盖另一张。

### 11.7 Q6：业务计算口径

**结论：成立，P0。** PE_TTM 有滚动四季度、单季度年化；资金流“主力”有“大单+超大单”和“仅超大单”；ROE 有加权、平均、TTM；净利润有母公司/合并；营收有营业总收入/营业收入；ETF NAV 有 IOPV/官方净值。

**修订：**

1. 契约新增 `metric_definition` / `calculation_basis`，每个指标明确业务定义。
2. 行级增加 `definition_version`；质量门禁强制校验定义字段。
3. 不同定义分列或分表，禁止同列混写：
   - `pe_ttm_rolling_4q` / `pe_dynamic_annualized` / `pe_static`
   - `flow_main_super_large_plus_large` / `flow_main_super_large_only`
   - `roe_ttm` / `roe_weighted_period` / `roe_avg`
   - `net_profit_parent` / `net_profit_consolidated`
   - `revenue_total_operating` / `revenue_operating`
   - `nav_iopv` / `nav_official`
4. 因子按定义选列，不按列名猜口径。

**验收：** 100% 行有定义字段；同一列不出现两种定义；因子 SQL 明确引用定义列。

### 11.8 Q7：过渡期断档

**结论：成立，P1。** “新数据正确、旧数据错误”会在切换点造成量级跳变，因子窗口跨断点直接失效。

**修订：**

1. 每个数据集原子切换：存量修到 T-1，T 日收盘后一次性切换增量口径；或周末切换。
2. 若必须分批，增加 `unit_epoch` / `unit_break_date`；因子侧截断，不允许窗口跨断点。
3. 切换前做连续性校验：切换点前后 20 日 `vwap/close`、volume 中位数、turnover 中位数不能跳变。

**验收：** 任意因子窗口不跨 `unit_break_date`；切换点前后序列连续；切换后覆盖率不下降。

### 11.9 Q8：序列级质量门禁

**结论：成立，P1。** 单行校验发现不了连续 N 天无数据、价格超涨跌停、成交量突增突减 10 倍、静默停更。

**修订：**

1. 增加序列级门禁：
   - 连续性：应有交易日 vs 实际交易日，连续缺失 N 天标 `stale/partial`；
   - 价格：日涨跌幅是否越过板块涨跌停/ST 限制；
   - 量能：volume/amount 相对 20 日中位数是否 >10 倍或 <0.1 倍；
   - 单位连续性：`vwap/close` 是否跨日稳定；
   - 新鲜度：最新日期 vs 交易日历。
2. 每日跑序列门禁，写 `series_flags`；因子排除 flagged 行。

**验收：** 1,500 只停更标的能在 1 个交易日内被发现；不再依赖滞后的覆盖率台账。

### 11.10 Q9：`complete` 定义

**结论：成立，P1。** “核心字段非空”还是“所有字段非空”没定义，覆盖率会显示 99% 但辅助字段大量缺失。

**修订：**

1. 每个数据集在契约里定义 `required_fields` / `optional_fields`。
2. `complete` 严格判定：必填字段全部非空 + 单位校验通过 + 定义字段存在 + PIT 通过。
3. 覆盖率台账分别输出 `complete` 与 `partial`，分母明确（活跃标的 × 交易日 / 全市场日）。
4. 缺失字段不参与分子，不靠辅助字段凑覆盖率。

**验收：** 覆盖率只统计 `complete`；面板同时显示 complete/partial；抽样核对无注水。

### 11.11 Q10：影子双跑

**结论：成立，P1。**

**修订：**

1. 观察期：
   - 日频行情：至少 5 个交易日；
   - 财务：至少 1 个完整披露周期；
   - ETF：至少 20 个交易日。
2. 切读阈值：
   - 字段一致率 ≥99.99%；
   - 单位异常率 = 0；
   - `source_tag` 覆盖率 100%；
   - 冲突率 <0.01%；
   - 覆盖率不低于旧链路。
3. 灰度：10% → 50% → 100% 标的，每步观察 1 个交易日；任一阈值击穿即回滚。

**验收：** 阈值全部满足才允许切读；灰度每步有独立验收记录。

### 11.12 Q11：告警自动止损

**结论：成立，P1。**

**修订：**

1. 告警分级 P0/P1/P2，明确 owner、响应时效、runbook。
2. 自动止损：
   - 量纲闸触发 → 整批拒写 + 使用上一版合格快照兜底 + 标 `stale`；
   - 覆盖率跌破阈值 → 暂停因子发布，保留上一版因子；
   - 全源熔断 → 暂停同步，不空转；
   - 任何情况下不自动写入冲突数据。
3. 自动重试/切备源必须在预算内，超过预算转人工。

**验收：** 模拟量纲闸失败，脏数据未写入；因子使用上一版；告警被认领并记录处理结果。

### 11.13 Q12：主源恢复回切

**结论：成立，P1。**

**修订：**

1. **当日降级不回切**：当天一旦走了备源并落库，当日不再主动切回主源。
2. 次日同步时，主源优先重刷前一日；写新版本，`replacement_reason=primary_recovery`，旧行保留作证据。
3. 源守卫对 canonical 主源开放“恢复替换”例外，但必须整行替换、通过单位/口径门禁、记录 `source_break/replaced_by`。
4. 因子只读 canonical 版本，不读被替换的旧版本。

**验收：** 同一交易日不出现 source 反复翻转；次日替换通过门禁；因子序列无跳变。

### 12.2 Q13：股票代码复用与标的主数据

**结论：成立，P0。** A 股 6 位代码存在复用；只用 `symbol + trade_date` 做主键，会把两家不同公司的行情拼成一条序列。错误隐蔽，常规对账发现不了；退市/停牌标的也可能持续写入无效数据。

**修订：**

1. 新增 `instrument_master`：
   - `instrument_id`（永不复用，全局唯一）
   - `symbol`、`exchange`、`asset_type`、`calendar_id`
   - `list_date`、`delist_date`、`status`、`name_history`
   - `code_reuse_group`（同代码不同主体的分组）
2. 所有事实表主键改为 `(instrument_id, trade_date, ...)`；`symbol` 仅作展示字段。
3. 同步前校验标的状态：`listed` 可写；`suspended` 按规则写空/停牌标记；`delisted` 不再新增数据。
4. 存量迁移：按 `symbol + 日期区间` 映射到 `instrument_id`；代码复用按上市/退市区间拆成不同主体；无法判定的标 `legacy_unverified`。

**验收：** 全库无代码复用导致的串号序列；所有事实表主键含 `instrument_id`；退市标的无新增数据；复用代码按主体拆分。

### 12.3 Q14：统一交易日历

**结论：成立，P0。** 连续性校验、PIT 校验、因子窗口、跨源对账全部依赖交易日序列。日历不统一会导致主备源日期错位、公告日映射错误、因子窗口天数不准。

**修订：**

1. 以上交所/深交所官方日历为唯一权威源，维护 `trade_calendar`：
   - `calendar_id`（CN_A / HK / US 等）
   - `exchange`、`date`、`is_open`、`half_day`、`reason`
   - `calendar_version`、`source`
2. 所有源同步前做日期校验；非交易日数据直接丢弃或标 `non_trading_day`。
3. PIT 校验、连续性校验、因子窗口全部基于权威日历。
4. 非交易日发布的公告统一映射到下一个交易日；半日市单独标记。
5. 北交所沿用 A 股日历；港股/美股使用独立 `calendar_id`。

**验收：** 所有事实表日期均在权威日历内；主备源日期序列 100% 对齐；PIT 校验无日历错位误判；半日市处理正确。

### 12.4 Q15：契约版本、灰度、回滚

**结论：成立，P0。** 契约是整条链路的核心规则；配置改错会全量写入错误数据。没有版本管理、灰度和回滚，一次配置错误就能毁掉数月治理成果。

**修订：**

1. 契约新增 `config_version` / `contract_version`（语义版本 + 哈希），每次变更生成新版本并永久留存。
2. 版本状态：`draft / active / retired`；禁止原地修改 active 版本。
3. 变更流程：评审 → shadow → 10% 标的灰度 → 观察 1 个交易日 → 50% → 100%。
4. 每行数据绑定 `contract_version`；`batch_id` 记录当时生效版本；支持一键回滚到上一稳定版本。
5. 启动时校验契约 schema，非法配置 fail-closed，不允许带病启动。

**验收：** 契约变更全留痕；支持灰度放量；数据行可追溯对应契约版本；配置错误可在 5 分钟内回滚；非法配置无法启动。

### 12.5 Q16：回补与增量隔离

**结论：成立，P0。** 回补与增量共用配额、连接、调度，会打满源端 QPS、引发主键冲突/互相覆盖、拖慢线上因子计算。

**修订：**

1. 每个数据源拆分 `incremental_quota` 与 `backfill_quota`；增量配额预留，回补只用剩余。
2. 调度互斥：同一 `(instrument_id, trade_date)` 禁止回补与增量同时写入；用 advisory lock/队列保证。
3. 回补仅在增量完成后的低峰期执行；回补 QPS 严格低于增量。
4. 回补使用独立数据库连接池/只读副本，避免拖慢线上。
5. 增量异常（成功率、延迟、覆盖率）自动暂停回补。

**验收：** 回补运行期间增量成功率 ≥99%；增量配额不被回补占用；回补可随时暂停让位增量；无同键并发写冲突。

### 12.6 Q17：冲突闭环与仲裁

**结论：成立，P0。** 只记录不处理，冲突表会越积越多，对账只能“发现问题”，不能“收敛问题”。

**修订：**

1. `data_conflicts` 增加生命周期字段：
   `severity`、`status`（new/triaged/arbitrating/repaired/verified/closed）、`authority_source`、`owner`、`due_at`、`resolution`、`resolved_at`、`resolution_batch_id`。
2. 分级仲裁：
   - 有权威源：龙虎榜/两融/ETF 份额/公告以交易所/巨潮为准，自动修正；
   - 无权威源：容忍度内以主源为准，超容忍度挂起人工仲裁；
   - 行情/估值/资金流无单一权威，禁止自动用备源覆盖。
3. 流程：新增 → 分级 → 仲裁 → 修复 → 质量门禁复验 → 关闭；全程留痕。
4. P0 冲突 24 小时未处理自动升级；修复后的数据必须重新通过质量门禁，才可更新事实表状态；旧行标 `is_obsolete`。

**验收：** 冲突闭环率 100%；P0 冲突 24 小时内处理；修复后数据 100% 通过质量门禁；无永久挂起的 P0 冲突。

### 12.7 Q18：跨表一致性

**结论：成立，P1。** 单表校验全过，但表间口径脱节，多表关联因子仍会错。

**修订：**

1. 新增跨表门禁，每日执行：
   - 估值市值 ↔ 行情收盘 × 股本；
   - 资金流总额 ↔ 行情成交额量级；
   - ETF 规模 ↔ 净值 × 份额；
   - 龙虎榜金额 ≤ 当日成交额；
   - 财报净利润/营收与估值字段的极端偏离检查。
2. 股本缺失时标 `insufficient_data`，不强行判错。
3. 校验不通过标 `cross_table_mismatch`，排除出因子。

**验收：** 跨表校验覆盖率 100%；不通过数据不进入因子；`insufficient_data` 与真错分开统计。

### 12.8 Q19：作废/失效标记

**结论：成立，P1。** 不可变不等于永久有效；确认全错的批次、被替换的旧版本、退市作废标的，没有失效标记会持续污染因子。

**修订：**

1. 所有事实表新增 `is_obsolete`（默认 false）、`obsolete_reason`、`obsolete_batch_id`、`obsolete_at`、`obsolete_by`。
2. 作废对象：确认全错的批次、被 canonical 替换的旧版本、退市作废标的、修复失败的 shadow 数据。
3. 因子/回测默认过滤 `is_obsolete=true`；审计查询可显式包含。
4. 作废操作全程留痕，不物理删除。

**验收：** 作废数据不进入因子计算；所有作废操作可追溯；审计可查历史版本。

1. 新增 `corporate_action`：
   - `instrument_id`、`ex_date`、`record_date`
   - `action_type`（现金分红/送股/转增/配股/拆并股）
   - `cash_dividend`、`stock_ratio`、`rights_ratio`、`split_ratio`
   - `source`、`announcement_id`、`version`
2. 权威源：交易所 + 巨潮公告；Baostock/新浪/腾讯复权因子仅交叉校验。
3. 本地生成带 `factor_version`、`base_date` 的复权因子；事件更新后整段重算。
4. 新增除权日门禁：价格跳空幅度必须与分红/送转/配股比例匹配。
5. 双源对账统一基于“原始价 + 本地复权因子”。

**验收：** 除权日价格跳空与分红比例匹配度 100%；复权因子可追溯到公告；主备源经本地复权后偏差 ≤0.01%；因子变更有版本记录。

### 13.5 Q23：因子消费强制合格数据

**结论：成立，P0。** 数据侧有质量状态、源状态、作废标记，但没有技术强制绑定；因子 SQL/回测/业务服务仍可直接全表读，治理停留在“库内有标记”。

**修订：**

1. 建立统一数据服务层 `DataAccessService`；生产消费必须经过该层，禁止直连事实表。
2. 服务层默认过滤：
   - `quality_status='complete'`
   - `source_state in ('migrated','canonical')`
   - `is_obsolete=false`
   - `cross_table_mismatch=false`
   - `series_flags` 无阻断项
   - 停牌语义按 `is_suspended` 处理
3. 过滤器不可被业务 SQL 绕过；DB 角色/视图/查询扫描三重限制。
4. 定期扫描因子查询，违规直连阻断并告警。
5. 新增核心指标“因子计算数据合格率”。

**验收：** 生产链路无直连事实表查询；服务层默认过滤生效；因子计算数据合格率 100%；审计/研究模式需审批白名单。

### 13.6 Q24：写入幂等与乐观锁

**结论：成立，P1。** 仅靠调度互斥不够；重复执行、超时重试会导致重复写入、主键冲突、旧版本覆盖新版本。

**修订：**

1. 幂等键：`hash(source_tag + instrument_id + trade_date + payload_hash)`；重复提交直接返回成功，不重复写。
2. `batch_id` 仅作审计，不作为唯一幂等键（重试可能换批次）。
3. 乐观锁：`row_version`；低版本禁止覆盖高版本。
4. 同键不同源严格走 `data_conflicts`，不自动覆盖。
5. 写入事务内校验幂等键 + 版本，提交后记录 `write_token`。

**验收：** 重复提交同一批次无变化、无报错；低版本无法覆盖高版本；无重复行；同键不同源进冲突表。

### 13.7 Q25：涨跌停动态阈值

**结论：成立，P1。** 固定涨跌幅门禁会误判 ST/主板/科创板/创业板/北交所，且戴帽/摘帽会动态变化。

**修订：**

1. 新增 `price_limit_rules`：按板块、状态、生效日期维护涨跌停比例。
   - ST 5%；主板 10%；科创板/创业板 20%；北交所 30%；
   - 新股上市初期无涨跌幅/特殊规则按交易所公告；
   - ETF/基金按所属类型规则。
2. `instrument_master` 维护每日 `price_limit_pct`、`limit_up_price`、`limit_down_price`。
3. 价格门禁读取标的当日动态阈值；状态变更日按 `effective_from` 生效。
4. 涨跌停价按前收盘价与最小价位单位计算，避免四舍五入误判。

**验收：** 不同板块/状态按对应阈值校验；状态切换当日无异常误报；涨跌停价与交易所一致。

### 13.8 Q26：停牌日 0/NULL 语义

**结论：成立，P1。** “未知置空”没有区分合法零值与缺失值，适配器处理不一致会污染连续性、成交量、换手率。

**修订：**

1. 停牌日：`open/high/low/close = 前收盘价`；`volume/amount/turnover_rate = 0`；`is_suspended=true`；`zero_semantics='legitimate_suspension'`。
2. 非停牌日缺失：`NULL` + `partial`；`zero_semantics='missing'`。
3. 所有适配器按同一规则执行；事实表增加 `is_suspended`、`zero_semantics`。
4. 退市标的不再新增行；停牌行保留以维持序列连续。

**验收：** 停牌日数据格式 100% 统一；无 0 与 NULL 混用；连续性/成交量/换手率计算无歧义。

### 13.9 Q27：按资产类型拆分门禁

**结论：成立，P1。** 股票、ETF、指数、宏观、公告、财报的校验逻辑完全不同，一套规则会失效或误报。

**修订：**

1. 契约增加 `asset_type` + `gate_profile`，按类型拆模板：
   - 股票：OHLC、量价、换手率、复权、涨跌停、PIT；
   - ETF：NAV/收盘/溢折价/份额/规模；不套 ST 规则；
   - 指数：点位连续性、成分/权重；移除复权/换手率；
   - 宏观：按频率做 PIT/修订/vintage；不做日频量价；
   - 公告：编号唯一性、发布日期、来源；不做价格门禁；
   - 财报：公告日/PIT、字段口径；不做价格门禁。
2. 每个数据集绑定独立门禁规则集；非适用规则不执行、不误报。

**验收：** 每个数据集有独立门禁；非股票类无无效校验项；校验准确率 ≥99%。

### 13.10 Q28：关键操作权限与审计

**结论：成立，P1。** 契约变更、批量作废、冲突仲裁、存量修复上线都是高风险操作，没有权限/审批/审计，出问题无法追溯。

**修订：**

1. RBAC + 分级审批：
   - 契约变更、全量作废、源优先级/配额变更：评审通过才可执行；
   - 冲突仲裁、修复上线：按金额/影响面分级审批；
   - 禁止自审批，职责分离。
2. 新增 `operation_audit`：操作人、时间、对象、变更前/后、原因、审批单号。
3. 审计日志不可篡改、永久留存；关键操作双人复核。
4. 无权限人员无法执行高风险操作；API/DB 双重校验。

**验收：** 关键操作 100% 有审批记录；日志完整可追溯；无权限人员无法执行；审计可还原变更前后值。

### 14.2 R1：字段、价格口径与门禁

#### 14.2.1 存储与数值约定

MySQL 权威版本层金额 DECIMAL(28,8)，价格/NAV/点位 DECIMAL(24,8)，股数/份额 DECIMAL(28,8)，比率及百分数 DECIMAL(24,10)，复权系数 DECIMAL(28,16)。DuckDB 镜像保留相同 DECIMAL；计算可转 DOUBLE，比较采用本节容差。禁用 NaN/Inf；缺失为 NULL；有证据的零值为 0。字段后缀 pct 一律百分点，x 为倍数，cny 为人民币元。币种不是 CNY 的记录不能直接进入 CNY 数据集。

股票/ETF 行情原始事实只保存 raw_open/raw_high/raw_low/raw_close、volume_shares、amount_cny、turnover_rate_pct、is_suspended、synthetic_bar；派生关系保存 adj_open/adj_high/adj_low/adj_close、adj_factor_version、base_date、raw_data_version。旧 open/high/low/close 在生产兼容关系中唯一映射到 adj_*，旧 volume/amount/turnover_rate 映射到规范单位字段，不能再用同名 close 同时指 raw 和 adj。指数单独使用 index_open/high/low/close（点），不复权。

复权规范：对事件日 e，参考价 P_ref=(P_prev_raw-cash_dividend+rights_price×rights_ratio)/(1+stock_ratio+rights_ratio)，拆并股先转为分母对应比例；事件处理顺序按公告明确，无法唯一解释则拒绝生成因子。r_e=P_ref/P_prev_raw；F(t,b)=所有 t<e≤b 的 r_e 乘积；adj_price(t,b)=raw_price(t)×F(t,b)。base_date=b 为本次查询截止时点对应的最近已结束交易日，不使用未来事件；成交量/金额/股本不乘 F。corporate_action 增加 rights_price，所有事件字段均绑定公告版本与可知时间。负/零参考价、缺配股价或未知事件类型返回 ADJUSTMENT_UNAVAILABLE，不猜值。历史 raw 缺失时禁止从无基准证据的 qfq 反推。

#### 14.2.2 消费与门禁矩阵

| 规则 ID | 消费或门禁 | 输入/公式 | 阈值与失败行为 |
|---|---|---|---|
| P01 | 原始 OHLC | raw_low≤raw_open/raw_close≤raw_high，价格>0 | 差值容许 0.00000001；违反隔离该行 |
| P02 | 成交量/额 | volume_shares≥0，amount_cny≥0；有成交时 VWAP=amount/volume | VWAP 须在 [raw_low-ε,raw_high+ε]，ε=max(0.01,raw_high×0.005)；超界 quarantine；仅有 close 无 high/low 则 insufficient，不拒整批 |
| P03 | 市值 | raw_close×total_shares 或 float_shares | 与同日同币种市值相对差≤1%；不满足标 mismatch；股本未知为 insufficient；不以 free_float 替代 float |
| P04 | 换手率 | volume_shares/float_shares×100 | 仅 matching share_definition 比较；相对差≤2% 或绝对差≤0.01 百分点；否则 mismatch |
| P05 | 涨跌停 | raw OHLC 与官方当日上下限价 | 超过一个 tick 则 quarantine；官方参考价/规则缺失为 insufficient，不使用固定 ST 百分比兜底 |
| P06 | 除权事件 | 公告参数计算 P_ref，与官方除权参考价比对 | 容差一个 tick；真实开盘/收盘涨跌不要求等于事件比例 |
| P07 | 收益率/技术指标 | 同查询截止时点、同因子版本 adj 序列 | 每个窗口只允许一个复权定义与基准；缺依赖输出 NULL+原因，不跨缺日拉长窗口 |
| P08 | ETF 盘中溢折价 | (raw_price/iopv-1)×100 | 两者 observation_at 相差≤60 秒且同币种/估值市场口径；否则 NULL+TIME_BASIS_MISMATCH |
| P09 | ETF 收盘净值溢折价 | (raw_close/nav_official-1)×100 | 同 valuation_date，NAV 已可知；字段 premium_official_pct，不能回填到当日盘前决策 |
| P10 | ETF 规模 | nav_official×total_shares | 同估值日、同份额类别；误差≤0.5%；缺失为 NULL；IOPV 估算另存 fund_size_estimated_cny |
| P11 | ETF 跟踪误差 | std(净值总收益率−基准总收益率,ddof=1)×sqrt(252)×100 | 固定 60 个共同交易日收益（需 61 个净值点）；需分红再投资与基准总收益数据，无则 NULL，不以价格指数偷换 |
| P12 | 指数 | 点位 OHLC；volume/amount 按指数专用契约 | 不执行 amount/volume≈指数点位；amount 可缺，不跨源补；量单位未知为 partial |
| P13 | 双源比较 | raw close、真实量额；同 observation/definition | close≤max(0.01,主源×0.005)，量≤1%，额≤2%；超差仅产生冲突候选，不自动污染当前合格事实 |

ratio 差异分母取 max(abs(reference),10^-8)。P03/P04 参考输入未齐时仅阻断依赖该输入的消费，不连带禁止只需 OHLC 的技术因子。每行保留 gate_results JSON，值为 pass/fail/insufficient/not_applicable；required gate 不为 pass 的消费不得通过。协议结构错误或单位契约缺失拒绝整批；数值异常隔离逐行，其余行允许写入，发布时另过 R5 批次覆盖闸。

停牌：有权威状态证明才允许 synthetic_bar=true、is_suspended=true，量/额/换手=0；raw OHLC 使用当日官方参考价，无则无公司行动时沿用上一 raw close；当日有公司行动但无参考价则 NULL+partial。合成行不代表可成交，标签引擎不能在该日生成入场/出场成交。除权因子按事件照常作用，不人为重复扣除。

#### 14.2.3 单位契约键与必填集合

契约唯一键=(provider,endpoint,dataset,asset_type,instrument_family,contract_version)，历史有效区间独立维护；优先匹配具体 family，无匹配拒绝，不回退默认倍率。契约记录每个 wire_field、native_unit、scale、offset、definition_id、currency、evidence_hash。转换 normalized=raw×scale+offset；禁止按数值大小猜倍率。腾讯现有已验证族沿用：sh_star_688=1，sh_main/sz_main/sz_chinext=100，689/北交所等未验证族返回 UNIT_CONTRACT_UNVERIFIED。其余源沿用已验证端点契约；没有证据即隔离，不能采用第 3.2 节概括表替代端点证据。

| 数据集质量 profile | complete 的必填 payload | 可选字段/限制 |
|---|---|---|
| daily_bars/core | raw OHLC、volume_shares、is_suspended、synthetic_bar | amount、turnover 可缺；使用它们的因子单独要求非空和相关 gate pass |
| valuation/core | pe_ttm_x、pb_mrq_x、definition_id | 亏损 PE 允许负数；未知不能填 0；市值/股息率可缺 |
| financial/core | net_profit_parent、revenue_operating、net_profit_yoy_pct、revenue_yoy_pct、roe_weighted_period_pct | 不把加权 ROE 写进 roe_ttm；TTM ROE 为单独 derived profile，缺四季/权益依据则不可用 |
| capital_flow/core | main、super_large、large、medium、small 的净额及 flow_definition | 净额可负；main 定义固定 super_large+large，差异按金额精度检验 |
| lhb/core | institution_buy/sell/net、reason_scope、dedup_rule_id | 买卖额≥0，net=buy-sell；买卖合计不与单边全市场成交额简单比较 |
| hot_rank/core | rank、ranking_method、observation_at | total/pct 可空；pct=100×(total-rank+1)/total，仅知真实总体时计算 |
| etf/nav | nav_official、valuation_date、currency | IOPV 不可充当官方 NAV；shares、规模、TE 是独立 profile |
| etf/shares | total_shares、share_class、valuation_date | 未知不补历史 |
| etf/size | fund_size_cny、nav_data_version、shares_data_version | 严格按 P10，不以 estimated 替代 |
| etf/tracking | tracking_error_pct、window=60、benchmark_id、nav_return_version、benchmark_return_version | 严格按 P11，不足窗口为 partial |
| index/core | index OHLC、index_id | volume/amount 可空，依赖消费拒绝缺失输入 |
| macro/core | indicator_key、period、frequency、value、unit | revision/vintage 按 R2，非交易日发布合法 |
| announcement/core | authority、announcement_id、published_at 或原始发布日期、content_hash | 正文版本/撤回必须可追溯 |

complete 是指定 quality_profile 下必填字段与适用必需门禁通过，不意味着所有列非空。字段级多源只允许 ETF 各互斥 profile、财报的公告证据关联、估值市值与 PE/PB 组分离；每个字段须引用实际 data_version。财务五字段缺来源统一证据时为 partial，不能为了完整率拼接。每个消费在 manifest 中声明 required_fields/gates；不允许临时 SQL 自行豁免。

### 14.3 R2：双时态 schema 与 as-of API

#### 14.3.1 统一字段与约束

以下是物理规范：MySQL DATETIME(6) 存 UTC 无时区值，API 只接受带 offset 的 ISO8601；展示可用 Asia/Shanghai。DATE 不附时区。NULL 上界表示正无穷，区间一律左闭右开。

| 字段 | 类型/空值 | 唯一语义 |
|---|---|---|
| event_date | DATE NOT NULL | 业务发生日期：交易日/报告期末/宏观期末/股本生效日；公告取其原始当地发布日期 |
| published_at | DATETIME(6) NULL | 有证据的源端精确发布时间；只有日期时不伪造精确时间 |
| publication_date | DATE NULL | 源端发布日期，precision=date 时必填 |
| publication_precision | VARCHAR(8) NOT NULL | exact/date/unknown |
| public_available_at | DATETIME(6) NULL | 公众可知保守下界：exact=published_at，date=来源当地次日 00:00，unknown=NULL |
| observed_at | DATETIME(6) NOT NULL | 本系统首次取得该源版本的时间，不随重试刷新 |
| available_at | DATETIME(6) NULL | 该版本首次通过验证并获准消费的事务时间；隔离候选为空 |
| valid_from/valid_to | DATE NOT NULL / NULL | 业务有效区间；日频/公告事件为 [event_date,event_date+1日)，股本为生效日至下一变更日 |
| system_from/system_to | DATETIME(6) NOT NULL / NULL | 某个“认可状态/版本绑定”的系统有效区间，存于 acceptance_history，不混入业务区间 |
| revision_kind | VARCHAR(16) NOT NULL | original/correction/withdrawal/repair |
| supersedes_version | CHAR(64) NULL | 被替代版本；必须同逻辑键，禁止循环 |
| publication_evidence_hash | CHAR(64) NULL | 公共历史重建的时间与内容对应证据 |

约束：exact 必须有 published_at；date 必须有 publication_date；unknown 禁止 public_known 历史消费。available_at≥observed_at；有 public_available_at 时 available_at≥它；system_from≥available_at。valid_to>valid_from，system_to>system_from；同 logical_key 的系统认可区间不重叠。财报 valid 区间表示报告事实日期，不表示持有到下一报告：报表面板先按报告逻辑键选版本，再选 event_date≤信号日的最新报告，不能按“六月更正旧报告”误压过更新报告期。

股本后续事件缩短旧业务区间时创建新版本，旧快照仍保留旧区间；按查询知识时点构造区间，历史查询不得借用后来才知道的下一事件。公告发布时间不搬移到交易日；execution_eligible_at 单独映射为严格晚于信息可用时间的下一交易时点。本阶段日频交易只在下一开市时点使用，盘后公告不会进入当日收盘决策。

raw 行情历史回填没有公开内容版本证据时仅 system_known 自实际 available_at 起可用；不能因为交易日期较早就自称历史 PIT 已认证。历史导入现有 historical_asof_certified=false 继续保留，直到逐版本满足公共证据要求。

#### 14.3.2 唯一服务 API

服务接口固定：DataAccessService.read_as_of(request)。接口为应用服务契约，本阶段不新增对外 HTTP 地址。所有参数均必填，无静默日期回退。

```json
{"dataset":"financial","instrument_ids":[101],"event_range":{"start":"2026-01-01","end_exclusive":"2026-07-01"},"as_of":"2026-04-30T15:00:00+08:00","knowledge_mode":"public_known","snapshot_id":"S1","quality_profile":"financial/core","required_fields":["net_profit_parent"],"price_basis":"none","base_date":null}
```

knowledge_mode 只允许 public_known/system_known；price_basis 为 raw/adj/none，adj 要求 base_date 为 as_of 时最近已结束交易日。snapshot_id 不接受 latest；调用方在任务启动时先解析发布指针并锁定 ID。日频回测每个信号日使用对应 as_of 和对应因子集合，不能用结束日一次查询覆盖整个回测窗口的知识截止时间。

选择顺序：
1. 验证已发布 manifest、schema/profile/字段权限；从该快照显式成员及依赖闭包中取版本。
2. 限定 instrument、event_range；金融报表面板可由调用方请求足够早的历史区间，但不延长技术指标缺失窗口。
3. public_known：仅取 public_available_at≤as_of、有内容版本证据的认可来源版本；沿 supersedes 链选择当时最新的已公开版本，不能按 today.is_obsolete 过滤；不要求 observed_at≤as_of，返回 reconstruction=true。system_known：按 acceptance_history 中 system_from≤as_of<system_to 选唯一绑定，同时 available_at≤as_of；不得使用后来追认状态倒填历史。
4. withdrawal 在其可见时点后输出缺失，不自动恢复被撤回的旧值；withdrawal 之前仍返回原值。无可排序修订链的两个候选报 VERSION_AMBIGUOUS，不按插入序号任选。
5. 应用冻结的 profile 和字段门禁；adj 使用当前知识截止可知的事件集合；返回逐键数据和逐键 missing，不静默丢掉缺日。

```json
{"snapshot_id":"S1","knowledge_mode":"public_known","as_of":"2026-04-30T15:00:00+08:00","reconstruction":true,"rows":[{"instrument_id":101,"event_date":"2026-03-31","data_version":"V1","net_profit_parent":"100000000.00000000","public_available_at":"2026-04-20T10:00:00+08:00","available_at":"2026-04-21T09:00:00+08:00","source_state":"canonical","quality_status":"complete"}],"missing":[]}
```

V1/S1 等为样例短 ID，实际为 SHA-256。错误：INVALID_ARGUMENT/400、SNAPSHOT_NOT_PUBLISHED/409、SNAPSHOT_DEPENDENCY_MISSING/409、VERSION_AMBIGUOUS/409；合法查询无数据仍返回成功及 missing(reason=NOT_KNOWN/NOT_INGESTED/RETRACTED/QUALITY_BLOCKED/ADJUSTMENT_UNAVAILABLE)。缺数据不自动改 as_of，不把 NULL 变 0。

### 14.4 R3：版本键、当前指针与不可变快照

#### 14.4.1 逻辑身份与版本

实体 instrument_id 为 BIGINT、永不复用；instrument_alias 保存旧表名/旧 ID/交易所/代码/有效区间到 instrument_id 的映射。相同交易所代码的有效区间不能重叠；代码未知或生命周期不明拒绝 canonical 发布。无标的宏观/公告用 entity_key 命名空间，不伪造股票 ID。

| dataset | logical_key 的业务部分（dataset 自动加入） |
|---|---|
| daily_bars | instrument_id, trade_date；只存 raw 原始事实 |
| valuation | instrument_id, trade_date, definition_id |
| financial | instrument_id, report_period, report_type, definition_id；announcement 不在逻辑键 |
| capital_flow | instrument_id, trade_date, flow_definition |
| lhb | instrument_id, trade_date, reason_scope, dedup_rule_id；当前日汇总使用 reason_scope=all_disclosed_reasons |
| hot_rank | instrument_id, ranking_method, observation_at；日消费选 cutoff 之前最后一次真实快照 |
| etf | instrument_id, valuation_date, profile, share_class；IOPV 另加 observation_at |
| index | index_id, trade_date, definition_id |
| macro | indicator_key, period, frequency, definition_id；vintage 属于版本 |
| announcement | authority, announcement_id |
| share_capital | instrument_id, effective_date, share_class |
| corporate_action | instrument_id, authority_event_id |

logical_key=SHA256(UTF-8 canonical JSON 业务键)。JSON 键排序、日期 ISO8601、decimal 固定 scale 字符串、不包含空白；同哈希但业务键不同必须报 HASH_COLLISION。版本值不是“越大越新”。

| 表 | 字段与键约束 |
|---|---|
| fact_versions | PK data_version CHAR(64)；dataset VARCHAR(32)、logical_key CHAR(64)、key_json、payload_json、raw_hash、contract_version、definition_id、source_tag VARCHAR(128)、field_sources JSON、R2 时间字段、revision_kind、supersedes_version；均非空，除 R2 明示及 supersedes 可空；FK parent 必须同 logical_key |
| fact_current | PK(dataset,logical_key)；data_version FK、pointer_revision BIGINT、source_state、quality_profile、quality_status、provenance_mode、updated_at；每键一行 |
| acceptance_history | PK(dataset,logical_key,pointer_revision)；data_version、source_state、quality_status、system_from/to、decision_id；区间不重叠 |
| source_decisions | PK decision_id CHAR(64)；candidate_version、previous_version NULL、event、from_state、to_state、actor、evidence_hash、decided_at、expected_pointer_revision、result；不可变 |
| adjustment_sets | PK adj_factor_version CHAR(64)；instrument_id、base_date、as_of、knowledge_mode、algorithm_version、event_version_ids、factor_rows_hash；系数子表键(version,trade_date) |
| dataset_members | PK(dataset_version,data_version)；成员包含历史版本和撤回 tombstone，不只包含当前值；指针/认可历史/证据一起入包 |
| snapshot_manifest | PK snapshot_id CHAR(64)；manifest_json、manifest_hash、state、created_at、published_at NULL |
| snapshot_pointer | PK channel（production/research）；snapshot_id、pointer_revision；仅指 published |

data_version=SHA256(dataset+logical_key+source_tag+contract_version+definition_id+source_revision_token+normalized_payload_hash+publication_evidence_hash+supersedes_version)。未知 revision token 使用内容 hash，但只保证身份，不提供顺序。observed_at/batch_id 不参与版本身份；重复抓取记 observation 日志，不制造假修订。幂等键=SHA256(dataset+logical_key+data_version+operation_kind+decision_id)，幂等记录与事实、指针、认可历史同事务提交；write_token 同事务生成，禁止提交后补记。

fact_versions payload 插入后不可 UPDATE/DELETE；首次 available_at 保存在独立 version_availability(data_version PK/FK, available_at NOT NULL, decision_id NOT NULL) 中，获准时一次性插入，服务投影为 R2 的 available_at，未获准无对应行即 NULL，不能为认可候选而改写不可变事实。认可元数据只允许关闭 system_to 并新增区间，关闭操作有 source_decisions 审计。避免依赖数据库对 CHECK 的支持：writer 在锁住 fact_current 后显式验证区间/父链/枚举，DB 用 PK/UNIQUE/FK/NOT NULL 保障基础约束；生产 writer 为唯一写权限角色。DuckDB 镜像只读，不以 SQL 扫描代替权限控制。

派生价格子表 adjusted_bars 的 PK=(raw_data_version,adj_factor_version)，字段为 instrument_id、trade_date、base_date、adj_open/high/low/close；两版本均 FK，base_date 必须等于 factor set 基准。任何复权变化生成新的 factor set 和派生键，不改 raw_data_version。派生 ETF 指标同样保存 input_versions JSON，available_at 不早于任何依赖实际可用时间，public_available_at 不早于任何依赖公共可知时间；依赖任一未知则公共历史不可认证。

payload_json 采用每 dataset/profile 冻结的 schema：字段由 R1 必填集合和该行可选字段构成，未知字段拒绝；financial 的 report_type 为 annual/q1/half_year/q3，definition_id 固定记录合并范围、母公司净利润、营业收入、累计期间及加权 ROE；不能把不同口径仅凭字段名归入同 definition。百分比同比依源端明确同口径值，分母零导致未定义时 NULL+partial。definition_id 为规范定义文档 SHA-256，契约必须引用它。lhb 的 dedup_rule_id 固定为 reason-seat-union-v1：同一官方席位成交事实在多上榜理由中仅计一次，无法获得可去重身份则日汇总 partial，禁止相加后谎称完整。

#### 14.4.2 发布与回滚协议

单键写入：锁 current → 验证 expected_pointer_revision → 幂等校验 → 插入版本 → R4 决议 → 原子关闭旧认可区间/插入新区间/切 current/写审计与 outbox。CAS 失败返回 POINTER_STALE，重新读取后重新判定，不盲目重试覆盖。

跨库不假定分布式事务：MySQL outbox 记录确定的版本清单与源高水位；单 writer 将清单写入独立 shadow DuckDB 文件。构建期间不读会变化的 current。完成后校验行数、成员哈希、FK 依赖和 R5，关闭写连接，将文件作为不可变 artifact；最后在 MySQL 事务内把 manifest 状态与发布指针一并更新。状态为 building→validated→published，失败为 failed；published 永不退回 building。崩溃在指针更新前，旧快照继续服务；指针更新后新快照完整可读。文件丢失/哈希错误阻断读取，不混用另一文件。

manifest 必含：schema_version=governance-1.4、dataset_versions 映射、每个数据集 artifact 路径及 SHA256、member_count/member_hash、acceptance_history_hash、contract_versions、calendar_version、instrument_version、definition_versions、adjustment_sets 清单、quality_profile_versions、coverage_scope_hash、golden_set_version、created_at。dataset_version 为该数据集成员及认可历史、契约引用的哈希；snapshot_id 为规范化 manifest 内容哈希（不含自身 ID 和发布状态）。增量快照可引用父包，但依赖闭包必须可用并哈希一致。

任务启动固定 snapshot_id；每次计算记录 calc_batch_id→snapshot_id/as_of策略/knowledge_mode/代码版本。factor_values 与 factor_targets 均绑定它；共享 targets-labels 不能再成为跨快照覆盖槽，实际物理键增加 snapshot_id，旧接口只在任务绑定快照后映射。缓存键必须含 snapshot_id、as_of、mode、profile、base_date；评分候选池现有仅按日期的缓存必须切换。

当前生产默认 system_known；public_known 为带 reconstruction=true 的历史研究入口，不宣称系统当时实际取得。回滚只 CAS 发布指针至旧 published 快照，进行中任务不变；按需作废受影响计算批次，不删除历史 artifact。历史事实和快照不级联删除。保留 raw_daily_bars 为服务生成的兼容关系，不再是可写权威表；每日市场事实的权威来源统一为新 universe 行情版本层，daily_bars 仅投影。

### 14.5 R4：源状态与恢复

状态对象分开：fact_current/acceptance_history 表示当前获准版本；候选任务保存 candidate_state。recovery_pending/conflict 可属于候选，不能因为候选冲突就删除已有合格 current。

独立维度：source_state=legacy/claimed/canonical/backup_temp/recovery_pending/conflict；quality_status=complete/partial/quarantined；provenance_mode=single/composite；revision_kind 按 R2。is_obsolete 仅为“已非当前指针”的兼容派生字段，不能用来过滤所有历史查询。legacy/claimed/conflict 候选不可消费。backup_temp 允许 profile 合格的行情消费并显式返回 degraded=true；股票缺 amount 的备源不阻断纯价格因子，但阻断金额因子。

| ID | 起点 | 事件和守卫 | 动作/终点 | 不满足时 |
|---|---|---|---|---|
| T01 | 无事实 | 已登记主源，门禁满足 | 新版本获准 canonical | 候选 partial/quarantined，不切指针 |
| T02 | legacy | 有 migration_id、原始证据和生命周期映射 | 候选 claimed | 保持 legacy，不自动猜源 |
| T03 | claimed | R1/R2 全部要求满足，迁移审批有效 | 原子激活 canonical | candidate conflict，旧事实保留 |
| T04 | 无当日获准事实 | 主源失败/空/过期/熔断，同组备源门禁合格 | 激活 backup_temp，建 recovery_item | 无合格数据则 missing，禁止沿用昨日值伪造当日 |
| T05 | canonical | 主源失败但本键已有合法事实 | 指针不变；记录 stale/同步失败 | 不用备源覆盖已有 canonical |
| T06 | backup_temp | 同交易日主源恢复 | 仅记录恢复候选 | 当日不切回 |
| T07 | backup_temp | 次交易日及之后主源候选到达 | candidate recovery_pending | 失败保留 backup_temp，重试队列 |
| T08 | recovery_pending | 主源为登记 primary、同定义、raw 双源在 P13 容差内、无新旧顺序冲突 | canonical 新版本，旧版本保留，恢复项完成 | 超差转 conflict，不自动凭优先级覆盖 |
| T09 | canonical | 同源 source_revision 有可证顺序且更新 | 验证后新 canonical；关闭旧系统认可区间 | 旧 revision 忽略并审计；内容不同但无顺序转 conflict |
| T10 | 任意获准状态 | 任意不同源非恢复替换请求 | candidate conflict | 不改变 current |
| T11 | conflict | 两人仲裁、证据、期望指针一致、门禁通过 | 激活决议指定版本/withdrawal | CAS 失效重新仲裁上下文；不自动重放 |
| T12 | 任意 | 已获准数据被确认全错/撤回 | tombstone 获准，current 指向 tombstone | 此后返回 RETRACTED；过去快照不物理删除 |
| T13 | recovery_pending | 再次故障 | 保留 current 与候选待恢复状态 | 按队列退避，不重复建项 |

优先级严格为：契约/身份/时间合法性 → 幂等与 CAS → 可证版本顺序 → 已审批迁移 → T08 恢复 → T09 同源修订 → T10 冲突。相同 source_tag 的 raw_hash 变化不构成顺序；source revision 无序时仍需证据仲裁。契约修订或单位修复不是“更晚源数据”，使用 repair + 审批 decision_id，经 T11 生效。

recovery_items 字段：PK(dataset,logical_key,backup_data_version)，status=pending/running/conflict/done，attempts、next_attempt_at、last_error、candidate_version NULL、lease_until NULL、completed_at NULL。覆盖全部 backup_temp 日期，不限定昨天/10 日。成功提交指针和 done 同事务；任务 lease 120 秒，到期可接管，CAS 防双提交。失败退避 min(60×2^attempts,3600) 秒，叠加 0—10% jitter；每 provider 使用已登记限流，未登记禁止调用；持续 24 小时升级人工但不丢队列。

允许同定义、同复权基准的合格跨源时间拼接；保留 source_break 供审计，source_break 本身不阻断窗口。跨源边界若 P13 未通过/未验证则窗口输出 SOURCE_BOUNDARY_UNVERIFIED；不得要求全历史强制换源或忽略断点。缺失交易日用 calendar 显式保留 NULL，滚动窗口不压缩。

退市判断依据事实日期：list_date≤trade_date≤last_trade_date 可回补；今天状态 delisted 不影响；区间之外拒绝 OUTSIDE_LIFECYCLE。无可靠最后交易日时不自动扩展区间。退市历史不是“作废数据”。

### 14.6 R5：可复核的验收基准

#### 14.6.1 台账与 golden set

expected_repair_diff 物理字段：PK(repair_plan_id,logical_key,field_name)，old_data_version CHAR(64)、expected_new_payload_hash CHAR(64)、old_value/expected_value DECIMAL或规范字符串、operation(scale/replace/nullify/reclassify)、rule_id、absolute_tolerance、relative_tolerance、evidence_hash、reviewer_id、approved_at、result(pending/pass/fail)。old/new 值允许 NULL 但 nullify 必须新值 NULL；scale 必须 multiplier；无批准不计 expected。台账在影子输出验收前冻结，实际输出 hash 必须匹配；任何调整创建新 repair_plan_id 重新评审。

golden_set_version=GS-1.4.0，规范样例为 14.7 的全部案例，均为合成规则测试，不伪称实测行情。实现验收还必须固定真实证据集 GS-1.4.0-E：500 个逻辑键，按键哈希升序确定选样，至少 50 个腾讯 688 族、50 个其他腾讯股票族、50 个公司行动附近行情、50 个公告更正/日期精度案例、50 个退市或停牌案例、50 个 ETF 组合案例，余 200 覆盖其他数据集；各类不足数量不降低标准，验收失败。每个样本保存源响应/公告文件 hash、字段单位证明及两人核验记录。当前文档定稿不声称该真实证据包已采集；它是实施后切读的强制验收输入，不能作为设计待定项绕过。

规范样例必须 100% 通过；真实证据样本必须 100% 符合冻结预期；raw/adj 混用、未来信息泄漏、旧请求覆盖、快照混读、无授权换源、退市历史误排除任一出现均为阻断项，不按总体差异率稀释。

#### 14.6.2 覆盖率和差异

coverage_scope：scope_id/hash、dataset/profile、instrument_version、calendar_version、start/end_exclusive、knowledge_mode、cutoff_policy、required_fields/gates、snapshot_id。对比时冻结同一 scope 业务部分，只有 snapshot_id 不同。

日频分母 D=日期区间内按当时生命周期应有记录的 instrument×官方开市日；停牌仍属于行情分母，退市后/上市前不属于。ETF 按 profile 分开，指数按自身日历。财报按可知且应有的 report_period/report_type 清单；宏观按指标发布日历；公告/LHB 按权威事件目录及抓取完成证据；热榜按方法及实际公布名次集合。无法取得事件全集时报告 denominator_status=unknown、coverage=NULL，禁止报 100%；空榜仅在响应有“完整且为空”证据时成立，普通空返回不算完成。

N=同一 snapshot/as-of/profile 下合格且唯一的预期键数。coverage=N/D；D=0 返回 not_applicable，不当作 100%。partial/quarantined/unknown_publication 单列计数，来源 composite 不扣分。旧数据按相同 R1/R2 规则重评分；旧台账 complete 不直接进入新分子。修订撤回导致 N 降低时按当前快照重新计算，不继承旧 complete。

差异桶：expected_repair_diff、unexpected_diff、unverifiable。只在可比且不属于批准修复的键/字段上计算 unchanged_agreement=1-unexpected/comparable；comparable=0 返回 not_applicable。验收要求 unchanged_agreement≥99.99%，且所有 unexpected 都有关闭决议；unverifiable 不计一致率分母，但必须计覆盖损失。expected 修复正确率=100%；不接受“99.99% 一致”掩盖未解释的关键差异。

发布阈值：行情 core 最新日≥99.5%，资金流连续 60 个交易日每日≥95%，财报 core≥95% 应有报告，沪市 ETF shares≥95% 适用份额日。其他 profile 只发布实际覆盖，不宣称达标；消费级依赖不足输出 NULL/阻断该因子。与旧同口径覆盖相比不得下降，修复剔除错误旧值不构成下降（旧值也须按同门禁判不合格）。不影响旧缺陷的新增缺失必须修复。

观察期：行情 5 个连续交易日、ETF 20 个连续交易日、财报 1 个完整季度披露周期；灰度 10%→50%→100%，按 instrument_id 哈希固定分组，每级至少一个交易日并满足同一阈值。技术端点成功率、耗时为运维目标，不替代数据门禁，也不承诺第三方端点一定 99% 可用。回滚指针后新建计算任务使用旧快照，已运行任务继续固定原快照。

```sql
-- 1. 源标签分布
SELECT source, COUNT(*) AS rows FROM daily_bars GROUP BY source ORDER BY rows DESC;
SELECT source, COUNT(*) AS rows FROM universe_daily_bars GROUP BY source ORDER BY rows DESC;
SELECT source, COUNT(*) AS rows FROM index_prices GROUP BY source;
SELECT source, COUNT(*) AS rows FROM stock_valuations GROUP BY source;
SELECT source, COUNT(*) AS rows FROM capital_flows GROUP BY source;
SELECT source, COUNT(*) AS rows FROM etf_indicators GROUP BY source;

-- 2. 空列分布
SELECT source, COUNT(*) AS rows,
       SUM(volume IS NULL) AS volume_null,
       SUM(amount IS NULL) AS amount_null,
       SUM(turnover_rate IS NULL) AS turnover_null
FROM daily_bars GROUP BY source;

-- 3. 双表源标签不一致（近 90 天）
SELECT d.source AS daily_source, u.source AS universe_source, COUNT(*) AS rows
FROM daily_bars d
JOIN symbols s ON s.id = d.symbol_id
JOIN universe_symbols us ON us.symbol = s.symbol
JOIN universe_daily_bars u ON u.universe_symbol_id = us.id AND u.trade_date = d.trade_date
WHERE d.trade_date >= DATE_SUB(CURDATE(), INTERVAL 90 DAY) AND d.source <> u.source
GROUP BY d.source, u.source ORDER BY rows DESC;

-- 4. 单位 sanity：vwap/close 应接近 1
SELECT source, AVG(close) AS avg_close,
       AVG(amount / NULLIF(volume,0)) AS avg_vwap,
       AVG(amount / NULLIF(volume,0)) / NULLIF(AVG(close),0) AS vwap_close_ratio
FROM daily_bars WHERE volume > 0 AND amount IS NOT NULL GROUP BY source;

-- 5. 指数 amount 可用性
SELECT source, COUNT(*) AS rows, SUM(amount IS NOT NULL) AS amount_ok
FROM index_prices GROUP BY source;

-- 6. ETF 规模/份额单位
SELECT source, COUNT(*) AS rows,
       AVG(fund_size / NULLIF(nav * total_shares,0)) AS size_ratio
FROM etf_indicators
WHERE fund_size IS NOT NULL AND nav IS NOT NULL AND total_shares > 0
GROUP BY source;

-- 7. 人气榜分母
SELECT hot_rank_total, COUNT(*) AS rows
FROM stock_hot_rank_snapshots GROUP BY hot_rank_total ORDER BY rows DESC;

-- 8. 财务完整度
SELECT source, COUNT(*) AS rows,
       SUM(roe_ttm IS NOT NULL) AS roe_ok,
       SUM(net_profit IS NOT NULL) AS profit_ok,
       SUM(revenue IS NOT NULL) AS revenue_ok,
       SUM(net_profit_yoy IS NOT NULL) AS profit_yoy_ok,
       SUM(revenue_yoy IS NOT NULL) AS revenue_yoy_ok,
       SUM(roe_ttm IS NOT NULL AND net_profit IS NOT NULL AND revenue IS NOT NULL
           AND net_profit_yoy IS NOT NULL AND revenue_yoy IS NOT NULL) AS all5_ok
FROM stock_financial_reports GROUP BY source;

-- 9. 资金流全市场日
SELECT trade_date, COUNT(*) AS rows
FROM capital_flows GROUP BY trade_date ORDER BY trade_date DESC LIMIT 30;

-- 10. 换手率量级（正常中位数 ≈1.5–2.0；<0.1 基本可判定被 /100）
SELECT u.source, COUNT(*) n,
       SUM(u.turnover_rate > 0 AND u.turnover_rate < 0.1) AS too_small
FROM universe_daily_bars u
JOIN universe_symbols s ON s.id = u.universe_symbol_id
WHERE s.asset_type = 'stock' AND u.turnover_rate IS NOT NULL
GROUP BY u.source;
```

## 附录 E：一句话结论

**以 `universe_daily_bars` 为行情唯一事实表，以“股/元/份/倍/百分点 + qfq”为唯一口径，以契约注册表 + 单一写入 + 质量门禁 + 接通 Pacer/Breaker 为唯一入口，先修行情单位与限流、再修财报/估值/资金流、再切读、最后扩源。** 多数据源保留为冗余、补数和交叉校验，但任何时刻、任何字段只有一个 canonical，所有切换和字段组合都留痕、可对账、可回滚。
