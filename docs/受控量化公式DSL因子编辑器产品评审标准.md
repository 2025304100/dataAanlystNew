# 受控量化公式 DSL 因子编辑器产品评审标准

| 项目 | 内容 |
|---|---|
| 版本 | V1.0 |
| 日期 | 2026-08-14 |
| 评审对象 | 需求、交互、技术实现、测试结果、发布和上线后运行情况 |
| 评审原则 | 数据可验证、公式可复现、版本可追踪、风险可阻断、失败可回退 |

## 1. 评审阶段

```text
需求评审 → DSL/技术评审 → UI 交互评审 → 开发自测 → 测试评审
→ UAT 评审 → 发布评审 → 上线后复盘
```

任何阶段出现 P0 阻断项，项目不得进入下一阶段。

## 2. 需求评审标准

- 是否明确目标用户：普通配置用户、量化研究用户、审核用户。
- 是否明确支持的 DSL 语法、函数类别、返回类型和缺失值语义。
- 是否明确函数模式与高级表达式模式的关系。
- 是否明确旧因子、历史回测和现有生命周期不受影响。
- 是否明确数据覆盖不足时的处理和阻断条件。
- 是否包含可量化验收指标，而不是只写“体验更好”。

## 3. 技术评审标准

### 必须通过

- DSL 不执行任意 JavaScript/Python。
- 前端函数目录与后端目录来自同一 API。
- AST、依赖、编译器版本和执行计划哈希由后端生成。
- 编译器拒绝未知字段、未知函数、非法 AST、负 lag 和未来引用。
- 旧公式和旧 FactorVersion 有兼容读取路径。
- FactorVersion 被引用后不可原地修改。
- 编译失败不能进入 candidate。

### 需要提供的材料

- DSL 语法和类型说明。
- Parser/Normalizer 设计。
- 错误码和 API OpenAPI 契约。
- 数据依赖和执行计划样例。
- 安全拒绝测试和回归测试报告。

## 4. UI/交互评审标准

- 保持现有因子编辑 Modal 和三栏主框架，不引入与项目其他页面不一致的交互模式。
- 中央编辑器是主要工作区，左侧目录和右侧帮助不得抢占或遮挡主编辑区。
- 鼠标悬浮字段、函数和错误标记能显示用法、签名、参数和示例。
- 点击/拖拽插入不会覆盖已有公式。
- 条件配置器与表达式模式可以双向同步。
- 错误能定位到字符或参数，且提供可执行修复建议。
- Loading、Empty、Blocked、Error、Preview Ready 状态完整。
- 窄屏下右侧帮助变为抽屉，底部主操作始终可用。
- 颜色不是唯一状态表达方式，文本、图标和提示必须同步。

## 5. 测试评审标准

| 范围 | 放行标准 |
|---|---|
| Parser/编译器 | P0 用例 100% 通过；安全拒绝用例全通过 |
| API | 关键接口契约测试通过；错误码稳定 |
| 前端组件 | 核心编辑器和 Builder 用例 100% 通过 |
| E2E | draft → validate → preview → version → candidate 主链路通过 |
| UAT | 核心任务平均 ≥ 3.2/4，关键任务不得低于 3 |
| 回归 | 现有因子、回测、预警、复盘、FactorSet 无新增 P0/P1 缺陷 |

测试报告必须附命令、环境、数据版本、通过/失败数量和失败证据。

## 6. 产品数据和量化正确性评审

- 预览结果必须显示样本日期、数据截面、覆盖率和缺失率。
- 点时字段必须遵守发布时间约束。
- 缺失值不得默认全部填 0。
- 除零、非法对数、非法开方和异常值必须有明确策略。
- 因子方向、后处理、参数和数据依赖必须进入版本快照。
- 评估结果必须关联具体 FactorVersion，不允许只关联因子 code。
- 数据覆盖不足时只能保存草稿或研究结果，不得绕过正式评估门禁。

## 7. 发布评审标准

发布前必须确认：

1. 新能力由 feature flag 控制。
2. 旧编辑器和旧公式执行路径仍可回退。
3. 数据库迁移有备份、校验和回滚方案。
4. 前后端错误协议和中文文案已确认。
5. 监控包含编译失败率、预览失败率、平均耗时和异常函数调用。
6. 已准备发布说明、已知问题和回退操作手册。

## 8. 上线后复盘标准

上线后至少观察一个完整评估周期，复盘：

- 新建因子成功率和平均编辑时长。
- 函数搜索、自动补全和 Tooltip 使用率。
- 编译错误分布和最常见的修复路径。
- 预览阻断原因和数据覆盖问题。
- 因子版本回溯、回退和生命周期流转是否正常。
- 是否出现历史结果漂移、未来数据或函数目录不一致。

复盘结果必须形成问题清单、优先级、负责人和下一版本计划。

## 9. 评审结论分级

| 结论 | 条件 |
|---|---|
| 通过 | 所有 P0/P1 门禁通过，可按计划发布 |
| 限制通过 | 无 P0，存在已记录 P2，限定用户或 feature flag 发布 |
| 退回修改 | 存在 P0/P1，或量化结果、版本追踪、安全约束不完整 |
| 禁止发布 | 可执行任意代码、存在未来数据、历史版本可被覆盖或主链路不可回退 |
