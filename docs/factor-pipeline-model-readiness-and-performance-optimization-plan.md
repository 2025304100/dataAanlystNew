| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编制日期 | 2026-07-17 |
| 适用项目 | Personal Quant Workbench / dataAanlystNew |
| 当前阶段 | 因子流水线稳定性修复完成，进入模型有效性、数据覆盖与增量性能优化 |
| 核心目标 | 让流水线从“可以稳定跑完”升级为“可以稳定产出可验证、可解释、可回滚的 Ridge 候选模型” |
| 数据边界 | 继续使用免费 AkShare、本地 MySQL/SQLite 与 DuckDB，不新增付费数据源 |

## 0. 执行结论

当前第一优先级不是继续增加因子，而是修复训练数据就绪度和样本构造。

真实 550 天训练流水线已经可以稳定完成，但模型候选仍被拒绝。后续应按以下顺序实施：

1. 建立训练前数据就绪度检查，避免耗时计算后才发现无法训练。
2. 补齐估值、财报和主力资金数据，先覆盖可控的高流动性训练池。
3. 将 Ridge 从“所有因子必须同时非空”改为可审计的动态特征与缺失处理。
4. 将因子计算改为 SQL 日期下推、增量计算和有效行存储，控制 DuckDB 体积。
5. 增强长阶段取消、分阶段进度、错误摘要和失败续跑。
6. 完成严格时间可见性的滚动验证和至少 20 个交易日影子观察，再考虑人工激活 Ridge。

本方案不以降低模型门禁来制造“训练成功”。如果数据覆盖、样本数量或验证效果不合格，系统必须继续保持 manual，并给出可执行的修复建议。

## 1. 当前生产基线与问题证据

### 1.1 已完成的稳定性能力

- MySQL 日线读取使用短会话，查询结束立即释放连接。
- MySQL 2006、2013 和 Windows 10053 类断线支持安全重连重试。
- DuckDB 日线写入使用批量 DataFrame 合并，不再逐行 executemany。
- 范围镜像支持按 50 个标的保存临时断点，失败后可以续跑。
- 流水线拥有 15 秒任务心跳，长计算阶段不会被误判为失联。
- 页面能够展示细粒度镜像进度、运行时长和分模式 ETA。
- 后端任务时间带 UTC 时区，前端按本地时区显示。

以上能力作为后续优化的稳定基线，不应在后续重构中回退。

### 1.4 原始输入覆盖

本次镜像仅得到：

- 估值 6 行；
- 财报 336 行；
- 主力资金 0 行；
- 龙虎榜机构 229 行；
- 人气榜 300 行；
- 尾盘代理 0 行；
- 宏观 539 行。

因此，Ridge 失败不是算法故障，而是训练输入未达到可用条件。

### 1.5 训练样本归零的直接原因

当前训练样本加载逻辑要求所有 model_enabled 因子和 target 同时非空，然后统一 dropna。

第一版核心模型因子包括：

1. ep_ttm；
2. negative_pb；
3. roe_yoy_growth；
4. main_inflow_5d_ratio；
5. turnover_z20。

由于 main_inflow_5d_ratio 覆盖为 0，且其他基本面因子覆盖接近 0，五个因子的完整交集必然为空。

## 2. 优化目标与非目标

### 2.1 必须达到的目标

1. 点击训练前 3 秒内给出数据是否就绪以及阻断原因。
2. 第一阶段先让 300～500 只高流动性 A 股形成至少 120 个交易日的可训练样本。
3. 每次模型运行保存实际使用的特征清单、缺失策略、覆盖率和排除原因。
4. 日常非训练流水线目标耗时不超过 3 分钟。
5. 周度 550 天训练流水线目标耗时不超过 10 分钟。
6. 日常运行不得重复写入整段历史的无效空因子行。
7. DuckDB 日均净增长控制在 100 MB 以内，周度训练净增长控制在 300 MB 以内。
8. 用户取消任务后，普通阶段 10 秒内停止；不可中断阶段必须明确显示“正在安全结束当前批次”。
9. 新模型未通过数据、统计和回测门禁时，不允许自动切换 shadow 或 ridge。

### 2.2 明确不做

1. 不为了提高样本数而把所有缺失值直接填成 0。
2. 不把龙虎榜、人气榜和尾盘代理强行改成全市场每日因子。
3. 不承诺免费接口可以立即提供全市场、无缺口、严格历史时点的所有基本面数据。
4. 不引入消息队列、分布式训练或新的大型基础设施。
5. 不自动激活 Ridge，不自动下单。
6. 不绕过公告日、数据截止时间或模型可用日。

## 3. 目标业务链路

    数据同步
        -> 原始表覆盖统计
        -> 训练就绪度预检
        -> 可用训练池冻结
        -> 增量因子计算
        -> 特征覆盖与缺失策略
        -> T+5 标签对齐
        -> Purged Walk-Forward Ridge
        -> 数据门禁与模型门禁
        -> Shadow 评分
        -> 回测与 20 日影子观察
        -> 人工激活或回退

关键原则：

- 数据未就绪时，停止在预检阶段，不进入大规模因子计算和训练。
- 稀疏事件因子只参与解释或事件增强，不阻断核心模型。
- 每次训练的股票池、特征集和缺失规则都必须版本化。
- 日常评分和周度训练分开，避免每天重复训练和重算 550 天历史。

## 5. Phase A：训练就绪度与预检

### 5.1 建设目标

在运行 Ridge 前先判断：

- 训练池有多少股票；
- 各核心因子覆盖多少股票和交易日；
- 标签覆盖是否足够；
- 完整样本和缺失处理后的预计样本是多少；
- 本次哪些因子允许进入模型；
- 是否值得继续执行训练。

### 5.2 后端任务

新增 training_readiness 服务，输出：

| 字段 | 说明 |
|---|---|
| as_of_date | 数据截止日 |
| universe_scope | 训练池版本与范围 |
| symbol_count | 股票数 |
| trade_date_count | 交易日数 |
| target_coverage | 可交易标签覆盖率 |
| factor_coverage | 各因子股票日覆盖率 |
| complete_case_samples | 现有严格完整样本数 |
| usable_samples | 应用获批缺失策略后的预计样本数 |
| usable_features | 本轮可用模型因子 |
| blocked_features | 被排除因子及原因 |
| training_ready | 是否允许训练 |
| blocking_reasons | 可执行阻断原因 |

新增接口建议：

- GET /api/v1/factors/training-readiness
- POST /api/v1/factors/training-readiness/refresh

### 5.3 预检门禁

训练可执行门禁：

- 股票数不低于 100；
- 交易日不低于 120；
- 标签覆盖率不低于 90%；
- 至少 3 个可用核心特征；
- 可用特征至少覆盖 2 个因子类别；
- 预计可训练样本不低于 10,000；
- 任一覆盖为 0 的因子不得进入模型。

正式候选发布门禁仍保持更严格标准：

- 所有实际入模核心因子覆盖率不低于 70%；
- 验证期不少于 40 个交易日；
- 数据不达标时只能生成 readiness 报告，不生成 validated 模型。

### 5.4 前端任务

在“设置 → 因子模型”新增训练就绪卡片：

- 绿色：可以训练；
- 黄色：可以研究训练，但不允许进入正式候选；
- 红色：阻止训练；
- 展示每个因子的覆盖率、缺失原因和推荐修复动作；
- 未就绪时，“训练 Ridge”按钮旁显示阻断原因；
- 允许关闭训练，只运行日常镜像、因子和标签。

### 5.5 验收标准

- 数据明显不足时，3 秒内返回阻断结果；
- 当前生产数据必须准确显示 main_inflow_5d_ratio 覆盖为 0；
- 未就绪时不创建 Ridge 模型记录；
- readiness 结果与真实训练样本审计误差不超过 1%。

## 6. Phase B：核心数据覆盖提升

### 6.1 两级股票池策略

免费接口条件下，不直接对 5,000 多只股票逐日高频抓取全部昂贵接口。

采用：

1. 训练池：300～500 只高流动性、非 ST、上市时间充足的股票。
2. 评分池：现有全市场股票池；因子不足时继续使用 manual，不强制 Ridge。

训练池每月冻结一个版本，选取规则必须只使用当时可见的本地日线：

- 过去 60 日平均成交额；
- 上市天数；
- 停牌比例；
- ST 和退市风险状态；
- 价格与成交活跃度。

不得用未来是否退市、未来市值或当前最终成分回填历史股票池。

### 6.2 估值数据

目标：

- 训练池估值历史覆盖率第一阶段达到 50%；
- 第二阶段达到 70%；
- 日常估值快照覆盖率达到 90%。

实施：

- 全市场当日估值优先使用单次批量行情快照；
- 历史 PE/PB 使用 stock_a_indicator_lg 按训练池逐股回填；
- 每只股票保存独立水位和失败原因；
- 每次网络请求保持随机休眠和接口级退避；
- 失败任务支持从股票水位继续，不重复抓取已完成股票；
- 估值不得超过配置的新鲜度后继续向前填充。

### 6.3 财报与 ROE

目标：

- 训练池至少具有最近 8 个季度；
- 同期 ROE 配对覆盖率达到 70%；
- 公告日和报告期字段完整率达到 99%。

实施：

- 财报任务从自选股前 20 只扩展为训练池分批任务；
- 以公告日作为 point-in-time 可见时间；
- 同一报告期多版本公告保留历史版本；
- 同比计算必须匹配上年同期，不使用简单上一期替代；
- 财报抓取按周运行，失败不阻塞日常行情流水线。

### 6.4 主力资金

目标：

- 训练池过去 120 个交易日覆盖率达到 70%；
- 最近 5 日覆盖率达到 90%。

实施：

- 使用 stock_individual_fund_flow 按训练池逐股回填；
- 一次接口返回的完整历史序列批量入库；
- 分清“真实净流入为 0”和“接口缺失”，缺失不得写 0；
- 远端断开时记录 provider_error，并保留前次有效数据；
- 连续 5 日不足时 main_inflow_5d_ratio 保持缺失；
- 在资金接口持续不可用时，本轮模型自动排除该因子，而不是删除全部样本。

### 6.5 数据任务调度

建议默认计划：

| 任务 | 频率 | 默认状态 |
|---|---|---|
| 全市场当日估值快照 | 每日 16:20 | 开启 |
| 训练池估值历史补齐 | 周六 09:00 | 初次手工开启 |
| 训练池财报补齐 | 周六 10:00 | 开启 |
| 训练池主力资金补齐 | 每日 16:40 | 分批开启 |
| 训练就绪度刷新 | 每日 17:10 | 开启 |
| 周度 Ridge | 周六数据补齐后 | readiness 达标后开启 |

### 6.6 风控

- 单次任务设置最大股票数和最大运行时长；
- 每个接口独立限速，不允许并发轰炸免费数据源；
- 三次连续失败后暂停该接口当日请求；
- 原始响应哈希和接口版本必须保存；
- 严禁在回测或调参过程中访问外网。

## 7. Phase C：样本构造与 Ridge 有效性

### 7.1 动态特征准入

每次训练按实际覆盖决定特征准入：

| 覆盖率 | 处理 |
|---:|---|
| 0%～30% | 排除本轮模型，记录 blocked_feature |
| 30%～70% | 只允许研究训练；使用批准的截面填充和缺失指示变量 |
| 70% 以上 | 可进入正式候选 |

最低要求：

- 至少 3 个特征；
- 至少覆盖 fundamental、capital_flow、sentiment 中的 2 类；
- turnover_z20 不能成为唯一有效特征；
- 特征集变化必须生成新的 feature manifest 和模型 ID。

### 7.2 缺失处理规则

允许：

- 同一交易日、同一行业的截面中位数；
- 行业样本不足时回退到当日全市场中位数；
- 每个被填充特征新增 missing indicator；
- 所有填充结果设置 is_imputed 和 imputation_method；
- 训练与验证必须复用相同的、只基于当时数据的规则。

禁止：

- 覆盖为 0 的因子批量填 0；
- 使用未来日期的中位数；
- 对稀疏事件因子做连续前向填充；
- 将接口失败解释为真实业务数值 0。

### 7.3 样本审计

每个模型保存：

- 原始股票日数量；
- 标签过滤后数量；
- 各因子缺失数量；
- 完整样本数量；
- 填充后样本数量；
- 因停牌、涨跌停、未来窗口不足而剔除的数量；
- 训练、验证各自股票数和交易日数；
- 每个特征的实际版本、覆盖率和填充比例。

### 7.4 时间验证升级

将当前时间切分升级为 Purged Walk-Forward：

- 训练窗口 250 日；
- 验证窗口 50 日；
- T+5 标签在训练和验证之间设置至少 5 个交易日 purge gap；
- 不允许训练标签的退出日进入验证区间；
- alpha 不能只按总体 MSE 选择；
- 同时统计每日截面 Rank IC、IC 均值、ICIR、MSE 和 R²；
- 主要选择指标使用验证期每日截面 IC 均值，MSE 作为辅助约束。

### 7.5 发布门禁建议

| 指标 | 研究候选 | 正式候选 |
|---|---:|---:|
| 样本数 | 10,000 | 30,000 |
| 股票数 | 100 | 200 |
| 交易日数 | 120 | 200 |
| 验证交易日 | 40 | 50 |
| 平均 Rank IC | 大于 0 | 不低于 0.01 |
| ICIR | 可记录 | 不低于 0.20 |
| 分层多空收益 | 可记录 | 扣成本后为正 |
| 系数稳定性 | 可记录 | 不得频繁翻转 |

门禁最终数值必须通过回测和 Shadow 结果再校准，不应在没有样本证据时直接写死为生产标准。

## 8. Phase D：增量计算与 DuckDB 仓库治理

### 8.1 SQL 日期下推

当前因子引擎先加载完整历史面板，再在 Pandas 中按 start_date 和 end_date 过滤。

改造为：

- 日常计算只查询目标日期；
- turnover_z20 额外读取前 20 个交易日作为预热；
- main_inflow_5d_ratio 额外读取前 5 个交易日；
- 财报查询读取目标日期之前已公告的最新期和上年同期；
- 估值只读取目标日可见的最近有效快照；
- 日期范围直接进入 DuckDB SQL WHERE 条件。

### 8.2 有效行存储

当前 15,717,080 行中只有 1,860,712 行 eligible，约 88% 为无效空值。

建议：

- 历史 factor_values 只保存 eligible 或明确执行过填充的行；
- 缺失数量、覆盖率和原因保存到 factor_batch_stats；
- 最新截面可以保存完整诊断视图，历史不重复保存全量空行；
- 稀疏事件因子仅保存真实事件日；
- 模型禁用因子不参与 550 天全量历史物化，除非有解释或回测需求。

预计可将单批历史因子明细减少 70%～88%。

### 8.3 增量批次

- 日常流水线只生成最新交易日的新 calc batch；
- 周度训练复用过去已验证的 immutable 因子批次；
- 原始数据水位、因子批次水位和标签批次水位分开管理；
- 输入没有变化时复用已有 calc_batch_id；
- full_refresh 必须显式确认，并展示预计写入量和磁盘需求。

### 8.4 保留与清理

增加仓库维护任务：

1. 保留所有活动模型及其引用批次；
2. 保留最近 5 个成功周度训练批次；
3. 保留最近 20 个日常评分批次；
4. rejected 且未被回测引用的中间批次保留 30 天；
5. 删除前先建立 dependency 清单；
6. 清理后执行 DuckDB CHECKPOINT；
7. 设置页提供预览、执行、释放空间和审计记录；
8. 不允许删除被模型、回测、评分或解释快照引用的批次。

### 8.5 性能目标

| 场景 | 目标 |
|---|---:|
| 单交易日非训练流水线 | 小于 3 分钟 |
| 550 天周度训练 | 小于 10 分钟 |
| 取消响应 | 小于 10 秒 |
| 日常 DuckDB 净增长 | 小于 100 MB |
| 周度训练净增长 | 小于 300 MB |
| 相同输入重复运行 | 不产生重复物理数据 |

## 9. Phase E：任务控制与产品可观测性

### 9.1 可取消阶段

当前心跳可以证明任务仍在工作，但因子计算、标签计算和 Ridge 拟合仍只能在阶段结束后检查取消。

优化：

- 因子标准化按交易日块处理；
- 标签按日期块处理；
- 每块完成后检查 cancellation；
- Ridge 候选 alpha 之间检查 cancellation；
- 对 DuckDB 长 SQL 评估 connection.interrupt；
- 无法安全中断时显示“正在安全结束当前批次”；
- 取消后必须关闭 DuckDB 连接并释放文件锁。

### 9.2 细粒度进度

统一进度事件：

| 字段 | 说明 |
|---|---|
| stage | 当前阶段 |
| substage | 当前子阶段 |
| processed | 已处理数量 |
| total | 总数量 |
| throughput | 行/秒或股票/秒 |
| heartbeat_at | 最近心跳 |
| stage_started_at | 阶段开始时间 |
| stage_eta_seconds | 阶段 ETA |
| overall_eta_seconds | 总 ETA |

阶段建议：

- readiness；
- universe_mirror；
- business_mirror；
- factor_inputs；
- factor_calculation；
- target_generation；
- ridge_training；
- score_materialization；
- cleanup。

### 9.3 错误展示

页面不再直接显示完整 SQL 和数百个参数。

用户层错误示例：

    MySQL 连接在读取第 41 个行情批次时中断，系统已重试 1 次。
    已完成批次会保留，可点击“从断点重试”。

技术详情放入展开区：

- error_code；
- exception_type；
- stage 和 batch；
- 精简 SQL 模板；
- 参数数量，不默认展示全部参数；
- trace_id；
- 完整日志路径。

### 9.4 失败续跑

- 镜像失败：从股票批次水位续跑；
- 因子计算失败：从日期批次续跑；
- 训练失败：复用已完成因子和标签批次；
- 模型门禁拒绝：标记 rejected，不归类为系统失败；
- 用户可以选择“仅重试失败阶段”或“重新完整运行”。

## 10. Phase F：Shadow、回测与正式发布

### 10.1 Shadow 前置条件

- readiness 为绿色；
- Ridge 状态 validated；
- 核心因子覆盖满足正式门禁；
- 无未来数据泄漏；
- 训练池版本和特征 manifest 可追溯；
- VectorBT 和事件驱动回测均能固定模型版本复现。

### 10.2 回测验收

至少输出：

- manual 与 ridge 同期对照；
- 沪深 300 或中证 500 基准；
- 年化收益、夏普、最大回撤；
- 换手率、佣金、印花税、滑点；
- Top-N 分层收益；
- 行业暴露和单股集中度；
- 因子贡献、系数轨迹和稳定性；
- 严格历史可见性检查结果。

### 10.3 影子观察

至少持续 20 个交易日：

- 每日记录模型 Top-N 与 manual Top-N 差异；
- 记录预测分数、实际 T+5 回报和复盘结论；
- 记录因子覆盖波动和数据源失败；
- 不自动生成真实交易指令；
- 任一核心数据源连续异常时保持上一有效模型。

### 10.4 激活与回滚

激活必须由用户人工执行。

立即回滚条件：

- 核心因子覆盖低于 70%；
- 模型 IC 连续显著恶化；
- 数据截止日异常；
- 活动模型解释缺失；
- 评分批次与模型版本不一致；
- 回测或实时评分出现未来可见性问题。

回滚动作：

1. 将 weight_mode 切回 manual；
2. 保留 Ridge 模型和失败批次供审计；
3. 停止周度 Ridge 计划；
4. 不删除历史 Score、扫描和交易计划记录；
5. 记录原因、操作人和时间。

## 13. 测试矩阵

### 13.1 数据正确性

- 财报只能在 announcement_date 当日及以后可见；
- 估值新鲜度超过限制后不得继续填充；
- 资金流缺失不得写成 0；
- 训练和验证缺失填充不得使用未来截面；
- T+5 标签必须满足退出日不晚于 data_cutoff_date；
- purge gap 必须覆盖标签持有期。

### 13.2 模型测试

- 覆盖为 0 的因子自动退出本轮特征；
- 少于 3 个可用特征时阻止训练；
- feature manifest 改变时模型 ID 改变；
- 同一输入重复训练结果可复现；
- 每日 Rank IC 计算按交易日分组；
- rejected 不得自动激活。

### 13.3 性能测试

- 单日数据范围不加载 550 天完整面板；
- 10,000 行批量写入不退化为逐行写入；
- 重复运行不增加重复物理行；
- 清理任务不删除活动模型依赖；
- 任务取消后 DuckDB 文件锁释放。

### 13.4 黑盒测试

- 数据不足时页面明确阻止训练；
- 数据达标后允许训练；
- 进度至少每 15 秒有心跳；
- 取消任务后按钮和状态正确；
- 失败信息不显示超长 SQL 参数；
- 从断点重试后任务可以完成；
- 页面时间与本地时区一致。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 免费逐股接口耗时过长 | 补齐任务数小时 | 两级股票池、周度补齐、独立水位、严格限速 |
| 接口历史字段变化 | 覆盖突然下降 | 字段契约、原始响应、schema 探测、健康告警 |
| 动态特征导致模型不可比 | 权重轨迹解释困难 | 保存 feature manifest，按特征集分组比较 |
| 缺失填充引入伪信号 | 回测虚高 | 缺失指示变量、填充比例门禁、消融实验 |
| 训练池带来流动性偏差 | 泛化到全市场变差 | 明确适用范围，分池回测，逐步扩大 |
| 仓库清理误删历史 | 回测不可复现 | dependency 预览、活动引用保护、审计与备份 |
| 取消中断写事务 | 水位与数据不一致 | 数据和水位同事务提交，批次完成后再推进 |
| 过度追求 IC | 实盘换手和成本过高 | 同时约束换手、成本后收益和最大回撤 |

## 15. 最终验收标准

### 15.1 数据验收

- 训练池不少于 300 只；
- 历史不少于 120 个交易日，正式候选不少于 200 日；
- 实际入模因子覆盖率均不低于 70%；
- 标签覆盖率不低于 90%；
- 公告日、数据截止日和模型可用日检查全部通过。

### 15.2 模型验收

- 样本数不少于 30,000；
- 股票数不少于 200；
- 验证交易日不少于 50；
- 平均 Rank IC 不低于 0.01；
- ICIR 不低于 0.20；
- 成本后分层收益为正；
- 无系数全零、非有限或高频翻转；
- 所有特征和缺失策略可解释。

### 15.3 工程验收

- 日常流水线小于 3 分钟；
- 周度训练小于 10 分钟；
- 取消响应小于 10 秒；
- 失败支持断点或阶段续跑；
- DuckDB 增长满足预算；
- 全部白盒、前端、黑盒和历史可见性测试通过。

### 15.4 产品验收

- 设置页可在训练前看懂“为什么能训练或为什么不能训练”；
- 任务运行时可以看到阶段、吞吐、心跳和 ETA；
- 错误摘要简洁且技术详情可展开；
- 模型只能人工激活；
- manual 一键回退可用且不丢历史记录。

## 16. 推荐的立即执行顺序

第一批开发只做以下四项，不并行扩展新因子：

1. training_readiness 服务、API 和设置页卡片；
2. Ridge 样本过滤漏斗与实际特征 manifest；
3. 覆盖为 0 的因子自动阻止入模，禁止盲目填 0；
4. 训练池定义及估值、财报、资金流补齐任务。

完成第一批后，使用真实数据重新运行一次 readiness。只有满足最低训练条件，才进入动态特征、Purged Walk-Forward 和仓库治理。

## 17. Definition of Done

本后续优化完成必须同时满足：

- 系统不会再产出 sample_count=0 但耗时数分钟的无意义训练；
- 用户在训练前即可看到完整阻断原因；
- 至少一个版本化训练池达到数据覆盖门禁；
- Ridge 能生成具有真实样本、真实权重和验证指标的候选；
- 因子历史严格遵守时间可见性；
- DuckDB 不再因重复空因子行无限膨胀；
- 日常任务、周度训练、取消、续跑和回滚均完成真实环境验收；
- 正式决策保持 manual，直到 Shadow 和回测验收完成并由用户人工激活。
