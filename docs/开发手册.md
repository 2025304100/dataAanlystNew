## 1. 项目定位与能力地图

**Personal Quant Workbench（个人量化工作台）** 是一套面向个人投资者的量化投研与模拟交易系统，覆盖从数据采集到交易决策的完整闭环。

| 能力域 | 说明 | 主要入口 |
|--------|------|----------|
| 基础数据 | 全市场标的池（universe）、日线/指数/财务/资金流同步，多源降级 | `universe.py` `market_data.py` `external_data.py` |
| 因子中心 | 受控 DSL 公式编辑、因子编译执行、评估/压力测试、影子观测、Ridge 模型 | `factors/*`（42 个模块） |
| 综合评分 | 6 维加权评分（趋势/动量/波动/流动性/活跃/题材），预设可按资产类型切换 | `scoring_config_engine.py` |
| 机会发现 | 脏集合增量扫描、阶段预算与超时、快筛 → 候选池 | `discovery_*.py` |
| 标的研究 | 单标的 K 线/因子解释/风险参考/回测/交易计划/关联标的 | 前端 `symbol-research/` |
| 决策引擎 | 11 步统一编排，证据链与订单计划全量落表 | `decision_engine.py` |
| 组合交易 | 成员管理、七态治理、模拟撮合、自动交易、守恒对账、净值快照 | `portfolio_*.py` |
| 回测 | 条件树 v2 / 扁平条件 v1 双形态，vectorbt 引擎，过滤治理（BFG） | `backtest.py` `vectorbt_backtest.py` `backtest_filters/` |
| 通知中心 | Outbox 异步投递，6 类渠道，模板/策略/免打扰 | `notifications/` |
| AI 助手 | 多 Profile 主备降级、结构化输出、7 类工具、草案确认流、审计留存 | `ai/` |
| 任务与调度 | 异步任务状态机 + 跨平台持久化调度器（9 类周期任务） | `async_tasks.py` `scheduled_tasks.py` |
| 设置中心 | 数据库切换、评分配置、自定义指标、API 管理、通知、AI 配置 | 前端 `Settings.tsx` |

**前端一级导航**（`src/App.tsx`）：今日决策 · 组合交易 · 机会中心 · 宏观数据 · 行情消息 · 设置。
右上角常驻通知中心与帮助菜单，全局浮动 AI 助手抽屉（`AIAssistant`）。

## 4. 架构总览

五层单向依赖，箭头方向即允许的依赖方向，**禁止反向引用**：

```
展示层 (React)  →  接入层 (FastAPI /api/v1)  →  业务服务层  →  数据与调度层  →  存储与外部源
```

详见 [架构图](./架构图.html)，其中含：

1. 总体分层架构（五层 + 每层模块）
2. 核心业务链路 7 步（采集 → 因子 → 评分 → 发现 → 决策 → 交易 → 回测/通知）
3. 后端模块地图（因子域 / 机会发现 / 组合交易 / 横切能力）
4. 运行时生命周期（启动 4 步 / 关闭 4 步 + 调度任务表）
5. 外部数据网关 L1–L4 缓存与治理
6. 测试与交付体系

**核心业务链路**

| 步骤 | 产物 | 关键模块 |
|------|------|----------|
| 01 数据采集 | `daily_bars` `index_prices` `stock_valuations` | `universe_sync` `market_data` `external_data_gateway` |
| 02 因子流水线 | DuckDB 因子面板 + `factor_runtime` | `factors/pipeline_task`（mirror→factors→targets→train→score） |
| 03 综合评分 | `scores` 表 6 维加权 | `scoring_config_engine` `factors/scoring_bridge` |
| 04 机会发现 | 候选池 / 扫描记录 | `discovery_dirty_set` `discovery_fast_scan` |
| 05 决策引擎 | `decision_runs` `decision_evidence` `decision_order_plan` | `decision_engine`（11 步） |
| 06 组合交易 | 持仓 / 成交 / 对账 | `portfolio_members` `simulation_matching_engine` |
| 07 回测通知 | 绩效归因 + Outbox 投递 | `vectorbt_backtest` `notifications/dispatcher` |

## 5. 后端分层与职责

### 5.1 接入层（`app/main.py`）

- 应用工厂：`FastAPI(title="Personal Quant Workbench API", version="0.1.0", lifespan=lifespan)`
- 路由总装：`app.include_router(api_router)`，前缀 `settings.api_prefix = /api/v1`
- 中间件：`DeprecationLogMiddleware`（命中废弃端点时加 `Deprecation`/`Sunset`/`Link` 头并落 `api_deprecation_logs`）
- 全局异常处理器（7 个），全部收敛为统一 `UserError`：

| 异常 | 错误码 | HTTP |
|------|--------|------|
| `UnifiedErrorException` | 业务自定义 | 自带 |
| `RequestValidationError` | `VALIDATION_ERROR` | 422 |
| `SQLAlchemyError`（Operational） | `DB_CONNECTION_FAILED` / `DB_LOCK_TIMEOUT` | 503 |
| `IntegrityError` | `DB_INTEGRITY_VIOLATION` | 409 |
| `HTTPException` | 按状态码映射（409→`BUSINESS_BLOCKED`，503→`CAPABILITY_BLOCKED` 等） | 原样 |
| `CircuitBreakerOpenError` | `CIRCUIT_BREAKER_OPEN` | 503 |
| `DataValidationError` / `StaleDataError` | `DATA_VALIDATION_FAILED` / `STALE_DATA` | 422 / 503 |
| 兜底 `Exception` | `UNKNOWN_ERROR` | 500 |

- 静态与 SPA：`/static` 挂载；`/`、`/workbench`、`/{full_path}` 优先代理到 5173 开发服务器（TTL 1s 探测），否则回落到 `app/web/dist/index.html`。
- 健康检查：`GET /health` → `{"status": "ok"}`。

### 5.2 路由层（`app/api/routes/`）

46 个模块，按领域拆分，`router.py` 统一 `include_router(...)` 并打 tag。
详细 tag 见 [第 7 节](#7-api-约定)。

### 5.3 服务层（`app/services/`）

120 个模块，纯 Python 业务逻辑，**不感知 HTTP**。约定：

- 全部接收 `db: Session` 作为首个/前部参数，由路由注入
- 跨领域调用必须走防腐门面（如 `app.services.factors.__facade__`），禁止直连他域内部 ORM
- 长任务走 `async_tasks`（线程执行器 + 状态机），不在请求线程内跑分钟级计算
- 业务侧不直接发通知，只写 Outbox（`governance_outbox` / `notifications/outbox`）

### 5.4 数据与调度层

- `external_data_gateway`：统一外部数据入口，L1 进程缓存 → L2 业务库 → L3 DuckDB → L4 第三方；单飞 + 三维限流 + 熔断 + 降级
- `async_tasks` + `task_state_machine`：任务状态持久化，30 分钟无更新判僵死
- `scheduled_tasks`：跨平台持久化调度器，`TASK_DEFINITIONS` 定义 11 类任务类型
- `notifications/dispatcher`：lifespan 内 `asyncio.to_thread(dispatcher.run_once)` 轮询投递

## 6. 数据层：模型、连接与迁移

### 6.1 连接管理：`DatabaseManager`

`app/db/manager.py` 单例，支持运行时热切换 SQLite ↔ MySQL。

**优先级（`main.initialize_runtime_database()`）**：

1. 环境变量 `DATABASE_URL`（最高优先级，隔离测试/预览进程，避免误连共享 MySQL）
2. `config/db_config.json` 中 `use_mysql=true` 且配置了 host → 构造 `mysql+pymysql://...`
3. 兜底 `settings.database_url` → SQLite，默认路径 `%TEMP%/quant_workbench.db`（Linux/macOS 为 `/tmp/quant_workbench.db`）

> 切库后需重启进程；`DatabaseManager.dispose()` 在 lifespan 关闭时释放引擎。

### 6.2 模型分组（66 个模型 / 108 张表）

| 分组 | 代表模型 |
|------|----------|
| 基础数据 | `symbol` `universe` `daily_bar` `index_price` `financial_report` `stock_valuation` `capital_flow` `etf_indicator` |
| 评分与信号 | `score` `scan` `signal_rule` `trade_setup` `scoring_config` `discovery_score_snapshot` |
| 因子域 | `factor` `factor_model` `factor_runtime` `factor_evaluation` `factor_governance` `factor_weight_snapshot` `factor_sets`（见 `factor_*.py`） |
| 机会发现 | `discovery` `discovery_candidate` `discovery_plan` `opportunity_transition_event` |
| 组合交易 | `portfolio` `portfolio_member` `portfolio_candidate` `portfolio_equity_snapshot` `portfolio_factor_usage` `sim_account` `position` |
| 回测 | `backtest` `backtest_filter_event` `strategy_execution_snapshot` |
| 决策 | `decision_engine`（DecisionRun / DecisionEvidence / DecisionOrderPlanRecord / ManualPriceOverride） |
| 任务 | `async_task` `scheduled_task` `portfolio_cron_schedule` |
| 通知 | `notification`（Outbox / Channel / Policy / Template / Delivery） |
| AI | `ai_profile` `ai_session` |

### 6.3 初始化：`init_db()`

启动时执行，包含三类动作：

1. `Base.metadata.create_all` 建表
2. `_auto_align_all_schema`：针对 SQLite/MySQL 差异自动补列（如 `_ensure_sqlite_portfolio_columns`）
3. `_auto_repair_basic_data_integrity` + 种子数据（核心自选股列表等）

> **注意**：`init_db` 是「自动对齐」而非迁移，正式 schema 变更仍应写 Alembic 迁移。

### 6.4 迁移：Alembic

```bash
# 生成迁移（autogenerate 后务必人工校对）
alembic revision --autogenerate -m "描述"

# 升级 / 回滚
alembic upgrade head
alembic downgrade -1

# 查看历史
alembic history
```

- 配置文件：`alembic.ini`；脚本目录 `alembic/versions/`
- 现有迁移按 `2026_08_17_00XX_wps_XXXX_*.py` 编号，覆盖 external endpoint、daily_bar、factors、portfolio_members、notification、ai_session、async_tasks 等
- 有专门的链路测试：`tests/test_migration_alembic_chain.py`

### 6.5 因子数仓：DuckDB

- 路径：`FACTOR_WAREHOUSE_PATH`，默认 `<repo>/tmp/factor_warehouse.duckdb`
- `SCHEMA_VERSION = "3"`
- DuckDB 支持多读者但**单写者**，所有写入通过 `warehouse_locks` 串行化
- 关闭时 `shutdown_factor_warehouse_pools()` 释放连接池

### 7.3 统一错误响应

所有错误均返回同一结构：

```json
{
  "error_code": "VALIDATION_ERROR",
  "user_message": "参数校验未通过",
  "impact": "本次请求未执行",
  "next_actions": [{"label": "修改后重试", "action_type": "retry", "reason": "请按提示修正输入参数"}],
  "correlation_id": "a1b2c3d4",
  "technical_details": {"exception_type": "...", "status_code": 422, "error_message": "..."}
}
```

- 前端默认展示 `user_message`，`technical_details` 折叠
- `correlation_id` 用于日志检索

### 8.2 评分（`scoring_config_engine.py`）

`calculate_symbol_score(db, symbol, trade_date)` 委托 `calculate_symbol_score_with_config`，按 `symbol.asset_type` 取激活预设；无预设时回退 `_legacy_calculate_symbol_score`（硬编码）。

### 8.3 机会发现（`discovery_*.py`）

- `discovery_dirty_set`：维护脏集合，只重算发生变化的标的
- `discovery_stage_budget`：阶段预算与超时熔断，防止长尾任务拖垮整轮扫描

### 8.4 组合与交易（`portfolio_*.py`）

- `portfolio_members`：成员 CRUD，**删除默认归档**（置 `effective_to`）而非物理删除；有持仓时提示「仅停止买入」或先卖出
- `portfolio_state_machine` / `portfolio_fsm`：七态治理（含 reconcile / confirm-reconciliation / transition-state）

### 8.5 决策引擎（`decision_engine.py`）

G1-WP0-3a 引入的统一编排层，采用「新增编排 + 旧服务 adapter」方式，不重写四个旧服务。

### 8.6 回测

### 8.7 通知（`notifications/`，14 个模块）

## 10. 日常开发 SOP

### 10.1 新增一个业务接口

1. **写/改模型**：`app/models/xxx.py`，继承 `Base`，定义 `__tablename__`
2. **写 Schema**：`app/schemas/xxx.py`（Pydantic v2），请求/响应分离
3. **写服务**：`app/services/xxx_service.py`，接收 `db: Session`，不引入 FastAPI
4. **写路由**：`app/api/routes/xxx.py`，`APIRouter(prefix=..., tags=[...])`，用 `Depends(get_db)` 注入会话
5. **注册路由**：`app/api/router.py` 中 `include_router`
6. **写迁移**：`alembic revision --autogenerate -m "..."` → 人工校对 → `alembic upgrade head`
7. **写测试**：`tests/test_whitebox_xxx.py`（标记 `@pytest.mark.whitebox`）+ 必要时 `test_blackbox_*.py`
8. **前端联调**：`frontend/src/api` 增加请求函数 → 组件调用 → 补 Vitest 用例

### 10.2 新增一个定时任务

在 `app/services/scheduled_tasks.py` 的 `TASK_DEFINITIONS` 中登记 `task_type / name / description / default_payload`，并在调度执行分支中挂接实际执行函数；如需随版本预置，加入 `DEFAULT_SCHEDULES`（注意 bump `DEFAULT_SCHEDULE_SEED_KEY`）。

### 10.3 新增一个通知渠道

在 `app/services/notifications/` 下新增适配器（继承 `base.py` 的 Channel 基类，实现 `channel_type` 与发送逻辑），在 `registry.py` 注册，并补 `policies` / `channel_state` 相关分支。

### 10.4 新增一个前端业务组件

- 放 `src/components/<domain>/`，跨页复用才上提到 `src/components/` 根
- 文案一律走 `src/i18n`（`t("key")`），**禁止硬编码中文**
- 数字/日期格式化统一用 `src/utils/format.ts`
- 错误展示统一用 `src/utils/errorRender.ts`（解析 UserError 的 `next_actions`）
- 必须补 `src/components/<domain>/__tests__/` 下的 Vitest 用例

### 10.5 修改数据库 schema

1. 改 ORM 模型
2. `alembic revision --autogenerate -m "..."` → **人工校对**（autogenerate 对 SQLite 支持有限）
3. 若涉及 SQLite 存量库，同时在 `app/db/init_db.py` 补 `_ensure_sqlite_*_columns` 兜底
4. 跑 `pytest tests/test_migration_alembic_chain.py`
5. 备份：`python scripts/db_backup.py`

## 11. 编码规范与硬约束

### 架构约束（必须遵守）

1. **层间单向依赖**：路由 → 服务 → 数据；服务层不得 import 路由层
2. **因子域防腐**：域外禁用 `app.models.factor_*`、`app.services.factor_set_service`、`factor_usage_service`，只能走 `app.services.factors.__facade__`
3. **错误归一**：所有对外异常必须收敛为 `UserError`，禁止把原始堆栈直接抛给用户
4. **脱敏**：密码 / API Key / Webhook / SMTP 出现前必须过 `sanitize_message`；MySQL 连接错误不得暴露明文密码
5. **事务**：关键数据操作必须 `commit` 后再继续后续处理
6. **第三方依赖软失败**：akshare / sklearn 未安装时用 MagicMock stub（见 `tests/conftest.py`），不得阻断 `import app.main`
7. **消息语言**：后端日志与异常消息用英文；前端展示用 `t()` 国际化
8. **哈希稳定**：`normalized_params` 必须先排序 dict 再哈希

### 风格约定

- Python：类型注解齐全（`from __future__ import annotations`）；模块顶部写中文 docstring 说明职责与来源（规范/工单号）
- 时间：统一 UTC naive（`utcnow_naive()` / `utc_naive_to_shanghai()`），禁止混用本地时间
- 命名：路由文件名与领域一致；服务 `<domain>_service.py` 或 `<domain>.py`；测试 `test_whitebox_<domain>.py` / `test_blackbox_<domain>.py`
- 前端：函数组件 + hooks；一级 Tab 状态放 `AppContext`；`data-settings-content` 等 `data-*` 属性用于测试选择器与深链定位
- 提交：pre-commit 自动跑白盒 + 前端测试（`.pre-commit-config.yaml`），提交前必须绿

## 15. 常见坑与排错

| 现象 | 原因 / 处理 |
|------|-------------|
| 启动后连到了共享 MySQL | 环境变量 `DATABASE_URL` 优先级最高；测试/预览进程务必显式设置，否则会读 `config/db_config.json` |
| 默认库「不见了」 | 未配置时 SQLite 落在系统临时目录（`%TEMP%/quant_workbench.db`），清临时文件会丢库；生产请显式配置 `DATABASE_URL` 或切 MySQL |
| DuckDB `lock` 报错 | DuckDB 单写者；确认无多进程写同一 warehouse；用 `diagnose_warehouse_lock()` 定位，必要时删除残留锁 |
| 因子流水线卡住 | 启动时 `recover_stale_pipeline_tasks` 会恢复；长期卡死检查 stage budget 与 worker 线程 |
| 导入报 `NoReferencedTableError` | 测试里未显式 import 相关 ORM 模块，参考 `tests/conftest.py` 的显式导入清单 |
| 测试收集阶段 `RuntimeError`（因子域） | 触发了防腐层导入门禁，改用 `app.services.factors.__facade__` |
| 前端白屏 / 404 | 未构建：`npm run build` 生成 `app/web/dist`；开发态确认 5173 已启动（后端 1s TTL 探测代理） |
| `/api` 404 | 确认路径前缀是 `/api/v1` |
| 通知没发出去 | 业务只写 Outbox，投递靠 lifespan 内的 dispatcher；检查 `poll_interval`、渠道配置与 `anti_disturb` 免打扰窗口 |
| 净值曲线断档 | `portfolio_equity_snapshot` 是每日快照，**历史不可回溯**，务必保持调度任务开启 |
| 回测结果不可复现 | 检查是否启用了 `portfolio_backtest_snapshot` 冻结；数据源变更会导致漂移 |
| 定时任务没跑 | 调度器由 lifespan 托管，进程重启后恢复；检查 `scheduled_task` 表 enabled 与 seed 状态 |
