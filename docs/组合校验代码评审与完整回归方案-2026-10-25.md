### 4.9 数据库验收SQL与无丢行校验

完整分阶段只读 SQL 见同目录 **`组合校验迁移验收-2026-10-25.sql`**。必须先在生产规模副本执行并保存输出；迁移前/后/重启后各一次。SQL文件无修数据操作，迁移前缺 `id` 时不要执行标为“0081之后”的区块。

```sql
-- 先核身份；预期为批准的实例/副本，版本以现场值为准。
SELECT DATABASE() AS db_name, @@hostname AS server_host, @@port AS server_port,
       VERSION() AS db_version, @@sql_mode AS sql_mode, @@tx_isolation AS isolation_level;
SELECT version_num FROM alembic_version;

-- 同组合同标的至多一个未闭合版本；预期0行。
SELECT portfolio_id, symbol_id, COUNT(*) AS current_count
FROM portfolio_members
WHERE effective_to IS NULL
GROUP BY portfolio_id, symbol_id
HAVING COUNT(*) > 1;

-- 必须精确比较，避免MySQL大小写不敏感/尾空格比较掩盖脏值；预期0行。
SELECT id, portfolio_id, symbol_id, status, execution_mode, effective_to
FROM portfolio_members
WHERE status IS NULL OR BINARY status NOT IN ('active','paused','archived')
   OR execution_mode IS NULL OR BINARY execution_mode NOT IN ('manual','confirm','auto')
   OR (status='archived' AND effective_to IS NULL)
   OR (status<>'archived' AND effective_to IS NOT NULL);

-- 0082后预期datetime_precision=6；这不证明旧回执挂接成功。
SELECT column_name, column_type, is_nullable, datetime_precision
FROM information_schema.columns
WHERE table_schema=DATABASE() AND table_name='security_status_daily'
  AND column_name='source_updated_at';
```

**COUNT相同不代表没有丢行，SUM相同不代表关键字段没丢。** 配套只读工具 `scripts/review_migration_integrity.py` 对迁移前所有业务表的**全部旧列**按原主键顺序流式计算SHA-256，并记录逐列NULL数量；升级后继续用原列/原键比较，幂等表新增id不影响按旧key核对。旧表/旧列缺失直接失败，无主键表直接要求人工方案，不会静默跳过；只排除允许变化的 `alembic_version`。新增表/列仍需SQL/ORM契约验证，该工具不代替结构校验，也不代替可恢复备份。
