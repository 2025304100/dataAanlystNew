# AI 助手功能评估与布局优化方案

> 评估日期：2026-10-25 · 评估人：阿沃 · 性质：只读排查评估（未改动任何代码）
> 证据基线：代码走查 + MySQL 实测 + Playwright 五视口实测 + DOM 探针 + vitest 8/8 复跑

---

## 一、结论（TL;DR）

**功能成熟度：骨架完整、闭环可用、产品化不足——处于「能用的内部工具」到「好用的产品功能」之间的过渡带。**

1. **已闭环的主链路**：Profile 配置 → 会话创建 → SSE 流式对话 → 结构化响应（answer/证据/警告/建议/草稿/元数据）→ 审计 → 90 天保留期。全链路有测试（8/8 绿）、有真实使用记录（库内 14 个会话 / 43 条消息 / 61,990 tokens）。
2. **三套 AI 表面共用一套底座**：全局助手（对话抽屉）、公式 AI（指标/因子编辑器内嵌）、挖掘 AI 生成（GA 骨架）——都走 AIProfile + 主备降级。
3. **三个明确的"半成品"**：
   - **工具调用层空转**：`TOOL_REGISTRY` 注册了 7 个只读工具（能力门禁/数据健康/任务状态/标的研究/候选解释/组合摘要/回测解释），但**只被测试引用，从未接入对话主链路**——AI 每轮只能拿预构建的 context pack，不能按需取数，实质是「单轮 RAG」，不是 Agent。
   - **草稿三步确认只接通 1/7**：7 种草稿（indicator/factor/filter/alert/note/review/order）后端齐备，前端只有 `draft_factor` 有确认 UI；库内 3 条审计全是 `draft_note` 且 `user_confirmed=0`——**从未被确认执行过**。
   - **两套 AI 配置体系并存**：全局助手用数据库 AIProfile；公式 AI 用 `config/ai_config.json` 文件配置。用户配了两处、行为不一致，是明确的架构分裂。
4. **布局结论**：抽屉是「桌面优先」的固定 520px 设计，平板（768px）上吞掉 68% 屏幕且会话列表被裁到只剩 2 条；缺停止生成、缺滚动锁、缺空状态引导、输入区浪费一行。优化方案见第七节，按 P0/P1/P2 分三批，P0 一批可在不动后端的前提下显著改善。

### 4.2 公式 AI（编辑器内嵌）
- 指标/因子双模式；流式回复；**公式自动抽取 + 「插入公式」按钮**；指标模式白名单校验（不在函数范围内的公式追加警告）；支持中断（AbortController）；支持清空对话；500 字上限。
- 局限：**无状态**（刷新即丢）、配置走独立 JSON 文件、无会话持久化。

### 4.3 配置与治理（设置 → AI 助手）
- Profile CRUD、测试连接、模型发现、当日用量、健康状态四卡片；
- Provider：OpenAI / OpenAI 兼容 / Ollama（须 /v1 结尾）；**Anthropic、Azure 在 UI 禁用**；
- 用途（purpose）：chat / factor_mining_ai_generate 可选；explanation、draft 禁用；
- 保留期 90 天可配（`AI_SESSION_RETENTION_DAYS`），软删归档 + 用户永久删除；
- 审计：会话审计记录（脱敏上下文摘要）。

### 4.4 真实使用画像（DB 实证，2026-10-25 只读）
- 会话 14 个：settings 11 / macro 1 / decision 1 / portfolio-inspection 1；消息 43 条（user 22 / assistant 21）；
- 累计 61,990 tokens；assistant 平均耗时 **≈13.3 秒/轮**（279,198ms ÷ 21）；
- Profile 3 个（京东云 / DeepSeek / 测试）全部 `openai_compatible`、`purpose=all`、**无一配置 is_fallback**——主备降级实际只有单链；
- 审计 3 条，全部 `draft_note`、全部未确认；
- 用户真实提问样本：「你好，你能干什么」「你是什么模型」「当前项目基础数据完整度，是个什么情况」——**以探询能力边界为主**，说明引导缺失。

## 五、功能边界与已知限制

### 5.1 能力边界（设计使然，非缺陷）
1. **只读解释型**：AI 不直连数据库、不调用第三方接口；所有数据经受控上下文包预注入。
2. **副作用三步确认**：AI 只能生成草稿；preview 校验 → 用户 confirm → execute，未确认零写入。
3. **检查类会话锁定**：portfolio-inspection 会话只能沿用原始服务端 scope，客户端上下文不能重定向（防伪造快照）。
4. **模拟订单草稿**须重过全部交易校验；**自动交易永远不由对话触发**。
5. 上下文预算默认 8192 tokens，超限按字段截断；历史消息 100 条封顶。

### 5.2 已知限制（可修复，按优先级）
| # | 限制 | 影响 | 证据 |
|---|---|---|---|
| L1 | **7 个只读工具未接入对话**（TOOL_REGISTRY 仅测试引用） | AI 不能按需取数；问「XX 股票最新数据」只能靠上下文包里预置的那一点 | `call_tool` 无生产调用点 |
| L2 | **草稿确认 UI 只通 1/7** | note/order/alert/indicator/filter/review 草稿生成了也没法确认；DB 3 条全未确认 | `FactorDraftConfirmModal` 仅 factor |
| L3 | **两套 AI 配置体系** | 全局助手配 DB Profile，公式 AI 配 JSON 文件；用户易配错地方、行为分裂 | `_load_ai_config()` vs ai_profiles |
| L4 | 无 markdown 渲染 | 回答里的列表/代码/表格以纯文本呈现（前端无 markdown 依赖） | ExplanationCard `whiteSpace: pre-wrap` |
| L5 | 无停止生成 | sending 中无法中断；输入框未禁用可再发一条排队双发 | `streamAISession` 的 signal 形参闲置 |
| L6 | 自动滚动劫持 | 每个 SSE delta 触发 scrollIntoView，上翻历史被拽回底 | `messagesEndRef.scrollIntoView` |
| L7 | 流式预览依赖模型输出 JSON | `_stream_answer_preview` 只从 `{` 开头提取 answer 字段；模型输出 markdown 围栏时预览空白直到结束 | ai_sessions.py:321 |
| L8 | 无消息级操作 | 不能复制、不能重试/重新生成、气泡无时间戳、无模型标识 | AIAssistant 渲染层 |
| L9 | 会话列表 20 条封顶 + 无搜索 | 老会话难找；settings 页公式 AI 的旧会话混入全局列表（11/14） | `getAISessions(20, 0)` |
| L10 | 平均响应 13.3s 且无进度细分 | 长等待无取消手段，体感差 | DB 实测 |
| L11 | 测试覆盖薄 | 8 个用例覆盖主链路；无流式中断、无错误恢复、无响应式用例 | AIAssistant.test.tsx |
| L12 | purpose=explanation/draft 禁用、实际 Profile 全 all | 按用途路由/限额的能力形同虚设 | AISettings 下拉 + DB 实证 |

## 六、页面布局问题清单（Playwright 五视口实测）

> 实测数据：1920/1366/1280 → 抽屉恒 520px；768 → 520px（占视口 68%）；390 → 被 antd `maxWidth:100vw` 兜底为全屏。无任何视口出现横向滚动条。

### P0 — 直接影响可用性
1. **抽屉宽度恒定 520px，无断点适配**。768px 平板上吞掉 68% 宽度，背后内容全被遮罩挡住；<520px 靠 antd 内部 `maxWidth:100vw` 被动兜底，不是设计意图。
2. **会话列表是 120px 滚动窗，且无搜索**。实测 14 个会话 × 58px = 812px，窗口只露 ~2 条；**第 2 个会话的来源标签和日期行正好被折叠线裁掉**（DOM 实测：item2  y=151–209，可见区到 ~177），截图里只剩一行标题，看起来像"半条消息"。老会话只能靠精准滚动捞。
3. **无法停止生成**。sending 期间没有停止按钮；输入框未禁用，可以再发一条（双发排队）；前端 `streamAISession(payload, handlers, signal)` 第三个形参（AbortSignal）从未被使用。
4. **自动滚动劫持**。`useEffect([messages])` 里无条件 `scrollIntoView`，流式期间每个 delta 都执行；用户上翻看历史会被持续拽回底部。

### P1 — 体验明显受损
5. **输入区竖排浪费一行**：TextArea 一行 + 「发送」按钮单独占一行右对齐。520px 宽度下这一行几乎是纯占位（实测按钮行 y=1036，输入 y=996）。
6. **空状态零引导**：「还没有消息，输入一个问题开始对话」——不告诉用户能问什么。DB 实证用户真实第一句就是「你好，你能干什么」。
7. **「新会话」入口位置不合理**：唯一入口窝在会话列表头（截图 + DOM 实证），抽屉打开后要先看到列表头才能找到；且与「历史会话」标签挤在同一行。
8. **消息气泡缺基本要素**：无头像角色区分、无时间戳、无复制/重试；assistant 回复与 user 气泡视觉权重相近（对比公式 AI 的头像实现，全局助手反而没有）。
9. **FAB 无安全区适配**：`right:24/bottom:24` 硬编码，移动端不避让软键盘/手势条；`zIndex:1000` 与 antd Drawer 同级，靠 DOM 顺序压层，脆弱。
10. **上下文标签裸 key 上屏**：`symbol_id: 100` 这类原始字段名直接展示，无友好译名。

### P2 — polish 与技术债
11. **无 markdown 渲染**（前端无 markdown 依赖），回答结构靠纯文本。
12. **硬编码浅色气泡色**（`#e6f4ff`/`#f5f5f5`/`#f0f0f0`），暗色主题切换即破。
13. **会话来源混杂**：设置页公式 AI 的历史会话混入全局列表（14 个里 11 个来自 settings）。
14. 无快捷键（如打开/新建会话）、无未读提示、无消息编辑。

## 七、布局优化方案（具体到改法）

### 7.1 响应式抽屉骨架（P0）
宽度分档表：

| 视口 | 抽屉宽度 | 说明 |
|---|---|---|
| ≥1440px | 560px | 大屏略放宽，证据卡两列更舒展 |
| 1024–1439px | 520px | 保持现状 |
| 768–1023px | min(480px, 62vw) | 不再吞 68% |
| <768px | 100%（全屏） | 显式声明，不依赖 antd 兜底 |

实现要点（`AIAssistant.tsx` 单文件为主）：
```tsx
import { Grid } from "antd";
const { md = true } = Grid.useBreakpoint();          // md = ≥768px
const drawerWidth = md ? 520 : "100%";
<Drawer width={drawerWidth} styles={{ wrapper: { maxWidth: "calc(100vw - 24px)" } }} … />
```
- 头部紧凑化：标题 + 未配置 Tag + 关闭；**「＋新会话」收进抽屉头部 `extra`**（一级操作放头部，列表头只留搜索）（修 P1-7）。
- 上下文标签行改为可折叠：默认一行 ellipsis + Tooltip 看全（修 P1-10 同时做 key→友好名映射：symbol_id→标的、candidate_id→候选、task_id→任务）。

### 7.2 会话区重构（P0，核心）
把「顶部 120px 滚动列表」换成**可折叠会话条**：

```
收起态（默认，高 40px）：
[🤖 组合 1 检查与对账诊断] [ts_delta_bars…] [历史 14 ›]   ← 横向 chip，可横滑
展开态（点击「历史」，高 300px 内嵌面板）：
[搜索框____________]
今天
  ● 组合 1 检查与对账诊断   [portfolio-inspection] 10-23 12:08  🗑
本周
  ○ 你好，你能干什么        [decision] 09-27 00:58            🗑
更早
  ○ ts_delta_bars…          [settings] 09-22 15:33           🗑
```
- 收益：消息区可视高度 +80px（实测桌面 810→890，移动 574→654）；14 个会话可搜索、可按时间分组；当前会话高亮 + 来源 Tag + 完整日期不再被裁（修 P0-2）。
- chip 条同时解决「设置页旧会话混入」的观感（P2-13 治标）；彻底治理需给会话加 `surface` 字段区分全局/公式 AI，列为后续项。

### 7.3 输入区（P0）
- TextArea 与按钮**同行**：`display:flex; gap:8px`，输入 `flex:1`，按钮列右侧竖排两个小按钮。
- **停止按钮**：`sending` 时「发送」变为「停止」（StopOutlined），点击 → `abortRef.current?.abort()` 并把已收到的 abort signal 传给 `streamAISession`（client 第三形参现成）；中断后保留已流出的部分内容并标注「已停止」（修 P0-3）。
- 保留 Enter 发送 / Shift+Enter 换行；加 2000 字上限与计数。

### 7.4 消息流（P0/P1）
- **智能滚动**：滚动容器记 `atBottom = scrollHeight - scrollTop - clientHeight < 80`；仅 atBottom 才自动滚；不在底部时显示「↓ 回到最新」浮动小按钮 + 未读 delta 计数（修 P0-4）。
- **气泡升级**：加头像（user=蓝底 UserOutlined / assistant=RobotOutlined，对齐公式 AI 的既有实现）；消息右下角小字时间戳；hover 出现「复制」「重新生成」两个图标按钮（重新生成=重发上一条 user 消息）（修 P1-8）。
- **回答渲染**：两档方案——
  - 方案 A（推荐，零依赖）：60 行轻渲染器，处理代码块 / 无序列表 / 粗体 / 行内代码，其余 pre-wrap；
  - 方案 B（需依赖评审）：引入 react-markdown + remark-gfm。
  建议先上 A，与设计评审后再定 B。

### 7.5 空状态引导（P1）
按 `source_page` 渲染 3–4 个建议问题 chips，点击即填充并发送：

| 来源页 | 建议问题 |
|---|---|
| opportunity / discovery | 「解释这个候选为什么得分高」「它有哪些风险点」 |
| task | 「这个任务为什么失败」「下一步该做什么」 |
| portfolio-inspection | 「对账差异可能是什么原因」「当前数据健康吗」 |
| 通用 | 「你能做什么」「数据截止到哪天」 |

### 7.6 移动端专项（P1，<768px）
- 抽屉全屏（7.1 分档表）；FAB 改 `bottom: calc(24px + env(safe-area-inset-bottom))`、`right: calc(24px + env(safe-area-inset-right))`。
- 会话 chip 横滑 + `scroll-snap-type: x proximity`；触控目标 ≥44px。
- 头部标题降为 16px，关闭按钮触控区 44×44。

### 7.7 视觉与技术债（P2）
- 气泡/边框/会话底色全部改 CSS 变量（`--ai-bubble-user` 等，定义在 workbench.css `:root`），暗色主题只改变量不动组件。
