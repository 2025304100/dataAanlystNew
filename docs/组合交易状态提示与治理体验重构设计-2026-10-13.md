## 1. 背景与问题诊断

用户反馈：顶栏「待就绪」「自动接管：未就绪，暂不下单」原因一大段、无从下手；「治理」一栏无厘头、不知从何下手。

通读前后端链路后，根因有四个：

### 根因 1：三套状态体系互不联通，用户自行脑补关系

| 状态体系 | 数据源 | 典型呈现 |
|---|---|---|
| HG1 九状态机 | `GET /portfolios/{id}/status`（portfolio_governance.py） | 红色「对账差异阻塞」徽章 |
| 就绪五维门禁 | `GET /portfolios/{id}/auto-trade/readiness`（auto_trade.py） | 「未就绪」+ 数据 NO（MARKET_DATA_STALE） |
| G7 运维阻断 | `GET /portfolios/{id}/auto-trade/g7-operational-status` | 藏在治理→运行保障，`operational_blockers` 为纯字符串 |

同一时刻可能「对账差异阻塞」与「行情数据过期」并存，分属两套体系、两个去处，但界面无任何位置归并为「你现在有 N 件事要处理」。

### 根因 2：修复知识是「说明文」而非「行动项」

- `PortfolioTradingShell.tsx` L66-208 硬编码约 20 个 code 的长文本修复指引，全部不可点击。
- 已发生腐化：L136 指引「点击页面中间『就绪检查』旁的『刷新状态』」，但组合交易页面不存在该元素，指引指向空气。
- 修复知识散落在前端硬编码，后端新增 blocker 时无法保证前端同步。

### 根因 3：治理页按「系统内部结构」而非「用户任务」组织

- 整页级常驻三栏说明书（PortfolioGovernanceTab.tsx L2566-2641：5 个子 Tab 分工/3 种场景/心智模型）。
- 系统状态面板内还有第二块常驻说明（L387-419「两步上手」）。
- 真正的状态与操作按钮被挤到首屏以下；熟手每天重复看同一份说明书且无法收起。

### 根因 4：内部契约语言泄漏到用户界面

HG1/G5/G6/G7、FR-P0-10、`operational_blockers`、`is_auto_simulation_eligible` 等开发代号与英文字段名出现在用户可见 tooltip；副标题「审计 & 对账 & 双跑中枢」为系统视角语言。

### 已具备的基础设施（本次直接复用，不重复造轮子）

- 回测预检 `PrecheckBlockerItem`（app/schemas/bfg_precheck.py L41-60）：`code/severity/category/title_zh/detail_zh/fix_link` 结构化六元组。
- `errors.py` L230-245 已有 `next_actions: [{label, action_type, target}]` 模式，支持 `redirect/sync/retry/dismiss`。
- 因子评价实验室 `applyFixLink`（FactorEvaluationLab.tsx L858）有成熟的点击修复跳转模式。
- `frontend/src/utils/navigate.ts` + `settings:navigate` 自定义事件可完成跨页跳转。
- 状态标签守护模式：`govStatusLabel.ts`、`precheckFixLink.ts` 的 `KNOWN_*` 常量 + 守护测试。

## 2. 目标与非目标

### 目标

1. 任一时刻，用户一屏看清「有几件事、每件事影响是什么、点哪个按钮修」。
2. 每个阻断项有且仅有一个主操作按钮；跨页操作直达目标，不让用户找路。
3. 治理页首屏是状态与动作，解释收进帮助；去掉黑话代号。
4. 修复知识后端化、结构化，新增 blocker 有测试守护，杜绝文案与 UI 再次脱节。

### 非目标（明确不碰）

- 不改九状态机定义、转移规则与 HG1 权限矩阵。
- 不改 cron 调度、fail-closed 语义、自动交易执行链路。
- 不改审计写入逻辑、对账计算逻辑。
- 不做统一健康领域模型的持久化改造（行动项为实时聚合的只读视图）。
- 不涉及实盘自动交易放开（仍仅模拟账户）。

## 3. 总体设计：统一行动项（ActionItem）

### 3.1 数据流

```
HG1 status ──┐
readiness ───┼──▶ portfolio_action_items 服务（只读聚合，排序去重）──▶ ActionItem[]
G7 ops ──────┘                                    │
                                                  ├─▶ 顶栏修复抽屉（ReadinessRepairDrawer）
                                                  └─▶ 治理「待办总览」（同源同数据，单一注册表）
```

聚合为只读、实时计算，不写库、不触发任何状态转移。

### 3.2 ActionItem 契约

```
ActionItem
├─ id            string   稳定标识 = source + ":" + code
├─ source        enum     hg1_status | readiness | g7_ops
├─ code          string   后端原始 code（技术折叠区展示）
├─ severity      enum     blocker | warning | info
├─ title         string   一句话问题，≤12 字，如「行情数据过期」
├─ impact        string   一句话影响，如「今日不会真实下单；回测与手动分析不受影响」
├─ detail        string?  长说明，前端默认折叠
├─ steps         string[]? 分步引导（仅 guided 动作使用，如对账三步）
├─ primary_action         主动作（见 3.3），信息项为 null
├─ correlation_id string?  排错溯源（沿用 precheck 模式）
└─ detected_at   string   检测时间 ISO
```

排序规则：blocker 在前、warning 次之、info 最后；同源按 code 注册表顺序。同源同 code 去重（如 MARKET_DATA_STALE 同时触发 DATA_INCOMPLETE_PAUSED 时合并为一条，保留最高 severity）。

### 3.3 主动作类型（复用并扩展 errors.py 的 action_type 模式）

| action_type | 行为 | 编排位置 | 例子 |
|---|---|---|---|
| `toggle` | 抽屉内原地拨动自动交易开关，调现有 `updatePortfolio`，成功后自动重检 | 前端 | 开关未开 |
| `redirect` | 跨页跳转，走 navigate.ts / `settings:navigate` 事件，直达并高亮目标 | 后端给 target | 行情过期→设置数据中心 |
| `subtab` | 组合内子 Tab 切换，格式 `tab[:sub]` | 前端注册表 | 规则未配→strategy；对账→governance:reconciliation |
| `open-modal` | 打开前端既有弹窗 | 前端 | 无候选→添加候选标的弹窗 |
| `guided` | 抽屉内分步引导，逐步调用现有接口 | 前端编排 + 后端 steps | 对账差异：重新对账→查看差异→单人确认 |
| `none` | 仅解释，无按钮 | — | 今日无买入信号（正常节奏） |

分工原则：**后端是 code 语义与跨页 target 的唯一来源；组合内导航、弹窗、分步编排由前端按 code 绑定。** 纯部署类问题（环境变量熔断）无自助按钮，给明确说明。

### 3.4 完整 code → 行动项映射注册表

#### A. readiness 阻断项（后端实际发出的 8 个 blocker 常量）

| code | severity | title | impact（一句话） | action_type | 动作目标 |
|---|---|---|---|---|---|
| PORTFOLIO_DISABLED | blocker | 自动接管未开启 | 开关关闭，不会自动下单 | `toggle` | 抽屉内开启 |
| ACCOUNT_NOT_SIMULATED | blocker | 账户类型不支持 | 自动接管当前仅支持模拟账户 | `redirect` | 组合编辑（改模拟；实现期核对编辑组合入口） |
| RULE_NOT_CONFIGURED | blocker | 未配置激活策略 | 没有可执行的选股与风控规则 | `subtab` | `strategy`（定位保存按钮） |
| RULE_INVALID_PARAMS | blocker | 策略参数不合法 | 百分比/阶段限制等字段超出范围 | `subtab` | `strategy`（定位首个标红字段） |
| SOURCE_MODE_INVALID | blocker | 标的来源配置非法 | 决策引擎取不到选股范围 | `subtab` | `governance:operations`（实现期核对来源配置控件） |
| NO_TRADEABLE_RANGE | blocker | 没有可交易对象 | 无持仓也无合格买入计划 | `open-modal` | 添加候选标的；detail 提示随后跑 Dry Run |

#### B. readiness 警告项（6 个 warning 常量）

| code | severity | title | impact | action_type | 目标 |

|---|---|---|---|---|
| READY | 否 | — | 不生成项（健康） | — |
| RUNNING_AUTO_SIMULATION | 否 | — | 运行中，不生成项 | — |
| RUNNING_BACKTEST | 否 | — | 回测中，不生成项 | — |

| SCORE_STALE | 是 | blocker | 评分不新鲜 → 同步并重算评分 | `redirect` 因子输入/数据中心（实现期确定落点） |

|---|---|---|

### 3.5 对账差异三步引导（guided 示例）

在抽屉内完成，复用现有接口，不新增后端接口：

1. **重新对账**：调用 `POST /portfolios/{id}/reconcile`，展示通过/不通过结论。
2. **查看差异**：展示 reconcile 返回的差异明细（沿用 ReconciliationPanel 的结论呈现，只读精简版）。
3. **差异确认**：勾选确认 + 备注（沿用 confirm 现有约束），调用 `POST /portfolios/{id}/confirm-reconciliation`，成功后自动重检，HG1 状态由后端按既有规则转移。

任一步失败停在当前步并显示后端错误（经 `t()` 本地化，遵守错误信息不裸露的硬约束）。

要点：

- `toggle` 动作在抽屉内直接执行，不跳页；执行中按钮 loading，失败 toast 并保留卡片。
- `redirect/subtab` 动作后抽屉不关闭（便于回来重检）；`guided` 在抽屉内联展开步骤。
- 空态（无 blocker/warning）：绿色「全部就绪，真实下单门禁已通过」。
- 宽度建议 420-480px，深色主题沿用 `--pt-*` 变量；无感叹号恐吓性文案（遵循用户偏好）。

## 9. 风险与回滚

| 风险 | 缓解 |
|---|---|
| dataclass 增字段影响旧消费方 | 全部带默认值；readiness 旧接口契约不变；回归现有 readiness 相关测试 |
| action target 路由不存在（重蹈「指引指向空气」） | 本设计 §3.4 已标「实现期核对」清单；注册表守护测试只允许登记已存在的导航目标；P0 开工前先跑一遍 target 存在性核对 |
| 三源状态口径不一致导致计数困惑 | 去重合并规则固化在聚合服务并有单测；卡片显示 source 折叠信息 |
| 治理页改名影响既有使用习惯/深链 | 旧子 Tab 键做兼容映射；帮助弹窗保留概念说明 |
| 回滚 | 前端为新增抽屉 + 展示层切换，可独立回退；后端仅增字段与新接口，不停用旧路径 |
