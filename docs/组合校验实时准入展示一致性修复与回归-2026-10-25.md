## 修复判断

| 编号 | 级别 / 结论 | 根因及修改位置 | 验收与限制 |
|---|---|---|---|
| DISP-01 | P2 / ✅ 修复根治 | `PortfolioTradingShell.tsx`、`PortfolioSelectorDropdown.tsx`、`PortfolioInspectionWorkbench.tsx` 使用 `usePortfolioAdmission.ts` 和 `portfolioAdmission.ts`，不再把 READY 翻译成当前准入 | 同一组合在顶部、已展开列表、检查页读取同一快照；原始状态未被改为其他值；风险退出独立显示 |
| DISP-02 | P2 / ✅ 修复根治 | `portfolio_governance.py` 的 GET status 原来仅按 `current_state == READY` 返回 is_auto_simulation_eligible；改用真实 runtime 的新买入及自动恢复权限，并返回 permissions / admission_checked_at | 旧实现真实 HTTP 测试为红；修复后 READY + 过期数据仍保留 READY，但 eligible=false；当前业务日通过时为 true |
| DISP-03 | P2 / ✅ 修复根治 | 共享 store 有组合身份校验、请求代次、10 秒超时、卸载失效及错误降级；只读 GET，无状态补写 | 组合切换、同组合新旧请求乱序、503、离线、超时后迟到、缺字段和权限未知均不回退绿色 |
| DISP-04 | P2 / ✅ 修复根治 | 顶部“添加候选标的”入口及禁止原因也使用当前准入，避免徽章已暂停但入口仍按旧 READY 放行或提示“可以运行” | 实际提交与下单仍由服务端重新门禁；界面准入不是成交承诺 |

状态映射统一如下。新买入、自动恢复和风险退出是三个独立权限，不将一个权限失败推断成全部交易都不可用。

| 实时结果 | 顶部、列表、检查页共用文字 |
|---|---|
| 正在读取 / 重新核实 | 正在核实当前运行条件 |
| HTTP 失败、超时、响应身份/结构不合格、关键权限或检查未知 | 当前交易状态待核实 |
| 服务端明确允许新买入，所需检查没有未知结果 | 当前运行条件已满足 |
| 当前检查已通过，只缺本人审核 | 阻断已清除，等待本人审核 |
| 当前数据与绑定合格，覆盖等条件尚未到期 | 等待运行条件到期 |
| 当前明确禁止新买入 | 新买入已暂停 |

每个有订阅者的组合每 30 秒刷新；focus、online、重新可见、跨页/跨标签检查变更、修复后刷新也会重新核实。离线和页面隐藏清除可用快照，失败不沿用旧 READY。该设计是有界轮询及事件刷新，不是服务端零延迟推送；实际订单必须在执行事务中重新校验。
