## 一、已确认（待统一写入）

### ✅ A1 小生境/生态位 → 正式命名「赛道竞争」

- **决策：采纳，首期完整版必做。**
- **命名：赛道竞争**（学术名 Niche / Niche Selection；本系统刻意不用"小生境/生态位"，避免被误解为"挖小众规律/需要稀有数据"）。
- **本质（防止再被误解）：** 不是按股票样本分区、不要求稀有数据；是按**因子类型**（趋势/反转/波动率/估值/质量/量价 6 类）给种群分区，区内竞争、区间保底，防止 ICIR 略高的单一类型（如趋势类）逐代垄断种群。用的是普通量价/估值/财务字段，唯一前提是公式生成时能自动打类型标签（字段分类器已有）。

**核心机制（4 环节）：**
1. 初始种群：每类保底名额（与经典底座"均衡覆盖"呼应）
2. 每代选择：不做全局 Top N%，改为**每类区内独立排序选种子**，不跨类比绝对 ICIR
3. 变异交叉：同类型变异为主（保方向），跨类型交叉为辅（造新组合）
4. 结果端：6 类都产出候选，结果页可按类型筛选（对应 H1 类型多样性验收）

**配套术语（已和用户对齐用词）：**

| 子概念 | 命名 | 含义 |
|--------|------|------|
| 因子分区 | 类型分区 | 种群按 6 类划成 6 个区 |
| 区内竞争 | 区内选择 | 每类区内独立排序选种子 |
| 分区配额 | 区内保底名额 | 每区最低保留名额，防强势区垄断 |
| 跨区交叉 | 跨类型交叉 | 不同类型区个体交叉产生新组合 |
| 名额流转 | 弱区/空区名额转移 | 某区无数据或连续垫底，名额转给表现好的区 |
| 多样性分数 | 类型均衡度 | 6 类数量分布均衡程度，用于监控反馈（对应 D3） |

**缺陷规避（用户要求把负面降到最低）：**
- 会"保护落后" → 用「保底 + 动态名额」：每区先给最低保底名额，剩余名额按各区实际表现分配
- 某类无数据（未选对应字段）→ 该区关闭，名额流转其他区，不硬凑
- 某类连续多代垫底（数据本身无 alpha）→ 名额动态转给强区，不浪费算力
- 类型归属有歧义（如"放量突破"既趋势又量价）→ 定一套归类优先级规则
- 分太细每类样本太少 → 首期固定 6 类，不再细分；种群 100、平均每类约 16 个可进化

**落地细节（2026-09-10 写文档时已定，详见详细设计6.5.2 / 技术3.8）：**
- [x] 动态配额：活跃赛道保底总额60%均分(base=floor(S×0.6/|active|))，剩余40%按各赛道最优(rank优先、ICIR次之)加权；单赛道不超存活数、缺口回流；空赛道关闭释放；连续W=3代最末层且低于预筛门槛→保底减半转出，恢复还原。
- [x] 区内选择：赛道内用B2锦标赛（抽K=3，按B1的rank→CD取优）；精英不参与锦标赛。
- [x] 跨类型交叉：默认80%同赛道/20%跨赛道（cross_category_crossover_ratio=0.2，高级可调），须过字段依赖/复杂度/去重校验。
- [x] 类型均衡度：category_evenness=(1−Σp²)/(1−1/n)，0~1，存generations，供D3反馈（D3待定）。
- [x] 归类优先级：quality>valuation>volatility>volume_price>reversal>trend，trend兜底，AST纯函数生成时定category。
- [x] 数据结构：candidates加category/generation_rank/crowding_distance/generation_turnover/generation_complexity；generations加category_distribution_json/category_evenness/pareto_front_count；配额参数存evolution_params_json.track_competition。

**成本估算：** 约 3~4 天，无需额外数据/GPU。

### ✅ B1 多目标优化 NSGA-II（帕累托）——首期做

- **决策：首期做。** 目的：不唯 ICIR，综合平衡多目标，避免选出"ICIR高但低覆盖/高换手/过拟合/高相关"的不可用因子。
- **第一期目标（4个，已基本对齐，待用户最终拍板）：** ICIR↑、覆盖率↑、换手率↓、公式复杂度↓。min方向取负统一成越大越好。**与已有因子相关性(<0.95)走硬门禁，不进帕累托**（避免目标过多分层失效）；OOS稳定性、分层单调性作为可选目标池，默认不开。
- **目标数限制：** 启用目标限定3~5个；目标池系统内置固定，用户只能开关/选偏好，不能自建目标，方向锁死不可改。
- **算法：** 非支配排序定rank（支配=各维都不差且至少一维严格好，不要权重、不要加权总分）；同rank算拥挤度CD=Σ(邻居间距/该前沿极差)，边界CD=∞，极差归一化消除量纲；比较算子字典序：rank小者胜→同rank CD大者胜（质量优先，同质量才比多样性）。
- **与B2/A1关系（叠加不打架）：** A1分类型赛道 → 赛道内用B1的(rank,CD)当比较钥匙 → 用B2锦标赛抽K个取最优。B1是"评判尺子/标准"，B2是"选人程序/动作"。
- **复杂度：** O(m·N²)，N=100,m=4约4万次比较/代，毫秒级，不影响10分钟性能。
- **配置位置/交互：** Step4进化参数页，复用简单/高级模式。简单模式只露"选优偏好"档位（均衡balanced默认/稳健stable/进攻aggressive/简洁simple），界面不出现帕累托/非支配/拥挤度术语；高级模式才展开目标维度勾选。**偏好档位不进进化选择计算（保持客观、不拍权重），只在Step5结果页前沿排序/高亮时体现。**
- **数据结构：** evolution_params_json 增加 multi_objective{enabled,preference,objectives[]}；candidates 补 generation_turnover（ICIR/coverage已有、complexity生成时即得）、generation_rank、crowding_distance。
- **结果端：** Step5 帕累托散点图（X换手/Y ICIR，颜色=覆盖、大小=复杂度，Front1高亮，坐标轴可切），偏好一键重排，悬停看4目标值，最终由用户在前沿上人工挑因子。
- **唯一硬骨头：** 换手率口径需新补（Top20%组合每期换仓比例），其余3指标现有。
- 成本估算：算法3~5天 + 换手率口径1~2天 + 前端散点2~3天，约1~1.5周。

### ✅ B2 锦标赛选择（Tournament）——首期做

- **决策：首期做，作为统一选择算子。**
- **机制：** 每次从种群随机抽K个（K=3默认），用B1的比较钥匙(rank升→CD降)取最优出线，重复到选满种子；随机性只在"抽谁进组"，组内比较严格按B1。
- **作用：** 实现极简（约0.5~1天）；选择压力靠K调（K小偏探索、K大偏全局、K=3平衡）；避免早期超强个体垄断；不要求分数为正/不需归一化，适合ICIR有正有负；固定随机种子可复现。
- **配套：** 与精英保留(B3已有)并存——精英Top K直接进下一代，其余名额用锦标赛选；在A1赛道配额内执行。
- 参数：tournament_k=3（高级可调）。

### ✅ C1+C2+C3 合并为「繁殖模块」——首期做

- **决策：C1/C2/C3 不分开实现，合并为一个繁殖模块。** C2的4种变异和C3子树交叉已有，C1是包在外面的"状态调度器"。
- **三者关系（正交不冲突，1+1+1>3）：**
  - C2 = 变异的操作库（参数微调/算子替换/字段替换/结构变异，4种招式）
  - C3 = 交叉的操作方式（子树交叉）
  - C1 = 调度器，不仅调总变异率/交叉率/注入率，还调**4种变异的内部比例分布**和**跨赛道交叉比例**
  - 关键：C1开着时，C2/C3内部比例自动调度，用户不手动配；C1关掉才解锁手动配比例（二选一，不打架）
- **分阶段联动策略：**
  - 早期：变异率高(0.7)、结构变异/字段替换为主(60%)、跨赛道交叉高 → 广撒网
  - 中期：变异率中(0.6)、4种均衡 → 稳健进化
  - 后期：变异率低(0.45)、参数微调为主(70%)、同赛道低交叉 → 精修
  - 停滞：变异率拉高(0.75)、注入拉高、结构变异/跨赛道拉高 → 自救
- **C1输出：** 本代繁殖策略对象 `{mutation_rate, crossover_rate, random_rate, mutation_type_distribution{param/op/field/struct}, cross_category_ratio}`，落库到generations，可复现、可画曲线。
- **配置交互（降门槛设计）：**
  - 简单模式：只露"进化强度"滑块（弱/中/强），背后联动一整套，零配置
  - 高级模式：展开"繁殖与变异"折叠区，可调自适应开关/基线率/敏感度/勾选变异类型；**自适应开启时C2/C3内部比例灰色锁定为"自动"，关闭才解锁手动配**
  - 阈值用"自适应敏感度"三档（保守/平衡/激进）代替原始数值（0.5/2代），不暴露专业阈值
  - 安全上下限[0.4,0.8]永久锁死，滞回+限幅防震荡，精英保留永远开启不暴露关闭
- 成本：C2/C3已有，C1约2~3天，合并实现不额外增加。

### ✅ D1-D5 决策汇总

- **D1 收敛早停：** 已有，升级为「先自救后停」——停滞时C1先提高变异率自救，连续3代自救无效才触发D1早停。不在高原期误停。
- **D2 随机注入：** 已有，注入率交C1自适应调节（多样性健康时5%，趋同时15%~20%），不固定10%。
- **D3 多样性监控反馈：** 首期做。**后台并入C1状态调度器**（三层多样性：类型均衡度+基因型AST距离+表现型因子值相关性，合成健康分作为C1输入升级）；**前端独立做可视化**（多样性曲线、低多样性告警、三层详情）。不单独做调参模块，避免和C1重复。
- **D4 Tabu禁忌表：** 不做。与C2变异后的formula_hash去重+三层指纹相似度预筛功能高度重叠，重复建设。
- **D5 年龄结构淘汰：** 不做。**与B1多目标选择标准真冲突**——都在选择阶段决定谁当父代，D5给老个体适应度打折等于篡改B1的rank+CD比较结果；且与精英保留直接矛盾（精英往往就是老个体）。

**机制分层矩阵（进化流程4阶段，确认无冲突）：**

| 阶段 | 机制 | 管什么 |
|------|------|--------|
| ②选择 | A1赛道/B1多目标/B2锦标赛 | 选谁当父代（范围/标准/动作三层叠加） |
| ③繁殖 | C1调度+C2变异+C3交叉+D2注入 | 怎么生下一代（调度/执行） |
| ①评估后 | D3多样性监控 | 算健康分、画曲线、喂信号给C1 |
| ④停止 | D1收敛早停 | C1自救无效才停 |
| ❌砍掉 | D4（重叠）、D5（冲突） | — |

**协作闭环：** D3监控多样性 → 喂C1 → C1调繁殖参数自救 → 自救无效D1停。选择阶段A1/B1/B2独立运作，和繁殖/监控/停止完全正交。
