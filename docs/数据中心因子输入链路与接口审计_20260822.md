# 数据中心因子输入链路与接口审计

## 结论

当前“设置 → 数据中心 → 因子输入”并非直接把数据写入因子模型表，而是两段式链路：

```text
外部数据同步
  -> 业务数据表（StockValuation / StockFinancialReport / CapitalFlow 等）
  -> 因子流水线 mirror_factor_inputs()
  -> 因子仓库（FactorWarehouse / raw_*）
  -> 因子计算与 FactorValue
  -> FactorModelRun / FactorSet
  -> 组合评分、DecisionEngine、回测/自动推演
```

因此，外部数据同步成功只代表业务数据表已更新；它不会自动代表因子模型已经重新训练，也不会自动代表组合当天已经重新评分。需要启动因子流水线任务，或由调度器按计划触发。

2026-08-22 起，因子输入页面提供“更新因子评分”按钮：它调用现有
`POST /factor-pipeline/tasks`，以 `train_model=false`、
`materialize_scores=true` 执行输入镜像、因子计算和评分物化。该按钮不会擅自重训
因子模型；模型训练仍由因子模型页面显式发起。

## 日期范围语义

- `incremental` 强制使用 `end_date` 当日快照；即使传入更长的 `lookback_days` 也不会回填历史。
- `backfill` 才使用 `start_date/end_date`；未填写开始日时按 `lookback_days` 从结束日倒推。
- 龙虎榜、资金流等数据源有供应商历史范围限制，超出范围应由预览接口返回错误，而不是静默填补。
- 历史范围只保存数据源真实返回的日期，不用前值伪造缺失日期。

## 接口使用审计

以下旧接口仍被保留用于兼容，但当前主界面不再调用：

- `POST /external-data/fundamental/sync`
- `POST /external-data/financial-reports/sync`
- `POST /external-data/lhb-institution/sync`
- `POST /external-data/hot-rank/sync`
- `POST /external-data/tail-proxy/sync`
- `POST /external-data/capital-flow/sync`
- `POST /external-data/etf-indicators/sync`

它们的用途是旧版同步脚本、定时任务和外部集成的兼容入口；新功能应使用 `sync-tasks` 异步接口，以获得断点、取消、重试和分片错误记录。暂不删除，避免破坏已有调度器。

## SQLite / MySQL 兼容要求

- 业务数据通过 SQLAlchemy ORM 写入，SQLite 和 MySQL 使用同一套模型。
- 因子仓库由 `FactorWarehouse` 管理，镜像批次和水位必须在业务事务提交后推进；不能依赖 SQLite 特有的 `INSERT OR REPLACE` 语义。
- MySQL 环境必须执行完整 Alembic migration，并确认连接池允许后台同步任务使用独立短事务。
- 任何新增 SQL 应优先使用 SQLAlchemy 表达式，避免 SQLite 专用日期函数和隐式类型转换。

## 当前风险与后续动作

1. 外部同步完成后，页面应明确提示“业务数据已更新，是否启动因子流水线”；不能把同步完成直接显示为模型已更新。
2. 因子流水线失败时要展示 `mirror`、`factors`、`scores` 具体阶段和错误，而不是只显示“同步失败”。
3. 需要增加一条端到端验收：同步一条估值/资金流记录 → 因子仓库出现同批次 raw 记录 → 因子值/评分更新 → 组合决策证据引用新评分版本。

## 2026-08-23 收尾验收与人工参与边界

已在“设置 → 数据中心 → 因子输入”完成页面验收：

- 外部数据同步、任务进度、失败原因、断点继续和“更新因子评分”均可操作；
- 覆盖诊断原因已转换为中文，并在顶部汇总需要补充的数据集；
- “去因子模型”“去接口管理”会跳转到对应设置项；数据健康卡仍可从“今日决策”直达行情底座/因子输入/因子模型；
- 同步数据和评分流水线是两个可追溯批次：同步成功后需要再次点击“更新因子评分”，不会自动重训模型。

当前需要人工处理的内容仅限外部数据源或大批量数据：

1. **股票估值**：本地已有历史，但最近一次全量任务因 `RemoteDisconnected` 中断。可先在页面选择“自选股/持仓 + 最近快照”重试；若仍中断，请在“设置 → 接口管理”更换可用供应商或降低请求范围，再考虑“同步全量估值历史”。
2. **资金流**：当前本地无有效记录。需要可用供应商/凭证，或者导入符合接口约定的外部数据；代码不会用空值或其他数据集冒充资金流。
3. **尾盘代理（二期预留）**：当前已提供 CSV 导入和候选池自动同步入口，但分钟数据源、非交易日处理、主备源和任务审计仍属于二期建设，不应把 CSV 准备责任长期交给用户。二期完成后系统应自动从候选池/自选股/持仓抓取最近真实交易日分钟数据；当前 CSV 仅作为临时验收和数据源不可用时的补充入口。有效会话仍须满足 `symbol,timestamp,open,high,low,close,volume,amount`、每日至少 180 根分钟线、20 根尾盘线且最后时间不早于 14:59。
4. **ETF 指标**：现有记录字段有效值为 0，需要可返回溢价折价、规模、份额的 ETF 数据源；供应商不支持时保持“暂不可用”。
5. **评分更新**：上述数据补齐后，回到“因子输入”点击“更新因子评分”；该操作默认只重算最近约 11 天，不会增大存储，只会生成一个可清理的评分批次。

不需要人工介入的部分：页面导航、覆盖率诊断、失败原因展示、任务轮询/取消/断点继续、因子流水线触发、SQLite 默认路径以及 SQLAlchemy/MySQL 兼容路径均已由系统完成。尾盘代理的自动化采集、主备数据源和生产准入是二期开发任务；在二期完成前不要把“上传 CSV”当作产品最终流程，也不要在没有数据源的情况下反复点击全量回填，这只会重复产生失败任务和外部请求。

## 批次保留策略

- 因子仓库默认保留最新 30 个 `factor_values`/`factor_targets` 计算批次；可通过
  `FACTOR_BATCH_RETENTION_COUNT` 调整，且不可小于 1。
- 清理仅删除超过保留数量的计算行；`ingestion_batches` 审计元数据继续保留。
- 评分表也按同样批次窗口清理，但只删除未被 `DecisionEvidence`、`JournalEntry` 或
  `TradeSetup` 引用的旧评分。因此历史决策、复盘和交易计划可继续追溯。
- 计算批次清理在因子流水线成功完成后执行，并进行 DuckDB `CHECKPOINT` 以回收本地文件空间。
