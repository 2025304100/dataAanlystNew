# 因子挖掘系统技术开发文档（当前项目落地版）

> 版本：v2.0（遗传算法范式重构版）  
> 日期：2026-09-08  
> 原则：复用现有 FastAPI、SQLAlchemy、DuckDB、异步任务和 React，不平行建设新技术栈

## 1. 技术边界

```text
React Settings/FactorCenter
        ↓ 业务 Facade / DTO
FastAPI 因子路由、评估路由、scoring facade
        ↓
Factor services（registry/compiler/evaluation/lifecycle/pipeline）
        ↓
SQLite/SQLAlchemy 元数据 + DuckDB 因子值仓库
```

禁止前端解析 `hyperparameters_json`、权重内部格式或调用内部路由；禁止回测、组合、交易直接访问因子域 ORM/Session/DuckDB。跨域只依赖公开 DTO/Facade。

## 2. 复用与新增文件边界

### 2.0 已确认运行约束

- 候选池有效标的硬下限为 50，由后端校验，前端不能降低。
- 全局最多一个训练任务处于 `queued/running`；创建接口必须使用事务/分布式锁做原子检查，已有任务时返回业务拒绝及当前任务信息，不创建额外排队任务。
- 字段完整性校验是独立的异步任务，不占用训练任务锁；同一草稿、同一配置哈希只能存在一个活动校验任务，可按分片续跑。
- 完成任务的未引用中间数据默认保留 7 天，并提供经过引用保护检查的手动清理接口。

## 3. 数据模型

### 3.0 数据能力门禁

创建挖掘/评估任务前，服务必须读取 `formula-catalog`、readiness 和数据源路线状态，按字段能力拒绝不成立的组合：连续日线行情和换手率可进入首期正式评估；估值原始表虽包含 PE_TTM、PB、股息率、总市值和流通市值，但当前 DSL 仅开放 PE_TTM、PB，其他字段须先注册并通过 PIT/readiness 校验；财报原始表的净利润、营收及同比字段亦须先完成公告日映射后开放。ROE/资金流必须限制到实际覆盖股票池；龙虎榜、热度和 ETF 快照只能按 event/snapshot 模式评估；`proxy_score`（尾盘代理）为 `blocked`。禁止把稀疏字段填零或以最新快照回填历史。

财报回填复用现有 `financial` 外部数据任务和 `sync_symbol_financial_reports`，按标的分片、增量/回填/缺口修复执行；将结果先写业务财报表，再经既有 mirror 写入 `raw_financial_reports`。任务必须保存源接口、请求范围、成功/失败标的、重试次数和镜像批次 ID。回填完成后执行 PIT 泄漏、报告期连续性、公告日有效性、目标股票池覆盖率和异常值检查；未通过检查的数据只能保留为原始数据，不得提高 factor readiness 或进入模型训练。

### 3.0.1 训练候选池隔离模型

候选池不写回 `symbols`、行情或财报主表，采用独立表并通过外键关联：

- `training_candidate_pools`：候选池定义、`source_type`（`import`/`filter`）、规则 JSON/导入批次、状态、版本和审计字段。
- `training_candidate_pool_members`：`pool_id`、`symbol_id`、纳入校验摘要、`included_at`、软删除字段；对 `(pool_id, symbol_id)` 建唯一约束。
- `training_candidate_pool_snapshots`：训练提交时冻结的成员、规则哈希、数据截止日、统计摘要和快照状态；训练只引用 `snapshot_id`。增加 `analysis_json`（候选池分析结果：市值分布/行业分布/风格暴露/市场环境/数据质量/因子类型建议）、`analysis_status`（`not_analyzed`/`analyzing`/`analyzed`/`reset`）、`analyzed_at`（分析时间）、`is_locked`（是否锁定筛选/导入功能）。

导入服务只接收模板字段，通过 `symbol` 匹配主数据；名称/市场不回写主表。条件过滤服务读取主数据生成成员关联。`source_type` 创建后不可切换。成员列表批量删除只做关联软删除并写审计，不删除主数据。训练启动时一次性加载快照成员，避免逐股票查询。

首期训练接口固定限制 A 股市场（`sh/sz/bj/cn` 及板块映射），不接收 `region` 筛选参数；非 A 股代码在导入匹配和条件过滤阶段均返回结构化拒绝原因。区间预设不能由前端硬编码金额或分位点：`GET /candidate-pool-filter-presets?as_of_date=&markets=` 由服务端基于 A 股当前可用样本返回市值、PE/PB、近 N 日日均成交额、上市交易日数的 `preset_code`、实际边界、样本量、分位数、缺失策略和数据版本；创建快照时将预设展开后的 `filter_config_json` 与元数据一起固化。筛选界面右侧按市场与交易状态、风险标记、估值与市值、盈利质量、流动性、上市时间、行业分组，API 接收结构化分组规则而非页面文案。

行业过滤首期只能读取 `symbols.industry`（或资产主数据当前标签），并在 `training_candidate_pool_snapshots` 记录 `industry_value`、`industry_source`、`industry_observed_at`。它仅适用于 A 股候选池创建时的静态筛选，严禁被评估/训练服务解释为历史 PIT 条件或中性化暴露。

需要历史行业能力时新增 `security_industry_classifications`：`id`、`symbol_id`、`taxonomy`、`industry_code`、`industry_name`、`level`、`effective_from`、`effective_to`、`announced_at`、`source`、`source_version`、`ingested_at`、审计字段；建立 `(symbol_id, taxonomy, effective_from, source_version)` 唯一约束和按 `symbol_id/effective_from/announced_at` 的查询索引。只有分类变更可按 `announced_at <= trade_date` 完成 PIT as-of join、覆盖率与分类版本检查后，才可以启用训练期行业筛选、行业中性化及行业横截面处理。

训练表必须保存 `candidate_pool_snapshot_id`，不能只保存可变的 `pool_id`。同一候选池被多个训练使用时，每个训练生成自己的快照，确保成员、过滤规则和数据截止日完全隔离。

### 3.1 `factor_mining_runs`

字段：`id`、`status`、`draft_id`、`template_id`、`template_version`、`rule_hash`、`candidate_pool_snapshot_id`、`data_cutoff_at`、`start_date`、`end_date`、`rebalance_frequency`、`risk_monitor_frequency`、`risk_exit_config_json`、`target_horizon`、`split_method`、`split_config_json`、`purge_points`、`embargo_points`、`filter_config_json`、`evolution_params_json`、`random_seed`、`current_generation`、`max_generation`、`converged`、`created_by`、`created_at`、`updated_at`、`error_code`。

**`evolution_params_json` 包含：** 种群大小、最大代数、选择比例、精英保留数、变异率、交叉率、随机注入率、收敛阈值、每代评估样本长度、最终验证Top数、复杂度上限、初始种群两层结构配置（经典底座：classic_enabled/classic_cap/classic_categories/classic_coverage_strategy；探索层：ai_random_ratio[ai,random]；冗余系数redundancy_factor）。

**选择机制配置（嵌套在evolution_params_json中，对应3.8实现）：**
- `track_competition`（赛道竞争A1）：enabled(默认true)、base_guarantee_ratio保底比例(默认0.6)、weak_category_generations弱赛道判定代数W(默认3)、cross_category_crossover_ratio跨赛道交叉率(默认0.2)、category归类优先级内置不可配。
- `multi_objective`（多目标B1）：enabled(默认true)、preference偏好档位(balanced默认/stable/aggressive/simple，**只影响结果展示、不写进进化计算**)、objectives数组[{key,direction(内置只读),enabled}]，key∈{icir,coverage,turnover,complexity,oos_stability,monotonicity}，启用数量校验3~5个，相关性门禁不在此数组。
- `tournament`（锦标赛B2）：k(默认3，范围2~7)。
- 简单模式只写preference，其余用默认；高级模式写入全部显式参数。

**繁殖自适应配置（`adaptive_reproduction`，嵌套在evolution_params_json中，对应3.9实现）：**
- `adaptive_enabled`(默认true)、`sensitivity`(conservative/balanced默认/aggressive，映射health阈值与stall代数，不暴露原始数值)
- 基线三率 base_mutation_rate=0.6/base_crossover_rate=0.3/base_random_rate=0.1；安全区间锁死：mutation[0.40,0.80]、crossover[0.10,0.50]、random[0.05,0.20]，三率和归一为1
- 防抖：hysteresis_generations=2（连续2代满足才调）、max_step=0.10（单次调幅上限）
- C2四种变异启用开关 mutation_ops_enabled{param/op/field/struct}（默认全开，至少保留一种校验）
- 关闭adaptive_enabled时，mutation_type_distribution与cross_category_ratio改由用户固定配置，系统不自动调度（开启时这两项系统计算、前端灰色）。

**AI生成配置（`ai_generation_config`，嵌套在evolution_params_json中）：**
- 基础：生成骨架数量、因子类型偏好权重、模型选择、温度
- **自由度约束（可调约束盒子）：** 最大公式长度、最大嵌套深度、最大字段引用数、窗口期范围(min/max)、允许算子子集(数组)、允许字段子集(数组)、创新程度(conservative/balanced/aggressive)、类型严格度(strict/loose)、禁止结构(数组)
- 预设：conservative_exploration / balanced / aggressive_exploration，选预设后自动填充所有约束参数

约束同时作用于两层：Prompt约束层（动态注入系统提示词）和系统校验层（输出后逐项校验，不合法丢弃并用随机个体补）。

状态：`queued/running/paused/cancel_requested/validating/succeeded/failed/cancelled/converged`。`paused`为用户主动中断状态，保留全部checkpoint和已进化结果，释放计算资源，可通过resume接口从断点恢复。`validating`为最终全量验证阶段。`converged`为收敛后提前停止状态。任务状态沿用现有异步任务语义，支持进度和 ETA；另存用户可见的草稿状态，不把"待修复后重校验"混入训练任务终态。

时间切分服务以候选池快照为范围生成有效调仓点：必须满足数据完整性、交易状态和完整预测标签；按时间顺序默认 60%/20%/20%，允许用户传入自定义比例或明确日期边界，但比例总和必须为 100%，日期必须严格递增，且不得绕过三段最低点数配置。禁止随机切分。周频总有效调仓点少于 104、月频少于 36、日频少于 252 时阻断；三段各自的最低点数也必须满足配置。调仓频率只控制信号重算/常规换仓，风险监控频率独立保存，首期支持每日监控；停牌、退市及配置的风控退出可在调仓点之外触发。若风险退出规则参与目标标签，必须纳入标签生成、purge/embargo 和字段校验；切分边界按最终预测持有期执行 purge，必要时增加 embargo；公式回看窗口仅生成起始前置数据缓冲。服务返回每段日期/点数、扣除原因统计和 `split_config_hash`，并将结果写入训练快照。

### 3.2 `factor_mining_candidates`

字段：`id`、`run_id`、`factor_code`（可空）、`factor_version_id`（可空）、`formula_expr`、`canonical_formula`、`formula_hash`、`execution_plan_json`、`dependency_json`、`generation`（第几代，0=初始种群）、`parent_ids_json`（父代候选ID列表，变异1个，交叉2个）、`operation`（`elite`/`mutation`/`crossover`/`random`/`ai_generated`/`enumerated`）、`generation_icir`（该代短样本评估ICIR）、`generation_coverage`（该代覆盖率）、`generation_turnover`（该代Top20%换仓比例，与prescreen_fingerprints.turnover_rate同源冗余、供多目标选择直接读取）、`generation_complexity`（AST算子数，公式生成时即得，复杂度目标用）、`category`（赛道类型：trend/reversal/volatility/valuation/quality/volume_price，生成时按AST规则确定，变异改变类别时重算）、`generation_rank`（该代NSGA-II非支配层级，整数，越小越优）、`crowding_distance`（该代同层拥挤度，越大越稀疏；边界个体为+∞）、`dedup_status`、`review_status`、`latest_evaluation_status`（未评估/评估中/通过/失败）、`latest_ic`（冗余，列表展示用）、`latest_evaluation_id`、`elimination_status`（`alive`/`eliminated_low_icir`/`eliminated_similar`/`eliminated_complexity`/`final_verified`）、`elimination_reason`、`similar_to_candidate_id`、`similar_to_factor_id`、`similarity_score`、`island_id`（**远期岛屿模型预留，可空，本期恒为NULL、不参与逻辑**）、`parent_island_id`（**远期迁移来源岛预留，可空，本期恒NULL**）、`created_at`。

唯一约束：`(run_id, formula_hash)`。跨批次可重复，但转正式版本时必须通过同一公式哈希检查。评估完成后回写 `latest_evaluation_status` 和 `latest_ic`。**被进化淘汰的候选不物理删除**：候选元数据、短样本评估结果、代数、父代、操作类型完整保留，仅不进入下一代，全量评估指标为空，`elimination_status` 记录淘汰原因，用户可在结果页查看完整进化历史。

### 3.2.1 `factor_mining_prescreen_fingerprints`

预筛/每代评估阶段的统计指纹表，用于三层指纹相似度的第二层粗筛。字段：`candidate_id`、`long_short_direction`（多空方向，1/-1）、`ic_mean_short`（短样本IC均值）、`factor_std`（因子值截面标准差时序均值）、`turnover_rate`（Top20%换仓比例）、`top_overlap_vector`（Top20%股票集合的MinHash签名，用于快速估算重合率）、`created_at`。

对通过语义类别过滤的候选对，先比对指纹：任意3项差异超过阈值则直接判定不相似，跳过精确相关计算。指纹在短样本因子值计算完成后同步写入，不增加额外计算开销。

### 3.2.2 `factor_mining_generations`（新增）

每代汇总表，用于进化曲线和种群分析。字段：`id`、`run_id`、`generation`（代数）、`population_size`（种群大小）、`best_icir`（该代最优ICIR）、`avg_icir`（该代平均ICIR）、`median_icir`（中位数）、`diversity_score`（种群多样性评分，0~1）、`category_distribution_json`（6类赛道个体数分布，如{"trend":20,"reversal":15,...}）、`category_evenness`（类型均衡度=(1−HHI)/(1−1/n)，0~1，赛道竞争与D3多样性反馈输入）、`pareto_front_count`（该代rank=1前沿个体数）、`diversity_genotype`（基因型多样性，复用AST树编辑距离均值）、`diversity_phenotype`（表现型多样性，复用三层指纹因子值相关/ICIR离散度）、`diversity_health`（三层合成健康分0~1，C1输入，diversity_score以其为准）、`stall_count`（连续无进步代数，D1观测）、`actual_mutation_rate`/`actual_crossover_rate`/`actual_random_rate`（**本代C1实际使用的三率，落库可复现**）、`mutation_type_distribution_json`（本代C2四种变异实际占比{param,op,field,struct}）、`cross_category_ratio`（本代C3实际跨赛道交叉比例）、`adaptive_state`（本代所处状态early/mid/late/rescue/fast_progress）、`elite_count`（精英保留数）、`mutation_count`（变异个体数）、`crossover_count`（交叉个体数）、`random_count`（随机注入数）、`eliminated_count`（淘汰数）、`evaluation_duration_ms`（该代评估耗时）、`convergence_delta`（与上一代最优ICIR差值）、`island_id`（**远期岛屿模型预留，可空，本期恒NULL；本期单种群所有记录为同一空值**）、`created_at`。

索引：`(run_id, generation)` 唯一。进化曲线直接查询此表，不需要聚合candidates表。

### 3.3 `factor_evaluation_runs/results`

评估运行固定引用：`candidate_id`（或 `factor_version_id`）、股票池快照、目标定义、过滤配置、PIT 模式、数据截止日、代码版本和参数哈希。一个候选因子可在不同股票池/时间范围下多次评估，评估运行与候选为多对一关系，候选列表默认展示最新一条评估结果。结果按 `period=is/oos/all` 保存 `ic_mean`、`ic_median`、`ic_std`、`icir`、`coverage`、`valid_cross_sections`、`monotonicity`、`missing_streak`、`sample_count`、`gate_status`、`warnings_json`。

### 3.4 血缘要求

候选 → 因子版本 → FactorSet member → FactorSet → FactorModelRun → Score 必须使用不可变 ID/版本引用。任何“最新版本”查询只能用于列表展示，不能用于历史任务重算。

### 3.5 向导草稿、校验、模板与 checkpoint

- `factor_mining_drafts`：保存向导 5 步的部分/完整配置、当前步骤、草稿状态（`draft`、`waiting_data_recheck`、`invalidated`）、候选池快照 ID、更新时间和 owner；草稿允许多份并存。
- `factor_data_validation_runs`：保存字段选择、公式/目标/时间配置哈希、分片进度、覆盖率/PIT/截面报告、状态（`queued/running/succeeded/failed/cancelled`）和报告版本。同一 `draft_id + config_hash` 活动任务唯一。
- `factor_training_checkpoints`：保存 `run_id`、阶段/代数、输入快照哈希、随机种子、结果位置、可恢复状态和保留截止时间；取消请求不立即删除，用户完全放弃或保留期到期后清理。
- `factor_mining_templates` 与 `factor_mining_template_versions`：保存系统预设/个人模板、规则配置、版本说明和 `rule_hash`；不保存具体股票代码、计算结果或可变数据快照。单用户场景下 `scope` 仅区分 `system`（预设，不可修改删除）和 `personal`（个人创建，可编辑），不涉及团队共享和权限控制。部分模板可以作为草稿使用，执行前仍需补齐并通过全部门禁。

### 3.6 因子公式模板（初始种群经典因子来源）

`factor_formula_templates`：存储经典因子公式模板，用于初始种群的枚举经典因子来源。与 `factor_mining_templates`（挖掘向导配置模板）是不同的表，前者存公式模板，后者存挖掘配置模板。

字段：`id`、`name`（模板名称）、`category`（因子类型：trend/reversal/volatility/valuation/quality/volume_price）、`formula_template`（公式结构，带参数占位符如 `{n1}`、`{n2}`）、`param_definitions_json`（参数定义数组，每个参数含name/type/range/default）、`economic_logic`（经济逻辑解释）、`priority`（优先级，数字越小越优先）、`scope`（`system`系统预设不可删除/`personal`个人模板可增删改）、`source`（`system_builtin`/`ai_generated`/`manual_created`）、`complexity`（模板复杂度，算子数）、`enabled`（是否启用）、`created_at`、`updated_at`。

**系统预设25个经典因子模板（初始化数据）：**

| 类别 | 数量 | 模板名称 |
|------|------|----------|
| trend趋势类 | 5 | 均线趋势、价格动量、通道突破、MACD、均线斜率 |
| reversal反转类 | 4 | 短期反转、超买超卖、均值回归、量价背离 |
| volatility波动率类 | 4 | 波动率收缩、波动率突破、ATR比率、布林带位置 |
| valuation估值类 | 4 | PE反转、PB反转、估值比价、盈利收益率 |
| quality质量类 | 4 | ROE变化、盈利加速度、毛利率变化、资产周转率 |
| volume_price量价类 | 4 | 换手率异常、成交量趋势、量价背离、资金流强度 |

系统预设模板通过数据库migration初始化，`scope=system`，不可删除，可复制为个人模板。个人模板由用户从挖掘结果保存或手动创建，`scope=personal`，可增删改。

**模板参数展开逻辑：** 每个模板的 `param_definitions_json` 定义参数名、类型和取值范围（如 `n1: [5,10,20]`）。展开时对所有参数做笛卡尔积，生成具体公式。如均线趋势模板 n1∈[5,10,20], n2∈[20,60,120] → 3×3=9个具体公式。展开后经过AST校验、字段依赖检查、复杂度检查、formula_hash去重，按模板优先级+复杂度升序排序，取Top N加入初始种群。

### 3.7 初始种群三来源实现逻辑

初始种群采用**两层结构**：先生成并锁定经典底座，再用AI+随机填充剩余名额。`evolution_params_json` 的初始种群配置包含：`classic_enabled`(是否启用经典)、`classic_cap`(经典上限，默认40)、`classic_categories`(启用类别数组)、`classic_coverage_strategy`(balanced均衡/priority优先级)、`ai_random_ratio`(AI:随机，默认[57,43])、`redundancy_factor`(冗余系数，默认2.0)。

**第一层：经典底座实现（均衡覆盖算法）：**
1. 查询 `factor_formula_templates` 中 `enabled=true` 且类别在 `classic_categories` 内的模板，按 `priority` 排序
2. 字段联动过滤：只保留字段依赖在用户已选字段范围内的模板；估值/质量类在未选对应字段时不可勾选（前端置灰+后端二次校验拒绝）
3. 每个模板按参数定义做笛卡尔积展开，生成具体公式
4. 批量校验：AST语法+字段依赖+复杂度+类型匹配
5. 来源内去重：formula_hash精确去重 + AST结构相似度聚类（树编辑距离>0.9留1个）
6. 按覆盖策略分配名额（总名额=`classic_cap`，硬上限=种群大小×60%）：
   - **balanced均衡（默认）：** 按类别分组，每类基础名额=floor(cap/启用类别数)，余数按类别优先级依次补；每类内部按模板优先级+复杂度升序取Top到该类名额；某类合格候选不足其名额时，缺口回流名额池分给其他候选充足的类
   - **priority优先级：** 不分类别，所有合格候选统一按模板优先级+复杂度排序取Top到cap
7. 锁定经典底座C个（C≤cap，不足不硬凑），`operation=enumerated`，`generation=0`
8. 计算剩余名额 R = 种群大小P − C；AI目标=round(R×ai_ratio)，随机目标=R−AI目标

**第二层：AI生成骨架实现（填充剩余名额）：**
1. 提取环境特征：股票池平均市值/行业分布/风格暴露、时间范围市场阶段/波动率/趋势强度、可用字段列表+覆盖率
2. 组装Prompt：系统角色+生成约束（自由度盒子）+可用资源（字段/算子定义）+市场环境+用户偏好（类型权重）+Few-shot示例（从经典底座选2~3个）+**已入库经典底座公式和已生成AI骨架（防重复清单）**+输出要求（JSON Schema）
3. 分4批调用大模型API（每批约5个骨架），每批把前批已通过的骨架加入防重复清单
4. 单骨架去重反馈：输出与已有重复时，反馈"此公式已存在请换结构"重新生成，最多重试3次，仍重复则放弃（名额后由随机补）
5. 输出解析+校验：JSON Schema解析→AST语法→字段依赖→算子白名单→复杂度→类型匹配→禁止结构
6. 每个骨架按参数范围展开（2~3个值），按冗余系数2.0超额生成
7. 来源内+跨来源formula_hash去重、AST结构聚类
8. 取Top到AI目标（不足则缺口交随机），`operation=ai_generated`，`generation=0`
9. 失败降级：API失败/超时→AI目标清零，剩余名额全部交随机

**第二层：受约束随机生成实现（填充+补位）：**
1. 字段自动分类：价格类(close/open/high/low/vwap)、成交量类(volume/amount)、估值类(pe_ttm/pb/ps_ttm)、质量类(roe_ttm/roa/gross_margin)、换手率(turnover)
2. 算子类型签名定义：每个算子定义输入类型→输出类型（mean(数值)→数值、rank(任意)→无量纲、+(同类型,同类型)→同类型）
3. 受约束随机树生成：随机决定复杂度（1~4算子）→根节点随机选算子→按输入类型递归生成子节点→叶子选对应类型字段→参数随机（窗口5~120）→类型匹配校验
4. 生成时规避：实时formula_hash拦截（与经典+AI+已生成随机撞了立即重生成，单公式最多20次）；同AST结构最多保留3个参数变体；按"复杂度×字段组合×算子类型"分层采样保证结构分散
5. 按冗余系数2.0超额生成（随机目标×2，同时预留AI补位量）
6. 批量校验+formula_hash去重+AST结构聚类
7. 多样性排序：与已锁定经典底座、AI候选算AST树编辑距离，相似度低的优先，同相似度按复杂度升序
8. 取Top到"随机目标+AI缺口"，`operation=random`，`generation=0`

**入库与补位规则：** 按"经典底座→AI→随机"顺序锁定。AI不足随机补；随机也不足时允许最终种群略小于目标P，不硬凑重复因子（记录actual_population_size及缺口原因）。严禁为凑数保留重复或校验不通过的公式。

**四层去重实现（对应需求文档）：**
- 第1层生成时规避：见上述AI分批/去重反馈、随机实时哈希/同结构限变体/分层采样
- 第2层formula_hash：公式规范化器（交换律归一、参数排序、去冗余括号、算子别名统一）后算哈希，跨来源合并统一去重，保留优先级经典>AI>随机
- 第3层AST结构聚类：树编辑距离计算结构相似度（0~1），>0.9用并查集聚类成组，初始种群每组按经典优先+复杂度低留1个
- 第4层因子值相关：初始阶段无因子值不做，放到每代短样本评估时由 `factor_mining_prescreen_fingerprints` 三层指纹处理，相关≥0.95置`eliminated_similar`

### 3.8 选择机制实现（赛道竞争 A1 + 多目标 B1 + 锦标赛 B2）

本节为每代选择父代的工程实现，输入为本代短样本评估完成的种群，输出为繁殖父代与直接保留的精英。三层顺序：先用B1给每个体算比较钥匙(rank, CD)，再用A1分赛道定配额，最后用B2在赛道内抽选。

**（1）因子类型归类器（classify_category）**
- 经典模板继承模板category；AI/随机/变异/交叉后代按AST一次性推断：命中多类按 quality>valuation>volatility>volume_price>reversal>trend 优先级定主类，trend兜底；结果写入candidates.category，结构变异后重算。
- 归类只依赖算子类型与字段标签（字段分类器已存在），为纯函数、零数据IO。

**（2）多目标：非支配排序 + 拥挤度（B1）**
- 组装目标向量：min方向（turnover、complexity）取负，统一为越大越好；相关性门禁在此之前已过滤，不参与。
- 非支配排序：标准 fast-non-dominated-sort，输出每个体rank；同rank内按各目标排序、相邻间距除以该前沿极差后累加得CD，每目标两端个体CD=+∞。复杂度O(m·N²)，N=100、m=4约4万次比较，毫秒级。
- 比较算子（严格字典序，禁止加权）：
```python
def better(a, b, rank, cd):
    return rank[a] < rank[b] or (rank[a] == rank[b] and cd[a] > cd[b])
```

**（3）赛道动态配额（A1）**
- active=有存活个体且用户选了对应字段的赛道；需选父代总数 S=round(种群×选择比例)。
- 每活跃赛道保底 base=floor(S×base_guarantee_ratio/|active|)（默认保底总额60%）；剩余 rem=S−Σbase 按各赛道最优个体质量（rank优先、ICIR次之）加权分配；单赛道配额不超过其存活数，缺口回流rem再分。
- 空赛道关闭、保底名额释放；连续W代（默认3）赛道最优个体rank为最末层且ICIR低于预筛门槛→保底减半并转出，恢复后还原（维护每赛道连续垫底计数 weak_streak[c]）。
- 类型均衡度 category_evenness=(1−Σp_c²)/(1−1/|active|)，与category_distribution_json一并写入generations表。

**（4）锦标赛抽选（B2）与精英保留**
```python
def select_parents(pop, rank, cd, quota, K=3, rng=None):
    elite = pop.elites()                         # 精英直接进下一代、不抽选
    parents = []
    for cat, need in quota.items():
        pool = [p for p in pop if p.category == cat and p not in elite]
        for _ in range(need):
            cs = rng.sample(pool, min(K, len(pool)))      # 赛道内随机抽K
            w = max(cs, key=lambda p: (-rank[p], cd[p])) # rank升、CD降
            parents.append(w)
    return elite, parents
```
- 抽选用runs.random_seed派生的代级随机种子，保证可复现；允许重复抽中；pool不足K时按实际数量抽。
- 父代产出后代：默认(1−cross_category_crossover_ratio)=80%在同赛道内交叉、20%跨赛道交叉，跨赛道后代须过字段依赖/复杂度/去重校验，变异以同赛道为主。

**（5）换手率口径（唯一新增评估指标）**
- 每个调仓日取因子值Top20%股票集合，换手率=相邻两期集合的对称差/2占组合规模比例，再对时间序列取均值；与 factor_mining_prescreen_fingerprints.turnover_rate 同源，选择阶段直接读取，不重复计算。

**（6）结果端多目标数据**
- 最终Top50全量验证后再跑一次非支配排序/拥挤度，回写最终rank、CD；API返回每个因子的category、4目标值、rank、CD及各Front成员，供前端绘制类型分布图与帕累托散点；preference偏好档位只在API返回顺序/高亮标记上体现，不改变已落库的rank、CD。

**（7）明确不纳入本期实现的机制**

以下机制经评估后明确排除在本期开发、代码评审与排期范围之外，不得在本期代码中混入相关逻辑：

| 机制 | 不做理由 |
|------|---------|
| D4 Tabu 禁忌表 | 与C2变异后的formula_hash去重+三层指纹相似度预筛功能高度重叠，重复建设 |
| D5 年龄结构淘汰 | 与B1多目标选择标准冲突（都在选择阶段决定父代，D5给老个体打折等于篡改B1的rank+CD比较结果），且与精英保留直接矛盾 |

### 3.9 繁殖与自适应实现（C1/C2/C3 + D1/D2/D3）

本节为选择之后生成下一代的工程实现。**观测—决策—执行三层分离：D3/D1只产信号，C1只算参数，C2/C3/D2只按参数执行，禁止执行器自带比例、禁止D3直接改率。**

**（1）D3 多样性观测（只算不改）**
```python
def observe_diversity(pop, gen):
    evenness = category_evenness(pop)                       # 复用A1类型均衡度
    genotype = mean_pairwise_ast_distance(pop)              # 复用去重树编辑距离
    phenotype = mean_factor_corr(pop)                       # 复用三层指纹相关性
    health = weighted_mean(evenness, genotype, phenotype)   # 默认等权，输出0~1
    return health
```

**（2）C1 自适应调度器（纯函数，输入信号输出策略）**
```python
def c1_schedule(g, max_g, health, stall, delta, cfg, prev_rate):
    stage = "early" if g < 0.3*max_g else ("late" if g > 0.7*max_g else "mid")
    # 基线随阶段
    mut = {"early":0.70,"mid":0.60,"late":0.45}[stage]
    rnd = {"early":0.12,"mid":0.10,"late":0.05}[stage]
    mut_dist = {"early":{param:.15,op:.15,field:.30,struct:.40},
                "mid":  {param:.25,op:.25,field:.25,struct:.25},
                "late": {param:.70,op:.15,field:.10,struct:.05}}[stage]
    cross_cat = {"early":.30,"mid":.20,"late":.10}[stage]
    # 停滞自救（D3 health低 或 D1 stall>=2）
    if health < 0.50 and hysteresis_ok(cfg) or stall >= 2:
        mut, rnd, cross_cat = 0.75, 0.15, 0.40
        mut_dist = {param:.15,op:.15,field:.30,struct:.40}
        state = "rescue"
    elif delta > fast_progress_threshold:                  # 快速进步则降扰动
        mut, rnd, state = 0.45, 0.05, "fast_progress"
    else:
        state = stage
    mut = clamp_with_step(mut, cfg, prev_rate)             # 夹在安全区间+限幅+滞回
    cross = 1 - mut - rnd                                   # 三率和归一，交叉夹回区间
    return Strategy(mut, cross, rnd, mut_dist, cross_cat, state)
```
- 安全区间、滞回代数、单次限幅见3.1 `adaptive_reproduction`；clamp保证三率不越界、和为1。
- 关闭自适应时不调用本函数，直接使用用户固定基线，执行器按固定比例运行。

**（3）C2/C3/D2 执行器（严格按strategy，不自带比例）**
```python
def reproduce(parents, strat, cfg, rng):
    children = []
    children += c2_mutate(parents, strat.mutation_rate, strat.mutation_type_distribution, cfg, rng)
    children += c3_crossover(parents, strat.crossover_rate, strat.cross_category_ratio, cfg, rng)
    children += d2_random_inject(parents, strat.random_rate, cfg, rng)   # 受约束随机
    return validate_and_fill(children, cfg)  # AST/复杂度/字段依赖/去重校验，非法丢弃、随机补位
```
- `c2_mutate` 内部按 mutation_type_distribution 选4种变异之一，类型比例不硬编码；`c3_crossover` 按 cross_category_ratio 决定同/跨赛道配对；`d2_random_inject` 数量由 random_rate 决定。
- 字段替换只能在已选字段子集内；后代重新classify_category（见3.8）。

**（4）D1 先自救后停（只判断停止）**
```python
stall = update_stall(best_icir_now, best_icir_prev, thr)   # |delta|<thr则+1
if stall == 2: trigger_c1_rescue()                         # 先让C1自救，不停
if stall >= 3: return "converged"                          # 自救后仍3代无进步才早停
```

**（5）每代主循环（贯通3.8选择与本节繁殖）**
```python
for g in range(max_generation):
    metrics = short_evaluate(pop, g, subexpr_cache)        # 评估，G2缓存复用
    health = observe_diversity(pop, g)                     # D3观测
    stall  = update_stall(...)                             # D1观测
    rank, cd = nsga2(pop, metrics)                         # B1
    quota = track_quota(pop)                               # A1
    elite = pop.elites(); parents = tournament(pop, rank, cd, quota, K)  # B2

    pop = elite + offspr
    persist_generation(g, metrics, health, stall, strat)   # 落库实际策略与三层多样性

```

**（6）性能与复用：** D3基因型/表现型复用去重树编辑距离与三层指纹，不重复遍历；C1为纯函数O(N)；执行器仍向量化。每代自适应计算<50ms，归入每代预算可忽略。

> **工程边界：多种群岛屿模型（Island Model）为远期演进方向，本期不开发任何运行时能力**——不拆分种群、不实现岛间迁移、不做分岛/合岛调度、不做多进程岛间通信、不提供分岛 API 与前端。本节仅记录未来设计要点，并已在 3.2/3.2.2 预留可空字段（`island_id`、`parent_island_id`，本期恒 NULL）。本期及代码评审中不得出现岛屿运行逻辑。

**与本期方案的关系：** 本期单种群内用"赛道竞争"（按因子类型分区、区内选择、区间配额）做软隔离；岛屿模型是硬隔离，未来融合为"岛内赛道竞争 + 岛间迁移"。

**增量价值与解决的痛点（为什么未来值得做）：**
- 赛道竞争是软隔离，6 类同处一个基因池，长期经交叉可能趋同；岛屿硬隔离显著减缓趋同。
- 赛道只按因子类型单维度分区，同类型内无法多路径并行；岛屿可让各岛走不同参数风格/市场假设/复杂度方向。
- 全局早期走偏时软隔离难以纠偏；多岛独立路径+迁移可逃逸局部最优，且迁移个体质量高于随机注入。
- 多岛天然多进程并行，大种群时提升 CPU 利用率。

**本期不实现的工程原因：**
1. 规模门槛：每岛需≥约50个体，默认种群100开4岛每岛仅25，选择/变异基因池不足，效果反降；有效需总种群150~300+。
2. 算力：单次耗时约翻3~5倍（10分钟→30~50分钟），内存同步上升。
3. 复杂度：多岛状态机、迁移点同步、多进程通信、自适应分合岛、跨岛血缘、分岛前端，约2~3周。
4. 配置成本：迁移间隔/迁移率/拓扑/迁出策略需额外配置辅助。

**未来实现要点（仅备忘，不在本期排期）：**
- 弹性岛屿：起跑单种群+赛道竞争，连续N代`diversity_score`下降且`convergence_delta≈0`（疑似局部最优）才分裂新岛，岛间方向趋同（质心距离低于阈值）则合并；岛屿数硬护栏 `min(4, floor(population/50))`，种群<150 禁开。
- 迁移：间隔 `max(3, max_generation/5)` 代、每岛迁出约5%优质个体、环形拓扑；迁移写入预留的迁移事件表 `factor_mining_migrations`（run_id、from_island、to_island、candidate_id、generation、created_at），本期不建表。
- 配置降门槛：只暴露"关闭/标准探索/强探索"档位，底层参数自动推导；AI配置顾问只做推荐/术语翻译/配置体检，规则兜底。

- 触发立项条件：上线后单种群+赛道竞争反复陷入局部最优、扩大变异率/随机注入仍无法跳出，且接受种群200+与更长耗时。

#### 3.13.1 G2 公共子表达式缓存实现（层面1）

**AST遍历提取子表达式：**
```python
def extract_subexpressions(ast):
    """递归遍历AST，提取所有子表达式（包括叶子节点）"""
    results = []
    def traverse(node):
        results.append(node)
        for child in node.children:
            traverse(child)
    traverse(ast)
    return results
```

**SHA-256强哈希（不用Python内置hash）：**
```python
import hashlib
import json

def subexpr_hash(node, data_snapshot_version):
    """子表达式哈希：算子类型+参数+字段唯一ID+数据快照版本，SHA-256"""
    def node_hash(n):
        child_hashes = tuple(node_hash(c) for c in n.children)
        payload = json.dumps({
            "op": n.op_type,
            "params": n.params,
            "field_id": n.field_id if hasattr(n, 'field_id') else None,
            "children": child_hashes
        }, sort_keys=True)
        return hashlib.sha256(payload.encode()).hexdigest()
    # 顶层加上数据快照版本，确保快照变了缓存失效
    payload = json.dumps({"node": node_hash(node), "snapshot": data_snapshot_version})
    return hashlib.sha256(payload.encode()).hexdigest()
```

```python
def compute_generation_with_cache(population, data, data_snapshot_version):
    # 1. 提取所有子表达式
    all_subexprs = []
    for factor in population:
        all_subexprs += extract_subexpressions(factor.ast)
    # 2. SHA-256哈希去重
    unique = {}
    for sub in all_subexprs:
        h = subexpr_hash(sub, data_snapshot_version)
        if h not in unique:
            unique[h] = sub
    total_count = len(all_subexprs)
    unique_count = len(unique)
    dedup_rate = 1 - unique_count / total_count
    # 3. 向量化批量计算唯一子表达式
    cache = {}
    for h, sub in unique.items():
        try:
            result = evaluate_vectorized(sub, data)  # 向量化，500×300
            # 结果合法性校验
            if np.any(np.isnan(result)) or np.any(np.isinf(result)):
                cache[h] = {"status": "failed", "error": "NaN/Inf in result", "value": None}
            else:
                cache[h] = {"status": "valid", "value": result.astype(np.float32)}
        except Exception as e:
            cache[h] = {"status": "failed", "error": str(e), "value": None}
    # 4. 因子组装查缓存（断言：不触发新计算）
    results = []
    for factor in population:
        factor_value = assemble_from_cache(factor.ast, cache)
        results.append(compute_metrics(factor_value))  # IC/ICIR/覆盖率等
    # 5. 抽样校验：随机抽5个因子，缓存结果与直接全量计算对比
    sample_indices = random.sample(range(len(population)), min(5, len(population)))
    for idx in sample_indices:
        direct = evaluate_full(population[idx].ast, data)
        cached = assemble_from_cache(population[idx].ast, cache)["value"]
        if np.max(np.abs(direct - cached)) > 1e-6:
            raise CacheValidationError(f"Factor {idx} cache mismatch, discarding cache")
    # 6. 落库去重率
    generations.log(total_subexprs=total_count, unique_subexprs=unique_count, dedup_rate=dedup_rate)
    return results
```

**贪心负载均衡：**
```python
def estimate_complexity(node):
    """预估子表达式计算复杂度"""
    if node.op_type in ("field", "const"): return 1
    if node.op_type in ("mean", "delta", "abs"): return 5 * estimate_complexity(node.children[0])
    if node.op_type in ("rank", "zscore"): return 10 * estimate_complexity(node.children[0])
    if node.op_type in ("add", "sub", "mul", "div"): return estimate_complexity(node.children[0]) + estimate_complexity(node.children[1])
    return 3

def balance_tasks(subexprs, num_workers):
    """按复杂度降序，贪心分配给当前负载最小的worker"""
    sorted_exprs = sorted(subexprs, key=lambda x: estimate_complexity(x), reverse=True)
    workers = [[] for _ in range(num_workers)]
    worker_load = [0] * num_workers
    for expr in sorted_exprs:
        min_worker = worker_load.index(min(worker_load))
        workers[min_worker].append(expr)
        worker_load[min_worker] += estimate_complexity(expr)
    return workers
```

**主进程汇总写入（子进程不写共享存储）：**
```python
def compute_parallel(population, data, pool):
    # 1. G2去重
    unique_subexprs = deduplicate(population)
    # 2. G1负载均衡分配
    tasks = balance_tasks(list(unique_subexprs.values()), pool._processes)
    # 3. 并行计算（子进程只计算，结果通过共享内存返回）
    results = pool.map(compute_subexpr_batch, tasks)
    # 4. 主进程汇总写缓存（唯一写入点）
    cache = {}
    for batch_result in results:
        cache.update(batch_result)
    # 5. 并行组装+算指标
    factor_tasks = balance_factor_tasks(population, pool._processes)
    factor_results = pool.map(assemble_and_compute_batch, [(t, cache) for t in factor_tasks])
    # 6. 主进程汇总写generations表
    all_results = []
    for batch in factor_results:
        all_results.extend(batch)
    return all_results
```

**心跳检测与异常处理：**
```python
def worker_heartbeat(worker_id, queue):
    """子进程每5秒发心跳"""
    while True:
        queue.put((worker_id, "alive", time.time()))
        time.sleep(5)

def monitor_workers(heartbeat_queue, workers, timeout=30):
    """主进程监控心跳，超时杀了重试"""
    last_heartbeat = {w: time.time() for w in workers}
    while True:
        while not heartbeat_queue.empty():
            wid, status, ts = heartbeat_queue.get()
            last_heartbeat[wid] = ts
        now = time.time()
        for wid, last in last_heartbeat.items():
            if now - last > timeout:
                # 杀进程，重试该任务
                workers[wid].terminate()
                retry_task(wid)
        time.sleep(5)
```

import numpy as np

def create_shared_matrix(shape, dtype=np.float32):
    """创建共享内存矩阵，子进程直接attach不复制"""
    nbytes = np.prod(shape) * np.dtype(dtype).itemsize

## 5. 任务执行与性能

1. 生成、字段校验和评估均进入现有异步任务中心；请求接口只创建任务，不同步执行长计算。字段校验与训练任务使用不同任务类型和并发配额，不能互相占用单训练锁。
2. DuckDB 只读连接可并行；写入使用现有单写锁和批次提交。取消检查点至少放在候选批次、日期分片和结果落库前。
3. 先实现按日期/股票池分片的向量化计算；不要以 Python 逐股票循环作为正式实现。
4. 性能目标按当前单机基线重新压测后确定；原稿"6000 因子/5 分钟、12 代/1 小时"在未有基准证据前只作为实验目标，不作为首期验收硬指标。**首期可接受基线（遗传算法范式）：**
   - 初始种群生成（AI+枚举+随机，100个体）：3分钟内完成（含AI API调用）
   - 每代短样本评估（1年×50调仓日×500股×100个体）：2分钟内完成
   - 20代进化总耗时：约40分钟（含初始种群+每代评估+变异交叉）
   - 最终全量验证（Top 50×300周×500股）：10分钟内完成
   - 端到端总耗时：约55分钟
   - 相似度计算：三层指纹预筛后，100个体两两比对控制在30秒内
   - AI生成API调用：单次调用（含重试）控制在30秒内，失败自动降级
   - 选择机制（B1非支配排序+拥挤度+A1配额+B2锦标赛，100个体/4目标）：每代50ms内，归入每代2分钟预算内可忽略；换手率复用预筛指纹turnover_rate、不新增评估遍历
5. 任务重试必须幂等，使用配置哈希、输入快照和任务 ID 防止重复写入。训练每个阶段写 checkpoint；取消与失败保留 checkpoint 直到用户放弃或保留期到期。
