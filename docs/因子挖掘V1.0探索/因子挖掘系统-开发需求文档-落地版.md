# 因子挖掘系统开发需求文档（当前项目落地版）

> 版本：v2.0（遗传算法范式重构版）  
> 日期：2026-09-08  
> 适用项目：`dataAanlystNew`  
> 基线：现有因子库、FactorSet、FactorModelRun、评分流水线和回测预检能力

## 1. 修订结论

原稿描述的是一个从宽表开始、使用 PyQt + DEAP、文件目录保存结果的独立桌面系统；当前项目实际是 FastAPI + SQLAlchemy/DuckDB + React/TypeScript 的 Web 工作台，且已经存在因子治理和模型训练链路。因此本功能不新建一套系统，采用以下落地定义：

1. **因子挖掘是因子中心内的研究实验**，不是新的顶层菜单，也不是因子模型训练。
2. **设置 → 因子中心**负责候选公式生成、数据校验、单因子评估、去重和因子版本登记。
3. **设置 → 因子模型**是后续独立业务：仅消费因子中心已冻结的 FactorSet，负责多因子组合权重、评分、激活/回退。
4. 本期实现**遗传算法范式**的因子挖掘：初始种群（AI生成+枚举+随机）→ 逐代进化（选择→变异→交叉→评估）→ 收敛判断 → 最终全量验证 → 结果输出。不再使用"模板+参数网格一次性枚举"的范式。
5. 所有结果写入现有数据库和任务体系，禁止以 JSON 文件目录作为唯一事实来源，禁止绕过 Facade 直接访问其他业务域表。

## 2. 目标与范围

### 2.1 本期目标（MVP）

完成如下链路：

```text
选择股票池/数据截止日 → 创建候选因子或批量导入候选
→ 静态校验/预览 → 单因子评估（IC、ICIR、覆盖率、分层单调性）
→ 去重与相关性检查 → 人工提交/审批 → 加入 FactorSet
→ 冻结 FactorSet → 训练 FactorModelRun → 影子运行/人工激活
→ 设置页流水线生成 Score → 回测/决策消费已冻结快照
```

### 2.2 本期包含

- 因子挖掘任务配置、异步进度、取消、失败重试和结果查询。
- 5 步挖掘实验向导：候选池 → 时间与目标 → 字段与校验 → 进化参数 → 进化执行与结果；资源确认改为提交时弹窗。候选池选择完毕后需执行"生成训练物料"，系统自动分析候选池特征（市值分布/行业分布/风格暴露/市场环境/数据质量）并生成分析看板，用户确认看板后才能进入下一步；看板为只读模式，生成训练物料后锁定候选池筛选/导入功能，用户可点击"重新选择"清除分析结果并释放锁定。
- 字段完整性异步校验、数据修复回流、草稿恢复、模板快速开始和训练结果总览。
- **遗传算法范式候选生成**：初始种群由AI生成骨架（40%）+枚举经典因子（30%）+受约束随机生成（30%）混合；逐代执行选择→变异→交叉→评估；每代用短样本快速评估，最终Top因子用全量验证。
- 因子公式 AST 校验、字段/数据源依赖检查、复杂度约束、最近完整交易日预览。
- IS/OOS/ALL 时间切分的 IC、ICIR、覆盖率、分层收益和缺失统计。
- 候选因子去重、与已有因子相关性预警、人工确认。
- 候选因子转正式因子版本，进入已有生命周期和 FactorSet。
- 结果与模型/评分/回测的血缘、数据截止日、过滤配置和审计记录。
- 进化曲线（最优/平均ICIR随代数变化）、种群多样性监控、收敛判断、血缘追溯（每个因子的代数/父代/变异交叉来源）。

### 2.3 明确不纳入首期

- 不新增 PyQt 桌面端、DEAP 依赖、Airflow/ClickHouse 或分布式训练。
- 不自动激活因子或模型，不自动把候选加入已冻结集合。
- 不把单次 IC 达标等同于可交易策略，不在挖掘任务中直接产出实盘订单。
- AI 只能生成草案、解释和测试建议，不能跳过公式校验、评估门禁或审批。
- **多种群岛屿模型（Island Model）不在本期需求**，仅作为远期演进参考方向（详见 5.1.3）：本期不拆分种群、不做岛间迁移/分岛合岛/分岛界面，只在数据结构预留可空字段。本期单种群内以"赛道竞争"维持因子类型多样性。

### 2.4 当前数据就绪结论（2026-09-06）

当前本地因子仓库可用，日线行情最新至 2026-09-04，约 217 万行；但仓库健康为 `degraded`，不能把“已有源表”误认为“全市场、全历史、可生产评估”。首期挖掘范围必须按字段能力约束：

| 数据类别 | 当前能力 | 首期用途 |
|---|---|---|
| 开高低收、量额、换手率 | 连续日线；`turnover_z20` 截面覆盖约 99.7% | 可作为 MVP 主输入，支持时间序列/截面因子评估 |
| 估值快照 | 原始表含 PE_TTM、PB、股息率、总市值、流通市值；当前 DSL 仅注册 PE_TTM、PB，数据截至 2026-08-27，且仅允许 2026-08-01 后增量使用 | 先将未注册字段补入字段目录、PIT 校验和 readiness 后开放；所有估值研究禁止伪造历史 IC |
| 财报 | 原始表含 ROE_TTM、净利润、营收、净利润同比、营收同比，按公告日 PIT；当前约覆盖 2,010 标的，已注册字段以 ROE_TTM 为主 | 先限定高流动性股票池；新增字段须完成公告日映射、字段目录和覆盖门禁后开放 |
| 主力资金 | 约 320 标的、70 日连续，最新至 2026-08-24 | 仅限该覆盖池的观察/试验；达成完整性和复权口径验证前禁止正式训练 |
| 龙虎榜、热度 | 事件数据/当前快照，非连续横截面 | 仅事件研究、解释或候选增强，不用于全周期 IC 或常规回测 |
| 尾盘分钟代理 | `blocked`，仓库无数据 | 本期禁止进入 Testing、Shadow、Active 或 Ridge |
| 宏观 | 可作市场状态条件 | 仅作 regime 条件，不作为个股横截面因子 |

因此，首个验收股票池应选用行情覆盖完整的 A 股子集，优先验证价量/换手类公式；估值、财报和资金流作为按覆盖范围逐步开放的增强层。指数数据和用户自定义宽表均尚未形成可直接用于公式 DSL 的受控输入，属于后续数据接入项。

**首期降级策略：** 财报和估值字段的补齐不阻塞 MVP 交付。首期挖掘默认只使用已通过 readiness 的价量和换手率字段（覆盖率约 99.7%），即可完成候选生成、评估和筛选的完整闭环；财报、估值等字段在完成 PIT 校验和覆盖门禁后逐个开放，用户可在字段选择页看到每个字段的可用状态。

### 2.5 财报 ROE 补齐方案

可以补齐。当前项目已有按标的同步财务分析历史、按 `announcement_date` 保留同报告期不同公告版本、`financial` 增量/回填/缺口修复任务，以及同步后镜像至 DuckDB 的链路。补齐按以下顺序实施：

1. 先以固定的可交易股票池（建议沪深 300 / 中证 500 或高流动性 300–500 标的）执行财报历史回填，保留原始响应摘要和来源时间。
2. 对每个标的校验 `report_period`、`announcement_date`、`roe_ttm`，同公告日多版本按可审计规则去重；无公告日或 ROE 的记录不得以报告期替代。
3. 镜像后按交易日执行 `announcement_date <= trade_date` 的 as-of PIT join；仅在公告后日期可见，禁止向前回填。
4. 以股票池为单位计算每个交易日覆盖率、连续报告期数、公告日延迟和异常值比例；不达门槛的标的/日期从评估样本排除并写入统计。
5. 通过数据质量门禁后，先开放 ROE/ROE 同比等财报因子至 Testing；完成 OOS、成本和影子观察后才可进入正式模型。

补齐验收不以“表中有记录”为标准：目标池内有效 ROE 覆盖率、PIT 泄漏检查、历史连续性、异常/缺失比例和同步失败重试率均须达到配置门槛。全市场历史覆盖受上游接口可获得历史、限流和缺失报告影响，不能承诺一次任务完全补全；任务应分片、可续跑、可重试，并优先保障首期目标股票池。

**补齐失败降级：** 若财报补齐因上游限流、数据缺失等原因未达门禁，不阻断因子挖掘功能上线。未通过门禁的财报字段在字段选择页标记为"暂不可用"，用户仍可使用价量和换手率字段完成完整的挖掘闭环；财报字段待补齐通过后自动开放。

### 2.6 已确认的产品硬规则

- 股票池过滤后有效标的数少于 50 时，任务阻断；50 是系统硬下限。
- 全系统训练任务最多保留一个 `queued` 或 `running` 任务。任何再次点击运行的请求，后端先检查并直接拒绝，不创建第二个排队任务。
- 已完成任务的未引用中间数据默认保留 7 天；任务详情提供手动提前清理，且不得删除仍被模型、评分、回测或审计引用的数据。

### 2.7 体验优化变更审核结论（2026-09-07）

体验优化变更文档中的 C01-C13 已纳入本需求，但以下规则经过工程审核后按本节执行：

- 挖掘实验向导由 8 步精简为 5 步。模板“直接开始”只能预填并跳过填写页面，不能绕过候选池快照、字段完整性校验、最终准备校验、资源确认或挖掘任务锁。
- 用户勾选的字段必须全部通过深度校验，系统不得自动剔除、降级、填零或用其他字段替代。校验任务可以异步运行、分片和续跑，但不占用全局训练任务锁；同一草稿的相同配置不得重复运行校验。
- 校验失败只提供“重新选择字段”和“去修复数据”两个主路径。去修复数据前保存草稿，用户从数据修复页面明确点击返回后才自动触发重新校验，不根据外部同步状态猜测修复完成。
- 训练提交前增加秒级最终准备校验，负责跨步骤一致性、校验有效期、资源和任务锁，不重复执行字段深度扫描；字段校验有效期默认 24 小时，可配置。
- 训练跟踪展示进化进度（当前代数/最大代数、收敛状态、种群多样性），实时更新进化曲线（最优/平均ICIR）和当前种群Top因子排行榜，用户可随时查看已进化候选详情，不等全部完成。提供中断（暂停，保留现场可续跑）、提前停止（保留已进化结果进入最终验证）、完全放弃三种操作。每代用短样本快速评估，最终Top因子用全量验证。
- 取消/失败任务在保留期内保留 checkpoint，用户可选择续跑或完全放弃；只有完全放弃或清理策略到期才删除可续跑数据。训练完成后进入结果总览，不自动激活因子或模型。
- 模板支持系统预设和个人两类，保存规则不保存具体股票代码和计算结果；模板版本、规则哈希和使用时的数据截止日必须进入训练快照。部分模板只能作为草稿，配置完整并通过全部校验后才可执行。单用户场景下不涉及团队共享和权限控制。
- **每代评估与最终验证：** 遗传算法每代个体使用短样本（默认1年）快速评估ICIR/覆盖率/换手率，用于选择种子；进化结束后对最终种群Top 50做全量验证（完整训练区间），计算精确IC/ICIR/分层收益并通过门禁。相似度计算采用三层指纹预筛（语义类别→统计指纹→采样相关），只对可疑对算全量精确相关。被淘汰个体不物理删除，元数据和短样本评估结果完整保留，记录代数、父代、操作类型和淘汰原因。

## 4. 页面与职责

### 4.1 设置 → 因子中心

保留现有设置页承载方式，因子中心内部页签建议固定为：总览、因子库、因子编辑器、评估实验室/因子挖掘、审计。因子模型作为设置下独立页签，不嵌入挖掘向导。

- 因子库：按状态、来源、类别、关键词分页；查看版本、依赖、引用关系。
- 编辑器：新建草稿/版本，填写公式、方向、参数、缺失策略、经济含义和数据依赖；保存前必须校验。
- 评估实验室：选择因子版本、股票池、区间、目标周期和过滤配置；预检通过后创建异步评估任务。
- 评估实验室/因子挖掘：创建候选公式实验、评估 IC/分层收益和稳定性、去重，并将人工确认的因子版本加入 FactorSet；不训练 Ridge、不生成评分、不激活模型。
- 审计：查看状态迁移、评估、训练、影子、激活、回退和失败原因。

候选股票池采用互斥入口：同一候选池页面顶部提供“条件筛选”（默认）和“外部导入股票池”两个 Tab，切换前确认清空当前未保存配置，切换后只显示当前方式内容，不同时展示或合并。外部导入必须使用系统模板并按股票代码匹配主数据；条件过滤只使用系统已有行情、估值、财报和资产标签。候选池保存后写入 `source_type` 且不可切换，改变方式必须新建候选池。

首期训练范围固定为 A 股，不提供地域筛选；条件过滤页采用左侧“常用区间”选项卡和右侧纵向可折叠分类：预设覆盖市值、PE/PB、近 N 日日均成交额和上市交易日数，且由后端按数据截止日、A 股有效样本分位数生成；条件变化后 300ms 防抖刷新预览，生成候选池时必须由后端重新计算并冻结快照；右侧依次展示市场与交易状态、风险标记、估值与市值、盈利质量、流动性、上市时间、行业。分类之间有分隔线，单类可收起，标题展示已选条件数并支持仅清除该类。预设最终必须展开为实际边界、样本范围、数据版本和数据截止日写入快照，不能仅存“低估值/大盘”等文案。

行业首期来自资产主数据的当前标签，可用于 A 股候选池创建并随快照固化，但不能用于训练期逐日 PIT 筛选、行业中性化、行业横截面缺失填充或历史行业暴露分析。地域筛选从本期需求中移除；导入或筛选结果出现非 A 股资产必须拒绝。后续扩展其他地区时另行增加市场范围、数据源和门禁设计。

### 4.2 设置 → 因子模型

该页不编辑因子或集合，只负责运行：

- 因子功能开关、仓库健康、最新完整交易日。
- 训练窗口、验证窗口、测试窗口、调仓频率、风险监控/退出频率、预测持有期、数据截止日、是否训练、是否物化评分。调仓频率表示信号重算和常规换仓节奏，不表示锁仓；月频下仍允许按日执行停牌、退市、流动性失效和已配置风控规则的强制退出。默认按有效调仓点的时间顺序 60%/20%/20% 切分，用户可自定义三段比例或日期边界；比例总和必须为 100%，且不得破坏时间顺序、各段最低样本数和数据门禁。禁止随机切分；切分边界执行按持有期的 purge/embargo，避免未来标签穿越。风险退出规则改变持有路径时，必须重新生成目标标签并重新校验。
- 训练开启时必须显式选择 `frozen` 且 readiness 通过的 FactorSet；多集合时禁止默认第一项。
- 阶段展示：数据准备 → 因子公式计算 → 目标生成 → 单因子评估 → 去重/人工确认；不包含 Ridge 训练、评分生成或模型激活。
- 查看任务进度、ETA、取消、重试；失败保留上一个可用模型和评分。

挖掘实验向导统一采用 5 步状态机。Step 1-3 的草稿可长期保存并支持多个草稿并存；Step 3 的深度校验为异步任务，Step 4 提供简单/高级进化参数模式（简单模式只显示进化强度滑块，高级模式展开种群大小/代数/变异率/交叉率等全部参数），Step 5 在同一页面承载进化执行跟踪和结果总览。提交按钮必须经过最终准备校验和资源确认弹窗，资源确认不单独占步骤。向导完成后仅产出候选因子评估结果，不创建或激活因子模型。

## 5. 功能需求

### 5.1 候选生成（遗传算法范式）

输入必须包含 `universe_id`/股票池快照、`data_cutoff_at`、调仓频率、目标收益周期、种群大小、最大代数、选择比例、变异率、交叉率、随机注入率、收敛阈值、随机种子和初始种群来源配置。

**初始种群生成：** 采用**两层结构**——经典因子是独立的"保底底座"（优先保证6类维度覆盖），AI生成和受约束随机负责"探索剩余名额"。经典不与AI/随机放在同一比例池竞争（避免用户调小经典比例导致维度覆盖不全、失去保底意义）。

**第一层：经典因子底座（独立保底）：**
- 系统预设25个经典因子模板，按6类分组（趋势类5个、反转类4个、波动率类4个、估值类4个、质量类4个、量价类4个），每个模板带参数占位符和参数范围，参数网格展开后入库。模板在设置→因子基础配置→因子模板配置中维护，系统预设不可删除，个人模板可增删改。
- 用户可勾选启用哪些类别（默认全选）、设置经典数量上限（默认40，硬上限不超过种群大小60%）、选择覆盖策略。
- 覆盖策略：**均衡覆盖（默认）**每启用类别均等分名额（floor(上限/类别数)，余数按类别优先级补），保证6类都有代表，某类候选不足或字段未选时缺口流转其他类；**优先级覆盖（可选）**所有模板按优先级+复杂度统一排序取Top。
- 字段联动：估值/质量类依赖估值/财报字段，Step3未选对应字段时该类别置灰不可选。可完全关闭经典底座（全部名额交AI+随机）。实际入库数有多少合格用多少，不硬凑。

**第二层：AI/随机探索（填充剩余名额）：**
- 剩余名额 = 种群大小 − 经典实际入库数，由AI和随机按比例分配。
1. **AI生成骨架（默认占剩余57%）**：大模型根据市场环境生成有经济逻辑的公式骨架，参数展开后填充。AI生成在**可调约束盒子**内运行，用户可配置自由度：最大公式长度（3~8算子）、最大嵌套深度（1~3）、最大字段引用数（1~4）、窗口期范围、允许算子子集、允许字段子集、创新程度（保守/中等/激进）、类型严格度（宽松/严格）、禁止结构。提供保守探索/平衡模式/激进探索三个预设。约束同时作用于Prompt约束层和系统校验层。AI生成时参考经典模板作为Few-shot示例，并注入已入库经典公式避免重复；AI生成的优质因子可保存为个人模板反哺模板库。
2. **受约束随机生成（默认占剩余43%）**：字段自动分类（价格/成交量/估值/质量/换手率）+算子类型系统（输入类型→输出类型）+类型匹配约束+复杂度上限（算子≤4、嵌套≤2、字段引用≤3）的随机组合，保证种群多样性。核心作用：防止种群趋同、提供变异交叉的基因原材料、探索人类和AI都没想到的组合、防止局部最优。
- AI:随机提供三个预设：保守探索40:60、平衡57:43（默认）、激进探索70:30。AI不足由随机补，AI API失败时其名额全部由随机填充，仍不足允许种群略小于目标（不硬凑重复因子）。

**数量链路与冗余系数：** 各来源按"目标数量×冗余系数（默认2.0，高级可配）"超额生成（经典展开60~80、AI约20骨架×2~3展开、随机目标×2），经校验（损耗10~20%）、来源内去重（15~25%）、跨来源去重（约10%）后，按"先锁定经典底座→AI取Top→随机补足"顺序入库。

**四层去重（控制AI/随机高重复，生成顺序经典→AI→随机，后生成能看到先生成的）：** ①生成时规避（AI分批生成+Prompt注入已有列表+类型配额+去重重试最多3次；随机实时哈希拦截+同AST结构最多3变体+分层采样）；②formula_hash精确去重（交换律归一，完全相同只留1个，保留优先级经典>AI>随机）；③AST结构相似度聚类（树编辑距离>0.9归组留1个，解决换参数重复）；④运行时因子值相关性去重（每代短样本评估时用三层指纹，相关≥0.95标记eliminated_similar）。最终初始种群结构唯一性>95%。

**两层结构优势：** 经典独立保底保证6类维度不缺、比例易把控；AI/随机弹性探索新颖空间；某来源失败可补位、鲁棒性强；经典结构+AI视角+随机组合在进化中交叉可能产生更优后代；初始就有已知有效因子底座，收敛更快；四层去重防重复。单独使用任一来源都有缺陷：纯经典无新颖性、纯AI无保底且依赖API、纯随机有效率低收敛慢。

**逐代进化：** 每代执行评估→观测→选择→自适应调度→繁殖→校验/停止完整流程：
1. 评估：短样本（默认1年）计算每个体ICIR/覆盖率/换手率/复杂度
2. 观测：D3计算三层多样性健康分，D1更新最优ICIR进步幅度与连续停滞代数（只产信号）
3. 选择：按5.1.1"赛道竞争+多目标评价+锦标赛"选出父代（非简单全局Top），精英保留Top K直接进入下一代
4. 自适应调度（C1）：按5.1.2依据多样性/停滞/代数，计算本代变异率、交叉率、注入率、变异类型比例与跨赛道比例
5. 繁殖：C2四种变异（参数微调/算子替换/字段替换/结构变异，比例由C1定）、C3子树交叉（同赛道/跨赛道比例由C1定）、D2随机注入（注入率由C1定，不固定）
6. 校验与停止：复杂度+去重+字段依赖检查，不合法丢弃用随机个体补；D1在C1自救后仍连续3代无进步则收敛早停

每个候选必须记录：唯一公式哈希、规范化公式、表达式树/执行计划、字段依赖、代数、父代ID列表、操作类型（elite/mutation/crossover/random/ai_generated/enumerated）、随机种子和生成时间。相同规范化公式幂等，不重复入库。

#### 5.1.1 选择机制：赛道竞争 + 多目标评价 + 锦标赛（本期必做）

逐代"选出父代"由三个正交环节叠加，职责分别为：赛道竞争决定"在哪个类型池选、每池选几个"，多目标评价决定"用什么标准判优劣"，锦标赛决定"用什么动作选出父代"。

**（1）赛道竞争（A1）——功能需求**
- 因子固定分为6类赛道：trend趋势/reversal反转/volatility波动率/valuation估值/quality质量/volume_price量价；每个候选在生成时按AST规则确定主类别并存储category，命中多类按 quality>valuation>volatility>volume_price>reversal>trend 优先级归类，trend为兜底类。
- 每代选择在赛道内独立进行，不跨赛道比绝对ICIR。配额采用"保底+动态"：活跃赛道（有存活个体且用户选了对应字段）按选择名额的60%均分保底，剩余40%按各赛道最优个体质量加权分配；空赛道关闭、保底名额释放；某赛道连续3代最优个体都处于最差层且低于预筛门槛，则其保底名额减半转出给强赛道（防保护落后），恢复后还原。
- 变异以同赛道为主；交叉默认80%同赛道、20%跨赛道，跨赛道交叉须通过字段依赖与复杂度校验；变异改变类别的后代重新归类。
- 每代产出类型均衡度 category_evenness（0~1，越接近1越均衡）并记录，用于多样性监控；结果端按6类分组展示有效因子数量（类型验收），某类为0如实提示。

**（2）多目标评价（B1，NSGA-II）——功能需求**
- 第一期默认4个目标：ICIR↑、覆盖率↑、换手率↓、公式复杂度↓（最小化方向系统内部统一处理）；另提供OOS稳定性、分层单调性两个可选目标默认关闭；与已有因子相关性（<0.95）不参与多目标，仍走硬门禁。
- 启用目标数限定3~5个；目标池系统内置、方向锁死，用户只能开关目标/选偏好，不能自定义目标。
- 系统对每代个体做非支配分层（rank）并在同层计算拥挤度（CD），比较规则为"先比rank、同rank比CD"，不使用加权总分。该计算为内部实现，界面不得出现帕累托/非支配/拥挤度等术语。
- 需新增"换手率"指标口径：Top20%组合每期换仓比例；ICIR、覆盖率已有，复杂度在公式生成时即得。
- 用户通过"选优偏好"表达取舍：balanced均衡（默认）/stable稳健/aggressive进攻/simple简洁；偏好不进入进化计算（保持客观），仅作用于最终结果排序与前沿高亮。

**（3）锦标赛选择（B2）——功能需求**
- 每条赛道内随机抽取 K=3 个个体，用"(rank升、CD降)"取最优出线，重复至该赛道配额满；允许重复抽中；固定随机种子可复现。
- 锦标赛K高级可调（2~7，默认3）；精英保留个体不参与锦标赛、直接进入下一代。

**（4）配置与界面需求**
- 配置位于Step4进化参数页。简单模式仅显示"选优偏好"单选（默认均衡，可不选），赛道竞争/多目标/锦标赛默认开启并自动使用推荐参数；高级模式折叠展示：赛道竞争（保底比例默认0.6、弱赛道判定代数默认3、跨赛道交叉率默认0.2）、多目标（目标勾选，3~5个限制，方向只读+口径说明）、锦标赛K（默认3）。
- Step5结果端：提供6类有效因子数量分布图（可按类过滤）、帕累托前沿散点图（X换手率/Y ICIR，颜色=覆盖率，大小=复杂度，第一前沿高亮，坐标轴可切换，偏好档位一键重排，悬停显示4目标值与公式）；因子列表默认按rank→CD排序并展示category与4目标值，最终因子由用户人工确认、不自动激活。

**（5）明确不纳入本期的机制**

以下机制经评估后明确排除在本期开发、排期与验收范围之外，不得在本期代码中混入相关逻辑：

| 机制 | 不做理由 |
|------|---------|
| D4 Tabu 禁忌表 | 与C2变异后的formula_hash去重+三层指纹相似度预筛功能高度重叠，重复建设 |
| D5 年龄结构淘汰 | 与B1多目标选择标准冲突（都在选择阶段决定父代，D5给老个体打折等于篡改B1的rank+CD比较结果），且与精英保留直接矛盾 |

未来如重新评估需单独立项。

#### 5.1.2 繁殖与自适应机制：C1/C2/C3 + D1/D2/D3（本期必做）

C1/C2/C3 合并为一个繁殖模块，D3只产信号、C1只做调度、C2/C3/D2只做执行、D1只做停止，观测—决策—执行三层分离，禁止两个机制同时写同一参数。

**（1）C1 自适应调度器**
- 输入：D3多样性健康分、D1停滞代数与进步幅度、当前进化阶段（早/中/后期）。
- 输出本代繁殖策略：变异率/交叉率/注入率、C2四种变异类型占比、C3跨赛道交叉比例；实际值落库，固定种子下可复现。
- 调节规则：早期广撒网（变异率约0.70、结构/字段变异为主、跨赛道偏高）；中期均衡；后期精修（变异率约0.45、参数微调为主）；停滞自救（健康分<0.5持续2代或停滞2代时变异率提至0.75、注入提至0.15、结构变异与跨赛道拉高）；快速进步时降扰动。
- 安全护栏：三率夹在变异[0.40,0.80]/交叉[0.10,0.50]/注入[0.05,0.20]，三率和归一为1；连续2代才调、单次调幅≤0.10防震荡；精英永不参与变异交叉；安全上下限锁死不暴露。

**（2）C2 四种变异 / C3 子树交叉（执行器）**
- C2提供参数微调、算子替换、字段替换、结构变异四种操作，类型比例严格由C1决定、自身不定比例；字段替换只能在用户已选字段范围内；变异后过AST/复杂度/字段依赖/去重校验。
- C3子树交叉的同赛道/跨赛道比例由C1决定（基准80/20，停滞拉高、后期降低），后代重新归类，校验同上。
- 自适应关闭时才允许用户手动配变异类型比例与跨赛道比例，自适应开启时这两项为"自动"、不可手改（二选一，避免打架）。

**（3）D2 随机注入（执行器）**
- 注入率由C1动态决定（0.05~0.20），不再固定10%；生成受字段范围、算子子集、复杂度上限约束的随机公式，复用初始种群随机生成器；非法丢弃重生成。

**（4）D3 多样性监控（只观测+展示，不调参）**
- 计算三层多样性：类型均衡度（复用A1）、基因型（复用去重AST树编辑距离）、表现型（复用三层指纹相关性/ICIR离散度），等权合成健康分（0~1，高级可调权重）。
- D3只产健康分、写库、画曲线、告警，不直接改任何率（调参统一归C1）；运行中健康分持续偏低时黄色提示"种群多样性偏低，系统已自动加大探索"。
- Step5提供多样性健康分曲线、本代实际变异率/注入率曲线、三层多样性明细。

**（5）D1 收敛早停（先自救、无效再停）**
- 停滞2代先交C1触发自救，自救后仍连续3代最优ICIR提升<阈值才置converged进入最终全量验证，避免高原期误停；D1只负责停止判断，不负责调参。

**（6）配置与界面需求**
- 位于Step4"繁殖与变异"折叠区。简单模式只见"进化强度"（保守/平衡/激进），全部自动、零配置；高级模式可开关自适应、调基线三率、选敏感度、勾选启用哪几种变异。自适应开启时变异类型比例/跨赛道/注入率显示灰色"自动"；关闭才解锁手动。阈值用"敏感度"档位表达，不暴露原始数值。
- 贯通约束：新增任何机制必须登记唯一职责与上下游，禁止双向耦合、禁止重复调参（验收点）。

#### 5.1.3 远期参考方向：多种群岛屿模型（⚠ 不在本期需求）

> **本节为远期演进参考，明确不纳入本期开发、排期与验收。** 本期不拆分种群、不做岛间迁移、不做分岛/合岛、不做分岛界面，仅在数据结构预留可空字段。

**是什么：** 本期在单种群内用"赛道竞争"（按趋势/反转/波动率/估值/质量/量价 6 类因子类型分区、区内竞争、区间保底）维持类型多样性，属于不拆分总种群的"软隔离"。多种群岛屿模型是更进一步的"硬隔离"：把种群拆成多个物理独立、独立进化、定期迁移优质个体的子种群；未来与赛道竞争融合为"岛内分赛道 + 岛间迁移"的两层结构。

**相对本期赛道竞争的增量优势：**
1. 真正独立的多路径搜索：各岛可走不同探索方向（短/长周期、价值/量价、不同复杂度取向），物理隔离不互相拉拽；
2. 更强的局部最优逃逸：某岛陷入局部最优，其他岛优质个体迁移可打破僵局（单种群只能靠随机注入缓慢恢复）；
3. 更高质量的基因交流：迁移的是别的岛已进化过的优质个体，优于未经验证的随机注入；
4. 多样性更持久（硬隔离趋同更慢），且天然适配多进程并行。

**解决赛道竞争的哪些局限：** ①软隔离下各类同处一个基因池，长期可能经交叉逐渐趋同；②赛道只按"因子类型"单一固定维度分区，同类型内无法走多条独立路径；③全局早期走偏时类型分区无法纠偏；④多样性崩溃后仅靠随机注入恢复慢。

**本期不做的原因：** ①规模门槛最根本——每岛需≥约50个体才能有效进化，默认种群100开4岛每岛仅25，反而弱于单种群，有效需总种群150~300+；②单次耗时翻3~5倍（约10分钟→30~50分钟）、内存上升；③多岛调度/迁移通信/多进程同步/分合岛/跨岛血缘/分岛前端，开发约2~3周；④迁移间隔/迁移率/拓扑等配置门槛高。

**未来落地形态（仅参考）：** 弹性岛屿（起跑单种群+赛道竞争，监测到局部最优才分裂、趋同即合并）+ 规模护栏（岛屿数=min(4,floor(种群/50))，种群<150禁开岛）+ 参数自动推导/预设档位（关闭/标准/强探索）+ AI配置顾问（推荐档位、术语翻译、配置体检，规则兜底，AI不可用不影响运行）。

**本期仅预留数据结构（运行时不使用）：** `candidates.island_id`、`generations.island_id`、`candidates.parent_island_id` 可空字段本期恒空；迁移事件表 `factor_mining_migrations` 远期再建。**未来立项条件：** 上线后实际任务反复出现单种群+赛道竞争陷入局部最优、扩大变异率/随机注入仍无法跳出，且用户接受种群提升到200+和更长运行时间时再启动。

#### 5.1.4 AI引导变异（F2，本期必做）

> **定位：因子挖掘进化过程内部的智能增强功能，不是独立模块。** 只在进化过程中起作用，通过C1调度触发，与C2随机变异并列执行。

**是什么：** 当种群停滞或多样性低时，调用大语言模型分析当前种群状态、市场环境、缺失类型，生成有方向的变异建议，和C2随机变异混合执行。解决"随机变异大量无意义组合、停滞时盲目乱碰"的痛点。

**触发时机（不是每代都调，有成本控制）：**
1. D1检测停滞（stall≥2）时必触发——AI分析"为什么停滞、该往哪个方向突破"
2. D3检测多样性低（health<0.5）时必触发——AI分析"当前种群缺什么类型、补什么方向"
3. 每3代定期触发一次——对Top因子做定向优化建议
4. 正常进化（无停滞、多样性足够）时不触发——纯C2随机变异，省AI成本

**与其他机制的边界与联动：**
- **C1（调度器）**：决定F2的触发时机、AI引导变异占总变异的比例（默认30%~50%，停滞/低多样性时提到50%~70%，不超过70%）、根据B1评估的AI变异效果反馈动态调整比例。F2不自己决定调多少。
- **C2（随机变异执行器）**：与F2并列执行，C1分配名额后各执行各的。C2随机变异、F2定向变异，都走相同的AST/字段/复杂度/去重校验管道。AI校验不通过的名额回退给C2。
- **D1/D3（观测器）**：停滞/低多样性时触发F2，把停滞代数、缺失类型传给AI。
- **B1（评估器）**：评估F2引导变异和C2随机变异的效果，分别统计平均ICIR，反馈给C1调整AI比例。AI变异的因子在B1评估中没有特权，和随机因子公平竞争。
- **F1（历史经验库，独立模块）**：F2通过F1的**读接口**查询相关经验作为AI输入参考，不直接操作F1数据。F1和F2的边界见5.7节。

**AI输入输出：**
- 输入：当前种群Top10因子（公式+ICIR+类型）、市场环境、缺失类型、用户选的字段范围、约束盒子（最大公式长度/嵌套深度/允许算子/字段）、F1相关经验Top5
- 输出：5~10个定向变异建议，每个包含目标因子、变异类型（参数/算子/字段/结构）、具体变异内容、自然语言理由
- 输出必须经过AST语法校验、字段范围校验、复杂度校验、三层指纹去重，不合法丢弃，名额回退C2

**效果反馈闭环：** B1对比"AI引导变异因子平均ICIR"vs"随机变异因子平均ICIR"，C1据此动态调整AI比例——AI明显更优则提高比例，明显更差则降低甚至暂停1~2代。持续无效时自动降权，避免AI瞎指挥浪费算力。

**前端展示：** Step4高级模式可开关F2、调AI变异比例上限、选触发敏感度；Step5运行页显示AI引导状态（已触发/未触发+原因）、本代AI变异数/通过数/回退数、AI效果对比（AI平均ICIR vs 随机）、可展开查看AI建议列表（目标因子+变异方向+理由）；结果页因子详情显示来源标签"AI引导变异"及AI建议理由。

**异常处理：** AI调用失败/超时回退纯C2随机变异；AI建议全部校验不通过则名额全部回退C2；用户可手动关闭F2回退纯随机。

#### 5.1.5 超参数元学习（F3，⚠ 未来规划方向，不在本期）

> **明确不纳入本期开发、排期与验收。** 本期C1自适应调度器已覆盖动态调参的核心价值，F3待积累足够历史任务后再立项。

**是什么：** 用元学习自动学习"什么超参数配置在什么任务/市场环境下效果最好"，不是手动调变异率、种群大小这些，而是系统根据历史任务经验自动推荐甚至动态调整超参数。

**本期不做的原因：**
1. **数据门槛**：元学习需要50+历史任务数据才能学到可靠策略，本期系统刚上线没有足够样本；
2. **C1已覆盖核心价值**：C1自适应已经能根据停滞/多样性动态调变异率/交叉率/注入率，F3想做的"动态调超参数"C1已经在做；
3. **超参数空间小**：种群、代数、变异率、交叉率、注入率就那么几个，都有标定默认值，简单模式零配置，不需要元学习；
4. **实现复杂收益不明确**：MAML/Reptile类框架实现复杂调试难，因子挖掘场景收益不明确，且本身有过拟合风险。

**未来立项条件：** 系统积累50+已完成历史任务；用户频繁做大量类似任务，超参数调优成为瓶颈；C1自适应明确不够用（出现C1调参后仍持续收敛慢的场景）。未来先做"基于历史任务相似度的超参数推荐"（简单匹配），再考虑真正的元学习。

#### 5.1.6 性能优化：并行评估（G1）+ 公共子表达式缓存（G2）（本期必做）

> **定位：遗传算法评估阶段的性能保障，确保100个体×20代的评估在可接受时间内完成。G1负责"快算"（多进程并行），G2负责"少算"（去重缓存），两者叠加先去重再并行，效果1+1>2。**

**G1 并行评估：**
- 子表达式级并行：G2去重后的唯一子表达式分到多个进程并行计算，每进程算30~40个
- 因子级并行：组装后的100个因子的IC/ICIR/覆盖率/换手率/分层收益等指标计算分到多进程并行
- 进程数自适应：按CPU核心数定，默认`min(6, cpu_count-2)`，根据可用内存自动调整（内存<8GB开4进程，<4GB开2进程，<2GB退化为串行）
- 进程池复用：任务开始时启动一次，全程复用，不每代启动销毁
- 主进程汇总写入：子进程只计算，结果通过共享内存返回主进程，由主进程统一写入DuckDB和日志，子进程不写任何共享存储
- 贪心负载均衡：按子表达式预估复杂度降序排列，每次分配给当前负载最小的进程，避免有的进程早干完等别的

**G2 跨个体公共子表达式缓存（层面1，本期做）：**
- AST遍历提取所有因子的所有子表达式，100个因子平均拆出500~800个子表达式
- SHA-256强哈希去重（算子类型+参数+字段唯一ID+数据快照版本号全部序列化后算哈希），去重后通常只剩150~250个唯一子表达式，去重率约60%~70%
- 唯一子表达式向量化批量计算（500股×300日一次算完，不逐股票循环），结果缓存到DuckDB内存表
- 因子组装时递归查缓存，所有子表达式均已缓存，不触发新计算
- 缓存生命周期与挖掘任务绑定，任务结束释放；断点续跑时持久化到磁盘，恢复时校验数据快照哈希，快照变了自动废弃重算
- 预筛阶段（短样本1年）和全量验证阶段（3~5年）分别建缓存，数据范围不同不混用
- 层面2（父子代增量评估）放P1，本期不做

**G1+G2配合流程：** 100个因子→G2提取子表达式→G2哈希去重（150~250个唯一）→G1分到多进程并行计算→结果汇总写缓存→G1多进程并行组装因子+算指标→主进程汇总写generations表。

**性能目标（遗传算法范式）：** 初始种群生成（AI+枚举+随机，100个体）3分钟内；每代短样本评估（1年×50调仓日×500股×100个体）2分钟内；20代进化总耗时约40分钟；最终全量验证（Top50×300周×500股）10分钟内；端到端总耗时约55分钟。G1+G2叠加后每代目标25~35秒，20代约8~12分钟，端到端约20~25分钟。该目标为基线参考，实际以压测结果为准。

**风险与规避（必须落实，不能只追求速度牺牲正确性）：**

| 风险 | 影响 | 规避措施 |
|------|------|---------|
| 缓存哈希碰撞/语义不等价 | 因子值算错，结果不可信 | SHA-256强哈希（非Python内置hash），哈希包含算子+参数+字段ID+数据快照版本；每代随机抽5个因子用缓存结果与直接全量计算对比，差异超1e-6报警并废弃缓存重算 |
| 缓存污染（错误结果被缓存） | 一个子表达式错，几十个因子跟着错 | 每个子表达式算完后检查NaN/Inf/空值比例，异常不写入缓存标记为failed；缓存表加status字段（valid/failed/computing）；失败记录错误原因，前端展示数据质量问题 |
| 数据竞争/写入冲突 | 任务崩溃、数据损坏 | 主进程汇总写入，子进程不写共享存储；DuckDB单连接写入利用自带锁；进度用原子操作更新；主进程监控子进程心跳，超30秒无响应杀了重试 |
| 内存爆炸 | OOM崩溃或swap变慢 | 行情数据只读共享内存不复制；缓存矩阵用float32；进程数按内存自适应；每代结束及时释放上一代缓存；因子值矩阵用稀疏存储（大量NaN停牌缺失） |
| 并行结果不一致/浮点误差 | 固定种子不可复现，用户困惑 | 子表达式级并行（每个子表达式单进程内完整计算，不跨进程合并部分结果）；IC/ICIR等指标主进程单线程计算；验收用容差比较（<1e-6算一致）；提供串行严格复现模式兜底 |
| 去重率不达预期 | 缓存收益打折 | 每代统计去重率并写入generations表，前端展示；持续<40%提示用户减少字段范围或降低AI创新度；基础计算（字段引用、常用均线/排名）总是预计算缓存，去重率100% |
| 并行效率不达标 | 只快3~4倍而非6倍 | 进程池复用避免启动开销；贪心负载均衡按复杂度分配；大任务优先分配；子进程只返回结果矩阵（共享内存零拷贝），不返回日志/调试信息；每代监控并行效率，持续<50%自动减少进程数 |
| 进程崩溃/异常 | 任务卡死 | 子进程每5秒发心跳，主进程超30秒杀了重试；同任务重试3次失败标记跳过不阻塞；崩溃不影响主进程和其他子进程；错误汇总任务结束统一展示 |
| 断点续跑复杂 | 恢复不全或结果不一致 | 代级断点（每代结束写checkpoint），不做进程内细粒度断点；缓存可选恢复（快照没变加载缓存省时间，快照变了重算保正确）；恢复后第一代抽5个因子校验一致性 |
| 缓存版本不兼容 | 升级后结果错或崩溃 | 缓存带schema_version和hash_algorithm_version，恢复时校验不匹配自动废弃；算子定义带版本号，逻辑变了版本+1缓存失效；版本升级写迁移脚本 |

**核心原则：先保证结果对，再追求跑得快。** 缓存和并行都加结果校验兜底，哪怕慢一点也不能算错。G2层面2（父子代增量评估）、G3评估早停剪枝放P1，G4代理模型不做。

### 5.2 评估与门禁

评估必须固定 `factor_version_id`、股票池快照、过滤/PIT 配置、目标定义和数据截止日。输出 IS/OOS/ALL：IC 均值、中位数、标准差、ICIR、覆盖率、有效截面数、分位数组合单调性、最大缺失连续期和样本量。

默认门禁仅作为配置，不写死“IC≥0.08”：覆盖率、最小交易日数、ICIR、OOS 方向一致性和相关性阈值均可配置，并在报告中显示实际阈值。门禁失败只能阻止提交/冻结/训练，不删除候选。

**门禁默认推荐值（用户可修改）：**
- 截面覆盖率 ≥ 80%
- ICIR ≥ 0.3
- OOS 区间 IC 方向与 IS 一致
- 与已有因子相关性 < 0.95
- 有效调仓点数满足最低硬门槛（周频104、月频36、日频252）

评估必须复用现有过滤治理和结构化错误契约，明确 `production_faithful`、`data_cutoff_at`、排除统计和非保真原因。

### 5.3 去重与人工筛选

先按公式哈希去重，再按因子值相关性/残差增量检查。**高度相关定义：** 默认阈值为斯皮尔曼相关系数 ≥ 0.95（计算各调仓日截面因子值排名的相关系数，再取时间序列均值），阈值可配置；高度相关只产生 warning，是否保留由用户确认。候选表支持批量选择、查看证据、提交审批和批量加入 FactorSet，不允许直接激活。

**批量加入 FactorSet 重复处理：** 加入前按 formula_hash 检查目标 FactorSet 中是否已存在相同公式，已存在的跳过并在结果中提示"X 个因子已存在，已跳过"，不报错不覆盖。

### 5.4 生命周期

候选因子沿用现有生命周期：`draft → candidate → testing → shadow → active → deprecated`；非法迁移返回 409 并写审计。因子版本创建后不可覆盖，修改必须创建新版本。FactorSet `draft → frozen → deprecated`，冻结后不可编辑，只能复制为新草稿。

**候选流转说明：**
- `candidate`：挖掘任务产出的候选因子，仅有公式和评估结果，未进入正式因子库
- `candidate → testing`：用户在挖掘结果页点"提交评估"，系统在现有 `factors` 表创建 draft 状态的因子版本并触发正式评估，评估通过门禁后状态变为 testing
- `testing → shadow`：用户手动确认后进入影子运行
- `shadow → active`：影子运行达标后人工审批激活
- 挖掘向导不直接创建 active 因子，必须经过 testing 和 shadow 阶段

### 5.5 模型与流水线

训练输入必须是 frozen FactorSet 的精确成员版本；模型记录 `factor_set_id`、成员版本、训练/验证区间、数据截止日、超参数、权重快照和门禁结果。模型训练完成默认 `validated` 或 `rejected`，不得自动 `active`。

### 5.6 向导提交、跟踪与结果

最终准备校验必须确认 5 步完整、候选池快照成员数不少于 50、时间与目标一致、字段校验未过期、训练参数合法、资源余量达标且不存在 `queued/running` 训练任务。通过后冻结不可变训练快照并获取服务端任务锁。

运行中支持离开页面、后台跟踪、阶段日志、断线补拉和取消。首期模板+网格模式展示候选生成进度和评估进度（已处理/总数），评估完成后展示 IC 分布直方图与 Top 因子列表；逐代 IC 曲线、收敛提示和提前停止为遗传算法模式专属（P3）；遗传算法模式结果页还须提供6类因子类型分布图与多目标帕累托前沿散点图（见5.1.1）。成功或取消评估后展示产出概览、排行榜、公式详情、数据质量说明和后续回测入口，结果不得自动激活。

**回测入口：** 结果页选中因子后可点"回测验证"，跳转到现有回测模块并自动携带因子公式、股票池快照和调仓频率作为回测参数；若现有回测暂不支持单因子回测，首期提供"导出因子公式"功能，回测联动作为后续增强。

**模板完整性校验：** 模板使用前检查配置完整性，不完整的模板禁用"直接开始"按钮，仅允许"查看并修改"，并在模板卡片上标注"配置不完整"。

### 5.7 历史经验库（F1，独立功能模块，本期必做）

> **架构原则：F1是独立于因子挖掘的功能模块，功能内聚、边界明确。因子挖掘只是F1的输入输出一个口子，不与F1的维护逻辑耦合。核心红线保证功能贯穿——挖掘→沉淀→复用→再挖掘的闭环通过明确接口实现，不是模块硬凑。**

#### 5.7.1 定位与架构

**是什么：** 独立的因子经验沉淀与复用模块，负责存储、维护、检索、导入导出历史优质因子骨架。设置中单独开页签（设置→因子基础配置→历史经验库），所有查看、维护、导入、导出、清理、统计功能都在这个独立页面完成，不嵌入因子挖掘向导流程。

**为什么独立：**
1. **功能内聚**：经验库的查看、维护、导入导出、清理是独立的业务功能，有自己的页面和交互，不应和因子挖掘的进化流程堆在一起；
2. **边界清晰**：F1不需要知道因子挖掘的内部流程（进化、选择、繁殖），因子挖掘也不需要知道F1的内部维护逻辑（清理、标签、导入导出）；
3. **可独立演进**：F1的功能（第三方格式兼容、共享库、智能推荐）可以独立迭代，不影响因子挖掘的核心流程；
4. **单用户场景**：单用户无多租户权限，F1库可放共享目录多项目共用，独立模块更易管理。

**和因子挖掘的边界：**
- F1不知道因子挖掘的进化、选择、繁殖等内部机制，只提供"存经验"和"取经验"两个接口；
- 因子挖掘不知道F1的清理、标签、导入导出、统计等维护逻辑，只调用F1的存取接口；
- 两者通过明确的API接口交互，不直接读写对方的数据库表；
- F1的维护页面完全独立，用户不需要进入因子挖掘流程就能管理经验库。

#### 5.7.2 和因子挖掘的两个接口（核心红线贯穿）

因子挖掘和F1之间只有两个明确的接口，这是唯一的交互通道：

**接口1：输出口子（因子挖掘→F1，唯一写接口）**
- 触发时机：因子挖掘中，因子经过全量验证有效且人工确认入库后，自动存回F1；
- 传递内容：因子公式AST、类型、复杂度、来源、效果数据（ICIR/覆盖率/换手率）、来源任务信息（股票池/市场环境/时间段/字段范围）；
- F1内部处理：参数泛化（具体数值参数替换为占位符）、三层指纹去重、自动分类、自动打标签、写入4张表；
- 因子挖掘不直接操作F1的表，只调用`POST /api/f1/experience`接口提交，F1内部自行处理去重和存储。

**接口2：输入口子（F1→因子挖掘，唯一读接口）**
- 场景A：初始种群生成时，因子挖掘调用`GET /api/f1/experience/sample`，传入任务配置（股票池/字段范围/市场环境/频率），F1内部执行字段硬过滤→场景匹配打分→加权随机抽取→参数实例化，返回N个具体公式加入初始种群；
- 场景B：F2 AI引导变异时，因子挖掘调用`GET /api/f1/experience/related`，传入当前种群Top10和缺失类型，F1返回相关经验Top5作为AI输入参考；
- 因子挖掘不读取F1的维护数据、统计数据、清理状态，只接收最终的抽取结果或相关经验列表；
- F1内部的加权衰减、场景匹配、去重逻辑对因子挖掘透明，因子挖掘只传配置、收结果。

**核心红线贯穿：**
- 挖掘→沉淀（接口1）→复用（接口2）→再挖掘的闭环通过这两个接口实现，不是模块耦合；
- F1中标记的"优质经验"在抽取时权重更高（F1内部处理，因子挖掘无感知）；
- F1中归档/删除的经验在抽取时自动排除（F1内部过滤，因子挖掘无感知）；
- F1的经验使用效果（成功/失败）通过接口1的反馈更新F1内部的use_count/success_count，形成正向循环。

#### 5.7.3 F1独立页面功能

**页签位置：** 设置→因子基础配置→历史经验库（独立页签，与因子模板配置并列）

**页面功能（4个Tab）：**

1. **概览Tab**：
   - 统计卡片：总经验数、本月新增、总使用次数、平均成功率、库大小；
   - 图表：类型分布饼图（6类）、来源分布饼图（AI生成/随机/经典模板/手动/第三方导入）、积累趋势折线图（按周/月新增）、成功率分布柱状图、ICIR分布直方图；
   - 快捷操作：导入、导出、生成清理建议。

2. **经验列表Tab**：
   - 列表字段：公式模板（过长折叠）、类型、来源、创建时间、最后使用时间、使用次数、成功率、平均ICIR、状态（正常/优质/归档/待补字段/不可用）；
   - 筛选：按类型/来源/状态/时间范围/最小成功率/最小ICIR筛选；
   - 排序：按创建时间/使用次数/成功率/ICIR排序；
   - 搜索：按公式关键字搜索；
   - 批量操作：批量导出、批量标记优质、批量归档、批量删除；
   - 点击某条→详情弹窗（公式结构、标签、效果历史曲线、使用记录、关联因子、操作按钮）。

3. **导入导出Tab**：
   - 导入：3种方式（上传文件JSON/CSV、共享库同步、从其他项目拷贝），自动解析预览→确认范围→异步执行→导入报告（成功/更新/过滤/缺字段/格式错误各多少条）；
   - 导出：选择范围（全部/按筛选/勾选）、选择格式（系统JSON完整/通用CSV简化/第三方兼容格式预留）、选择内容（是否含效果数据/标签/字段依赖、参数模板还是具体公式），生成文件下载；
   - 第三方格式：首期支持系统JSON+通用CSV，预留WQ Alpha/qlib等第三方格式转换接口（插件式，新增格式只需写转换器）。

4. **清理建议Tab**：
   - 系统每季度自动生成清理建议（也可手动生成），消息中心通知；
   - 三类清单：待清理（超3年且成功率<20%）、过期（超5年且成功率<30%）、不可用（字段已废弃）；
   - 每条显示系统建议（归档/删除/保留/重新验证），人工可逐条改主意或一键"按建议批量清理"；
   - 默认建议是归档不是删除（保守，可恢复），删除有二次确认；
   - 清理完成显示报告（归档/删除/保留各多少条、释放多少空间）。

#### 5.7.4 数据自动沉淀与反馈机制

- **自动存回**：因子入库后通过接口1自动存回F1，不需要人工额外操作；
- **自动去重**：存回时三层指纹比对，重复的不重复插入，只更新use_count和效果数据；
- **自动打标签**：从来源任务提取市场环境/股票池/时间段/字段范围标签；
- **自动加权**：按时间衰减/场景匹配/历史效果/成功率自动计算抽取权重，不需要人工调；
- **自动反馈**：经验被抽取使用后，实例化因子的验证结果通过接口1反馈，更新use_count/success_count/效果数据，成功率高的经验权重自动提高，形成正向循环；
- **自动过期标记**：超过时间阈值且成功率低的经验自动标记过期/待清理，抽取权重降低。

#### 5.7.5 共享库模式（单用户推荐）

- 单用户场景下，F1库文件可配置为共享目录路径（如`D:\ai_project\shared\factor_experience.duckdb`），多个项目实例读写同一个库；
- A项目积累的经验B项目直接能用，连导出导入都省了；
- DuckDB单文件支持并发读，单用户场景写入冲突概率极低，加文件锁防止并发写入；
- 每个经验记录origin_project_id（来自哪个项目），但所有项目都能检索使用；
- 不配置共享目录时，每个项目使用自己的本地F1库，通过导入导出迁移。

#### 5.7.6 与F2的边界重申

- F2是因子挖掘内部的功能，通过F1的**读接口**（接口2场景B）查询相关经验作为AI输入，不直接操作F1数据；
- F2不读取F1的维护数据、统计数据，只接收相关经验列表；
- F1不知道F2的存在，只提供通用的"相关经验查询"接口，调用方是F2还是其他模块对F1透明；
- 两者通过接口解耦，F2的改动不影响F1，F1的维护逻辑改动不影响F2。

## 6. 验收标准

1. 用户可在页面完成候选创建、校验、评估、筛选、审批和加入 FactorSet。
2. 候选、因子版本、FactorSet、模型、Score 均可按 ID 和版本回查，历史引用不可漂移。
3. 评估和流水线均显示数据截止日、股票池、过滤配置和任务阶段。
4. 训练开启时无 frozen 集合或存在多个集合未选择时，接口明确阻断，不静默选择。
5. 失败任务不覆盖活动模型、上一批评分或手工回退配置；可重试任务返回 retryable。
6. 非法状态迁移、激活、回退和审批均有 actor、reason、时间和对象快照审计。
7. 现有因子、设置、组合、回测、交易和告警回归测试通过。
8. 默认 5 步流程、模板快速开始、字段异步校验和提交最终校验均不能绕过服务端门禁。
9. 用户选择的字段有任一阻断项时不能进入训练；不允许静默降级或自动排除字段。
10. 训练失败/取消可在保留期内从 checkpoint 续跑；提前停止保留结果并进入总览；结果页不自动激活模型。
11. 选择机制验收：固定随机种子下每代父代选择可复现；父代按赛道配额产生、任一活跃赛道不低于其保底名额（弱赛道流转除外）；个体比较严格遵循"rank优先、同rank比拥挤度"，不出现为多样性选中更差层级个体的情况；启用目标数限制在3~5个、用户无法自建目标或更改目标方向；结果页类型分布图与帕累托前沿散点可正常渲染，偏好档位仅改变展示排序、不改变进化结果。
12. 繁殖自适应验收：D3只产出健康分与曲线、不直接改任何率；C1是唯一修改变异率/交叉率/注入率/变异类型比例/跨赛道比例的模块，C2/C3/D2严格按C1策略执行、不自带比例；三率始终在安全区间且和为1；停滞2代先触发C1自救、连续3代自救无效才D1早停；每代实际繁殖策略落库且固定种子可复现；自适应开启时前端变异类型/跨赛道/注入率为灰色自动态，关闭后才解锁手动配置；不存在两个机制同时写同一参数。
13. AI引导变异（F2）验收：F2仅在停滞(stall≥2)、多样性低(health<0.5)或每3代定期时触发，正常进化不调用AI；C1是唯一决定AI引导变异比例的模块，比例不超过70%，F2不自行决定比例；AI输出必须经过AST/字段范围/复杂度/三层指纹去重校验，不合法的丢弃且名额回退C2随机变异；B1分别统计AI引导变异与随机变异的平均ICIR并反馈C1，C1据此动态调整比例（AI持续无效时自动降权甚至暂停）；AI调用失败/超时自动回退纯C2随机变异不阻塞进化；Step5显示AI引导状态（触发/未触发+原因）、本代AI变异数/通过数/回退数、AI效果对比、AI建议列表（含自然语言理由）；结果页因子详情显示来源标签"AI引导变异"及建议理由；F2通过F1读接口查询相关经验，不直接读写F1数据表。
14. 历史经验库（F1）独立模块验收：设置→因子基础配置下存在独立的"历史经验库"页签，包含概览/经验列表/导入导出/清理建议4个Tab，所有查看维护功能不嵌入因子挖掘向导；因子挖掘与F1之间仅通过两个接口交互（输出口子：因子入库后自动存回；输入口子：初始种群抽取+F2相关经验查询），不存在因子挖掘直接读写F1表、或F1调用因子挖掘内部逻辑的情况；F1内部的字段过滤/场景匹配打分/加权随机抽取/参数实例化对因子挖掘透明，因子挖掘只传配置收结果；F1中归档/删除/优质标记的经验在抽取时自动过滤或加权，因子挖掘无感知；经验被使用后的验证结果自动反馈更新use_count/success_count，成功率高的经验抽取权重自动提高；导入支持系统JSON+通用CSV，自动解析预览、去重、字段校验、异步执行、返回导入报告；导出支持按范围/格式/内容选择；清理建议每季度自动生成，默认归档不删除，人工确认后执行；共享库模式可配置共享目录路径，多项目读写同一库；F1与F2通过接口解耦，F1不知道F2的存在。
15. 性能优化（G1+G2）验收：G2正确执行AST遍历提取所有子表达式、SHA-256强哈希去重（非Python内置hash）、唯一子表达式向量化批量计算、因子组装时递归查缓存不触发新计算；每代统计子表达式总数/唯一数/去重率并写入generations表；缓存生命周期与任务绑定、断点续跑校验数据快照哈希、快照变了自动废弃；预筛与全量缓存分开。G1正确执行子表达式级并行+因子级并行、进程数按CPU和内存自适应、进程池复用、主进程汇总写入子进程不写共享存储、贪心负载均衡。G1+G2配合流程正确（先去重再并行）。正确性兜底：每代随机抽5个因子缓存结果与直接全量计算对比差异<1e-6，超阈值报警并废弃缓存重算；子表达式计算结果NaN/Inf检查不写入缓存；子进程心跳检测超时杀了重试；代级断点续跑恢复后第一代校验一致性。性能基线：每代短样本评估2分钟内（无G1+G2），G1+G2叠加后目标25~35秒（实际以压测为准）；提供串行严格复现模式兜底。

## 7. 分阶段交付

| 阶段 | 交付 |
|---|---|
| P0 | 5 步向导骨架、候选批次/任务、字段异步校验、最终准备校验、单因子基础评估（IC/ICIR/覆盖率）、结果持久化、分页列表、模板+参数网格候选生成、两阶段评估（短样本预筛+全量评估）、可配置预筛门禁、预筛进度跟踪、IC分布直方图、向导内模板管理 |
| P1 | 分层收益/单调性、门禁配置、去重/相关性预警、审批入口、结果总览、FactorSet 链路、训练血缘、草稿恢复、断点续跑、影子与激活联动、流式边算边杀、与已有因子库比对、三层指纹预筛加速、被预筛淘汰候选展示与复活 |
| P2 | 独立模板管理页面（模板数>20 后）、自由 DSL 公式编辑器（语法高亮+自动补全+实时校验）、高级模板维护、候选评估顺序配置 |
| P3 | 遗传算法适配器（逐代 IC 曲线、收敛提示、提前停止）、AI 解释和报告增强 |

**首期（P0+P1）明确不做：** 逐代 IC 进化曲线、收敛判定、提前停止（均为遗传算法专属，P3 启用）、独立模板管理页面、自由 DSL 编辑器、AI 评价。
