# 受控量化公式 DSL 因子编辑器 UI 交互评测方案

| 项目 | 内容 |
|---|---|
| 版本 | V1.0 |
| 日期 | 2026-08-14 |
| 评测对象 | `FactorFormulaEditorModal`、`FactorFormulaBuilder`、公式校验、预览和版本保存流程 |
| 目标 | 验证专业用户能快速、准确、可理解地创建复杂因子 |

## 1. 评测原则

- 围绕现有 Modal、三栏布局和 Ant Design 组件增量评测。
- 评测“完成任务的效率和正确性”，不只评估视觉美观。
- 所有结论必须有录屏、截图、错误日志或任务数据证据。
- 先验证桌面主布局，再验证窄屏降级。

## 2. 典型任务

| 任务 | 目标 |
|---|---|
| T1 | 用函数库创建 `mean(close, 20)` |
| T2 | 创建 `if(pe_ttm > 30, 0, roe_ttm)` |
| T3 | 使用 `&&`、`||` 完成多条件公式 |
| T4 | 悬浮查看函数参数、窗口范围和示例 |
| T5 | 从错误位置修复未知字段和窗口越界 |
| T6 | 配置缺失值、去极值和标准化 |
| T7 | 预览最近交易日结果并判断覆盖率 |
| T8 | 保存新版本并提交 candidate |

## 3. 布局评测

### 桌面布局

- 左侧字段/函数目录宽度稳定，搜索和分类不跳动。
- 中央编辑器是第一视觉焦点，公式、行号和错误标记不重叠。
- 右侧帮助面板可折叠，展开时不遮挡编辑器和底部操作栏。
- 底部状态栏始终可见，展示校验、依赖和回看窗口。
- 底部“取消 / 校验 / 预览 / 应用并返回”按钮固定且不被内容遮挡。

### 窄屏布局

- 右侧帮助转为底部抽屉。
- 左侧目录转为可打开的抽屉或 Tab，不挤压公式输入区。
- 操作按钮不溢出，不依赖横向滚动完成保存。

## 4. 交互评测指标

| 指标 | 目标 |
|---|---:|
| T1-T2 首次完成率 | ≥ 90% |
| T3 多条件公式完成率 | ≥ 80% |
| 首次找到函数时间 | ≤ 10 秒 |
| 悬浮帮助出现时间 | 200-300ms |
| 错误定位成功率 | ≥ 95% |
| 模式切换后结果一致率 | 100% |
| 因编辑器布局导致的误操作 | 0 个 P0/P1 |
| 普通校验反馈时间 | ≤ 1 秒 |

## 5. 交互检查项

- 鼠标悬浮字段、函数、错误标记显示 Tooltip/Popover。
- 光标进入函数参数后，右侧自动显示当前参数说明。
- 点击函数在光标位置插入，不覆盖已有内容。
- 插入函数后第一个参数自动选中。
- `Ctrl/Cmd + Space` 打开自动补全，方向键和 Enter 可完成选择。
- `Ctrl/Cmd + Enter` 触发校验或预览。
- Esc 可关闭 Tooltip、Popover、抽屉和未提交弹窗。
- 格式化、清空、撤销和重做不会丢失版本状态。
- 预览期间按钮 loading，禁止重复提交。
- API 错误、数据阻断和语法错误视觉层级不同。

## 6. 评测量表

每项 0-4 分：

| 分数 | 定义 |
|---:|---|
| 4 | 无需帮助，快速完成，反馈清晰 |
| 3 | 可完成，有轻微理解成本 |
| 2 | 需要试错或查看外部说明 |
| 1 | 能完成但容易误操作或丢失内容 |
| 0 | 无法完成或结果错误 |

放行条件：核心任务平均分 ≥ 3.2，T2/T3/T5/T8 任一任务不得低于 3 分。

## 7. 评测流程

1. 产品和设计先进行启发式检查。
2. 前端完成桌面和窄屏自测，提交截图和录屏。
3. 量化用户执行 T1-T8，不提供额外口头解释。
4. 记录完成时间、错误次数、求助次数和最终结果。
5. 汇总问题，按 P0/P1/P2 分级并回归验证。

## 8. UI 放行门禁

- 不得有文字、按钮、Tooltip 或错误提示互相遮挡。
- 不得出现函数库与后端实际能力不一致。
- 不得在用户输入期间清空公式或自动覆盖内容。
- 不得因帮助面板展开导致底部主操作不可见。
- 不得以颜色作为唯一状态提示，必须同时有文本或图标语义。
