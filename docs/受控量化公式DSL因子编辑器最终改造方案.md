# 受控量化公式 DSL 因子编辑器最终改造方案

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编制日期 | 2026-08-14 |
| 适用项目 | Personal Quant Workbench / dataAanlystNew |
| 改造目标 | 将当前简单公式编辑升级为可表达复杂因子、可校验、可预览、可版本追踪的专业因子编辑器 |
| 核心原则 | 受控量化公式 DSL，项目函数库，统一 Factor AST，安全编译，版本不可变 |

---

## 1. 最终结论

本项目不改成任意 JavaScript 编辑器，也不采用完全拖拽式搭建。最终采用：

```text
受控量化公式 DSL
        +
项目字段/函数目录
        +
条件与后处理配置器
        ↓
统一 Factor AST
        ↓
现有编译、执行、预览、评估和生命周期流程
```

用户可使用类似 JavaScript 的函数化语法，但只能调用项目白名单中的字段、函数和运算符。前端函数面板、条件配置器和 AI 草稿都必须生成同一套 DSL/AST，不能各自维护一套计算逻辑。

## 2. 当前项目能力与缺口

### 2.1 可直接复用

- `app/services/factors/factor_compiler.py` 已有字段目录、函数目录、AST 白名单、函数参数约束、回看窗口限制、依赖提取、复杂度限制和执行计划哈希。
- 编译器已允许比较、布尔运算和 `IfExp`，具备实现条件分支的底层能力。
- `app/api/routes/factors.py` 已提供 `/factors/validate` 和 `/factors/preview`，可以作为编辑器实时校验和小样本预览的后端基础。
- `FactorVersion` 已包含 `formula_expr`、`formula_ast`、`postprocess`、`parameter_schema`、`data_dependencies`、`compiler_version`、`execution_plan_hash`、`validation_status` 等字段。
- `frontend/src/components/factors/FactorFormulaEditorModal.tsx` 和 `FactorFormulaBuilder.tsx` 已有编辑器、字段/函数插入、校验和预览入口。
- 因子生命周期、Shadow、FactorSet、模型回退和人工审批流程已经存在，本次不改变其状态语义。

### 2.2 需要补齐

1. 前端函数分类与后端 `FUNCTION_CATALOG` 不是同一数据源，存在“前端可见但后端不可执行”的风险。
2. 当前编辑体验缺少统一的 `&&`、`||`、`!`、条件函数和高级公式参数提示。
3. 错误信息需要返回字符位置、参数位置、字段类型、数据覆盖率和可执行建议。
4. `postprocess`、缺失值策略和参数目前偏 JSON，专业用户需要结构化配置。
5. 复杂公式缺少因子引用、依赖图和循环依赖检查。

## 3. DSL 语法规范

### 3.1 基础运算

```js
close / max(prev_close, 0.01)
abs(roe_ttm)
log(max(amount, 1))
sqrt(abs(pb))
pow(momentum, 2)
```

支持 `+ - * / % **`、比较运算 `> >= < <= == !=` 和括号。除零、非法对数、负数开方必须由执行器按统一缺失/无效值策略处理，禁止产生无限值污染因子库。

### 3.2 条件和逻辑

```js
if(pe_ttm > 30 && roe_ttm < 0.1, 0, roe_ttm)
pe_ttm > 30 ? 0 : roe_ttm
close > highest(high, 20) || volume > mean(volume, 20) * 2
!is_null(roe_ttm)
```

第一阶段统一推荐 `if(condition, true_value, false_value)`；三元语法作为兼容写法，编译后统一为 `If` AST 节点。明确 `&&`、`||`、`!` 的优先级和缺失值参与条件时的行为。

### 3.3 项目公式库

#### 数学函数

`abs`、`min`、`max`、`round`、`log`、`sqrt`、`pow`、`exp`

#### 时间序列函数

`sum`、`mean`、`sma`、`ema`、`stddev`、`highest`、`lowest`、`ref`、`pct_change`、`count`

#### 横截面函数

`rank`、`zscore`、`winsorize`、`neutralize`

#### 常用量化公式

`rsi`、`macd`、`bollinger`、`volume_ratio`、`cross_over`、`cross_under`

每个函数必须注册名称、分类、签名、参数类型、取值范围、数据频率、最大窗口、缺失值行为、说明和示例。后端目录是唯一事实来源，前端通过接口加载。

## 4. 编辑器产品形态

采用两个主 Tab，默认进入函数辅助模式：

```text
函数辅助模式（默认） | 高级表达式模式
```

### 4.1 函数辅助模式

- 左侧显示字段、函数、常用模板和已保存因子。
- 点击函数插入带占位符模板，例如 `mean(field, window)`。
- 右侧显示参数表单、类型、范围、示例和当前项目支持状态。
- 条件函数提供“条件 / 满足时 / 否则”三段式配置。
- 后处理提供缺失值、去极值、排序、标准化、中性化表单。

### 4.2 高级表达式模式

- 使用受控 DSL 文本编辑器，支持自动补全、括号匹配、错误定位和格式化。
- 可直接编辑复杂嵌套公式、复制模板和批量修改参数。
- 公式无法反向还原为结构化节点时，标记为“高级表达式”，不强行覆盖函数配置。

### 4.3 结果与风险区

编辑器底部实时展示：

- 依赖字段和数据源
- 最大回看窗口及所需交易日
- 返回类型：数值 / 布尔 / 事件
- 数据覆盖率和缺失原因
- 点时数据、未来函数和频率冲突检查
- 估算复杂度和执行成本

## 5. 编译与执行架构

```text
DSL 文本
  ↓ Lexer/Parser（新增）
规范化 Factor AST
  ↓ 静态校验（复用 factor_compiler）
编译计划 + 依赖 + 哈希
  ↓
DuckDB/现有 factor executor
```

新增轻量 DSL 解析层，将 JS-like 表面语法转换为现有安全 AST；不执行任意 JavaScript，也不使用 `eval`。现有字段白名单、函数白名单、AST 深度、节点数、函数调用数和回看窗口限制继续作为硬约束。

保存规则：

1. 前端只提交 `formula_expr`、参数和后处理配置，不提交可信 AST。
2. 后端保存前强制重新编译。
3. 编译成功后写入 `formula_ast`、`data_dependencies`、`compiler_version` 和 `execution_plan_hash`。
4. 已被回测、评估、FactorSet 或模型引用的版本不可原地修改，必须创建新版本。

## 6. 因子引用与复杂组合

第二阶段增加受控因子引用：

```js
factor_ref("quality_factor", 3) + factor_ref("value_factor", 5)
```

约束：

- 引用必须固定版本。
- 禁止循环依赖。
- 引用因子的频率、资产范围和返回类型必须兼容。
- 依赖图写入 `data_dependencies`，并在详情页可视化。
- 被引用版本保持不可变，避免历史回测结果漂移。

## 7. API 改造

### P0

- `GET /api/v1/factors/formula-catalog`：字段、函数、模板和 DSL 版本。
- 扩展现有 `POST /api/v1/factors/validate`：返回错误码、位置、参数、依赖、窗口和覆盖率检查。
- 保留并扩展现有 `POST /api/v1/factors/preview`：支持指定股票、日期、窗口和缺失策略。

### P1

- `POST /api/v1/factors/compile`：只编译并返回 AST 摘要和执行计划，不落库。
- `GET /api/v1/factors/{factor_code}/dependency-graph`：返回字段和因子引用图。
- `POST /api/v1/factors/{factor_code}/versions/{version}/dry-run`：执行受限样本预览。

### P2

- 因子引用解析、循环依赖检查和执行计划缓存。
- 函数目录的版本管理和废弃兼容提示。

## 8. 数据模型调整

优先复用现有 `FactorVersion` 字段，只新增必要元数据：

| 字段 | 用途 |
|---|---|
| `dsl_version` | DSL 语法版本 |
| `source_mode` | `function` / `expression` / `template` / `ai` |
| `return_type` | `number` / `boolean` / `event` |
| `parse_source` | 原始用户输入，便于审计和迁移 |
| `complexity_score` | 编译器计算的复杂度 |

不新增任意代码字段，不允许保存或执行 Python/JavaScript 源码。

## 9. 实施顺序

### Phase A：编译契约和目录统一

- 定义 DSL 语法、类型和缺失值语义。
- 增加 Parser/Normalizer，将 JS-like 语法转成现有 AST。
- 后端输出唯一函数目录，前端移除重复硬编码目录。
- 补齐 `if`、`coalesce`、`clip`、`rank`、`zscore` 等首批函数。

### Phase B：编辑器升级

- 函数辅助 Tab 默认入口。
- 高级表达式 Tab 和自动补全。
- 条件配置器、参数面板、后处理面板。
- 实时校验、依赖和窗口提示。

### Phase C：预览和生命周期接入

- 编译通过后才能保存为候选版本。
- 预览结果展示覆盖率、缺失率、分布和异常值。
- 沿用 Candidate → Testing → Shadow → Active 流程。
- 保持人工审批、Shadow 观察期和失败回退。

### Phase D：复杂组合

- 因子引用、依赖图和循环检查。
- 复合因子模板和参数化版本。
- 编译计划缓存和执行成本监控。

## 10. 安全与量化正确性

- 禁止 `eval`、导入、属性访问、下标执行、动态函数名、循环和任意变量赋值。
- 禁止负数 `lag`、未来数据字段和不可证明的未来引用。
- 所有点时字段必须带发布时间约束。
- 缺失值不得默认全部填 0，必须按因子类型选择策略。
- 公式、参数、数据截面、编译器版本和执行计划必须进入版本快照。
- 编译失败只能保存为 draft，不能提交 candidate。
- 数据覆盖率不足时阻断正式评估，但允许定义和有限预览。

## 11. 验收标准

### 功能

- 能创建并保存数学、时间序列、条件和常用量化公式。
- `&&`、`||`、`!`、`if` 和三元条件可正确编译。
- 函数模式与表达式模式切换后结果一致。
- 前端显示的每个函数都能通过后端编译和预览。
- 已保存版本可在回测、机会挖掘、预警、复盘和 FactorSet 中复用。

### 安全

- 任意非法 AST、未知字段、未知函数、超窗口和未来引用都返回稳定错误码。
- 不执行任意 JavaScript/Python 代码。
- 旧版本回测结果不因公式修改而变化。

### 性能和可观测性

- 普通公式校验在 1 秒内完成。
- 预览明确返回计算耗时、样本数、缺失率和覆盖率。
- 每次编译可通过 `compiler_version + execution_plan_hash` 复现。

## 12. 不做事项

- 不引入完整 JavaScript 运行时。
- 不允许用户编写任意 Python。
- 不先做遗传编程、表达式树搜索或深度强化学习挖掘。
- 不改变现有因子生命周期、Shadow 观察和模型手动回退规则。
- 不在数据覆盖率不足时通过填 0 制造可用样本。

## 13. 最终产品定义

本项目最终交付的是一个：

> **以函数辅助编辑为默认入口、以 JS-like 受控 DSL 为专业表达方式、以 Factor AST 为统一执行标准、具备静态校验、数据预览、版本冻结和生命周期治理的专业量化因子编辑器。**

## 14. 编辑体验优化

体验目标是让用户在不离开编辑器的情况下，知道“当前可以写什么、参数怎么填、为什么报错、插入后会产生什么依赖”。帮助信息采用上下文悬浮和就近展示，不依赖单独查文档页面。

### 14.1 鼠标靠近字段或函数

当鼠标悬浮在编辑器中的字段、函数或错误标记上时，显示轻量 Tooltip/Popover：

- 中文名称和一句话说明
- 函数签名，例如 `mean(field, window)`
- 参数类型、必填项和允许范围
- 数据频率和最大回看窗口
- 缺失值、除零和非法值处理规则
- 一个可直接插入的示例
- 当前项目是否已启用、是否存在数据覆盖限制

示例：

```text
mean(field, window)
滚动均值
field: 时间序列字段
window: 1-250 个交易日
示例：mean(close, 20)
```

### 14.2 光标上下文帮助

光标位于函数括号内时，右侧参数面板自动切换到该函数，并高亮当前参数。输入 `mean(` 后立即展示 `field`；输入逗号后切换到 `window`。参数不完整时，显示占位符而不是提交错误。

### 14.3 就近插入和自动补全

- 鼠标点击函数项：在当前光标位置插入模板，不覆盖已有内容。
- 拖拽字段或函数到编辑器：在光标附近插入，不采用覆盖式拖放。
- 输入函数名前缀：显示项目函数、描述、签名和示例。
- 输入字段名：同时显示中文名、字段 key、类型和数据源。
- 插入后自动选中第一个参数，方便直接替换。

### 14.4 条件逻辑的可视化辅助

悬浮在 `if`、`&&`、`||` 或三元表达式上时，显示条件结构说明。点击条件函数可打开三段式编辑器：

```text
条件：pe_ttm > 30
满足时：0
否则：roe_ttm
```

编辑器生成 DSL，DSL 修改后仍可回到条件配置器；无法结构化还原的复杂表达式保留在高级模式中。

### 14.5 行内校验与错误解释

- 错误直接标记在对应字符、参数或函数名下方。
- 悬浮错误标记显示错误码、原因和修复建议。
- 未知字段提示“选择项目字段”并提供相似字段。
- 窗口超限显示当前值、允许范围和一键修正入口。
- 未来函数、点时数据和频率冲突使用风险级别区分，不只显示“语法错误”。

### 14.6 公式结构提示

当公式较长或嵌套层级较深时，右侧显示折叠式结构树：

```text
除法
├─ 滚动求和 main_net_inflow, 20
└─ 最大值
   ├─ 滚动求和 amount, 20
   └─ 常量 1
```

点击结构树节点可定位到编辑器对应文本，帮助用户理解复杂因子的依赖关系。

### 14.7 交互性能和可用性约束

- 悬浮提示延迟约 200-300ms，鼠标快速移动时不闪烁。
- Tooltip 不遮挡当前编辑行，必要时自动向上或向侧边翻转。
- 所有悬浮内容必须支持键盘焦点和 Esc 关闭。
- 公式校验采用防抖，输入过程中不频繁请求后端。
- 函数目录、字段目录和最近使用项支持搜索，并记住展开状态。
- 移动端或窄窗口下，右侧帮助面板降级为底部抽屉。

## 15. 改造、新增与去除清单

### 15.1 需要改造

| 模块 | 当前形态 | 改造目标 |
|---|---|---|
| `factor_compiler.py` | Python AST 直接解析受限表达式 | 增加 DSL Parser/Normalizer，保留现有安全校验和执行计划生成 |
| `FIELD_CATALOG` / `FUNCTION_CATALOG` | 后端目录与前端目录存在重复维护 | 后端提供版本化目录 API，前端只消费目录 |
| `/factors/validate` | 主要返回是否通过 | 增加字符位置、参数位置、错误码、依赖、窗口、类型和覆盖率信息 |
| `/factors/preview` | 公式结果预览 | 增加指定股票、日期、样本量、缺失策略和预览诊断 |
| `FactorFormulaEditorModal` | 编辑器、左侧插入列表和底部按钮 | 保持现有 Modal 和三栏骨架，增加模式 Tab、上下文帮助、行内诊断和结构摘要 |
| `FactorFormulaBuilder` | 字段/函数树和点击插入 | 改为后端目录驱动，支持签名搜索、参数模板、最近使用和悬浮说明 |
| 参数 JSON | 直接输入 JSON | 改成结构化表单，同时保留“查看 JSON”折叠入口 |
| 后处理配置 | 编辑器下方配置较弱 | 增加缺失值、去极值、标准化、中性化和方向配置的可视化表单 |
| 版本保存 | 主要保存公式文本 | 保存 DSL、AST、依赖、编译器版本、执行计划哈希和来源模式 |
| 预览区域 | 主要展示数量或简单结果 | 增加覆盖率、缺失率、分布、异常值、样本日期和计算耗时 |

### 15.2 需要新增

1. `GET /api/v1/factors/formula-catalog`，返回字段、函数、模板、DSL 版本和启用状态。
2. DSL Parser/Normalizer，将 `&&`、`||`、`!` 和三元表达式转换为规范 Factor AST。
3. 函数签名和参数类型系统，至少支持 `number`、`boolean`、`series`、`window`、`string`。
4. 条件配置器：条件、满足时、否则三段式编辑。
5. 编辑器自动补全、括号匹配、参数高亮和行内错误标记。
6. 因子依赖摘要和复杂公式结构树。
7. `dsl_version`、`source_mode`、`return_type`、`parse_source` 等必要版本元数据。
8. 因子引用函数 `factor_ref(code, version)`、引用版本冻结和循环依赖检查。
9. 前端统一的 Tooltip/Popover、错误码本地化和窄屏底部抽屉。
10. 针对 DSL Parser、函数目录、条件分支、等价模式切换和安全拒绝的测试集。

### 15.3 需要去除或禁止

1. 去除前端硬编码且可能与后端不一致的函数目录，保留类型定义但不保留业务目录副本。
2. 去除用户直接编辑复杂参数 JSON 作为默认入口，JSON 仅作为高级查看/导入方式。
3. 去除“点击格式化后直接改变用户原文且无法恢复”的行为，格式化必须可撤销。
4. 禁止前端直接提交或修改 `formula_ast`，AST 只能由后端编译生成。
5. 禁止把 DSL 当作任意 JavaScript/Python 执行，移除 `eval`、动态函数名和任意代码入口。
6. 禁止编译失败的公式进入 `candidate`，只能保留为 `draft`。
7. 不再使用“只显示依赖 1 个字段”的静态文案，改为真实依赖分析结果。

## 16. 前端改造方案

### 16.1 布局原则

围绕当前 `FactorFormulaEditorModal` 的框架增补，不新增独立页面，也不改变现有用户熟悉的按钮位置。

```text
┌──────────────────────────────────────────────────────────┐
│ 标题 / 状态 / AI / 格式化 / 编译预览                      │
├───────────────┬──────────────────────────┬───────────────┤
│ 字段与函数库   │ DSL 编辑器                │ 上下文帮助     │
```

### 16.2 现有区域的具体调整

#### 顶部工具栏

- 保留“问 AI”“格式化”“编译并预览”三个现有入口。
- 在标题区域增加 `函数辅助 / 高级表达式` Segmented 控件。
- “编译并预览”只有在 DSL 校验通过后才进入数据预览。
- AI 只能生成草稿并填入编辑器，不允许直接应用或改变生命周期状态。

#### 左侧字段与函数库

- 保留当前树形分类和搜索框。
- 数据改为调用 `formula-catalog`，显示中文名、key、类型和数据层级。
- 函数项显示签名，例如 `mean(field, window)`，鼠标悬浮显示说明和示例。
- 点击插入当前光标位置；拖拽仅做插入，不覆盖已有公式。
- 增加“最近使用”“常用模板”“已保存因子”三个折叠分组。

#### 中间编辑器

- 保留当前编辑器、行号、撤销/重做和清空操作。
- 增加括号匹配、关键字高亮、自动补全和当前参数高亮。
- 行内显示未知字段、参数数量错误、窗口超限和未来引用风险。
- 支持 `Ctrl/Cmd + Enter` 编译预览，`Ctrl/Cmd + Space` 打开补全。
- 高级表达式无法结构化还原时，保留原文并提示“高级表达式模式”。

#### 右侧公式栏

- 从静态“公式栏”升级为上下文面板，随光标所在函数变化。
- 展示函数签名、参数类型、范围、示例、数据依赖和计算成本。
- 对条件函数显示条件、真分支、假分支三个输入区。
- 对错误显示错误码、原因和可执行修复操作。
- 面板可折叠；窄屏时转换为底部抽屉，避免压缩编辑区。

#### 底部配置和预览

- 方向、版本说明保留当前位置。
- 参数从纯 JSON 输入改成动态表单。
- 后处理按“缺失值 → 去极值 → 标准化 → 中性化”顺序展示。
- 预览增加结果表、样本日期、覆盖率、缺失率、分布摘要和异常值计数。
- 数据覆盖不足时允许保存草稿和有限预览，但阻断正式候选提交。

### 16.3 交互状态

编辑器至少区分以下状态：

```text
idle → editing → validating → valid/invalid → previewing → preview_ready
```

- `invalid`：允许继续编辑和保存 draft，不允许提交 candidate。
- `valid`：显示依赖、窗口和复杂度，可进行预览。
- `preview_ready`：显示样本和覆盖率，用户确认后才能创建新版本。
- 后端或数据源异常：显示可恢复错误，不清空用户公式。

## 17. 后续最终目标

### 近期目标：专业公式编辑 MVP

- 支持数学、时间序列、条件和常用横截面公式。
- 函数库、字段目录、校验和预览完全由后端契约驱动。
- 用户能在 1 个编辑器内完成“输入 → 校验 → 预览 → 保存版本”。

### 中期目标：复杂因子工作台

- 支持因子引用、依赖图、循环检查和复合因子模板。
- 支持参数化因子和多个版本并行评估。
- 接入 IC、Rank IC、分层收益、换手率、行业暴露和 Shadow 观察。

### 最终目标：可治理的因子生产链

```text
公式草稿
→ 编译和数据就绪检查
→ Candidate
→ Testing
→ 多维评估
→ Shadow
→ 人工审批
→ Active / Quarantined / Deprecated
```

任何公式都能回答：由谁创建、使用了哪些字段和函数、使用哪个版本、数据覆盖如何、经过哪些评估、当前在哪些模块被引用。

## 18. 最终验收标准

### 18.1 功能验收

- 函数模式和高级表达式模式可以完成同一公式，编译 AST 和预览结果一致。
- 支持 `&&`、`||`、`!`、`if`、三元表达式、数学函数、时间序列函数和首批常用量化公式。
- 鼠标悬浮字段/函数/错误标记可看到用法、参数、范围和示例。
- 点击或拖拽字段/函数只在光标处插入，不覆盖既有内容。
- 参数表单、后处理表单和 JSON 高级查看可以双向同步。
- 预览显示样本数、日期范围、覆盖率、缺失率、异常值和计算耗时。

### 18.2 编译和安全验收

- 未知字段、未知函数、参数错误、语法错误、窗口超限和未来引用均返回稳定错误码及位置。
- 不执行任意 JavaScript/Python，不允许导入、属性访问、循环和动态函数名。
- 除零、非法 `log`、非法 `sqrt` 和缺失值行为有明确且可测试的结果。
- AST、依赖、编译器版本和执行计划哈希由后端生成，前端无法伪造。

### 18.3 生命周期验收

- 编译失败只能保存 draft，不能提交 candidate。
- 数据覆盖不足时阻断正式评估，但允许定义和有限预览。
- 已被回测、评估、FactorSet 或模型引用的版本不可原地修改。
- 新版本沿用 Candidate → Testing → Shadow → Active 流程，并保留人工审批和回退。

### 18.4 体验和性能验收

- 常规公式校验在 1 秒内返回，输入过程中采用防抖，不阻塞编辑。
- 悬浮提示延迟 200-300ms，快速移动不闪烁，支持键盘焦点和 Esc 关闭。
- 编辑器在当前桌面布局下不遮挡底部操作按钮；窄屏下右侧帮助自动变为抽屉。
- 所有错误都能定位到具体字符或参数，并给出可执行修复建议。
- 现有因子列表、详情、版本、预览、回测和 FactorSet 引用功能回归通过。
