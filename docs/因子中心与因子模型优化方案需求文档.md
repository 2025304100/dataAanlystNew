# 因子中心与因子模型优化方案需求文档

> 版本：v1.0
> 日期：2026-09-02
> 范围：因子库、因子集合、因子模型、因子评分流水线，以及因子评价/回测的治理衔接

## 1. 最终目标：链式操作和零认知负担

本次优化的最终目标不是把功能分别放在几个页面，而是把因子和因子模型做成一条用户可以顺着完成的链式操作流程。用户不需要理解 Factor、FactorSet、FactorModelRun、Score 等内部概念，也不需要自己判断下一步去哪个页面。

产品原则是：把用户当作不熟悉系统的用户来服务。每一步只呈现当前能做的动作；缺少前置条件时直接说明缺什么、为什么缺、点击哪里补齐；完成后自动带到唯一合理的下一步。

最终用户体验必须是：

```text
创建/选择因子 → 添加到因子集合 → 检查因子质量 → 冻结因子集合
→ 评估与数据治理预检 → 冻结因子集合 → 训练模型 → 查看模型因子和权重
→ 影子运行 → 正式启用 → 运行流水线生成评分 → 回测/决策消费评分
```

这条链路中的任一步都不能出现“功能存在但没有入口”“操作成功但不知道下一步”或“缺少配置仍允许继续导致后面整体不可用”。

## 当前实现基线（2026-09-02）

本次项目改动已经补齐以下基础能力，后续开发必须在这些能力之上继续，不得另起一套实现：

- 因子评估报告增加生产保真标识、非保真实验原因、过滤规则开关、排除统计、目标标签批次和数据截止信息。
- 因子评估指标统一使用安全数值展示，缺失值不再伪造为有效结果。
- 回测增加提交前预检，返回最低交易日、可用交易日、目标覆盖、按规则排除统计、警告和阻断项。
- 回测增加次新股、ST、停牌、退市整理期、退市清算和停牌持仓冻结等过滤治理能力，并记录过滤审计事件。
- 回测错误统一返回 `error_code`、中文标题、详情、关联 ID、影响、修复入口和是否可重试等结构化字段。
- 回测结果增加 `stage`、`progress_pct`、`updated_at`、`error_code`、`retryable` 和数据截止快照，旧 `status` 仍保持兼容。
- 回测启动增加基于前端会话、配置哈希、组合和区间的短窗口去重，避免重复创建运行记录。
- 后端和前端增加跨域依赖审计门禁，因子域对外通过 Facade/业务接口提供能力。

当前已补齐的链路节点：

- 因子中心前端已支持 FactorSet 创建、复制、成员编辑、添加因子版本和冻结。
- 设置页流水线已支持 frozen FactorSet 显式选择，不再依赖旧的隐式默认集合。
- 因子模型页已增加链式步骤条、前置条件门禁、模型与因子集关联展示及因子权重展开。

当前仍需持续完善的能力：

- 历史未关联模型的迁移报告和人工确认流程。
- 训练结果不可变因子权重快照在更多历史/异常路径下的补偿和回查。
- 因子评价、模型训练、评分、回测之间的全链路端到端回归验收。

## 2. 开发约束与业务边界

以下约束是本需求的硬性要求：

1. 功能内聚：因子、因子集合、模型训练、模型启用和评分流水线由所属模块负责，不在多个业务页面复制同一套逻辑。
2. 业务边界清晰：因子中心负责因子资产和模型治理；设置页负责运行配置和任务调度；组合、回测、交易、告警等业务只消费已发布的模型和评分结果。
3. 跨模块必须通过业务接口、Facade 或 DTO 调用，禁止直接访问其他模块的 ORM、数据库 Session、DuckDB 连接、内部 service 或内部状态表。
4. 不侵占其他业务：本次改造不得改变组合、回测、交易、告警、数据中心等业务的规则、入口含义和已有使用方式。
5. 失败隔离：因子配置、模型训练或流水线失败时，只影响当前请求或任务，不得覆盖当前可用模型、破坏手工回退或导致总体功能失败。
6. 兼容和可回滚：已有模型、评分、策略和任务必须继续可查询；新增切换保留旧状态、审计记录和回退路径。
7. 最小修改：只修改本需求涉及的模块、接口和测试，不顺带重构无关业务。

统一依赖方向为：外部业务模块 → 因子域公开接口/Facade → 因子域内部实现。因子域不得反向依赖其他业务域，其他业务也不得穿透接口调用因子内部实现。

## 3. 目标

当前系统有因子库、因子集合、因子模型和因子流水线，但用户无法从页面完成一条连贯配置链路。本需求将所有页面统一到以下主流程：

因子库 → 因子集合 → 选择因子版本 → 冻结集合 → 训练模型 → 验证/影子运行 → 正式启用 → 流水线生成评分

本次改造必须解决：

1. 前端没有创建因子集合和添加成员的入口。
2. “因子中心 → 训练模型”和“设置 → 因子模型 → 运行流水线”职责容易混淆。
3. 模型页面看不到模型使用了哪些因子和因子版本。
4. 历史模型没有 factor_set_id 时只显示短横线，没有解释。
5. 流水线当前可能自动使用第一个冻结集合，存在误训练风险。

## 4. 统一概念

| 对象 | 定义 | 生命周期 |
|---|---|---|
| 因子 Factor | 一项有公式、输入字段、方向和质量指标的研究资产 | 草稿、候选、测试、影子、激活、废弃 |
| 因子版本 FactorVersion | 某个因子的不可变公式和参数版本 | 创建后不可覆盖 |
| 因子集合 FactorSet | 一组明确选择的因子版本，是模型训练输入 | draft、frozen、deprecated |
| 模型版本 FactorModelRun | 基于一个因子集合和历史数据产生的训练结果 | training、validated、rejected、shadow、active、retired |
| 评分 Score | 使用模型和最新因子数据计算出的证券评分 | 按流水线或任务更新 |

因果关系必须在页面和数据中一致表达：

因子 → 因子版本 → 因子评估/预检 → 因子集合成员 → 因子集合 → 模型版本 → 评分 → 回测/决策

数据库关联要求：

- factor_set_members.factor_id 指向因子。
- factor_set_members.factor_version_id 指向精确因子版本。
- factor_model_runs.hyperparameters_json.factor_set_id 指向训练使用的因子集合。
- 模型权重必须能按 factor_code 和 factor_version 回查到集合成员。
- 无法确认历史模型来源时显示“未关联”，禁止猜测补写。

## 5. 页面职责

### 5.1 因子中心

因子中心负责研究资产和模型版本治理。

- 因子库：创建因子、创建版本、查看因子质量和生命周期。
- 评估实验室：评估覆盖率、IC、缺失率和数据可用性。
- Shadow 观察：比较候选模型与当前模型。
- 因子模型：配置因子集合、冻结集合、训练模型、查看模型因子构成。

因子中心的“训练模型”定义为：针对用户明确选择的一个因子集合，创建一个模型版本。因子评估实验室只负责评估和预检，不直接代替模型训练。

### 5.2 设置 → 因子模型

设置页负责运行时和批处理，不负责编辑因子集合：

- 因子功能开关和仓库健康状态。
- 全量重算、训练窗口和验证窗口。
- 运行、取消和查看流水线任务。
- 是否在本次流水线中训练模型。
- 是否生成评分快照。
- 当前决策模式、活动模型和回退手工权重。

“运行流水线”表示执行数据同步、因子计算、目标生成、可选模型训练和可选评分生成，不是另一个模型配置入口。回测和因子评价只通过公开业务接口消费结果，不得直接进入因子内部实现。

## 6. 用户操作流程

### 6.1 首次配置

1. 进入 设置 → 因子中心 → 因子库。
2. 创建因子或选择已有因子，确认存在可训练版本。
3. 进入 因子模型 Tab，点击“新建因子集合”。
4. 输入集合名称和描述。
5. 点击“添加因子”，选择因子、精确版本、角色、方向约束和缺失策略。
6. 保存为 draft，查看成员和覆盖率预检。
7. 点击“冻结”，形成不可变输入快照。
8. 在该集合行点击“训练模型”。
9. 查看模型的因子构成、权重、验证 IC 和样本量。
10. 通过验证后执行影子运行，再正式启用。
11. 进入设置页运行流水线，更新因子数据和最新评分。
12. 运行回测前先执行预检；预检阻断时根据修复入口补齐数据或配置，不允许带着不完整数据继续。

### 6.2 修改因子配置

frozen 集合不可直接修改。必须复制为新的 draft，修改成员后重新预检、冻结、训练和影子验证。历史集合和历史模型保持不变。

## 7. 因子集合页面需求

因子集合卡片必须提供：

- 新建因子集合。
- 复制为新版本。
- draft 集合的编辑成员。
- 选择因子及其可训练版本。
- 展开查看代码、版本、角色、方向约束和缺失策略。
- 显示状态、成员数、覆盖率预检和冻结时间。
- frozen 集合只允许查看和训练模型。
- deprecated 集合只读。

集合为空、没有 feature 因子、因子版本不可训练时，禁止冻结并显示原因。

## 8. 模型页面需求

模型表每行必须显示：模型 ID、状态、因子集合名称和 ID、因子数量、验证 IC、样本量、数据截止时间和活动状态。

模型行展开后显示：

因子代码、因子版本、模型系数、归一化权重、训练 IC、验证 IC和覆盖率。

点击因子集合标签应定位并高亮上方集合；点击因子应能反查该因子参与的集合和模型。

模型缺少 factor_set_id 时，显示：

“未关联：该历史模型没有记录训练使用的因子集合，无法确认因子来源。请重新基于已冻结因子集合训练，或执行历史数据迁移。”

## 9. 流水线需求

流水线区域必须展示本次使用的因子集合、状态、成员数和以下阶段：

数据同步 → 因子计算 → 目标生成 → 可选 Ridge 训练 → 可选评分生成

当训练开关打开时：

- 必须选择因子集合。
- 只显示 frozen 且 readiness 通过的集合。
- 只有一个集合时可以预选，但必须显示名称和成员数。
- 多个集合时不得静默选择第一个。
- 没有可用集合时禁用运行并引导去因子中心配置。

当训练开关关闭时，提示本次不会创建模型，只会更新因子和评分。

因子评价和回测必须沿用同一套过滤配置、PIT 状态、数据截止和结构化错误契约；评价结果要明确区分“生产保真”和“非保真实验”。

## 10. 验收标准

1. 用户仅通过页面即可创建因子集合并添加因子版本。
2. 用户可以从集合行直接训练模型，不需要填写内部 ID。
3. 新模型明确显示因子集合和具体因子版本。
4. 设置页流水线运行前必须显示并确认因子集合。
5. 多个集合并存时不得自动选错集合。
6. 新模型的因子集合、成员版本和权重可以完整回查。
7. 历史未关联模型有解释和修复路径。
8. 训练、影子、启用和回退均写入审计记录。
9. 每个新增功能均通过所属业务接口完成，未侵占其他业务模块。
10. 因子或模型任务失败不会导致组合、回测、交易、告警或总体功能失败。
11. 改造范围外的接口、数据和业务行为通过兼容性回归测试。
12. 因子评价和回测的过滤、PIT、数据截止和错误提示不会绕过因子域边界，并且失败时只阻断当前运行。

## 11. 非目标

- 不自动挖掘或自动选择最优因子。
- 不自动把新因子加入已冻结集合。
- 不自动激活新训练模型。
- 不为无法确认来源的历史模型猜测关联关系。
