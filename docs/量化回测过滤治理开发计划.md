# 量化回测过滤治理开发计划

> 对应需求：`量化回测过滤治理正式需求文档.md`
> 版本：v1.0
> 日期：2026-08-30
> 目标：在不破坏现有回测和因子评价接口的前提下，落地 Point-in-Time 过滤、退市清算和可解释数据治理

## 1. 交付拆分与优先级

| 阶段 | 内容 | 优先级 | 产物 |
|---|---|---:|---|
| P0 | 配置收口、运行快照、接口契约 | 阻塞 | `BacktestFilterConfig`、config hash、迁移脚本 |
| P1 | 历史证券状态和股票池时效化 | 阻塞 | `security_status_daily`、PIT 查询服务 |
| P2 | 四类过滤器和审计事件 | 阻塞 | 过滤服务、`backtest_filter_events` |
| P3 | 退市持仓清算和停牌冻结 | 阻塞 | 清算状态机、净值事件 |
| P4 | 预检、异常提示和前端展示 | 高 | 预检 DTO、排除统计、数据治理面板 |
| P5 | 回测/因子评价全链路接入 | 阻塞 | 调仓、目标标签、IC、成本统一接入 |
| P6 | 测试、回放、性能和观测 | 阻塞 | 测试报告、历史事件回放、指标监控 |
| P7 | 灰度、基线对账和正式启用 | 阻塞 | 双跑报告、发布记录、回滚开关 |

## 2. P0：配置收口

### 工作项

- 在回测域新增不可变 `BacktestFilterConfig`，默认值全部开启，次新股阈值 120 自然日。
- 删除或适配原有分散的过滤全局变量，统一由依赖注入传入每日调仓和清算流程。
- 在回测请求中增加可选 `filter_config`；生产 API 只允许受控枚举和数值范围。
- 运行启动时生成 `config_hash`，写入 run、交易、净值和审计事件。
- 关闭规则时自动设置 `production_fidelity=false` 和 `non_fidelity_reason`。

### 验收

- 同一配置实例贯穿整个回测生命周期。
- 运行中修改前端配置不会改变已启动任务。
- 默认请求不传配置时四项规则均开启。

## 3. P1：状态数据和 PIT 查询

### 工作项

- 新增 `security_status_daily` 及必要索引：`(symbol, trade_date)`、`trade_date`。
- 新增数据源适配器，导入上市日期、ST、停牌、退市整理期、摘牌日期。
- 所有状态查询必须使用 `status_at(symbol, trade_date)`，禁止读取当前静态名称或当前 `is_active` 作为历史判断。
- 对没有历史状态的数据源返回 `unknown`，记录批次和更新时间。
- 对现有 `raw_asset_universe.is_active` 查询进行隔离：它只能作为当前列表展示，不能直接决定历史回测成员。

### 验收

- 用包含已退市股票、ST 变更和新股上市的历史样本验证状态在变更日前后不同。
- 同一股票在不同历史日期返回不同状态时，查询结果可重复。

## 4. P2：过滤器与审计

### 工作项

实现纯函数过滤器，输入为 `trade_date`、候选池、持仓、PIT 状态和配置，输出为：

```text
eligible_candidates
frozen_positions
delisting_candidates
filter_events
```

规则顺序固定为：

1. 数据状态时效检查；
2. 次新股过滤；
3. ST 过滤；
4. 停牌过滤；
5. 退市整理期过滤；
6. 输出退市清算候选。

每条过滤事件记录 `rule_code`、原始状态、配置 hash 和数据批次，禁止只记录最终股票池。

### 验收

- 单个开关关闭只跳过对应规则，不影响其他规则。
- 同一输入重复执行结果和事件顺序一致。
- 缺失状态不会被转换成“正常可交易”。

## 5. P3：清算和停牌状态机

### 工作项

- 调仓前执行退市清算，生成 `FORCED_DELISTING_LIQUIDATION` 事件。
- 清算价格使用退市最后交易日的有效收盘价；成交数量按持仓数量；盈亏和费用进入净值流水。
- 停牌持仓进入 `FROZEN` 日状态，当日跳过卖出和买入，下一可交易日再参与正常调仓。
- 无清算价格时进入阻断状态，回测不继续写入虚假净值。
- 交易、持仓、净值和审计事件使用同一 run 和 config hash。

### 验收

- 退市前最后一日、退市日、摘牌日各有明确事件。
- 停牌期间持仓数量不变且成交量为 0。
- 强制清算收益与手工计算一致。

## 6. P4：预检和前端

### 后端

- 扩展回测/因子评价预检 DTO，返回最小交易日、实际交易日、目标覆盖和按规则排除统计。
- 区分 `warning` 和 `error`，不得把告警序列化成硬错误。
- 目标标签缺失时保留真实标签子集，禁止 fallback 到因子自身变化。
- 对价格、成交量、状态未知、标签缺失分别提供 `code/detail/evidence/fix_link`。

### 前端

- 在提交按钮附近展示最低要求、当前可用交易日和缺口。
- 预检结果按“阻断项 / 告警项 / 已通过”分组，展示股票日数量和占比。
- 运行报告增加“过滤与数据治理”区域，显示四类规则开关、排除计数、目标标签批次、数据截止日。
- 关闭规则时显示“非保真实验”标签和关闭原因。
- 报告指标统一兼容后端嵌套结构，缺失值显示 `-` 并同时显示缺失原因。

### 验收

- 用户无需查看日志即可知道为什么样本减少。
- `status_unknown`、目标标签缺失和异常值均可通过详情证据定位到股票和日期。

## 7. P5：全链路接入

### 回测

- 回测启动：创建配置快照和状态数据快照引用。
- 每日调仓：按固定顺序调用过滤器、清算器和交易执行器。
- 净值：合并真实成交、冻结持仓和强制清算。

### 因子评价

- 因子面板与目标收益按同一交易日、股票和 PIT 状态对齐。
- 目标标签覆盖不足只减少真实样本并产生告警；低于最低切分要求则阻断。
- IC、分组收益、换手和成本后收益均记录过滤后分母。
- 报告中同时显示原始样本和有效样本，避免把覆盖率误解为全市场覆盖。

## 8. P6：测试计划

### 单元测试

- 次新股边界：119/120/121 自然日。
- ST 边界：状态生效日前、当日、解除日前后；持仓变 ST 不强平。
- 停牌：候选停牌、持仓停牌、入场停牌、退出停牌。
- 退市：整理期、最后交易日、摘牌日、无有效收盘价。
- 缺失和异常：NaN、Inf、零价格、零成交量、状态 unknown、标签缺失。
- 配置：默认全开、单开关消融、配置 hash 不同、运行中不可变。

### 集成测试

- 一段包含新股、ST、停牌和退市的历史日线回放。
- 回测交易流水与过滤审计事件逐日对账。
- 因子评价目标标签覆盖不完整时，不发生因子自身收益 fallback。
- 前端预检、提交、轮询、完成报告和错误详情全链路验证。

### 性能测试

- 状态表按交易日批量读取，禁止逐股票发 SQL。
- 过滤器在全市场日线规模下不引入 O(股票数 × 规则数) 的重复查询。
- 记录过滤耗时、状态查询耗时、清算耗时和审计写入耗时。

## 9. P7：灰度和发布

1. 先以只读诊断模式运行，不改变交易结果，只生成过滤事件和差异报告。
2. 选择包含历史 ST、停牌、退市和 IPO 的区间，与旧逻辑双跑。
3. 对账项目：成交笔数、持仓数量、强平收益、净值、覆盖率、排除统计和最后交易日。
4. 差异全部有规则 code 和证据后，默认全开切换为正式模式。
5. 保留旧逻辑只读回放能力；发现数据源错误时回滚到旧结果，但不得删除新审计数据。

## 10. 完成定义

- P0-P7 交付物和测试全部通过。
- 正式回测结果包含配置快照、状态批次、过滤事件和清算事件。
- 任何异常都能从报告定位到 `run_id + symbol + trade_date + rule_code`。
- 没有可靠历史状态时系统阻断或明确标记非保真实验，不生成看似正常的结果。
- 产品、数据治理和量化开发共同签署基线对账报告后，才允许将新链路设为默认。

## 11. 当前代码落点建议

- 回测过滤配置：回测域新增独立模块，避免继续散落在策略和因子模块。
- 目标标签校验：复用 `app/services/factors/wp5_eval_task.py` 的目标覆盖检查，但不得恢复同源 fallback。
- 因子报告：在 `frontend/src/components/factors/FactorEvaluationLab.tsx` 增加过滤与数据治理区块。
- 数据状态查询：由独立 PIT 服务提供 DTO，不让前端或回测直接读取 ORM/当前静态股票池。
- 审计和错误：沿用结构化 `code/severity/category/detail/evidence/fix_link` 契约，告警使用 `warning`，硬阻断使用 `error`。
