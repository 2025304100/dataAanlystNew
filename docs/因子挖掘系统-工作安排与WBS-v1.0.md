# 因子挖掘系统 开发工作安排与 WBS（v1.0）

> 版本：v1.0 ｜ 日期：2026-09-16 ｜ 状态：待评审 ｜ 配套文档：《因子挖掘系统-底层架构设计文档-v1.0.md》
> 本文件解决三件事：**① 代码怎么切模块（含边界与依赖）；② 谁做哪些模块、多少工作量；③ 多人如何并行不打架（接口冻结点 + 泳道 + 联调节奏）**。
> 使用方式：开发同学先读自己负责的「模块卡」拿到**职责 / 边界 / 交付物 / 依赖 / 接口**，再在 §5 的 WBS 表里认领任务编号，按 §6 的泳道图确认自己什么时候开始、卡在谁身上。

## 2. 协作机制（铁律）

### 2.1 接口先行与冻结

| 冻结批次 | 冻结内容 | 冻结时点 | 冻结后规则 |
|---------|---------|---------|-----------|
| **FZ-1** | `mining/contracts.py` 全部数据类（`MiningContext` / `Individual` / `Fitness` / `Strategy` / `GenerationStat` / `PoolSnapshotRef` / `ValidationReport` / `GradeResult` / `StatResult`） | M1a 第 1 周结束 | 只能**加可选字段**；改名/删字段需 TL 评审 + 通知全部消费方 |
| **FZ-2** | 表结构与 alembic 首版修订（候选池 3 表 + 挖掘核心 6 表 + `task_locks`） | M1a 第 2 周结束 | 加列必须新开修订；不得改既有列类型/名 |
| **FZ-3** | HTTP 契约（§8.2~§8.5 全部路径 + 出入参 Schema） | M1a 第 3 周结束 | 加可选参数允许；路径改名/删端点需 TL 评审 |
| **FZ-4** | 前端 `types/mining.ts` + 共享组件 Props（`GradeBadge` / `LockStatusCard` / `MiningTaskPolling`） | M1a 第 3 周结束 | 同上 |
| **FZ-5** | M1b：`experience` 4 接口 + `ai_generator` 入参出参 | M1b 第 1 周结束 | 同上 |
| **FZ-6** | M2：统计与分级接口（`statistical_tests` / `factor_grading` / 证据抽屉 API） | M2 第 1 周结束 | 同上 |

**冻结的落地方式**：冻结当周，B5 产出 `contracts.py` 与 `schemas/*.py` 的**空实现 + 完整签名 + docstring**，TL 评审通过后合入主干；其他开发基于空实现先写调用方与单测（用 stub），**不等待真实实现**。

### 2.2 分支与提交规范

| 项 | 规范 |
|----|------|
| 主干 | `main` 保护；只接受 PR 合入 |
| 特性分支 | `feat/mining-<模块编号>-<简述>`，如 `feat/mining-bm2-cs-rank` |
| 修订分支 | `fix/mining-<编号>-<简述>` |
| 提交粒度 | 一个任务编号一个 PR（WBS 编号写进 PR 标题，如 `[M1A-12] DSL cs_ 族实现`） |
| PR 要求 | ① 关联 WBS 编号 ② 自测证据（测试命令 + 结果）③ 涉及冻结接口的变更必须 @TL ④ 单 PR ≤ 600 行有效改动（超过则拆） |
| 合入前置 | CI 绿（lint + 后端 pytest 相关子集 + 前端 vitest 相关子集） |
| 冲突高危文件 | `factor_compiler.py` / `contracts.py` / `Settings.tsx` / `client.ts` / `requirements.txt` —— **单一 codeowner，禁止并行编辑**；需要改动走 issue |

### 2.3 评审机制

| 评审类型 | 触发 | 参与 | 时长 |
|---------|------|------|------|
| 架构评审 | FZ-1~FZ-6 冻结、新增依赖、跨域接口变更 | TL + 相关 codeowner | 1h |
| 代码评审 | 每个 PR | 模块 codeowner + 1 名邻居角色 | 当日完成 |
| 算法评审 | M8/M13 算法实现 PR | TL + B4 + B3 | 2h |
| 安全/红线评审 | 涉及 C3/C5/C6/C7/C8 红线的 PR | TL + QA1 | 1h |

### 2.4 联调节奏

| 节奏 | 内容 | 产出 |
|------|------|------|
| 每日 15min | 站会：昨天完成 / 今天计划 / 阻塞 | 阻塞项进看板 |
| 每周五 1h | 周集成：拉最新主干跑一次冒烟 | 集成报告 |
| 每个里程碑末 | 里程碑演示 + 验收演练 | 验收记录 + 回填修订 |
| 阻塞升级 | 任一任务被卡 >1 天 → 上报 TL | TL 裁决/改接口/调人力 |

### 2.5 独立开发保障（避免互相等待）

| 手段 | 说明 |
|------|------|
| 契约驱动 | FZ-1~FZ-6 冻结后，消费方用 stub 开发，产出方后补实现 |
| 测试替身 | `genetic_algorithm.run_evolution` 支持 `progress_cb` 与可注入 stub 种群；`ai_generator` 支持 mock `llm_client`；`statistical_tests` 为纯函数可直接对拍 |
| 数据替身 | M0 未完成前，B3/B4 用**小样本合成面板**（500 股 × 300 日）开发；`evaluation_adapter` 提供 `use_fixture=True` 开关（仅测试环境） |
| 前端替身 | MSW（或既有测试模式）mock `/factor-mining/*`；`types/mining.ts` 冻结后前端不等后端 |
| 功能开关 | `FACTOR_MINING_WRITE_ENABLED` 灰度；未完成模块不暴露到 UI |
