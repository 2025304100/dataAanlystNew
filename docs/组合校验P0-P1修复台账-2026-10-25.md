## 数据保全规则

1. 不删历史成员、状态、回执、交易、账务或审计行；不通过清空幂等表消除迁移失败。
2. 结构迁移与数据恢复分开验收。0082 升级前后旧秒值应相同；随后专项恢复仅允许清单内 source_updated_at 改变，并新增审计。
3. `scripts/review_migration_integrity.py` 按旧主键和全部旧列生成类型敏感 SHA-256、行数和 NULL 分布；不能仅比较 COUNT。新增列与映射另核验，不能用新摘要覆盖原基线。
4. 缺原 CSV、独立 hash、回执/状态指纹，来源冲突，重复 current，必填旧列无可证实回填值，非 InnoDB，旧新幂等字段冲突时均停止；不猜时间、补 0、删除重复或伪造数据。
5. 写操作和审计在同一 InnoDB 事务。MySQL DDL 隐式提交，不把事务 rollback 当作跨 revision 回滚；中断后按当前结构预检重跑。
6. 异常来源/历史脏行继续作为门禁未满足条件，不通过归档成员、删候选、手动 READY 或替代模型消红。

## 尚不能宣称关闭的事项

- 正式库存量的原始历史数据、生产规模 DDL 锁等待/训练/备份恢复耗时没有在本轮测量；本轮没有对正式库做数据恢复。
- baostock/东财外部连通性及 600519 类来源歧义未用伪数据绕过。源恢复必须真实下载并逐日验证，TCP 可达不足以证明可用。
- 无原证据的微秒和归档时间不能恢复；既存跨源混合行需取得原文件或字段级证据。工具会拒绝此类记录。
- 旧版本已吞掉的 key_members_json 不能凭当前成员列表反推；SQL NULL 也可能是用户合法选择的“默认全员”，不能一律改写。已知受影响组合须凭原请求/审计核实并补偿，缺证据列入待核查清单；新接口落库正确不等于旧选择已自动恢复。
- restore 保留原成员 ID 的现有产品约定未改为新增 SCD2 版本；若需要保留完整“归档到恢复”间隔，须独立修改契约和迁移设计，不能把旧间隔当未发生。
- 进程 RSS 监督属于轮询式预算，不是操作系统瞬时硬配额。全市场目标规格训练和生产级容量验收仍需在足够资源的副本执行。

- 跨域只读结构诊断覆盖 146 个模型表，其中组合相关 46 表；其他域仍有 11 处旧必填列与 ORM 映射差异，尚不能仅凭列定义判断为当前业务故障，未无差别修改。旧 portfolio_cron_schedules 的 hour/minute 没有当前运行时写路径，也保留原约束。详情见 `combination-schema-diagnostic.json`；本轮不能代替全应用各域的迁移写入验收。
