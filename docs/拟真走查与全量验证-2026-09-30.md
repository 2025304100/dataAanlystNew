## 十、“mock 抄漏方法被 catch 吞掉”的结构性防线（用户采纳 A+B 后执行）

### 先说清楚这个坑为什么难发现

前端 85 个测试文件几乎每个都**自己手写一份局部 api mock**，要用几个写几个。
抄漏一个方法时，`api.xxx` 是 `undefined` → `TypeError: ... is not a function`，
而组件普遍 `try/catch + console.error` —— **这个异常变成一行日志就被吞了**。
结果是测试跑的是“取数失败的降级路径”，断言却全通过。851 全绿里根本看不出来。

本次是前端全量输出里偶然看到的一行
`[notifications] inbox fetch failed: api.getInboxNotifications is not a function` 把它逗出来的
（该方法在 `client.ts:2651` 与后端 `/notifications/inbox` 均存在）。

### B（构造性照妖镜，已装）

`frontend/src/test/setup.ts` 新增：拦截 `console.error/warn` 中包含 `is not a function`
的消息并收集，`afterEach` **直接判失败**（即使组件把它吞了也跑不掉）。
真在测“接口不可用”分支的用例，必须调 `__allowMissingApiMethod()` 显式声明 ——
把隐式绕过变成显式选择。

**实际抖出来的东西**（一次跑完全量）：`1 file / 2 tests` 失败，全部是同一个缺口
`getInboxNotifications` —— 定位到我自己写的 `WP9Cleanup.test.tsx`：它渲染带通知下拉的
壳组件，但 mock 里没声明这个方法。也就是说之前那两条用例验证的是通知拉失败时的降级，
而它们看上去在测“投顾 tab 移除与路由兼容”。

双向验证已完成：装守卫时红 2 条（报出确切缺失方法）→ 补上 mock 后转绿；
补后全量 **85 files / 851 passed**，`tsc -b` 干净。

### A（类型约束，已加一半，剩下的诚实说明）

`makeMockApi(overrides: Partial<typeof ApiClient.api>)`（type-only import，不把真 api 拉进
测试运行时）：把方法名**拼错**（如 `getPosistions`）从“运行时 undefined 静默降级”
变成**编译期报错**。

但要说清局限：**它不能保证 mock “方法齐全”**——jsdom 下组件到底调哪几个方法，
类型系统看不出来。真正兼顶这个的是 B。另：`makeMockApi` 仍然 **0 使用者**
（本轮没组迁 85 个测试去用它，那个改动量太大且容易撞用户在途文件）。

### 待观察
后续新测试如果 mock 缺方法，会直接红并提示修法；如果谁真需要测降级分支，
要写 `__allowMissingApiMethod()` —— 评审时看到这一行就该问“为什么在测降级”。

## 十七、系统设置页那个大写 KEY 的真相（g12 定向复核）

单独写了一个只跑这一页的脚本（`tmp/ui_app_settings.py`：进设置→系统设置、等足、把含下划线的

```
可见文本长度: 291
  - DISCOVERY_AUTO_DATA_PREP_ENABLED  ← 上下文：当前来源：未修改，使用默认值（DISCOVERY_AUTO_DATA_PREP_ENABLED）
```

**不是“开关标题用了 key”**（标题 `label_zh` 本来就是中文：“…数据未就绪时自动补齐”），
而是 `AppSettingsSection.tsx:100` 无条件把 **环境变量名**括了出来：

```tsx
{item.env_var ? `（${item.env_var}）` : ""}   // 旧：source=默认值 时也照打
```

所以这是个**语义错**而不只是美观问题。修法经过一次修正：

- 我第一版改成“只在 `source === "env"` 时才括注”——**这版是错的**，被
  `AppSettingsSection.test.tsx` 直接拦下：测试注释写明“source=默认值 时也要把 env 变量名露出来”
  是**故意设计**（运维需要知道可用什么覆盖）。我把既有设计当成 bug 修了。
- 最终版：变量名**一直显示**，但说法跟 source 对齐 —— 默认值写「（可用环境变量 X 覆盖）」，
  真来自环境变量写「（来自环境变量 X）」。界面现在读作：
  「当前来源：未修改，使用默认值（可用环境变量 DISCOVERY_AUTO_DATA_PREP_ENABLED 覆盖）」。

两条教训（比这个 bug 本身值钱）：
1. **改完组件要跑“该组件自己的测试”**。上一轮我跑的是 `src/components/settings` 目录，
   而它的测试在 `src/components/__tests__/` —— 等于没验，是前端全量跑才兑出来的。
   “跑了个相近目录”不能当成验证。
2. 测试变红，未必意味着“测试钉住了旧行为”：这次是**我改错了、测试是对的**。
   先看测试注释里的意图，再决定改代码还是改测试。

## 二十七、#1 已结案：分片把同目录文件拆散 ⇒ pytest Dir 对象重复 ⇒ conftest fixture 不可见

### 结论（机制，不是相关性）
不是应用缺陷，也不是测试写错，而是**我们的分片调用方式**：`ci_shard` 按用例数 LPT 分桶后
没有按目录聚合，同一目录的文件被其它目录的 arg 插开。pytest 8.x 在这种交错传参下
会为同一目录创建**第二个 Dir 节点对象**；而 `_pytest.fixtures` 的
`_matchfactories` 只要走完第一条分支就不再看第二条：

```python
if fixturedef.node is not None:
    if fixturedef.node in parent_nodes: yield      # ← 只比对象身份
elif fixturedef.baseid in parentnodeids: yield     # ← baseid 兜底根本走不到
```
于是第二个 Dir 下的用例看得到“同名 nodeid 的父链”却得 `[]`，报 `fixture 'client' not found`。

### 证据链（三步，每一步都可验证）
1. **冻结集合后的探针 v3**（`tmp/probe3.txt`）：两条 item 的 `parents nodeids` 完全包含
   `'tests/integration'`，且 `_arg2fixturedefs['client']` 有两条（一条 baseid
   `'tests/integration'`、一条属于别的文件）；TR_1_1/TR_1_2 解析成功，
   而 `test_A_full_pipeline` 解析为 `[]` ⇒ 只能用 Dir 对象身份不同解释。
2. **隔离微实验**（`tmp/micro_dir_identity.py`，0.5 秒）：只改变一个变量——
   交错传参 → `ERROR tests/integration/test_two.py::test_two`；同目录相邻 → 4 passed。
   这就把机制与“仓库里的某些业务代码”彻底解耦。
3. **修复后重跑**：含两个受害文件的那一片 **1407 passed / 1 skipped / 0 FAILED /
   0 fixture not found（6:06，rc=0）**；分片自检仍为 4 片各 25.0%（319 文件 / 5633 用例），
   即**只改调用顺序，归属与负载完全不变**。

### 做了什么
- `scripts/ci_shard.py`：分桶后按 `(目录, 路径)` 稳定排序，**同目录文件必须相邻**；
- 新增**第 26 道守护** `test_ci_shard_keeps_same_directory_files_adjacent`：用6 个
  故意交错的文件验“同目录不得被拆开”，同时校“只改顺序不改归属与负载”
  （防止将来有人改回纯 LPT 排序又静默踩坑）；守护现共 26 道，25 passed（1 红是用户
  在建文件缺 marker）。

### 未归因的尾巴（不当作已解决）

### 根因（精确到行）

`radarOption(availableStyles)` 在 `availableStyles` 为空时，仍然返回
`series[0].data = [{ value: [] }]`（长度 1）但 `radar.indicator = []`。
而 `MiningChart` 的空态判定看的是 `series[].data` 非空 → 认为“有数据”，于是把

`TypeError: Cannot read properties of undefined (reading 'push')`。
用户看到的就是：点开候选池分析看板，风格那一块直接没内容。

### 修法（走现有空态约定，不臆造数据）
`radarOption` 在 `dims` 为空时返回 `{...base, series: undefined}` → `MiningChart`
现有逻辑（`series != null` 判定）会落入 `emptyText` 占位，不画图也不编数据。
同时导出 `radarOption` 以可测，新增 3 条回归（空维度不递 series / 有维度时
indicator 与数据点数量一致 / 单维度形状正确）。
