## 二、这轮改了什么（按主题，括号内为提交）

### 环境与"新机器能不能起来"
- `requirements.txt` 必须纯 ASCII：`pip._internal.utils.encoding.auto_decode` 在中文
  Windows（cp936）下按区域编码解码 `-r` 文件、失败即抛，导致 **`pip install -r requirements.txt` 整条命令失败**；Ubuntu CI 用 UTF-8 所以永远看不见。
  注释改英文 + 新增守护 #29。归属已核：加中文注释**之前**的 `40cadbe7` 同样读不了 → 历史遗留。(`709d6632`)
- 迁移链在 MySQL 上可从空库重放：TEXT/JSON 的 `server_default`(1101)、`version_num` 宽度(1406)、
  会话显式 InnoDB(1071)。(`cea5de5c`、`9dc88533`；**0032 的 1215 列型不匹配仍未修，需拍板**)
- `init_db()` 补写 `alembic_version`，让 `create_all` 与 alembic **互认**；CI 建库改走 `init_db`
  （与新机器同一路径），并加全表 Schema 漂移守护。(`9eac2cc8`)

### 用例质量（假绿 / 假红 / 空断言）
- 分片把同目录文件拆散 → pytest `Dir` 对象重复 → `fixture 'client' not found` 假红；
  改为按目录聚合 + 守护 #26。(`e96ebe38`)
- golden 归档写在被 gitignore 的目录里 → 基准从未真正比对。(`eb2a41e7`)
- 黑盒 409 断言 `KeyError: 'detail'`：真实响应是**统一结构化契约**（无 `detail` 键），
  过时的是断言；改按 `error_code/retryable/user_message` 校（更严）。(`ad2150ca`)
- e2e 里 **13 处裸 `wait_for_load_state("networkidle")`**：本应用持续轮询，networkidle 可能永不
  满足 → 30s 超时把整份文件打成 ERROR at setup。统一收敛为 `tests/_e2e_settle.py::settle()`，
  夹具改等真实渲染信号 `button.view-tab`。(`7a6d4ff6`)
- 持仓成员用例的前置 `rows.count() >= 1` 是**空断言**（空态占位行也满足）→ 改为断言真实行
  `tr[data-symbol-id]`，并把按钮查找收紧到成员行内（页面级会把候选池表的按钮一起数进来）。(`7a6d4ff6`)
- 探测收敛守护不再押注上游快慢：区分"在等上游（心跳新鲜+有阶段）"与"无解释滞留"，
  后者仍硬失败，另加"滞留 > 10%"总量闸门。(`7f89d8be`)
- 补 `pytestmark` 缺失（否则整文件被 `-m whitebox` 静默跳过）+ 清根目录 0 字节垃圾。(`1d9ae660`)

### 真业务缺陷（都是"本地绿、CI 红"顺出来的）
- 回测预检 auto-fill **从未工作过**：`union_all(...).distinct()` 在 SQLAlchemy 2.0 不存在
  → 每次抛 `AttributeError`，被 `except Exception` 吞成"0 只标的"，还对用户提示"去同步基础数据"。
  去掉非法调用 + 不再静默（`logger.warning(exc_info=True)` + evidence 里加 `universe_source_error`）
  + 回归测试（**可证伪**：把 `.distinct()` 加回去立刻变红）。(`9d4234a3`)
- `PUT /external-data/apis/{key}` 409：`_ensure_cfg_row` 的 select-then-insert 在 MySQL
  REPEATABLE READ 快照下必然竞态。改为 SAVEPOINT + 当前读取回已有行。(`853bfc89`)
- 应用启动即自动发起"全市场基础数据同步"（5 线程带重试打 akshare）→ 测试/CI 每轮都在
  和真实外网赛跑，拖爆无关用例的等待。新增 `AUTO_UNIVERSE_SYNC_ON_STARTUP`（默认 True，
  生产不变），测试会话与 CI e2e 关闭；5 条白盒双向钉语义。(`02d54606`)
- **自动预检弹模态锁住整页**：新装机一进「组合交易」就被一份未索取的报告挡住其他子导航。
  改为不遮挡行内提示 + 「查看原因」入口（原"点击查看"长在 disabled 按钮上，只删弹窗会藏信息）；
  fail-closed 未减；三条前端测试改为"先断言没弹 → 主动点开 → 再验原细节"，断言零删除。(`fd14b544`)

### 可观测性与数据前置
- CI env probe 步骤（`pip check` + 关键包版本 + 逐个 import），且**必须发 `::notice`**
  —— 只写 stdout 的话匿名侧仍读不到。(`a4c3d3e7`、`f48b3ce4`)
- e2e 最小数据种子 `scripts/ci_seed_e2e_fixture.py`（方案 A）：ORM 造 1 组合+2 标的+2 成员+2 持仓；
  双门禁 = `CI=true` **且** 库名在 `gpfx_ci` 白名单；按业务键幂等、绝不 DELETE/TRUNCATE。(`1454873c`)
  配套 8 条白盒，含两条**跨文件一致性**守护（workflow 的 `CI_DB_NAME`/`MYSQL_DATABASE` 必须在白名单；
  `app/**` 不得引用该脚本）与幂等、接口可见性断言。

## 六、后续更正（2026-10-13）：ENV-GAP-1 定性改写

上表“被否掉的假设”里那行 *vectorbt 红是最新 numba 破坏的* 仍然成立（确被否证），
但当时给的结论“只能不阻断”**是错的**。探针分支 `main_work_vbtjit`（run `f64b03c4`）
给出了真因：

> **CI 一直在测产品默认不用的那条路径。**
> `VectorBTConfig.disable_numba` 默认 `True`，但它是靠**导入时**的
> `os.environ.setdefault("NUMBA_DISABLE_JIT", "1")` 生效；若 numba 已被其它 import 拉起，
> 那句就是空操作 → 阻断道实际在跑 **JIT-on**。把变量放到 **CI job 级 env**（进程启动前）
> 后，那 2 条 vectorbt 用例在阻断道里**通过**（4 片全绿）。

由此已经做的改动：
- vectorbt 两条**回到阻断道**（摘掉 `env_gap`）→ 覆盖恢复；
- whitebox job 加 `NUMBA_DISABLE_JIT=1`（带完整成因注释）；
- 新增一个 **non-blocking** 步骤故意 `NUMBA_DISABLE_JIT=0` 跑同一文件：
  CLI 的 `--enable-numba`（JIT-on）**仍然坏**，让它每轮真实跑并可见，而不是当成不存在；
- `scripts/ci_shard.py` 加 `-rs`：之前无法从“绿”区分“跑过”还是“被 importorskip 跳过”；
- `requirements.txt` 注释改写：明确“别再试钉 numba，该路已实测关闭”，
  并记下 `vectorbt 1.0.0` 也已被实测否证。

**仍然开着的那个缺陷**（不再是“无解”而是“未修”）：`scripts/backtest_vectorbt.py --enable-numba`
在当前 numba 下会崩 `get_call_template`。要它真绿得改上游（或降级 numpy，已否），
所以待定的是产品决策：**保留但标注不可用 / 去掉该 CLI 选项 / 等 vectorbt 侧修复**。

## 七、机制速查
- **marker 分层**：`whitebox`（阻断）/ `slow`（真实联网，非阻断）/ `env_gap`（第三方环境债，非阻断但
  每轮跑）—— 三者与 `xfail` 的区别是**仍执行、仍显示失败**；`env_gap` 必须带理由 + 台账号。
- 改阻断道表达式时，**分片自检与实际分片两处**必须同步（`ci_shard --plan` 复核覆盖率）。
- `ci_digest.py`：把 FAILED/ERROR 摘要发到 annotations，自身永不失败（否则会把真因"掉包"）。
- Env probe 的 `::notice`：CI 里"这个环境的真实版本/import 结果"唯一能被自动化读到的通道。
- 守护清单增长到 **29 道**（本会话新增：i18n 标识棘轮 #25、分片同目录相邻 #26、tests 禁依赖
  `.workbuddy` #27、迁移禁 Text server_default #28、requirements 纯 ASCII #29）。
- 取证纪律（本会话反复付学费的三条）：① 截断输出不能当"不存在"的证据；② 结论前先看完整输出或
  提高上限；③ 改文件后读回核对 —— 编辑工具会替换形近汉字（本轮抓到并修回「环境→环墙」「徽章→徐章」等）
  且**不报语法错误**。
