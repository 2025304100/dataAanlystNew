### R1 · P1 · 静态资源接口允许越界读取

位置：[app/main.py:906](D:/ai_project/dataAanlystNew/app/main.py:906)，关键路径拼接位于 911 行。

处理器直接执行 `dist_root / "assets" / asset_path`，只检查 `exists()`，未解析路径并验证目录边界。开发前端不可用时会走该分支；编码后的 `../` 能进入 `asset_path`。

**证据：** 对真实应用路由请求 `/assets/..%2f..%2freview_probe.txt`，返回 **200** 和资源目录之外的安全标记文件内容。复现中的 `dist_root` 指向临时目录，未读取真实敏感文件。

**影响：** 不可信调用方可以读取后端进程有权限访问的资源目录外文件；泄露范围取决于路径及文件权限。

**建议：** 对根目录和目标执行 `resolve()`，确认目标位于资源根目录内并且为文件；越界返回 404。也可将资源交给支持目录边界校验的静态文件组件。回归用例应覆盖编码斜杠、Windows 反斜杠、绝对路径和正常资源访问。

### R2 · P1 · 数据库热切换后控制平面仍连旧库

位置：[app/db/manager.py:41](D:/ai_project/dataAanlystNew/app/db/manager.py:41)、[app/db/session.py:105](D:/ai_project/dataAanlystNew/app/db/session.py:105)、[app/db/session.py:115](D:/ai_project/dataAanlystNew/app/db/session.py:115)、[app/api/routes/db_config.py:104](D:/ai_project/dataAanlystNew/app/api/routes/db_config.py:104)。

`get_control_session_local()` 只在首次访问时创建 `_cp_factory`。`DatabaseManager.initialize()` 更换主引擎时未失效它；`reset_control_plane_cache()` 有测试引用，却没有生产调用方。

**证据：** 先连接临时 A 库并创建控制工厂，再初始化 B 库，得到主库 `b.db`、控制库 `a.db`，并且两次控制工厂是同一对象。

**影响：** 控制面的异步任务提交、查询、取消，以及部分挖掘任务更新可能继续使用旧库，业务数据和任务记录分裂，出现任务不存在、状态不更新或写错库。是否触发取决于热切换前是否建立过控制连接。

**建议：** 在引擎切换成功的统一位置失效控制缓存，或让缓存绑定引擎代际并在取用时检查；同时设计已有 worker/session 的切换策略。不要只在某个设置按钮路径补调用而遗漏其他 `initialize()` 入口。

### R3 · P1 · 数据库配置校验失败前已写入磁盘

位置：[app/api/routes/db_config.py:82](D:/ai_project/dataAanlystNew/app/api/routes/db_config.py:82)，必填字段检查与连接测试在其后。

`update_db_config()` 先 `save_db_config(new_cfg)`，然后检查 MySQL 字段、连接并切换。HTTP 400 并不能撤销已经保存的配置。

**证据：** 提交 `use_mysql=true` 和空主机/库名/用户名时返回 **400**，但模拟的 `save_db_config` 已调用且写入的 `use_mysql` 为 true。连接失败也走同样的先保存流程。

**影响：** 当前进程可能继续用旧引擎，而磁盘是新错误配置；下次启动可能改连错误目标、回落至其他数据库或无法启动，实际表现依赖具体字段及启动分支。

**建议：** 先验证候选配置和连接/Schema，再以有回滚策略的方式切换并原子保存；校验失败保证旧配置、主引擎、控制引擎一致保留。连接测试引擎应放进 `finally` 释放。

### R4 · P1 · 已实现的取消超时升级没有生产入口

位置：[app/services/async_tasks.py:835](D:/ai_project/dataAanlystNew/app/services/async_tasks.py:835)、[app/services/async_tasks.py:371](D:/ai_project/dataAanlystNew/app/services/async_tasks.py:371)、[app/services/task_heartbeat_service.py:190](D:/ai_project/dataAanlystNew/app/services/task_heartbeat_service.py:190)、[app/services/task_heartbeat_service.py:357](D:/ai_project/dataAanlystNew/app/services/task_heartbeat_service.py:357)。

运行中任务取消时写入 `cancel_requested`、`cancelled_timeout_at`，等待 worker 自止或巡检升级。生产 `_run_patrol()` 只调用另一套 `patrol_interrupted_and_stalled()`，未调用这里的超时处理；独立便利入口也无生产消费者。

**证据：** 对心跳仍新鲜、取消截止时间已过的 running 任务执行生产巡检，仍为 `running`、终态锁为 0、没有取消超时错误。手动调用未接入的超时巡检后立即变为 `cancelled`、锁为 1，并追加 `eval.task.cancel_timeout`。

**影响：** worker 失去取消响应时，取消请求无法按声明的期限收敛；界面可能持续等待或后来被另一套巡检标为中断/失败，并缺失相应取消超时审计。并非所有任务取消都会失败。

**建议：** 将超时升级接入生产周期巡检/现有统一巡检，确保不依赖用户刷新；同时接入需要的 outbox/audit 回调。回归应走真实取消→生产巡检链路，而不是直接调用辅助函数。逻辑终态不等于停止底层线程，worker 的停止检查也要一并验证。

### R5 · P1（可达性相关）· 数据库配置写接口没有认证保护

位置：[app/api/routes/db_config.py:68](D:/ai_project/dataAanlystNew/app/api/routes/db_config.py:68)、[app/main.py:488](D:/ai_project/dataAanlystNew/app/main.py:488)、[app/api/router.py:7](D:/ai_project/dataAanlystNew/app/api/router.py:7)。

数据库配置 router 没有身份/权限依赖，应用及 API router 也没有统一认证保护。项目中的 `STRICT_AUTH` 逻辑主要在组合治理路由内，不能覆盖此接口。

**证据：** 设置 `STRICT_AUTH=1`，向真实应用的 `PUT /api/v1/settings/db-config` 发送无凭据的无效配置，请求进入处理器并调用模拟的配置写入，最后因字段校验返回 **400**，而不是认证失败。

**影响：** 可以访问该后端的不可信调用方能够尝试修改数据库配置，或执行该 router 下的连接测试/迁移能力。证据证明写处理器缺少认证，并没有实际执行迁移；默认仅本机绑定时，不能直接推断公网可利用。

**建议：** 明确本机单用户与远程部署的身份边界。远程/共享部署应为数据库设置和其他系统管理接口统一添加可信身份和管理员权限校验；不能把客户端自行设置的身份头当作可靠身份来源。
