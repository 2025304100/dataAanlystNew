## 1. 测试分层

| 层级 | 目录/命令 | 目标 |
|---|---|---|
| 后端白盒 | `tests/test_whitebox_factor_compiler.py` 等，`pytest -m whitebox` | Parser、AST、安全约束、依赖和编译结果 |
| API 黑盒 | `tests/test_blackbox_*.py`，`pytest -m blackbox` | HTTP 契约、错误码、预览和版本行为 |
| 前端组件 | `frontend/src/components/__tests__`，`cd frontend && npm test` | 渲染、插入、悬浮、模式切换和状态 |
| E2E | `tests/e2e`，`pytest -m e2e` | 创建 draft 到保存版本的完整链路 |
| UAT | `docs/uat-checklist.md` 扩展清单 | 专业用户真实工作流和可理解性 |

## 2. 测试数据与环境

- 使用现有 SQLite 测试数据库进行白盒测试。
- API 黑盒使用本地 FastAPI 服务和固定测试数据集。
- 预览固定股票、日期和交易日窗口，避免实时数据导致结果漂移。
- 准备正常数据、全空字段、部分覆盖、点时数据和不完整横截面五类 fixture。
- 每个预览结果保存 `formula_expr`、DSL 版本、编译器版本和执行计划哈希。

## 3. 核心用例

### 3.1 DSL 和编译器

| ID | 场景 | 输入 | 预期 |
|---|---|---|---|
| DSL-001 | 基础四则运算 | `close / prev_close - 1` | 编译成功，依赖为 `close`、`prev_close` |
| DSL-002 | 数学函数 | `log(max(amount, 1))` | 编译成功，无无限值 |
| DSL-003 | 时间序列 | `mean(close, 20)` | 编译成功，最大窗口为 20 |
| DSL-004 | 逻辑运算 | `pe_ttm > 30 && roe_ttm < 0.1` | 返回 boolean 类型 |
| DSL-005 | 条件函数 | `if(pe_ttm > 30, 0, roe_ttm)` | 编译为 If AST，返回 number |
| DSL-006 | 三元表达式 | `pe_ttm > 30 ? 0 : roe_ttm` | 与 DSL-005 AST 等价 |
| DSL-007 | 多层嵌套 | `if(a > 0, mean(b, 20), zscore(c))` | 编译成功，依赖和窗口正确 |
| DSL-008 | 未知字段 | `mean(not_a_field, 20)` | 返回 `field_not_in_catalog` 和字段位置 |
| DSL-009 | 未知函数 | `unknown(close)` | 返回 `function_not_in_catalog` |
| DSL-010 | 参数数量错误 | `mean(close)` | 返回 `function_arg_count` |
| DSL-011 | 窗口越界 | `mean(close, 999)` | 返回 `lookback_window_exceeded` |
| DSL-012 | 非法代码 | `__import__("os")` | 拒绝执行，返回安全错误码 |
| DSL-013 | 属性/下标 | `close.x`、`close[0]` | 分别拒绝属性和下标访问 |
| DSL-014 | 未来引用 | `ref(close, -1)` | 返回 `negative_lag` |
| DSL-015 | 空公式 | 空字符串或空白 | 返回 `formula_empty` |
| DSL-016 | 超长公式 | 超过长度限制 | 返回 `formula_too_long` |

### 3.2 函数目录和 API

| ID | 场景 | 预期 |
|---|---|---|
| API-001 | 获取公式目录 | 返回 DSL 版本、字段、函数、签名和示例 |
| API-002 | 目录禁用函数 | 前端显示禁用原因，不允许插入 |
| API-003 | 校验成功 | 返回 valid、依赖、窗口、类型和复杂度 |
| API-004 | 校验失败 | 返回稳定 error_code、message、位置和 detail |
| API-005 | 预览成功 | 返回样本日期、值、覆盖率、缺失率和耗时 |
| API-006 | 数据不足 | 返回 blocked 原因，不伪造样本 |
| API-007 | 编译接口 | 只返回编译结果，不产生数据库版本 |
| API-008 | 旧公式 | 旧版本仍可读取、校验和执行 |

### 3.3 前端交互

| ID | 场景 | 预期 |
|---|---|---|
| UI-001 | 打开编辑器 | 保持当前 Modal 三栏布局和底部操作区 |

### 3.4 版本和生命周期

| ID | 场景 | 预期 |
|---|---|---|
| LC-001 | 编译失败保存 | 只能保存 draft |
| LC-002 | 编译成功保存 | 生成 AST、依赖、编译器版本和哈希 |
| LC-003 | 修改已引用版本 | 创建新版本，旧版本不可原地覆盖 |
| LC-004 | 提交 candidate | 必须通过校验和数据就绪门禁 |
| LC-005 | 进入 Shadow | 保留版本和评估证据 |
| LC-006 | 回退 | 不修改历史结果，恢复旧版本引用 |

## 4. 非功能测试

- 普通公式校验 1 秒内返回。
- 悬浮提示延迟 200-300ms，快速移动不闪烁。
- 公式输入采用防抖，不产生重复请求。
- 同一数据批次、DSL 版本、编译器版本和参数必须产生可复现结果。
- 不允许任意 JavaScript/Python 执行、文件访问、网络访问和动态调用。

## 5. 进入和退出标准

### 进入标准

- DSL 语法、错误码和 API 契约冻结。
- 测试 fixture 已准备。
- 新功能由 feature flag 控制。

### 退出标准

- P0 用例 100% 通过。
- P1 核心 UI 用例 100% 通过，整体前端回归无新增失败。
- E2E 主链路通过：draft → validate → preview → version → candidate。
- 无 P0/P1 未关闭缺陷，P2 缺陷有记录和负责人。
