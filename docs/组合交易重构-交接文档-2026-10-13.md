## 1. 这次解决了什么

用户原始痛点：顶栏「待就绪 / 自动接管：未就绪，暂不下单」弹一大段不可点的文字；治理页首屏被三栏说明书占满、黑话代号多、无从下手。

改造后的形态：

1. **三套状态归一**：HG1 九状态机、自动交易五维就绪门禁、G7 灰度运维，聚合为一份只读「行动项」。
2. **顶栏单胶囊**：`自动接管 · N 项待处理`（红）/ `已就绪，等待调度`（绿）/ `等待交易信号`（绿）/ `运行中`（任务实际执行）/ `已关闭`（灰），hover 只留五维灯，点击开右侧修复抽屉。
3. **修复抽屉**：每条 = 一句话问题 + 一句影响 + 唯一主动作；对账阻断支持抽屉内三步引导。
4. **治理页按任务重组**：默认「待办总览」，子页改为 待办总览 / 每日对账 / 运行状态 / 双跑验收 / 审计记录；说明书收进帮助弹窗；权限矩阵默认折叠；默认视图清除 HG1/G5/G6/G7 代号。

原 P0/P1 主要调整展示。本轮进一步补齐确认与执行门禁：应用新快照后锁定模型维度，本人查看变更并接受后解除；对账确认必须重新对账通过且无差异，审查备注写入现有审计表。原状态枚举、调度时间与对账计算不变，无新增生产库表或字段。聚合读取仍严格只读。

## 2. 架构与数据流

```
HG1 /portfolios/{id}/status ──┐
readiness /auto-trade/readiness ─┼─▶ portfolio_action_items（只读聚合/排序/同族去重）
G7 /auto-trade/g7-operational ──┘            │
                                             ▼
                         GET /portfolios/{id}/auto-trade/action-items
                                             │
                  ┌──────────────────────────┴─────────────────────────┐
                  ▼                                                      ▼
        顶栏 ReadinessRepairDrawer（P0）                  治理 GovernanceOverviewPanel（P1）
                       两者同接口、同前端动作注册表 actionItemRegistry
```

关键不变量：

- 聚合是**只读实时视图**，不写库、不触发转移/对账/审计。
- **数据新鲜度同族去重**：readiness 的 `MARKET_DATA_STALE` 与 HG1 的 `DATA_INCOMPLETE_PAUSED`/`SCORE_STALE` 合并为一条（family=`data-freshness`），保留最高 severity。
- 主动作六类：`toggle`（原地开关）、`redirect`（跨页）、`subtab`（组合内子页）、`open-modal`、`guided`（对账三步）、`none`（仅说明）。
- 后端是 code 语义与跨页 target 的唯一来源；组合内导航/弹窗/分步由前端按 code 绑定。
- 未经验证的导航目标一律降级为 `none`，杜绝「指引指向不存在的页面」。

## 8. 已知遗留与后续 TODO（均不影响本次功能）

4. **全局 `useApp must be used within AppProvider` 历史错误**：堆栈在 `src/main.tsx <Root>`，不在本次组件链，功能正常，建议单独排查全局初始化/Provider 嵌套。
5. **新手首次轻提示未实现**：设计稿提过「首次进入显示一次可关闭提示（localStorage）」，评估与帮助弹窗+默认总览信息重复，为减少打扰未做；如产品需要可补。
6. **服务进程无 reload**：后端开发时建议自行加 `--reload` 或沿用 `scripts/dev_services.py`，避免每次改后端手动重启。

## 9. 接棒注意事项（防腐化约定）

- 新增 readiness blocker/warning：在 `auto_trade_readiness.py` 加常量后，**必须**登记 `READINESS_FIX_REGISTRY`，否则守护测试 `test_whitebox_auto_trade_readiness_registry.py` 立即变红。

- 不要在聚合服务里写库或触发状态转移；读取状态也不得顺便建列或提交。写操作由专用确认接口处理，重新验证当前条件并记录审计。

### 10.1 用户确认的四个口径

1. 自动接管已开启、条件齐全、任务尚未执行：显示「已就绪，等待调度」。只有实际自动任务在执行时显示「运行中」。
2. 已有有效候选与策略，但无持仓/今日无买入信号：显示正常等待交易信号，不引导重复添加候选。仅在来源、资产范围、数据、治理锁、模型与调度均正常时适用；执行器原本不可下单的条件不放宽。
3. 工作台为单人使用：首次审查、暂停恢复、对账接受由本人处理。权限身份与后台鉴权机制不变。
4. 模型或策略变更：保存应用后查看待办卡的变更摘要，本人明确接受后恢复模型维度。确认不自动解除暂停、数据、对账或首次审查等其他阻断。

### 10.2 修复后的关键契约

- `summary.ready` 综合五维就绪、HG1、独立四维锁、DecisionEngine 来源、已应用快照及模型绑定，不再仅沿用 readiness 布尔值。配置就绪/等待信号/实际运行独立表达，顶栏与抽屉先展示阻断。
- 治理快捷动作与修复指引支持 `governance:state/reconciliation/audit` 深链，实际进入对应治理子页；关闭抽屉后可直接处理。
- 抽屉和治理页的确认均同步刷新行动项、HG1 权限和工作台数据；包括模型接受、初审/暂停恢复与对账确认。回调携带组合 ID，请求代次、组合标识与卸载保护防止旧响应覆盖当前组合。
- 对账确认透传用户备注与重新对账报告的 `trade_date`。省略日期时由后端交易日历决定，不再由浏览器强制「昨天」。两个确认别名均要求至少 10 字备注，必须再次对账 `PASSED` 且无差异，禁止跳过检查。
- 对账支持旧总体状态锁与独立对账维度锁；只清除对账阻断。真实重新对账及人工接受备注写入现有审计表，失败整体回滚。
- cron 自动推演预检同步检查四维状态，避免旧总体状态仍为就绪时绕过模型待确认、数据或对账阻断。
- 共享 DecisionEngine 的持久化自动推演入口检查运行态、独立锁与当前有效绑定；预检后的「自动推演执行中」是合法运行态。未确认/模型已切换时普通自动启动返回 409；`dry_run` 与回测诊断保留。
- 订单适配器保留风险退出路径，将被锁的新 BUY 证据改为拒绝；新买进入真实模拟撮合/账本前再次校验并锁定组合与活动模型配置。全局模型切换后即使旧四维状态仍为就绪，也不能新增买入。已部分成交计划沿用原订单/计划/证据续成交，重复同调度日不增加成交或重复扣款。
- 历史 `save_and_apply` 快照仍可在当前绑定已确认、其冻结模型/因子集及策略绑定与当前有效绑定一致时显式回放；不同绑定、未应用快照或无绑定快照不能用于新增真实买入。
- 治理锁变化后的退出推演使用包含稳定阻断摘要的决策 ID，正常决策 ID 不变；避免同一输入由 BUY 变成拒绝证据时复用旧记录造成外键冲突。开启 SQLite 外键的同日锁定/重复/解除回放已覆盖。
- 本人确认 POST 与最终新买采用当前读（组合、四维/旧状态、快照/绑定、接受审计与模型/因子集），避免事务旧快照覆盖行锁读到的新值。普通 GET 聚合仍只读且不加写锁。
- 状态读取移除兼容建列/提交行为；旧库缺列时只读回退，兼容写入只留在专用写路径。

新增模型确认接口：

```text
GET  /api/v1/portfolios/{id}/model-binding-review
POST /api/v1/portfolios/{id}/confirm-model-binding
```

GET 返回 `before/after`、`change_summary`、`can_confirm`、`requires_confirmation` 与中文 `blockers`。`before` 仅取此前本人接受的现有审计记录；没有记录就说明首次确认，不推测历史绑定。当前快照与执行器共用「最新 save_and_apply」选择规则，预检/任务锁定快照不算保存应用。

POST 接收 `snapshot_id`、`model_run_id`、`ack=true`、`review_note`。服务端在事务内锁定组合与活动模型配置，核对用户所见快照、模型和当前有效性；期间有变化或条件失效返回 409，前端刷新摘要、清空勾选和备注。接受后仅解除模型维度，并记录 `FACTOR_USAGE_APPLIED` 审计（`confirmation_type=MODEL_BINDING_CONFIRMED`）。

`save_and_apply_usage` 应用新的不可变快照时设置模型待确认；完全相同的已应用快照幂等返回，不重复锁定。生产源无新增 schema。
