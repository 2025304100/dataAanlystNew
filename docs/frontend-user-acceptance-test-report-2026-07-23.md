# 前端用户视角完整测试报告

## 1. 测试结论

本轮按普通用户操作方式，对前端一级导航、设置中心全部分类、主要弹窗、表单校验、任务入口和关键页面状态进行了黑盒测试，并补跑了完整前端自动化测试。

结论：**当前版本不具备发布验收条件**。基础页面大多能打开，宏观数据、行情消息、数据库连接、AI 配置界面、评分配置和定时任务管理可以使用；但消息管理真实接口缺失、AI 新建会话接口缺失、因子流水线真实运行失败、部分机会池未完成、前端自动化和 TypeScript 校验均未通过。

## 4. 关键黑盒缺陷

### P0：消息管理页面不可用

设置 → 消息管理会同时出现：

- 加载渠道失败 `Not Found`
- 加载策略失败 `Not Found`
- 加载模板失败 `Not Found`
- 加载发送记录失败 `Not Found`

前端组件位于 [ChannelConfig.tsx](/D:/ai_project/dataAanlystNew/frontend/src/components/notifications/ChannelConfig.tsx)，但后端没有对应 `/api/v1/notifications/*` 路由注册。

### P0：AI 真实发送链路未闭环

未配置 AI 时，浮动助手能正确提示“AI 助手未配置”。但配置 Profile 后，前端发送消息会调用 `POST /api/v1/ai/sessions`，后端会话路由只有查询、删除、审计和清理，没有创建会话接口。

相关文件：[AIAssistant.tsx](/D:/ai_project/dataAanlystNew/frontend/src/components/ai/AIAssistant.tsx)、[ai_sessions.py](/D:/ai_project/dataAanlystNew/app/api/routes/ai_sessions.py)。

### P0：因子流水线真实运行失败

用户点击“运行流水线”后，界面先显示“因子流水线已启动”，随后最近任务变为失败，错误为：

```text
Factor pipeline failed: cannot unpack non-iterable NoneType object
```

任务中心也能展开看到相同错误。因此进度条不是单纯显示问题，而是后端流水线启动/心跳处理存在真实异常。

### P1：数据库迁移与启动清理存在 schema 漂移

后端启动日志反复出现清理失败：

```text
Unknown column 'scan_runs.snapshot_id' in 'field list'
```

这说明当前 MySQL 表结构没有跟上代码模型，启动清理和过期结果治理不能认为可靠。

### P1：机会池功能仍有明确占位

- 观察池加载失败时没有具体错误原因，只显示“重试”。
- 已排除池显示“建设中”。
- 扫描记录显示“建设中”。
- 机会中心与机会挖掘存在重复入口，用户容易不知道应该从哪里开始。

### P1：数据时效性不达标

首页显示：

- 7 个标的 K 线过期；
- 发现池 1998 条结果已过期；
- 因子覆盖率只有 13.2%；
- 当前因子模型为 degraded。

系统能提示风险，但目前不能把“数据不新鲜”自动转化为稳定、可完成的补数闭环。

### P1：界面编码和错误信息问题

- 组合页面的默认组合名称显示为 `????`。
- 组合扫描失败只显示英文 `Service Unavailable`，不符合普通用户可理解错误要求。
- 观察池失败缺少接口、状态码和下一步动作。

## 7. 本轮安全边界

以下动作没有点击最终确认，原因是会改变真实数据或产生外部副作用：

- 删除组合、删除评分预设、删除定时任务；
- 保存新组合、新 Profile、新评分预设、新计划；
- 切换数据库或执行一键迁移；
- 真实发送通知、AI 请求或第三方接口探测；
- 触发全市场机会挖掘、宏观刷新和全部外部数据同步；
- 执行模拟买入/卖出或自动交易；
- 执行完整历史补数。

本轮曾误触发/检测到一个 7,206 标的增量同步任务，随后通过取消接口安全停止，最终状态为 `cancelled`，处理约 345/7206。

### 15.1 状态定义

为避免把“没测试”误写成“功能不存在”，本报告使用以下四种状态：

| 状态 | 含义 |
|---|---|
| 确定缺失 | 前端已经调用，但后端路由、页面或核心处理不存在 |
| 已实现但故障 | 入口和代码存在，真实操作可以复现报错或错误结果 |
| 占位未完成 | 页面明确显示“建设中”或只有空壳，目标业务流程尚未交付 |
| 已实现但未验收 | 代码和单元测试存在，但没有真实 API、数据库、性能或故障恢复证据 |

#### P0-03 因子流水线真实运行失败

| 最终目标 | 用户点击一次即可看到持续进度，任务最终明确成功/失败，成功后产生可追溯的因子日期、覆盖率、模型版本和评分快照 |
| 通过标准 | 默认参数流水线成功完成；进度持续更新；失败提示中文且可操作；取消/重启后无假运行和 DuckDB 锁残留 |

### 15.3 P1 主要功能与稳定性问题

#### P1-01 MySQL 数据库结构没有完整迁移

| 项目 | 内容 |
|---|---|
| 发生位置 | 后端启动清理、扫描历史与过期结果治理 |
| 当前表现 | 启动日志出现 `Unknown column 'scan_runs.snapshot_id' in 'field list'` |
| 未通过原因 | 当前 MySQL 旧库表结构落后于 SQLAlchemy 模型；新增字段主要依赖运行时补丁，Alembic revision 不完整 |
| 未完成部分 | 为扫描快照、通知、AI、组合成员、回测快照等新增表和字段建立完整迁移链，并提供回滚 |
| 最终目标 | 新库和旧库都能通过同一版本化迁移稳定启动，历史数据和 ID 保持不变 |
| 通过标准 | 全新/旧版 SQLite 和 MySQL 四套环境升级通过；重复升级幂等；启动无 unknown column；迁移失败可回滚 |

### 15.4 已实现但尚未真实验收的核心能力

以下项目不能判定为“缺失”，但也不能判定为“完成”：

| 功能 | 尚缺的验收证据 | 最终目标 |
|---|---|---|
| 候选→观察→组合流转 | 真实数据库双击幂等、事务回滚、审计记录 | 一次动作完成全部关系更新且可追溯 |
| 组合成员与持仓 | 新增/暂停/恢复/持仓冲突归档 | 成员是策略范围，持仓是账户事实，二者不混用 |
| 自动交易 | dry-run、三模式、风控阻断、订单幂等、双跑 | 自动交易只处理允许的成员，任何异常 fail-closed |
| 单股与组合回测 | 共享资金、历史成员快照、费用、引擎对比 | 无未来数据污染，不影响当前模拟账户 |
| 绩效与复盘 | 订单/成员/信号/规则/成交关联和样本不足 | 每笔结果可解释、可回到原始决策依据 |
| 外部接口网关 | 缓存不发网、单飞、熔断、半开恢复 | 免费接口失败时系统仍可控、可恢复、可解释 |
| 定时任务 | 重启补跑策略、错峰、并发冲突和幂等 | 重启不会无提示同时启动多个重任务 |

### 15.5 修复完成后的目标产品状态

最终不是“所有页面都能打开”，而是形成以下可重复闭环：

```text
本地数据健康检查
  → 必要时增量补数和降级
  → 生成版本化因子与评分快照
  → 5 分钟内完成机会扫描
  → 候选加入正式观察池
  → 研究后进入指定组合成为成员
  → manual / confirm / auto 执行
  → 单股或组合回测验证
  → 订单、收益、归因和复盘
  → AI 解释与多渠道通知
```

这条链路的每一步都必须满足：数据日期透明、来源透明、公式和版本可追溯、前置条件不足时阻断、错误可理解、任务可取消、失败可恢复、重复操作幂等、历史数据不被覆盖。

### 15.6 建议修复顺序

1. 消息管理 API、AI 创建会话 API、因子流水线异常。
2. MySQL schema 漂移和完整 Alembic 迁移。
3. 观察池真实加载、已排除池、扫描记录和组合错误提示。
4. 前端 90 个失败测试与 40 个 TypeScript 错误。
5. 候选→观察→组合→订单→复盘真实集成链路。
6. 自动交易、回测、AI、消息真实验收。
7. 五分钟扫描、接口熔断、断网、取消和重启测试。
8. 最终无 Mock 浏览器 UAT 和文档 Scenario 逐条签署。
