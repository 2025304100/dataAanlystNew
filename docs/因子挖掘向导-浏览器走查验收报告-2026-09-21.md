## 四、走查捕获的缺陷与修复（重要）

### 缺陷：`members_json` MySQL `Text`（64KB）截断 → 「生成挖掘物料」500

- **现象**：首次走查 Step1 点击「生成挖掘物料」（全市场 5544 只）无响应；后端日志：
  `JSONDecodeError: Unterminated string starting at line 1 column 63169`，栈在
  `analysis.analyze_pool` → `json.loads(snapshot.members_json)`。
- **根因**：`training_candidate_pool_snapshots.members_json` 为 MySQL `Text`（65535 字节上限）。
  数千成员（symbol/name/market/reason）的 JSON 序列化超限后被 MySQL **静默截断** →
  落库的是非法 JSON → 快照分析必然 500，向导 Step1 无法完成。（SQLite 的 TEXT 无长度上限，
  故本地单测未暴露；真实 MySQL 环境才触发。）
- **修复**（三层）：
  1. 模型 `app/models/mining_candidate_pool.py`：`members_json` 改用
     `Text().with_variant(MEDIUMTEXT(), "mysql")`（16MB，约可存 10 万+ 成员）；
  2. 迁移 `alembic/versions/2026_09_21_0062_wps_0023_061_snapshot_members_json_mediumtext.py`：
     MySQL `ALTER TABLE ... MODIFY members_json MEDIUMTEXT NOT NULL`（幂等探类型跳过），
     SQLite 无操作；已经 `bootstrap_db.py` 应用到真实 MySQL；
  3. 回归测试 `tests/services/factors/candidate_pool/test_e2e.py`：
     `test_large_members_json_roundtrip_not_truncated`（>64KB JSON 完整往返契约哨兵，2 passed）。
- **复跑验证**：修复后走查 **1.8/1.9/1.10 全部 PASS**（生成物料→锁定→看板→Step2）。
