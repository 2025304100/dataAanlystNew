## 四、跨页面矛盾（非本页 bug，但影响判断）

今日决策页"数据健康"挂件显示 **行情覆盖率 4.5%、99.6% 超 7 天未更新、1574 缺失、异常 38**，与数据管理页"100% 同步"矛盾。根因是**双存储**：

| | 新存储 | 旧存储 |
|---|---|---|
| 符号表 | `universe_symbols`（7,272） | `symbols`（7,639，is_active≈1,649） |
| K线表 | `universe_daily_bars`（1,173 万根，到 10-23） | `daily_bars`（142.7 万根，大量标的停在 10 月中前） |
| 写入方 | universe 增量/智能同步 | ETF 历史管道、手动 market-data 更新（universe 同步**不写**） |
| 读取方 | `/universe/stats`（数据管理页） | `/system/data-health`（今日决策页） |

评分/因子实际消费因子仓库镜像（到 10-23），功能链路不受影响 → 决策台红字是**误报**，且点"去行情底座"修复也消不掉（修的是新存储）。

## 五、Bug 清单（含代码定位）

### D1 ｜任务状态语义失真（两面都歪）｜P1
- **现象 A（小失败放大成全失败）**：10-16 估值同步 `status=failed`，result 实为 success 5549 / failed 6（AAPL+5 只无数据），5549 行已写齐。
- **现象 B（大面积跳过显示成全部完成）**：10-25 01:10 ETF 指标任务任务中心显示"1642/1642 已完成"，result 实为 success 11 / **skipped 1631** / records 106。
- **影响**：面板任务状态不能当"数据齐不齐"的依据；10-16 之后没人重跑估值（10-19 空窗可能与误判"已失败"有关）。
- **定位**：任务状态收敛逻辑在 `app/services/external_data_sync_task.py`（个股失败→任务 failed 的收敛点）与任务中心展示（`frontend/src/components/TaskCenter.tsx`，进度只展示 processed/total）。
- **建议**：引入 `partial_success` 终态；进度条旁露出 `success/skipped/failed` 三元组；skipped>50% 时给醒目提示。

### D2 ｜资金流接口降级后无兜底、无补漏路径｜P1
- **现象**：10-14/15/16 资金流三天全缺。任务记录："全市场资金流排行接口不可用，未执行逐标的兜底（避免 5,000+ 次请求）"。
- **定位**：`app/services/external_data_sync_task.py:1196`（`raise RuntimeError("资金流当日接口不可用，已停止同步，未执行逐标的兜底或历史下载…")`）。
- **影响**：接口抖一天数据永久缺一天；增量模式设计为"接口未返回的日期不会填补"（估值同理，G2 的 10-12/10-19 空窗即此），缺口语Never自动愈合。
- **建议**：① 接口不可用时记入"待补漏"清单，下次任务成功后自动重试近 N 天缺口（或提供显式"补漏回填"入口）；② 兜底请求量可用 async 批次+限速控制，而非直接放弃。

### D3 ｜任务中断无断点续传，留半截数据｜P2
- **现象**："Backend restarted before task completed" 出现 ≥4 次（10-11×2、10-14 估值、10-25 01:58 因子流水线）；10-14 估值仅 891 行、10-15 被取消仅 344 行。
- **定位**：`app/services/async_tasks.py:528`（重启后统一标记）。
- **建议**：恢复启动时扫描 `running` 态任务，按 partition/batch 粒度续跑或至少生成"半截数据"告警，避免缺口被静默遗留。

### D4 ｜指数同步无标的校验 + 源字段缺失｜P2
- **现象**：`index_prices` 混入 000001/000010/399001 三条杂项（sina 源按股票返回，242 根、停在 2026-08-07，名称=代码）；5 大基准指数 amount 全空。
- **定位**：`app/services/index_prices_sync_task.py:39-40`（`if symbols: return list(symbols)` 无白名单/格式校验）。
- **建议**：① 入口校验指数代码（交易所段位/白名单，拒绝股票代码）；② 清理 3 条杂项（`DELETE FROM index_prices WHERE symbol IN ('000001','000010','399001')`，验证库可执行）；③ sina 指数源补 amount 或在状态 API 标注该字段不适用。

### D5 ｜休市守卫行为不一致（人气榜）｜P3
- **现象**：10-18（周日）14:13 人气榜手动同步成功写入 100 条（stamped 10-18）；10-25（周日）01:14 的运行被"所选日期为 A 股休市日，无需更新"拒绝。
- **定位**：`app/services/external_data_sync_task.py:1039/1567/2075`（守卫存在，但 10-18 那次走的路径/时点绕过了判断）。
- **建议**：统一在写入前强制校验 trade_date 是否交易日，休市日一律拒绝或仅允许显式 `force`。

### D6 ｜UI 承诺未实现：估值"行业分位"｜P2
- **现象**："其他数据"页估值行描述为"PE/PB/市值/**行业分位**（仅 A 股）"，但 `stock_valuations.industry / industry_pe_percentile / pe_history_percentile` 与 `universe_symbols.industry` 全部 0 行。
- **建议**：要么实现行业字段同步（东财估值接口自带行业快照可顺带入库），要么从 UI 描述移除"行业分位"字样——二者选一，当前状态是描述与数据不符。

### D7 ｜今日决策数据健康误报（双存储口径分裂）｜P2
- 见第四节。**建议**（三选一）：① `/system/data-health` 的 K 线统计切到 `universe_daily_bars` 口径；② 观察池迁移到 `universe_symbols` 体系；③ 挂件标注数据口径与"行情底座"入口的修复目标一致化。修复前它每天都会误报"行情覆盖率 4.5%"。
