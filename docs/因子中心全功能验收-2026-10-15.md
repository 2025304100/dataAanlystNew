## 页面使用顺序

从因子库点击名称，先核对公式、方向、最新版本及编译状态。研究因子按详情的下一步提交候选、开始测试；点击去评估会携带当前因子和最新版本。预检通过后才能运行评价，评价通过不会自动上线。

训练模型时进入因子模型工作区，先准备集合、选择已校验版本、冻结，再训练与查看验证。实际运行资格仍由冻结集合、训练来源和模型证据共同检查；旧记录标记 validated 或 active，不能代替当前资格。

列表默认收起额外指标和负责人等低频信息，保留版本、真实覆盖、评价和生命周期。更多筛选揭示来源及补充信息；指标提示解释窗口、缺值和单位。版本选项使用版本号与编译状态，避免要求用户手填数据库 ID。

## 单天估值同步为什么慢

本任务确实只请求 **2026-10-15 单天、全量 5555 只标的的估值**，不是财报同步。它来自已有定时任务 ID 12“每日因子估值增量同步”，20:30 自动触发，分区计划 `16386d6e422c46f992dd70601a42bb81` 的起止日期相同。

慢点在供应商失败后的重复网络请求：全市场快照失败并重试 3 次后，4 个 worker 逐股兜底；每只股票又重复请求全市场快照并重试，然后请求个股估值历史，还额外请求行业信息并重试。日期跨度小，只限制最终写入范围，没有限制这条路径的网络开销。

已修复后续任务的兜底路径：已失败的全市场快照不再逐股重试，直接读取真实个股估值历史；行业复用本地主数据，并单独报告标签缺失。历史数据必须落在请求日期范围内，所选日期无记录时失败并写 0 行，不能拿旧日记录冒充当日。正常全市场快照成功仍保持一次请求。

公开 HTTP 隔离用例证明：全市场接口失败、两只股票兜底时，该接口实际调用由 **9 次降为 3 次**；历史调用为 2 次，行业远程调用为 0。此为可控供应商模拟，不是现场耗时承诺；旧 worker 在取消前没有热加载或自动加速。任务中心同时把 `external_sync_fundamental` 显示为“股票估值同步”，避免与财报混淆。
