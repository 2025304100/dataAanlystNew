## 三、P0（阻断，必须修）

### P0-1 「生成挖掘物料」请求 405，Step1 走不下去
- **现象**：Step1 输入筛选条件后点「生成挖掘物料」→ 页面弹错误提示，候选池永远无法锁定，后续步骤拿不到 `candidate_pool_snapshot_id`。
- **证据**：`POST /api/v1/factor-mining/candidate-pools//snapshot`（**双斜杠**）→ `405 Method Not Allowed`；请求体 `{"analyze":true,"as_of_date":null}`。截图 `31_step1_generate.png`。
- **根因**：`MiningShell.tsx:314` 渲染 `<MiningPoolStep onNext onSnapshot />` **未传 `poolId`**，组件默认值 `""`（`MiningPoolStep.tsx:38`），拼出空 id URL；且整个 Step1 **没有"按筛选条件建池"这一步**——`poolApi.ts` 里已有 `createPoolFromFilter`（`POST /candidate-pools/from-filter`），前端从未调用。
- **修复**：`onGenerateClick` 中先 `createPoolFromFilter`（命中 <50 / 覆盖率不足时后端会 4xx 且不落库，按契约展示阻断）拿到 `pool.id`，再 `createSnapshot(pool.id, {analyze:true})`；同时 `MiningShell` 需持有并下发 `poolId`。

### P0-2 Step3「字段与校验」没有任何字段可选
- **现象**：Step3 页面只有「已选字段: 0」和**永远禁用**的「开始校验」，无字段清单。
- **证据**：`document.querySelectorAll('[data-field-checkbox]').length === 0`；截图 `20_step_field.png`（近乎空白）。
- **根因**：`MiningFieldStep` 的 `fields` 靠 props 注入、默认 `[]`（`MiningFieldStep.tsx:41-48`），而 `MiningShell.tsx:347` 未传。**后端接口是现成的**：`GET /api/v1/factor-mining/candidate-pools/filter-fields` 返回 200 且字段完整（含 `field/label_zh/category/availability/blocked_reason_zh`），`poolApi.ts` 也已有 `fetchFilterFields()`，但**没人调用**。
- **修复**：Step3 挂载时 `fetchFilterFields()`，映射为 `MiningField[]`（code=field、name_zh=label_zh、group←category、blocked_reason←blocked_reason_zh）后注入。

### P0-3 Step4「确认提交」无请求、弹窗不关、无提示（交互死胡同）
- **现象**：点「开始挖掘实验」→ 资源确认弹窗正常弹出（文案「当前无其他写任务，可立即开始」正确）；点「确认提交」→ **无 `POST /factor-mining/runs` 请求**，弹窗不关闭，页面无任何错误提示，之后再点任何按钮都被弹窗遮罩拦截。
- **证据**：`deep2_report.json` → 该步骤 `new_reqs` 只有 `notifications/inbox`（轮询），无 runs 提交；截图 `37_step4_submitted.png`。
- **根因**：`MiningShell.tsx:206-211` `handleSubmit` 首行 `if (!cfg.candidate_pool_snapshot_id) { setSubmitError(true); return; }` —— 因 P0-1 快照 id 恒空直接 return；且 `MiningEvoParamStep.tsx:208` `onConfirm={onSubmit}` **不关闭弹窗**，错误文案还被弹窗遮住，用户完全看不到。
- **修复**：`onConfirm` 先 `setShowConfirm(false)` 再提交；提交前置校验失败时给出可关闭的明确提示（如「请先回到第 1 步生成挖掘物料」）并跳回 Step1。

### P0-4 Step1 预览统计恒为空，<50 硬阻断失效
- **现象**：输入最小总市值后底部出现「全市场: / 命中: / 排除:」，**三个数字全是空白**。
- **证据**：`POST /candidate-pools/preview` 返回 200：`{"universe_size":5554,"hits":5554,"excluded_total":0,...}`（有真实数据），但 UI 取不到值。
- **根因**：**字段名不匹配**——`poolApi.ts:24-31` 的 `PoolPreview` 声明为 `total/matched/excluded`，后端返回 `universe_size/hits/excluded_total`，`MiningPoolStep.tsx:182-193` 渲染 `preview.total/matched/excluded` 全为 `undefined`。连带后果：`blocked = preview.matched < MIN_POOL_SIZE` 恒为 `false`（`undefined < 50`），**"有效标的 <50 硬阻断"这条需求规则实际失效**。
- **修复**：前端适配后端字段（或在 `previewPool` 返回处做一次映射），并把 `blocked` 判定改为基于 `hits` 与后端 `min_pool_size/can_generate`。

## 四、P1（严重）

### P1-1 今日决策「执行预检」点击后完全静默
- **现象**：点「执行预检」→ **不发任何请求**、不出现 loading、不弹 toast，HG1/HG2/HG3 永远停在「未评估」，导致「进入自动推演 / Shadow」**永久禁用**。
