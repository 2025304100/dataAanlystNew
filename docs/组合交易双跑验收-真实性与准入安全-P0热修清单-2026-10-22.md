## 1. 热修目标与范围

确保没有真实执行证据、没有有效样本、报告不存在或不可解析时，系统不能给出可用于切换/扩大范围的双跑通过结论。当前环境未接通真实执行器时，明确报告能力不足。

保留已有模拟组合日常运行与风险处置的独立门禁。缺少可信双跑证据用于拒绝新的方案准入，不扩展为所有组合停止交易。

本清单不承接 Tab 合并、页面布局、版本选择器、完整真实双链平台、新账户基线、自动对账作业或 AI 助手。真实执行器与快照来源的后续建设按目标设计第 8、10.8 节实施。

### 2.1 准入证据政策（本次补充）

所有“可用于切换/扩大范围”的结论，必须同时满足以下三层证据。字段存在、非空哈希或布尔值为 true 都不构成证据。

**A. 来源层**

| `capture_mode` | 是否可用于准入 | 附加要求 |
|---|---|---|
| `real_dry_run_export` | 是 | 双侧真实运行引用可解析；输入清单与哈希由真实输入计算 |
| `historical_replay` | 有条件 | 必须是真实执行器对真实历史输入的回放；`source_run_id` 可解析到真实运行记录；日历来自已校验的 `trade_calendar`；输入清单可复核。缺少任一条件即拒绝 |
| `synthetic` / 虚拟 / 演示 | 否 | 只允许离线算法单测和明确标注的演示，不得进入正式报告 |

来源校验必须拒绝：

- `g5-virtual-*` 或其他自造来源 ID；
- `G5_VIRTUAL_WEEKDAY` 或其他工作日近似日历；
- `source_manifest_sha256` 由报告自身 ID 计算（自引用哈希）；
- 只有 `capture_mode` 标签、没有可解析真实运行记录的“伪真实”来源。

**B. 样本层**

有效样本必须同时满足：

```text
days_replayed == expected_trade_dates
每个回放日，双侧 coverage_pct > 0
valid_symbol_days >= acceptance_policy.min_symbol_days
skipped_days 为空（或仅含已批准豁免）
双侧来源引用均可在真实运行记录中解析
```

阈值 `acceptance_policy.min_symbol_days` 来自 `acceptance_policy_version`，由后端版本化策略返回，不在前端写死；策略变化必须重新预检并生成新报告版本。

零分母不是 1.0：

- `universe_jaccard` 在 `union == empty` 时为 `NOT_APPLICABLE`，不是 `1.0`；
- `action_match_rate` 在 `denom == 0` 时为 `NOT_APPLICABLE`，不是 `1.0`；
- 全 HOLD / NO_ACTION 只有在真实检查过标的后才计入有效样本，且必须保留数量与依据。

**C. 状态层**

报告状态至少区分：

```text
SUBMITTED / RUNNING / COMPLETED / FAILED / CANCELLED / NOT_FOUND / INVALID
```

只有 `COMPLETED + 有效报告` 才可能产生 `eligible=true`。排队、运行、失败、取消、未找到、解析失败一律不得展示绿色通过，也不得作为准入依据。

## 3. 独立热修项

| 编号 / 优先级 | 修复要求 | 验收条件 |
|---|---|---|
| HF-01 / P0 | 删除报告未找到时的虚拟结果；返回 404 + `G5_REPORT_NOT_FOUND`，不得附通过标记、假日期或假统计 | 任意不存在 ID、其他组合报告 ID 均不能得到可准入结果 |
| HF-02 / P0 | 删除解析失败和缺关键字段时的乐观默认；返回明确 `G5_REPORT_INVALID / G5_RESULT_UNAVAILABLE` 错误，区分存储异常 | 损坏 JSON 或已宣称完成却缺逐日报告、有效日期、来源/阈值/样本时，不能降级成可准入；排队/运行中按真实任务状态展示 |
| HF-03 / P0 | 正式入口不调用虚拟/合成 runner；没有真实适配器时返回 `G5_REAL_RUNNER_UNAVAILABLE`。旧/新版本无法解析到真实方案时拒绝启动。新增只读能力发现（`GET /portfolios/{id}/g5-dual-run/capabilities` 或状态字段 `real_runner_available`），前端在表单前展示能力缺失并禁用启动。能力发现路由必须置于 `GET /g5-dual-run/{replay_id}` 之前，避免 `capabilities` 被当作 replay_id | 随意填写版本字符串不能创建可准入报告；无执行器时表单直接显示不可用，不要求用户填完再收到失败 |
| HF-04 / P0 | 按 2.1 的准入证据政策，在持久化与最终准入处统一校验来源、完整日期清单、双侧真实运行引用、覆盖与有效样本；显式排除虚拟/合成来源和自引用哈希；`historical_replay` 只有满足真实重放证据才可用于准入 | 0 覆盖/空样本/`g5-virtual-*`/`G5_VIRTUAL_WEEKDAY`/自引用哈希/无真实运行引用的 `historical_replay` 绝不用于准入；非空清单哈希本身不足以通过；有效样本定义见 2.1 |
| HF-05 / P0 | G6 最终准入、G7 扩大范围判定、`can_switch_to_member_source` 切换来源门禁统一调用同一个 `validate_g5_report(...)`，复核报告存在性、状态、内容指纹、来源、样本、校验结论及适用组合/方案；核对 typed 列与 JSON 一致性 | 三个消费方对同一份无效报告结论一致；不能仅凭 JSON=true 或 typed 列=true 放行；无效最新报告不能通过偷偷回退某份旧通过报告规避 |
| HF-06 / P0 | 展示与准入读取同一报告有效性结果；缺样本显示“证据不足”，明确分母，禁止补造 100% 和全零比较证据。矩阵契约固定为嵌套二维或前端归一化扁平 36 键并加契约测试；不得用首日矩阵代表全区间，至少标注展示范围并支持按日/全区间。404 为终态：前端停止轮询、显示“报告不存在或已清理”并提供重新发起入口 | 接口错误、缺矩阵、结构非法或 404 时显示未完成/不可读；不能渲染绿色通过；首日通过但后续失败时不得显示绿色；404 不继续轮询 |
| HF-07 / P0 | 先只读盘点遗留虚拟/无效报告及 G6/G7/切换来源引用，输出报告与受影响组合清单；HF-01～HF-06 上线前冻结新的 G6 准入、扩大范围与来源切换；经审核实施追加式失效记录与可追溯准入隔离 | 冻结窗口内新准入被拒绝；原报告与审计保留；处理前后有清单、理由与回滚材料，不批量改余额、持仓或运行状态；恢复新准入需审核 |

约束：

- 合成 runner 可继续用于离线算法单测和明确标注的演示，生产准入入口必须隔离；不以修改单测让虚拟数据“更像真实”作为修复。
- 现有来源校验失败后的 `g5_validation_errors` 等原因须可被查询与准入消费，不能写入后又被响应模型丢掉。
- 无真实执行能力时优先明确拒绝启动；热修不要求临时拼一个新 runner 赶出“可用”结果。支持真实执行的入口，其实际日期/模式必须与输入契约一致。
- typed 列、JSON、哈希或来源校验冲突时按无效处理，先查明来源；不能任选一个真值覆盖其他证据。
- 遗留隔离采用追加式失效记录，保存报告 ID/原哈希、原因、范围、操作者、时间与审计引用；准入先检查失效记录，不原地重写不可变报告 JSON 或原哈希。相应持久化变更单独迁移并留恢复材料。
- 本文件拒绝新准入不等于自动撤销历史已采用方案。历史组合先逐个评估实际影响，日常交易门禁仍使用自己的事实依据。
- 准入校验必须由同一个服务函数提供，G6、G7、`can_switch_to_member_source`、查询接口与前端展示不得各自复制一套真值判断。
- 404、`NOT_FOUND`、`INVALID` 是终态；前端不得继续轮询或把错误吞掉后显示旧的成功结果。
- 现有测试中如存在 `g5_eligible_for_g6=True`、`avg_*=1.0`、`NOT_FOUND` 仍返回 200 的乐观断言，先逐条判定是产品缺陷还是测试预期错误；不得为了保持绿色保留乐观断言。

## 4. 回归验证清单

以下是实施时必须补齐/运行的验证，本次编写文档不代表已执行。

| 编号 | 用例 | 必须结果 |
|---|---|---|
| H1 | 查询不存在或不属于当前组合的报告 | 404，无虚拟结果或通过标记 |
| H2 | JSON 损坏、字段缺失、非法日期/矩阵 | 明确失败，不造日期/统计，不准入 |
| H3 | 双侧空样本或 coverage=0，动作一致率数学值恰为 1.0 | 业务验收为证据不足，不准入 |
| H4 | 真实来源标签但引用虚拟 ID/工作日日历/自造哈希 | 来源复核拒绝，原因可查询 |
| H5 | 没有真实执行器，版本字符串非空 | 启动被拒绝，不生成正式通过报告 |
| H6 | 只改 JSON 或 typed 列为 true，其他校验不通过 | G6 拒绝，G7 不显示可扩大范围 |
| H7 | 有效报告属于不同方案/日期范围，或已失效 | 不作为当前新准入依据 |
| H8 | 真实非空、来源完整、日期与阈值满足的报告 | 正常查询与准入；修复不误伤合法结果 |
| H9 | API 返回错误/无效矩阵 | 前端显示不可读或证据不足，不补零后标绿 |
| H10 | 缺报告但只恢复原方案人工暂停 | 保留与版本准入独立的恢复判定，不自动锁住全部日常买入 |
| H11 | 遗留报告盘点/隔离 | 原件、审计、组合与准入引用可追溯，无交易事实变更 |
| H12 | `can_switch_to_member_source` 读取同一份虚拟报告 | 拒绝切换，原因可查询，与 G6 结论一致 |
| H13 | `historical_replay` 携带 `G5_VIRTUAL_WEEKDAY`、`g5-virtual-*` 或自引用哈希 | 拒绝；真实重放证据完整时才允许 |
| H14 | 空 universe、零分母、全 HOLD 日 | 一致率为 `NOT_APPLICABLE`/证据不足，不当作 1.0 或有效样本 |
| H15 | 无真实执行器时打开双跑页 | 表单前显示能力缺失并禁用启动，不产生启动请求 |
| H16 | 查询返回 404 | 前端停止轮询，显示报告不存在/已清理，提供重新发起入口 |
| H17 | 首日通过、后续交易日失败 | 全区间不合格；界面不得只凭首日矩阵显示绿色通过 |
| H18 | 后端扁平矩阵、前端嵌套读取 | 契约测试锁定一种结构；不得补零后显示全零矩阵 |
| H19 | 现有测试中的乐观断言 | 逐条判定并修正；修复后测试不得再断言虚拟/空样本可准入 |

优先扩展现有 `tests/test_g5_dual_run_audit.py`、`tests/test_g5_dual_run_replay_framework.py`、`tests/test_g5_dual_run_report.py` 及相关 API/G6/G7 测试；补充 `auto_trade_dual_run.py::can_switch_to_member_source` 的切换来源回归；增加真实路由层错误回归、404 终态、能力发现与矩阵消费检查。先扫描现有测试中的 `g5_eligible_for_g6=True`、`avg_*=1.0`、`NOT_FOUND` 返回 200 等乐观断言，逐条判定是产品缺陷还是测试预期错误。算法框架测试通过不能代替正式 API 与最终准入回归。

## 5. 发布与验收边界

1. 上线 HF-01～HF-06 前，先冻结新的 G6 准入、扩大范围与来源切换；完成报告与准入保护后独立评审、回归、发布；记录当前版本和可恢复制品。
2. HF-07 先交付只读影响盘点；遗留数据的隔离/复核单独审核，并记录已引用报告的组合与处置状态。盘点完成并经审核后，才恢复新的准入。
3. 发布后验证“不存在/损坏/虚拟/空样本都不准入”及一条真实有效报告路径；未接通真实 runner 的环境验收明确拒绝启动路径，不强求凭空补一份成功报告。
4. 回滚可以关闭双跑启动/新方案准入、恢复兼容响应展示；不得重新引入乐观通过兜底，也不能删除审计或重写成交与资金事实。
5. 热修完成凭代码差异、回归结果、部署版本及影响盘点验收；目标设计里的真实双链平台、版本来源和交互原型仍分别按自己的里程碑交付。
