# 多标签页、日期并发与失败重试验收（2026-10-24）

本轮只修改“检查与对账”前端读取及重试处理，后台校验、确认与放行规则保持原样。最终浏览器验收通过；main权限、审计水位和连续核验日期均未变化。

## 修复内容

- 原订单来源的旧失败及旧finally原来缺少完整请求代次判断，可能覆盖新来源或结束新加载状态；现在成功、失败、结束均仅接受当前组合与最新请求。当前读取失败时清除旧来源候选并提供重试。
- 页面全量读取和作业单独刷新共用作业请求代次，旧全量结果不能替换新作业、队列或错误状态。材料刷新结束也检查最新报告请求，避免旧请求结束新日期加载。
- 历史多页恢复在后续页失败后保留完整恢复页数，原条件重试从新审计水位完整重建，不退化为第一页。
- 引擎状态读取增加组合、请求代次和返回身份检查；首次失败也展示明确只读重试入口。切换与准入操作函数未改变。
- 仅11个检查相关GET关闭同URL在途请求合并。A→B→C→A或返回原订单来源时会真正重新读取，而非复用最早A的挂起请求。一般GET仍保留原全局合并机制，所有写接口契约保持原样。

## 验收覆盖与边界

同一个BrowserContext中实际打开两个标签页；B通过window.open打开，初始复制sessionStorage并共享cookie/localStorage。随后分别浏览、切组合、改筛选并同时刷新，确认两页各自保留组合、交易日和筛选。浏览位置、分页恢复及作用域基础测试沿用上轮并纳入本轮回归。

本地业务组合实际只有main。第二组合B（900001）仅由验收浏览器GET响应提供，数据映射到main只读响应并替换组合身份；没有新建或修改业务组合。因此第二组合验证的是浏览状态和异步隔离，不证明第二套真实账本内容。
