# 验收服务端强制只读与异常关联来源标注（2026-10-24）

本轮按用户授权，仅增强验收进程的防误写边界并追加异常来源说明；交易校验、核对通过与放行规则未修改。

## 服务端保护

1. 专用启动入口 `scripts/serve_inspection_acceptance.py` 默认强制只读，删除原先对核对、修复、补证、登记等POST的白名单。所有非GET/HEAD/OPTIONS请求在路由处理前返回423，明确 request_registered=false、task_dispatched=false。不存在HTTP参数/请求头可关闭保护。
2. 同一验收进程注册SQLAlchemy Engine类和Session事件：ORM新增/修改/删除不能flush，Core/直接SQL写语句不能执行。覆盖主连接池、控制平面及后来创建的Engine，防止历史GET中的隐藏巡检/过期写入绕过HTTP层。只读状态接口在中间件直接响应，不受前端根挂载遮挡。
3. 任务创建、幂等创建和worker启动入口在打开会话/启动线程之前检查验收只读状态。未启用验收模式的普通应用进程不受影响，已有业务规则继续生效。
4. 专用lifespan只初始化连接并读取迁移版本，不启动调度、种子、清理、恢复或修复循环。无参数启动和旧 `--no-background-jobs` 参数启动均强制只读；没有开启后台作业的参数。启动失败不会切回普通业务入口。

保护由服务端承担，不依赖前端禁用按钮、浏览器拦截器或代理。当前验收服务可查看结果和回查原请求，登记、重检、修复、审核等修改动作均明确拒绝。数据库保护限定SQLAlchemy管理的应用会话/语句，不是修改数据库账号权限，也不宣称限制独立运维进程；本次被明确授权的迁移和来源标注通过单独离线脚本完成。

## 异常关联保留与来源

新增迁移78，只创建不可改写的来源备注表。按用户授权，为既有异常请求追加一条 `ACCEPTANCE_ROUTE_TEARDOWN_LEAK` 备注：标明本地界面验收关闭发起页时，浏览器拦截撤销造成来源重检登记意外到达后端；关联已有任务，不代表正式业务发起、对账通过或交易授权。备注保留说明人、时间和上一轮事故证据引用。

原请求键、操作人、日期、登记结果JSON、任务关联和创建时间均未改；没有删掉异常回执。精确GET返回来源备注，“原对账请求与任务”卡片直接显示“验收产生的请求关联”和说明。备注追加后也不能通过ORM修改或删除。
