# 断网、唤醒与后端短暂不可用后的恢复（2026-10-24）

本轮只改前端生命周期、读取保护和提交交互。恢复过程不调用任务提交、恢复、补单、账户基线接受或准入解冻接口；后台校验与放行规则未改。

## 修复行为

- 浏览器offline事件立即使旧依据、冻结确认和勾选失效，废止断网前的在途读取，停止离线轮询。断网状态下，即使此前请求晚返回成功，也不能解除过期保护。
- online事件立即只读核实，连续online/focus/pageshow合并在途检查，不重放写请求。通信恢复或版本未变化不自动清除过期标记，需完整重新读取并重新同意。
- 保留focus/visibilitychange并增加pageshow处理。检测到至少60秒的非计划停顿或时钟倒退时，先废止旧依据和旧请求，再检查最新状态；定时器恢复或审核动作本身也会检查，覆盖没有焦点事件的唤醒路径。
- 计划中的30/60/120秒网络退避不被误判为休眠。离线时暂停，重连或返回时立即核实，持续后端错误按未知处理，保留手动重新读取入口；失败及晚返回不能授予审核资格。
- 提交前的即时检查与原有报告/范围版本约束保留。网络离线时写请求在fetch前明确拒绝，不加入恢复队列、不自动重试。
- 修复提交增加同步在途锁，防止连续点击重复派发。提交响应丢失或5xx时清除勾选，提示先读取原任务记录并提供GET入口；已明确接收但后续读数失败时说明原任务已接收，不混为提交失败。
- 同一页面对结果不明的提交重新预览并明确确认时，保留原冻结请求和幂等标识；不会因重开确认生成另一批范围。成功或明确的计划过期/快照变化拒绝后才允许重新准备。作用域变化不恢复旧确认，刷新/重新进入只读任务历史，不重放写入。
- 日期、筛选、位置与审核理由继续保留，业务勾选必须重新确认。

## 验收方式与边界

浏览器固定加载最终dist资源，接口使用实际main和安全只读后端。断网使用Playwright浏览器上下文离线模式，不改变电脑网络；后端不可用由浏览器定向注入503，不停止服务。

休眠使用Chromium页面冻结/恢复以及浏览器内Date.now增加五分钟来模拟停顿，并触发页面恢复事件；另由隔离测试覆盖没有focus/pageshow的逾期定时器和提交前拦截。没有使电脑实际休眠，也没有修改系统时间。因此验证的是恢复事件/调度与前端保护，不声称做了物理电脑休眠测试。

任务“已接收但响应丢失”只在浏览器中模拟：来源页使用隔离修复计划/任务列表，POST被记录为模拟接收后直接中断响应，未转发后端。随后GET可读取该模拟原任务。没有创建真实后台任务。

## 最终结果

浏览器5条场景通过：真实离线事件即时失效及停止轮询；重连立即GET并拒绝断网前晚返回；后端持续503与恢复后完整读取；冻结/五分钟停顿后重新读取；响应丢失后重连/恢复不重提且GET原任务正常。浏览器模拟提交始终1次，全部恢复动作没有新增提交。

隔离回归覆盖休眠无焦点事件、BFCache恢复、旧响应、重连事件合并、持续失败退避、离线成功不能接受、离线写在fetch前拒绝、已勾选确认撤销、原理由保留、连续点击同步锁，以及明确人工重试时请求身份不变。最终17个测试文件177项通过（70.56秒），生产构建通过（34.73秒），git diff --check通过。

预期离线网络失败与受控503分别记录在browser-result.json；实际HTTP错误、浏览器异常和非预期写请求均0。
