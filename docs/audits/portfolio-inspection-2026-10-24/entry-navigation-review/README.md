# 检查与对账：查看、核查与返回入口走查

2026-10-24，main组合，最终生产前端资源。后台校验和放行规则不改。

已复现的旧行为见[复现结果](reproduced.json)：每日对账读取期间抽屉未打开；全局历史的09-30筛选在查看标的相关历史后变为空。对应修复为立即打开并反馈读取、按上下文保存浏览状态。另修复列表分页保留、详情对象滚动隔离、运行审核绑定详情承载、来源刷新反馈、异步日期乱序/关闭后重开及子浮层快速返回焦点时序。

## 入口矩阵

| 模块 / 入口 | 承载与返回检查 | 覆盖 |
| --- | --- | --- |
| 页面说明 → 开始引导 → AI解释 | 独立抽屉，逐层关闭回原位置 | main实测 |
| AI辅助 → 进入对应修复步骤 | 只进入既有处理引导，返回AI；不提交分析 | main实测 |
| 数据汇总 → 标的证据 | 独立详情、保留搜索；不同对象不共享滚动 | main实测＋公共抽屉测试 |
| 标的证据 → 相关历史 / AI | 返回原标的详情与滚动，关闭回原搜索列表 | main实测 |
| 最终运行审核 → 处理运行绑定 | 独立绑定详情，返回仍为最终审核，不切成另一引导步骤 | main实测＋回归测试 |
| 运行审核 → 历史缺口 | 独立缺口详情，返回审核原位置，确认持续禁用 | main实测 |
| 每日对账 / 日期选择 | 请求开始即开；加载、失败和原日期重试明确；旧响应不覆盖新日期、关闭后不重开 | main正常/模拟503实测＋乱序回归 |

| 历史缺口 → 三类来源方法 / 原订单 / 相关历史 | 查找说明可展开；空原订单有返回出口；关联历史返回保留展开 | main实测 |
| 历史缺口 → 无法恢复处置条件 → 历史 | 独立条件查看，原路返回，不申请或接受基线 | main实测；申请草稿由隔离测试覆盖 |
| 自动作业 → 主核查 / 逐日核查 | 居中快捷核对；显式返回按日核对保留下层日期 | main实测 |
| 作业、缺口与原订单来源刷新 | 有加载反馈；读取失败可见且可原地重试 | main实测＋模拟503 |
| 快捷核对 → 原订单 / 本日历史 → 返回 | 日期与原报告范围保持，焦点恢复到快捷核对原入口，Esc只退本层 | main实测＋立即恢复焦点断言 |
| 全局历史 → 批次 → 原材料 | 独立详情、确切材料，逐层返回列表筛选及滚动 | main实测 |
| 全局历史 ↔ 标的相关历史 | 各范围的草稿/已应用筛选及滚动隔离；水位不变重开保留已加载页 | main实测＋分页回归 |
| 数据中心 / 策略规则跨模块查看 | 明确面包屑及返回入口；数据证据独立详情；返回恢复搜索、绑定详情与审核位置 | main实测 |
| 引擎专项 / 引擎运行 | 打开、只读刷新、关闭返回 | main实测 |
| 双跑历史报告预览 | main真实无可选报告，检查空态与返回；独立详情、缺失/矛盾返回测试通过 | 隔离HTTP测试，未伪造生产报告 |

同一回调承载的逐日行、工作单及其他重复对象按入口类型复核；实际可用状态走查与条件不具备的隔离测试分别记录，不把空态认作报告验收通过。提交修复、重检、补证提交/审核、运行确认、接受基线、启动/回滚/解冻引擎等写操作没有在main点击。
