# 自动对账旧接口：原请求关联、幂等与只读恢复（2026-10-24）

## 完成范围

- 旧 `reconciliation-job/recheck` 接口接受 `request_key`，新版前端每次新请求都提供该键。新增回执表以组合和请求键唯一登记，保存操作人、请求日期、登记结果和任务关联。相同键换日期或操作人返回冲突。
- 先声明回执唯一键，再消费来源/登记原有重检需求；所有登记在同一事务提交。重复请求直接读取回执，不再次推进需求版本或派发。旧任务复用也显式关联；新任务身份在任务创建/启动前持久保存，覆盖任务已提交、HTTP响应丢失的窗口。
- 精确 GET `/portfolios/{portfolio_id}/inspection/reconciliation-job/requests/{request_key}` 执行原有组合鉴权，只查询回执及其确定任务。没有调用含巡检/过期写入的通用任务查询，不消费事件、不创建/恢复工作单或启动任务。没有用日期/名称/最新任务猜测关联。
- 前端 POST 前保存组合、原键、日期到 localStorage 并读回，Web Locks 覆盖登记和提交。刷新、关页、新标签、同浏览器配置重开从原键只读恢复。存储/锁异常时停止提交；404、503不删除原记录或更换键。精确404后，仅本人明确点击才能按原键和原日期再发送；已有未结束回执只读，不再 POST。
- “执行与对账”和“自动对账作业”提供原请求恢复卡及重新读取入口；跨标签存储通知、焦点/联网/页面恢复及可见时10秒只读补查发现回执，不要求发起页继续存在。延迟旧组合结果丢弃。登记完成不等于核对通过或授予权限。
- 需求已登记但没有确认任务存在时明确等待派发，不伪称已找回。只读恢复不会补派/重启任务，派发失败也不会被读取动作隐式重试。保留原自动对账作业和人工核查路径。

## 兼容及边界

缺少请求键的旧客户端保留原契约；既往无请求键的提交无法追溯生成精确关联，新版前端已统一带键。持久恢复限定为同源、同浏览器配置并保留网站存储；跨设备、清空存储不在此承诺内。任务/需求登记和校验仍走原实现，交易校验、核对通过条件、本人审核及放行规则均未修改。
