# 发起页关闭后的接收页独立证据检测（2026-10-24）

本轮把检测责任补到“检查与对账”的接收页。它通过现有GET接口自行读取后台证据，不再依赖发起页存活、轮询或发送完成通知。只改前端，未增加后台任务、迁移或放行规则。

## 实现

- 以当前页面实际完整读取过的运行审核、自动对账作业/队列和所选交易日报告为基准，保存比较用的版本标识。后台监测结果不直接替换页面报告、不自动确认权限。
- 页面可见且已知有queued/running任务时，每次检查完成后5秒再检查；平时30秒。最多一组检查在途，不叠加轮询。每组仅GET运行依据、自动作业和所选交易日报告。
- 任务完成、失败、部分产物更新、工作单证据代次或所选报告版本变化，均使旧依据失效；任务“结束”不被解释为“通过”。比较证据/报告版本、真实任务状态和处理代次，不用generated_at、心跳或下次扫描时间制造变化。
- 页面挂起时停止定时检查并废止旧请求；重新激活立即独立核实。离开检查模块、关闭页面或切换组合时清理定时器与监听，旧响应不得影响新上下文。
- 检查期间暂停审核提交并显示核实状态。发现变化或读取失败，使用原有过期提示、清除勾选与冻结确认，保留理由、日期、筛选和位置。重新完整读取成功后才解除失效状态，不自动同意或提交。
- 最终审核提交前再次GET核验，覆盖两次定时检查之间的完成窗口；发现变化或无法核实，停止提交。后台原有版本核验、证据校验和放行条件继续保留。
- 网络错误按未知处理并保留过期保护，自动检查退避30/60/120秒，最多120秒；返回页面或手动重新读取可立即核实。恢复通信本身不会自动解除旧报告的过期标记。
- 同时补了新页面组合尚未加载时的保护：不为组合0挂载检查或监测，不发送无效组合请求。

## 验收边界

实际main、后台只读验收服务及真实GET作为基础。为保持当前任务、审计和交易状态，本轮任务计划、来源事件及提交/完成结果只在浏览器响应中隔离模拟；模拟修复发起页还隐藏了其浏览器内的历史任务列表，避免原有任务干扰新任务前置条件，业务库历史记录未改。2次提交POST由浏览器直接响应，绝不转发后台；全部其他非GET/HEAD/OPTIONS请求阻止。

运行时后端优先代理Vite。本轮浏览器脚本明确从本地dist直接提供入口与静态资源，核查的是最终生产构建，接口仍读原只读后端；未改服务配置或重启。构建资产指纹另存built-assets.json。

因此本轮证明接收页独立检测与交互保护，不声称实际启动或完成了后台修复/对账任务。真实后台作业继续关闭。来源页关闭和切到设置为实际浏览器操作；接收页挂起/返回使用可控visibilityState及对应事件模拟，另有定时器隔离回归。接收页可见且网络正常时按5/30秒节奏检测，后台挂起/浏览器限速时以重新激活后的立即检查补足，不是服务端实时推送。

## 最终结果

浏览器5条组合场景通过：

1. 正常修复入口模拟提交后关闭发起页，接收页完整读取运行中基准；任务完成后由接收页自己的GET发现变化。发起页关闭后无继续轮询。
2. 正常自动对账入口模拟提交后，发起页切到设置；接收页独立发现失败/结果变化。发起模块不再读取对账/运行依据。
3. 接收页挂起时不轮询；挂起期间任务结果变化，返回后立即检测，无需发起页通知。
4. 独立检查遇到受控503时暂停旧审核，提供原位置重新读取，不把旧成功当新结果。
5. 没有已知运行任务及来源通知时，接收页通过平时30秒检查发现新的后台依据。
