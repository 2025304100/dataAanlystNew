# 同一组合双标签的报告失效与重新读取（2026-10-24）

本轮补齐同一组合跨标签的结果失效通知与前端审核保护。只修改前端读取、通知和交互保护；后台版本核验、放行规则和业务请求内容不变。

## 行为与职责

- 相关更新请求开始前立即发出失效通知，成功后再次通知。接收页显示“当前结果已过期，请重新读取”，不能继续使用旧依据审核。写请求失败也保留保守的失效状态，通过重新读取恢复，不将失败视为已经更新成功。
- 通知仅含组合范围、随机事件/来源标识和时间，不传报告、权限、审核理由或浏览草稿。使用BroadcastChannel与storage事件双通道，重复通知去重；标签页重新激活时核对持久化通知，补收挂起期间遗漏的变化。
- 组合专属更新只影响该组合；行情、评分、策略及组合数据修复等共享输入保守通知所有组合，不猜测依赖关系。原有sessionStorage浏览状态保持按标签页、组合和上下文隔离。
- 异步修复、行情/外部同步、评分任务在后续读取到进度或完成变化时再次通知；读取到自动对账作业及队列变化也通知所属组合。单次提交返回不被当作后台任务已经完成。
- 主工作台收到通知后废止在途读取代次、原确认弹窗、勾选和冻结依据；审核理由、日期、筛选和位置保留。重新读取全部当前依据成功且期间无新通知，才清除该页过期标记；失败或又有更新时继续保留。不会自动勾选或提交审核。
- 原订单关联、快捷核对和账户覆盖预览也独立失效。原订单撤销未提交的确认，保留说明；快捷核对保留交易日，提供只读刷新；覆盖预览清除旧快照，不会自动接受或启用范围。
- 相关审核入口同时检查即时失效引用，防止通知到达与界面渲染之间继续提交。状态、待办、运行绑定和覆盖读取也关闭同URL在途合并，避免刷新继续复用更早请求。一般GET仍保持原合并策略。

## 验收方式与边界

两个标签页均使用实际main和真实只读接口，不使用第二组合替身。为保持审计及交易状态原样，A页实际点击重检入口所产生的2次POST全部由验收浏览器直接模拟响应，绝未转发后端。该方式验证生产前端请求开始/成功通知、B页失效、重读和乱序保护；不声称在业务库实际重检或更新了行情。共享输入变更通知和报告版本使用浏览器受控输入；实际更新范围分类、任务进度通知及请求内容保持另由隔离测试验证。

最终浏览器6条组合场景通过：

1. A开始重检，B立即提示过期并保留自己所选09-30日期；A存储通知不可用时，BroadcastChannel仍送达。
2. B重新读取遇到受控503，过期标记继续保留，不恢复旧审核资格。
3. B刷新尚未完成时A再次重检；B的旧读取晚返回不能消除新过期状态；A更新完成后仍要求重读。
4. 最新依据完整读取后才解除标记，原日期和本日历史入口保持可用；无审核提交。
5. 共享输入通知触发过期，刷新保留510300筛选；其他组合专属通知不影响main。
6. BroadcastChannel不可用时，storage事件仍完成失效通知与只读刷新。

隔离回归还验证：已经打开并勾选的对账审核弹窗被撤销；重新读取后须重新同意、保留原理由；原订单确认撤销；快捷核对重新读取；历史分页与日期乱序保护继续通过。最终16个测试文件154项通过（60.97秒），生产构建通过（33.68秒），git diff --check通过。

本轮针对同源浏览器内使用新版前端的标签页。通知不是后端推送或跨设备同步服务；后台更新通过页面观察到任务/作业变化再发出通知。后台原有版本与证据核验仍作为最终提交保护，未以通知代替后台校验。已经打开旧资源的标签页需刷新加载本次前端。
